# 重跑任务库（guji job）

2026-10-25 起，重跑、A/B、评测一律**交到任务库**，不再靠传话发需求单。任务库在 Neon 中心库的 `jobs` schema 里，
谁交了什么、谁在跑、跑到哪一步、结果存在哪，所有会话都能用 `guji job ls／show` 看到，跑完不用通知谁。

代码：`open_guji_cv/jobs/`（`spec.py` 定义与指纹、`store.py` 读写库、`runner.py` 执行方、`cli.py` 命令行）、
`scripts/guji_jobs.sh`（云端启动器）、`scripts/rerun_prep.sh`（执行方每条单的准备）。

## 为什么不用现成的编排框架

Airflow、Prefect、Dagster、Temporal、ClearML 都要一台常开的调度服务器，我们的执行方是会休眠、会被回收的云会话，
没有常开的机器。业界在「只有 Postgres」时的通行做法是**拿 Postgres 当队列**：`SELECT … FOR UPDATE SKIP LOCKED`
领单，加租约心跳防会话死掉（PgQueuer、Oban、Graphile Worker、river 都是这一套）。我们照这个模式写了约 1300 行（含表结构、命令行、启动器），
不引新依赖、不起服务；pgmq 扩展 Neon 不提供，DBOS 之类需要把代码改造成它的工作流写法，都不划算。

## 怎么交任务

云端会话用 `guji_jobs`（Default 环境装好的启动器，总跑 dev 最新的 jobs 模块）；本机用 `guji job`（装了含本模块的 cv）。
先 `export GUJI_JOBS_WHO=<你的名字>`（如 A24），提交人和执行方都记这个名字。

```bash
# 从 seed_admit 起重跑 vol10，语料 16、字形库钉 2，开跑前人裁必须 146 格，跑完和 main 比
guji_jobs submit --book vol10 --cv v0.5.16 --from seed_admit --corpus 16 --glyph-pin 2 \
  --human-chars 146 --compare-to main --change seed-c16 --why "A24：语料 16 对 vol10 seed 的影响"

# 只重落 seed_admit；册钉的语料号和这版代码的字组文件对不上时，照 A31 10-25 的跑法放行语料漂移
guji_jobs submit --book vol10 --cv v0.5.16 --from seed_admit --to seed_admit --env GUJI_CORPUS_DRIFT=warn \
  --human-chars 146 --compare-to main --why "…"

guji_jobs submit spec.json          # 也可以写成 JSON（字段见 jobs/spec.py 模块头）
guji_jobs submit … --dry-run        # 只看规整后的定义和指纹，不交
guji_jobs submit … --priority 10    # 插队（越小越先，缺省 100）
guji_jobs submit … --after 12       # 等 #12 成功后再跑
guji_jobs submit --kind ab … --compare-to job:12     # 和 #12 存的包比
guji_jobs submit --kind eval --cv dev --run "eval run --json"
```

**同一配置只跑一次。** 提交时把定义规整成标准形（缺省值补齐、cv 的 tag／分支解析成 40 位提交），算指纹；
已有同指纹的单在排队、在跑或已成功，新提交记成 `duplicate`，指向那条，直接看那条的结果。
`why`、`priority`、`output`（存包名、说明）不进指纹：换个包名还是同一次计算。确要再跑加 `--again`。

**cv 必须写明。** tag、分支、提交都行，提交那一刻解析成提交号存下来；`dev` 也会钉成当时的 dev 头。

## 怎么看

```bash
guji_jobs ls                  # 排队和在跑的，加最近结束的 10 条；--book vol10、--all、--mine
guji_jobs show 12             # 定义、每次领单、进展流水（每步起止、耗时）、结果（包标签、R2 位置、对比报告开头）
guji_jobs show 12 --log       # 带日志尾巴
guji_jobs wait 12             # 等到结束；成功退出码 0
guji_jobs cancel 12           # 排队的直接取消；在跑的一分钟内停
guji_jobs retry 12            # 失败、拦下、取消的重新排队
```

状态：`queued` 排队 → `running` 在跑 → `succeeded`／`failed`／`blocked`（开跑前检查没过，比如人裁格数不对）／
`cancelled`；`duplicate` 是重复提交。时间按洛杉矶时间显示。

## 执行方怎么跑

定时例程每隔一段时间看库里有没有排队的单，有就开执行会话。执行会话只做一件事：

```bash
guji_jobs start      # 后台起执行方，跑到队列空就退出；--idle 30 空了再等 30 分钟
guji_jobs follow     # 跟着看日志，执行方退出或到时（缺省 110 分钟）返回，没退出就再 follow
```

每条单一口气跑完，中间不问人：

1. **prep**：`rerun_prep.sh <册> --cv <提交> [--corpus] [--glyph-pin] [--pin-args]`（同一会话已按同一配置备过就跳过；
   备过别的配置先 `--reset` 把本机册配置、钉子账还原）；
2. **cv**：核对 seed 检出正是单上的提交，记下版本号；
3. **base**：从中间某步起跑时先取铺底包（缺省 main）；
4. **check**：单上写了 `human_chars` 就数人裁绑定格数，不等就 `blocked`，不跑；
5. **run**：`guji pipeline … --pages all --no-pack [--from] [--to] [--force]`，`no_reuse` 时带 `GUJI_NO_REUSE=1`；
   command／eval 逐条跑 `run` 里的 guji 命令；
6. **compare**：给了 `compare_to` 就取那个包、`guji products diff`，报告开头记进结果；
7. **push**：`guji products pack push --change <change 或 job号>`，包标签和 R2 前缀记进结果。**永不标 main**，
   标 main、推中心库仍由用户亲口说。

实测（10-25，测试分支）：vol10 只重落 seed_admit，领单到存包 3 分半（同会话已备过，准备跳过）。

执行方每分钟心跳续租（租约 10 分钟）。会话死了，租约过期后下一个执行方把单收回重排，最多领 3 次。
同一册同时只跑一条（唯一索引兜底）；同一会话优先接上一条同册的单（省准备）。准备、取包、存包失败算环境问题，
自动换会话重试；跑 pipeline 失败、检查没过不重试，等人看。

## 表

| 表 | 一行是 | 要点 |
|---|---|---|
| `jobs.job` | 一条任务 | `spec`（标准形 JSON）、`spec_hash`、`status`、`priority`、`depends_on`、`duplicate_of`、`stage`／`progress`（当前进展）、`error` |
| `jobs.attempt` | 领一次单 | `worker`、`session`、`cv_commit`、`heartbeat_at`、`lease_until`、`outcome`、`log_tail` |
| `jobs.event` | 一条进展 | 每步开始／完成（含耗时）、警告、出错；只追加 |
| `jobs.result` | 一个结果 | `pack`（包标签、`r2:` 前缀）、`diff`（报告开头）、`check`（人裁格数）、`output`（命令输出尾巴） |

建表：`guji job init`（幂等，`open_guji_cv/jobs/schema.sql`）。测试用 `GUJI_JOBS_BRANCH=ci` 连 Neon 的 ci 分支。

## 不做的

- 不经 guji-data Worker：执行方和提交方都在有 `NEON_DATABASE_URL` 的环境里，直连（443 桥）更简单。以后要给
  没有库凭据的地方（网站、本机）交单，再在 Worker 上加 `/v1/jobs`。
- 不在库里存凭据：`env` 只收 `GUJI_` 开头、名字不像凭据的变量；写令牌由执行会话自己的环境给。
- `run` 不经 shell，只许读和跑的 guji 子命令，不许 push／sync／promote／--main。
