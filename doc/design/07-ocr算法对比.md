## 一、为什么要有这个对比

我们这条路（`open-guji-cv`）赌的是「定死字体 + 像素级比对」比「混合训练集的神经网络」准
（[04-横排ocr.md](04-横排ocr.md) 用户原话）。这个赌注到今天**没有任何数字支撑**。北行日录
是眼下唯一同时有「清晰图 + 可信文本 + 我们自己跑通的切分线」的书，是验证这个赌注的第一块试金石。

所以本对比的**主问题不是「谁第一」**，而是：

> 在一本字体单一的现代印刷古籍上，字形比对路线能不能打过通用 OCR 和大模型？
> 如果打不过，差在哪一类字上？

评测框架要能回答「差在哪」，不能只吐一个总分。

### 3.2 切页锚点

校對本里有 36 行是纯数字页码（`1940`…），是原书页码。但 79 逻辑页只有 36 个页码锚点

2. 页码锚点只能定到「原书页」，要再分成上下两个逻辑页，靠

⚠️ 实查踩到的坑：`labels.jsonl` 里的 `line_idx` 是**页内局部行号**，不是校對本全局行号。
拿它当全局行号去索引校對本，第 90 行以后会全部对空——写切页脚本时必经之路，先记在这里。

> 注意：这里用 labels.jsonl **只是借它的行→页映射做切分**，字符金标本身仍取校對本原文，
> 符合「校對本为唯一金标」的裁定。

### 3.3 噪声隔离：五类必须从分母里择出去

| 类 | 全书 / 本窗口 | 为什么不能计分 |
|---|---|---|
| **校勘記行** | 5 行 / **0** | 现代编者所加，**页面图上根本不存在**。任何引擎都不可能「识别」出来，计进去是纯粹的假失分 |
| **正文里的脚注标记** | ①② 12 处 / **0** | 同上，编者插入 |
| **小注括号 `【】`** | 46 对 / **23 对** | **实查 labels.jsonl：`【` 出现 0 次**。原书是双行小字，括号是编者为在纯文本里表达版式而加的（详见 §4.4） |
| **页码行** | 36 行 / 5 行 | 书口页码，是否计入取决于引擎是否被要求读书口。**统一不计**，另作 §4.4 单项报 |
| **校對本自身的换行** | 全文 | 06 卡实测逐列 94.3% 相等，剩下 5.7% 主要是校對本错。分行指标改用列边界并报（§4.3） |

选定的窗口（页 9–18）**前两类恰好为零**——这是选它的附带好处：本轮不必依赖排除逻辑
的正确性就能得到干净数字。但排除表仍要实现，因为 `【】` 这一类在本窗口有 23 处（46 个括号字符），
且将来换窗口/扩样本时前两类会回来。

排除表做成 `gold/exclusions.json`，是**框架的一等公民**，不是临时 hack。每份报告都要显式
写明「排除了 N 字的编者附加内容」——否则三个月后没人记得这个数是怎么来的。

```json
  "lines": ["三日乙卯，晴。習儀驛中已不及，習於參政府。梁郎中", "…"],
```

## 四、指标定义

所有指标建立在「金标串 vs 引擎串」的**编辑距离对齐**上（Levenshtein，返回对齐路径而非仅距离）。
一次对齐，五类指标全从同一条路径上读出来——不允许各指标各对齐一次，那样数字之间会互相矛盾。

### 4.1 字符层：三级准确率

用户明确要求区分「繁体归一化后一致」和「完全不一致」。定成三级：

| 级 | 定义 | 记作 |
|---|---|---|
| **L0 严格一致** | 码位完全相同 | `exact` |
| **L1 字形等价** | 异体/繁简归一化后相同（`攷`≡`考`、`録`≡`錄`） | `variant` |
| **L2 不一致** | 归一化后仍不同 | `wrong` |

```
严格字符准确率  CAR_strict = exact / (exact + variant + wrong + del + ins)
宽松字符准确率  CAR_loose  = (exact + variant) / 同上
字形分歧率      VDR        = variant / (exact + variant)
```

**VDR 是本对比最有价值的一个数**，它单独回答一个问题：引擎错的是「不认识这个字」
还是「认识但吐了另一个写法」。大模型的错多半是后者（训练语料以简体/通用繁体为主），
而我们的路线赌的正是**忠于刻本字形**（见记忆 `feedback_step56_only`「方针：忠于刻本字形」）
——这一栏上我们应该赢，赢不了说明字形库没起作用。

归一化表**不能现编**。用：Unicode 兼容分解 + Unihan `kSimplifiedVariant`/`kTraditionalVariant`
+ 本书自己的异体对照（从 `config/fonts/charset_bxrl.txt` 起）。表落成 `gold/variant_map.json`
并**入 git**，因为换一张表所有历史数字全部作废。

### 4.2 标点层：独立于文字

把标点从正文剥离成两条流（用户选项一）。原因：原刻本无标点，大模型会自行断句，
PaddleOCR 基本不吐标点——混在一起算，这一项差异会淹没字符差异。

```
标点 P/R/F1   : 以「(位置, 标点)」为单位。位置按其前一个汉字在对齐后的索引定
标点位置容差  : ±1 字（换行处的标点归属有歧义）
逗号/句号混淆率: 单独报——「，」↔「。」是断句品味差异，不是识别错误
```

⚠️ 校對本「小注前后的、。被省略」（06 卡）。标点指标**只在 A 级页**上算，且
小注边界 ±2 字内的标点差异标 `disputed` 不计分。

### 4.3 分行层

用户选了分行一致率，但 06 卡明确「校對本的换行不可靠」。所以分行指标**两口径并报**：

| 口径 | 准 | 用途 |
|---|---|---|
| `line_vs_witness` | 校對本换行 | 用户要的那个数，但带噪声 |
| `line_vs_column` | `labels.jsonl` 的 col 边界（= 图上真实列） | 干净，作真值参照 |

两者差值本身就是「校對本换行有多不可靠」的量化——**顺手把 06 卡的定性结论变成数字**。

指标：行数相等率、行边界 F1（边界位置按字符索引，容差 0）。

### 4.4 注文层级与其他标记

| 项 | 本窗口金标量 | 指标 |
|---|---|---|
| 双行小注 | **23 处** | 区间 F1（漏注 / 误注 / 边界偏移三分） |
| 引号 `「」` | 2 对 | 样本太少，报 `n/a` |
| 书名号 `《》` | 0 对 | 本窗口无，报 `n/a` |
| 书口页码 | 5 处 | 单独报「是否读出 + 是否放对位置」，**不计入主分** |

#### ⚠️ `【】` 不是页面上的字符——评分必须按区间而非字符

实查 `labels.jsonl`：20852 条字位标注里 **`【` 出现 0 次**，而校對本有 46 处。
原因是原书用**双行小字**表示夹注，`【】` 是现代编者**为了在纯文本里表达这个版式而加的标记**。

这有两个直接后果：

1. **`【】` 本身必须进 §3.3 的排除表**，和校勘記、脚注标记同类——否则每处小注都会
   凭空判引擎多漏 2 个字符，46 处就是 92 个假失分；
2. **注文指标只能量「区间」，不能量「括号字符」**。判据是引擎**有没有把这段标成注**
   （用任何它自己的表达：缩进、`<note>`、小字标记、`【】` 都算对），落到金标字符区间上算 F1。
   P2 档 prompt 要明确告诉模型「用 `【】` 包裹夹注」，把表达方式统一掉，否则量的是格式巧合不是能力。

注文层级是古籍数字化的关键结构信息，这一栏大模型大概率领先（它能从语义判断），
PaddleOCR 大概率归零（它只吐字）。这一栏的分差要单独看，别让它污染字符分的解读。

### 4.5 成本与速度

对比不能只看准确率——大模型准但贵，本地路线糙但免费。每个引擎记：

```
单页耗时（秒）、单页 token 数（输入/输出）、单页成本（USD）、
全书外推成本、失败/重试次数
```

10 页的成本可以忽略，所以这一栏要**外推**报：单页成本 × 79 页 = 本书成本，
再 × 索引里的书量 = 铺开成本。这一栏是路线选择的真正依据——
准确率差 1% 也许可以忍，成本差两个数量级不能。

## 五、大模型的 prompt 设计

用户要求「不但要文字，还有标点、分行排版」。这里有个**必须避开的陷阱**：

> 让大模型同时做「识字」和「断句排版」，会让它为了让句子通顺而**改字**。
> 这样测出来的字符准确率是被语言模型先验污染过的，测不出「看图认字」的真实能力。

所以设计成**两档 prompt，同一批图各跑一次**：

| 档 | 要求 | 测什么 |
|---|---|---|
| **P1 忠实档** | 只输出图上所见字符，逐列换行，**不加标点、不改字、不通顺化**，看不清的用 `□` | 纯视觉识字能力 → 喂 §4.1 字符指标 |
| **P2 排版档** | 在 P1 基础上加标点、识别双行小注、还原段落 | 结构化能力 → 喂 §4.2-4.4 格式指标 |

两档的差值 = 该模型「语言先验帮了多少 / 骗了多少」。这个差值对我们有直接用处：
它量化了 [05 方案](05-三模式管线方案.md) 里「用大模型做上下文裁决」那条路的收益上限。

输出统一要求 JSON（避免解析 markdown 的脏活）：

```json
{"lines": ["…", "…"], "uncertain": [{"line": 3, "col": 7, "alts": ["璋","章"]}]}
```

`uncertain` 字段是**白送的**：能拿到模型自报的不确定位置，就能算「置信度是否可用」
——这直接决定了能不能把大模型当作管线里的复核环节，而不是替代环节。

**公平性约束**（写进任务书，不许各人各调）：
- 同一张图、同样分辨率，不做任何针对性预处理；
- temperature = 0 / 等价设定；
- 每页独立调用，**不给跨页上下文**（否则模型会用前页内容补后页，测的就不是 OCR）；
- 同一 prompt 文本，只翻译不改写。

### 5.1 重复次数：单次全跑 + 稳定性探针

设计稿初版写「每模型跑 3 次取中位数」，用户质疑为什么要 3 次——**这个质疑是对的**，改掉。

要 3 次的**唯一理由**是 temperature=0 并不保证确定性（MoE 路由、批处理次序都会引入抖动），
不验一下就不知道单次数字能不能信。但这是「**测一次方差**」的需求，不是「**每个数都付 3 倍钱**」的理由。

改成：

| | 跑法 | 用途 |
|---|---|---|
| **主跑** | 10 页 × 2 档 × 1 次 | 出所有指标 |
| **稳定性探针** | **挑 1 页** × 2 档 × 3 次 | 只验该模型确定性 |

探针结果决定主跑数字怎么报：

- 3 次输出**完全相同** → 该模型确定性 OK，单次数字直接用；
- 3 次**有差异** → 记下字符级差异率，报告里给该模型的数字**挂误差棒**，
  差异大到会改变排名时才补跑。

调用量：主跑 10×2×5 = 100，探针 1×2×5×3 = 30，合计 **130 次**（原设计 2370 次，省 94%）。

⚠️ 探针页要挑**本窗口内容最杂的一页**（有小注、有标点密集段），不要挑干净页
——干净页上谁都稳定，测不出抖动。

```
      {run_id}.json           # 全量指标
      compare.md              # 横向对比表（人看的）

```

1. **引擎原始输出永不改写**（同 `data_full/` 扫描页永不改写的先例）。所有清洗、
   归一化都在评测时做，改了口径重算即可，不用重新花钱调 API。
2. **`meta.json` 必须记模型版本字符串**。`claude-opus-5` 和三个月后的 `claude-opus-5`
   可能不是同一个东西，没记版本的数字过期后无法解释。

### 实现期间实查推翻的两处

1. **缺列不全是注列**。原以为 labels 缺的列都是 Step3 切不动的双行小字；
   比对页图后发现 **p17 缺的 4 列是普通正文**，Step3 在那里就是没切出来。

2. **切页不能靠页码行**。影印页码在校對本里有缺（1943/1946 都没有），
   改用「labels 重建的列文字回校對本锚定行块」——文字自己认路。

### 自测揪出来的真 bug（已修，已加回归）

引擎**一条注都没输出**时，precision = 0/0 被算成 `None`，F1 跟着 `None`，
报告里显示「注文 F1 None」——看起来像「这项没测」，**实际是全军覆没**。
分行同理（全页并成一行时）。现在 `score.prf` 统一口径：
**`None` 只许表示「没有可量的东西」，不许表示「一个都没答对」**。

这正是 §八 第 2 步「自测不能省」要防的那种 bug：数字看着合理，没人会怀疑。

### 校對本将来更新怎么办

用户 2026-09-15 明确校對本有错字要更新。所以：

- **金标是生成的**，一条命令重建；`built_from` 记源文件 sha256，对不上就是该重建；
- **改字去改校對本**，不改金标 json，更不改打分器；
- 已有的 36 例人裁订正（`witness_corrections.md`）**默认不套用**
  （`--apply-corrections` 关着）——套了会和更新后的本子打架。
  其中 **5 例落在本窗口**，逐页记在金标的 `corrections_here` 里供比对；
- 历史 run 的**原始输出永不改写**，校對本更新后重新打分即可，不用重新花钱调 API。

### 性能 / token / 成本接口（用户要求的第三类产出）

打分器不调 API，量不到这些，由**跑引擎的脚本**写进 `meta.json`：

```json
{"engine":"claude","model":"claude-opus-5","prompt":"p1@v1","book_pages":79,
 "retries":0,"failures":0,
 "per_page":[{"page":9,"sec":3.2,"tokens_in":1250,"tokens_out":310,"usd":0.0071}]}
```

打分器据此报：秒/页、token/页、¢/页、**全书外推成本**。
**字段缺了报 `None` 不补 0**——0 会被读成「免费」「零耗时」，比没有数更糟。
本地引擎 `usd` 填 0 是对的（真不要钱），但 `sec` 必须如实填：速度是本地路线的主要代价。
