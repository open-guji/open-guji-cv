# 产物与版本钉：统一方案（GUJI-674／727／694，A20，2026-10-23）

> 状态：**设计稿，待评审**。不改任何代码。涉及存储位置变化，评审前要先通知 A21–A24、A30（经 A20 协调者发）。
> 依据：`doc/design/字形库按版本钉-细设计.md`（727，已定稿）、`datastore/packs.py`（R2 产物包）、`ops/freeze.py`（冻结基线）、`datastore/schema.sql`（登记三表）、`doc/snap_autoimport.md`（旧 snap 分支）。

## 一、问题

一册书的「结果」由四样东西决定：**cv 代码版本、语料库号（c）、字形库号（g）、中心库 rev（人裁与册配置）**。
现在这四样的登记和产物的存放各走各的：

| 存法 | 在哪 | 谁在用 | 缺什么 |
|---|---|---|---|
| ① snap 分支 | guji-workspace 孤儿分支 `snap/<ws>/<册>/<时刻>`，manifest `guji-snap/1`，含逐文件 sha256 | 冻结基线 `freeze.snapshot`（`ops/freeze.py`）、服务器 `snap watch` | 分支靠 git 运，体积大（guji-workspace `.git` 660 MB）；与中心库无登记关系 |
| ② R2 数据快照 | `derived/…`、`config/glyph-pack`、`corpus-pack` 清单 | 语料库、字形库按版本钉 | 只管输入，不管产物 |
| ③ R2 产物包 | `products/<ws>/<册>/<标签>/` ＋ `main-ptr/`，标签 `cv<版本>-c<N>-g<N>-<改动>` | 云会话取回上游、`guji exp`、`pack promote` | manifest 只记**文件个数**，没有逐文件 sha，不能顶替 ① 做冻结比对 |

结果：vol01 冻结基线登记在册 yaml（指向 ① 的分支），中心库 `freeze_baselines`／`snapshots`／`cv_versions` 三表全空，三处对不上；
close-check 只认 ①。

## 二、目标形态（一句话）

**产物只有一种存法：R2 产物包（③）。** 一个包标签就是一个「快照 id」；中心库三张登记表是唯一的账；输入版本（c、g、rev）写进包 manifest 与登记行；
snap 分支退役。任何一册的任何一个已登记版本，在新容器里 `db pull` ＋ `pack fetch` 就能复现，逐字节相同。

```
cv 发版（tag） ──写──▶ cv_versions(version, cv_commit, released_at)
产物包 push    ──写──▶ snapshots(snapshot_id=<包标签>, ws, book, cv_commit, db_branch, db_rev, doc{versions,files_index_sha,pack_sha256})
册冻结(0.1.0/1.0.0) ──写──▶ freeze_baselines(ws, book, version, cv_version, cv_commit, snapshot_id, db_branch, db_rev, doc{glyph_pin, corpus, human_fp})
close-check 1a ──读──▶ freeze_baselines → snapshots → R2 包 manifest 的逐文件 sha 索引
```

## 三、要改什么（分四步，每步可独立合并、缺省关）

### 步 1：产物包补「逐文件 sha 索引」（674 的前提）
- `push_products` 在 manifest 旁多存 `files.json`：`{相对路径: {sha256, size}}`（与 `guji-snap/1` 的 `files` 同形，路径去掉 `products/` 前缀），manifest 记 `files_index_sha256`。
  不改 tar 内容，旧包没有 `files.json` 时回退为取回后现算（慢，只在一次性迁移用）。
- `fetch_products` 取回后可选核对索引（`--verify`），保证逐字节相同。
- 验收：对 vol06 存包、新容器取回，`files.json` 全部 sha 与本机一致。

### 步 2：登记三表落账（674 的核心）
- `cv_versions`：打 tag 的流程（`process/tag.py` 之后）补一步 `guji release register <版本>`，写 `version`、`cv_commit`、`released_at`；补登 v0.1.0–v0.5.8 现有 tag。
- `snapshots`：`pack push` 成功后同一动作写一行（`snapshot_id`＝包标签，`doc` 带 `versions`、`files_index_sha256`、`pack_sha256`、各步 manifest 摘要 `products_digest`）。已有的包（`pack list`）一次性补登。
- `freeze_baselines`：新命令 `guji freeze register <册> --version 0.1.0 --snapshot <包标签>`（GUJI-694 的 D7 已在做，接口对齐这里），写一行；`db_rev`、`glyph_pin`、`corpus` 从包 manifest 的 `versions` 取，不手填。
- 登记表在 main 分支只由受控入口写（沿用「正式写令牌只在服务器」），实验分支不写正式表。

### 步 3：冻结读法改走中心库
- `ops/freeze.py`：`load_baseline` 优先读 `freeze_baselines` → `snapshots` → R2 `files.json`；册 yaml 的 `freeze:` 改为只写 `at:`（文本版本），`snapshot:` 字段保留为兼容读（读到就提示「请迁到登记表」）。
- close-check 1a、基线后新人裁计数、`stale_reason` 分级逻辑**不变**（规则见 `ai-team domain/CV/规范/冻结基线与重跑分级.md`）。
- 验收（674 原文）：`freeze_baselines` 有 vol01 一行，close-check 读它；新容器 `db pull` ＋ `pack fetch` 复现 vol06 char.json 逐字节相同。

### 步 4：snap 分支退役
- 先把仍被引用的 snap 分支（冻结册 vol01 等）转成 R2 产物包并登记（步 2 的补登），核对 `files.json` 与旧 manifest 的 `files` 逐个 sha 相同。
- 停服务器 `guji-snap-watch.timer`（交 Ops 经协调者转）；`guji snap pack/watch/import` 标「已退役」，保留只读命令一个版本周期后删。
- **删远端 snap 分支要用户点名单同意**（`process/branch_delete.py`，红线），本方案不含删除动作。

## 四、字形库号（727）怎么接进来

727 的细设计不动：快照 g<N>＝清单进中心库 `config/glyph-pack/g<N>/`、文本按 sha 进 R2。接口只有三处：
1. 包标签里的 `g<N>` 已经由 `version_label` 带上；包 manifest 的 `versions` 增记 `glyph_digest`（727 第六节已写）。
2. `freeze_baselines.doc` 记 `glyph_pin` 与 `glyph_digest`，冻结册重建时按 digest 取 g<N> 快照库，不用当前库。
3. 727 的第 7 步迁移（殿本出 g1、10 册写 `glyph_pin: 1`）**要用户点头**，建议放在本方案步 2 之后，这样迁移产生的过期与重算有 `snapshots` 行可追。

## 五、不做的事
- 不把 products 搬进 Postgres；不把建好的 `glyph-g<N>.db` 存 R2（727 待拍板第 6 条，本期不做）。
- 不改任何 Step 的 `code_deps`（改动只在 `datastore/`、`ops/`、`cli_*.py`），PR 附改前改后 17 步 `code_hash` 对照，应全相同。
- 不动服务器部署与 production 分支。

## 六、风险与待拍板

1. **谁来写登记表**：正式写令牌只在服务器。建议 `pack push --main` 与 `freeze register` 走 Worker 的受控接口（沿用 `/v1/packs` 的令牌分级），别让云会话直接写表。
2. **包标签即 snapshot_id**：标签只许 ASCII 且只增不改，天然唯一；同一内容重复 push 会出两个标签，`snapshots.doc.pack_sha256` 用来识别重复。
3. **补登历史包**：旧包没有 `files.json`，补登要整包取回现算，殿本十册约十几 MB 一册，成本可接受。
4. **冻结册 yaml 兼容**：过渡期两种写法并存一个 cv 版本；之后 `snapshot:` 写法报错。
5. **MINOR 还是 PATCH**：缺省关、新增命令与表写入，按版本号规矩属 PATCH；`freeze.py` 读法切换若让冻结册 close-check 行为变，需要单独评估。

需要用户定的：①是否同意把「产物只存 R2 包、snap 分支退役」作为方向；②迁移（补登历史包、殿本 g1）的时机；③删远端 snap 分支的名单（等迁完再列）。
