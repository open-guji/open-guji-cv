# 特殊符号进字符候选集（设计 v0.1，2026-10-21）

> 起因（用户 10-21）：刻本上有的格其实是图形符号（圈、方框、三角……），人审要能把它定成符号；
> 但**不是每张卡都给一排符号**，而是识别（5-a 库匹配、5-b 字体模板／CNN）或候选**碰到符号时**它才出现在候选里。
> kaiyuanguji-web #559（10-20）给每卡常驻了一排符号，已在 #565 撤掉；本文是替代它的 cv 侧方案。

## 一、现状：符号进不了任何一路候选

| 环节 | 现在怎么挡掉符号 | 位置 |
|---|---|---|
| 5-b `rare_candidates` 字表 | `build_charsets` 末尾只留 `_cjk(c)`，册配置 `font.charset.extra` 里写了符号也被滤掉 | `clustering/charset_spec.py` `_cjk`、`build_charsets` |
| 5-a `glyph_match` 字形库 | 本身不挡；但库里的字只来自人裁／种子，**还没有一条符号人裁**（中心库 10-21 查 0 条），所以永远匹配不到 | `steps/glyph_match.py` |
| 种子／整理本对齐 | `align_label.is_han` 只认汉字，整理本里的符号不当标签 | `clustering/align_label.py`、`seeding.py` |
| Step6 上下文 | 规则串用「◎」当目标位、「□」当未知字（`groups/ctx_l1.py` `MARK`），真符号进上下文会撞车；语料里几乎没有符号，语言模型对它无从判断 | `groups/ctx_l1.py`、`clustering/context_step.py` |
| 相似字 `alt` | `variant_sources.is_han` 只收汉字，符号进不了池子 | `clustering/variant_sources.py` |
| 网站卡片 | 候选（`lib_top`／`cand`／`ref`／`ctx`／`alt`）里是什么就显示什么，**不用改** | kaiyuanguji-web `shownCandidates` |

## 二、目标与验收

1. 一格真是符号时，卡片候选（候选按钮或相似字）里能出现那个符号，点一下就提交。
2. 不是符号的格，卡片上不多出符号。
3. 人定过的符号进本书字形库，同书后面的同形符号 5-a 直接匹配上，最终能自动放行。
4. 不让各书产物无谓过期：动 Step 及其 `code_deps` 的改动挂册配置开关，缺省关。

量法：在粗校基准 `rough-bench/` 上加「符号格」标签（先人工从 vol04–10 找，目标 ≥ 30 格），量
- 召回：符号格的候选／相似字前 10 里有正确符号的比例（目标 ≥ 90%）；
- 打扰：非符号格的候选里混进符号的比例（目标 ≤ 0.5%）；
- 送审率、错放数不变坏（基准原有 972 标签）。

## 三、符号表：一处登记

新增 `config/charset/symbols.tsv`（码位、名称、常见用途、是否允许自动放行），第一版：

| 字 | 码位 | 名 |
|---|---|---|
| ○ | U+25CB | 圆圈 |
| ◎ | U+25CE | 双圈 |
| ● | U+25CF | 实心圆 |
| □ | U+25A1 | 方框（真刻的；与阙文 □＋`lacuna` 区分，见 `doc/formats/F2_handoff.md` #3） |
| ■ | U+25A0 | 实心方框 |
| △ | U+25B3 | 三角 |
| ▲ | U+25B2 | 实心三角 |

「〇」（U+3007）是汉字（数字零），本来就在字表里，不进符号表。代码里一律从这张表读（`open_guji_cv/hanzi/symbols.py` 一个小模块），不在各处手写。

## 四、各环节怎么改

### 4.1 5-b `rare_candidates`（字体模板＋CNN）
- `build_charsets`：册配置 `font.charset.symbols: true` 时，把符号表并进**基集**（不受 `_cjk` 过滤）。
- 模板：用现有字体渲染（I.Ming／Jigmo 都含几何图形区）；渲染不出的符号记进 `failed`，和现在一样丢掉。
- 指纹：字表变 → 本册 5-b 及下游过期；只有开了开关的册重算。
- 风险：符号形状简单，CNN 可能把墨团、残字、圈点误配成 ●／○。所以 5-b 里的符号候选**只进候选、不进放行**（见 4.4）。

### 4.2 5-a `glyph_match`（本书字形库）
- 不改匹配算法。符号靠人裁进库：网站票 `char=○` → `guji cellvotes` 落 `confirm shape=○` → 走现有进库路径。
- 要核的是进库路径上有没有只认汉字的过滤（`seeding.py` 的 `is_han` 管的是整理本标签，不管人裁；需要用一条自造的符号人裁跑一遍单测确认）。
- 库里有了同书真刻的符号样本后，5-a 能给出高分匹配，这是最终能自动放行的那一路。

### 4.3 相似字 `alt`（出单时算，不进放行，不影响指纹）
- 近似字里出现符号（5-a／5-b 前几名、或人写过的字是符号）时，池子加入整张符号表（符号之间互为「形近」），按字块图排序。
- 另加一条兜底：字块图是「实心大墨块／单个圈」这类低复杂度图（前景占比、连通域数、圆度三个量），即使近似字里没有符号，也把符号表并进池子，排序交给 CNN。阈值在基准上定，先按「非符号格混入 ≤ 0.5%」卡。
- `is_han` 改为 `is_han(c) or is_symbol(c)` 只在 alt 池子这一处用。

### 4.4 Step6 上下文与 `seed_admit`
- `ctx_l1` 的目标位标记「◎」与未知字「□」换成私用区码位（如 U+E000／U+E001），规则文件里的写法照旧（加载时替换），避免真符号进上下文时误命中。这一步动 `code_deps`，挂同一个开关一起上。
- 上下文对符号**不投票**：目标格前几名是符号时，Step6 不用语言模型推翻也不加持。
- `seed_admit`：符号候选第一版**一律送人审**，`why` 加 `symbol`（网站原因显示「可能是符号」）；本书库里同一符号的人裁 ≥ 3 条后，5-a 强匹配才允许放行（与现有「库内同形」通道同口径）。

### 4.5 导出（Step9）
- 符号原样进 `text`；□ 没有 `lacuna` 标记就是真刻方框（F2 #3 已定），不用改。

### 4.6 网站
- 不加专门 UI。原因码 `symbol` 的中文短语加一条「可能是符号」。符号字体缺字时用现有 `Zi` 组件兜底显示。

## 五、分步执行（每步有输入／验收）

| 步 | 内容 | 动不动产物指纹 | 验收 |
|---|---|---|---|
| S1 | 符号表＋`hanzi/symbols.py`；alt 池子收符号（4.3）；单测 | 不动 | 自造卡：近似字含 ○ → alt 前 5 有 ○；纯汉字卡 alt 不含符号 |
| S2 | 基准加符号格标签（人工从 vol04–10 找 ≥ 30 格，交 M9 粗校基准） | 不动 | 标签文件入 `rough-bench/` |
| S3 | 5-b 字表开关（4.1）＋ ctx 标记换私用区（4.4 前半）＋ seed_admit 符号送审（4.4 后半），全挂 `font.charset.symbols` | 只对开了开关的册 | 基准上召回／打扰／送审率达第二节目标 |
| S4 | 人裁进库路径核对（4.2），一条自造符号人裁走通单测 | 不动 | 单测过 |
| S5 | 挑一册（建议 vol06）开开关重跑、重发待审单 | 该册过期重算 | 差异单里新增的符号候选格人看一遍 |

S1、S2、S4 可以马上做；S3、S5 会让开了开关的册重算，做之前先问用户。
