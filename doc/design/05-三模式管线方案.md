## 〇、一句话结论

**九步全部保留，没有一步要删；三种模式 = 一套 Step 代码 × 两条管线 yaml × 册配置里的四个字段。**
横排不另写一条切分链——**把页面旋转 90° 后横排就是竖排**（§三），Step2–4 一行不改。
唯一要新写的 Step 是「行探测」`line_detect`（顶替古籍的 `border_detect`，因为现代印刷没有版框界行）；
唯一要新写的标定命令是「字体判定」`calibrate font`。其余全是参数化与开关。

用户想法里最关键的一条——「**确定字体后做像素级比对，不靠神经网络**」——
对现代印刷体**成立的概率很高，但必须先量**（§一.2）：已有的负结果是「字体字形 vs 刻本不可分」，
那是刻本；现代印刷体是「字体 vs 同一字体的扫描」，是另一个问题，M0 用合成页先把可分性量出来再铺开。

### 一.2 为什么「字体像素级比对」要先量，不能直接信

`glyph_db_expansion_research.md` §6.2 是本项目最硬的一条负结果：四套字体渲染的字形去匹配刻本图块，
正确命中的 f1 中位数 0.65，错误命中也在 0.62～0.64，**两个分布压在一起（margin 全为负），
不是调阈值能救的**。所以字体字形在刻本链里只当候选生成器（recall@5 0.69），从不拍板。

现代印刷体的假设不同：书上的字**就是**那套字体渲染再经扫描退化，理论上正确命中的 cov 应接近同字异刻的水平
（刻本库内同字 0.90+，映射后 0.996+），错误命中则被形近字家族限制住。但两件事没量过：

1. **扫描退化有多大**——300dpi 下 10.5pt 字身约 44px，笔画 2～3px，模糊与墨扩会把 f1 压多少；
2. **形近字在字体里的差异够不够大**——己/已/巳、日/曰、末/未在宋体里差异是设计出来的，比刻本稳定，
   但像素级只有一两笔宽度的差。

M0 用合成页（字体已知、金标免费）把这两个数先量出来，量法照搬 §6.2：正确命中 f1 的 p10 是否高于错误命中 f1 的 p90。
**margin > 0 才走字体路；margin ≤ 0 就退回「库只靠书自己长」**，管线不用改。

## 二、三种模式的差异到底在哪

先把「模式」拆成互相独立的版式属性，三种模式只是三组预设：

| 属性 | 古籍（刻本） | 现代竖排 | 现代横排 |
|---|---|---|---|
| 行进方向 `writing_mode` | vertical-rl | vertical-rl | **horizontal-tb** |
| 版框界行 `frame` | ruled（有） | none（绝大多数无；少数影印有，仍走 ruled） | none |
| 行/列数 | 版式常量（9） | 页页不同（由探测给） | 页页不同 |
| 每行字数 | 版式常量（21） | 由块宽 ÷ 字距推，段末/缩进为空白格 | 同左 |
| 字距 | 页级 `period`，弹性 ±30% | **刚性**，页级常量 ±2px | 刚性 |
| 字内容 | 汉字，无标点 | 汉字 + 全角标点 | 汉字 + 全角标点 + **半角西文数字** |
| 夹注 | 双行小注 | 无（脚注另成行） | 无 |
| 特殊行 | 抬头、职名、目录 | 标题、页眉页脚、页码、脚注 | 同左 + 双栏 |
| 字形来源 | 刻工，同字异刻 | 一套字体，同字同形 | 同左 |
| 字形库域 | `wuyingdian-siku-zongmu` | `modern:<book>` | `modern:<book>` |
| 字表/语料 `script` | 繁 | 繁或简 | 繁或简 |
| 整理本 | 通常有 | **常常没有**（这本书自己就是整理本） | 同左 |

真正决定算法分叉的只有两个属性：`frame`（Step1 走版框探测还是行探测）和 `writing_mode`（要不要旋转）。
其余全是参数与阈值。**现代竖排与现代横排在代码上是同一条管线**，差别只有旋转。

## 三、关键设计：读序空间——横排 = 旋转 90° 后的竖排

现有规范空间 `raw_page_px@top-right`：原点右上、x 向左、y 向下，列从右到左编号，格从上到下编号，
与古籍阅读顺序一致。把横排页**顺时针旋转 90°**，恰好落进这个空间：

```
原图（横排）            旋转 90° CW 后
┌──────────────┐        ┌────┬────┬────┐
│ 第一行 →→→→   │        │ 第 │ 第 │ 第 │
│ 第二行 →→→→   │   →    │ 三 │ 二 │ 一 │  ← 列从右到左 = 行从上到下
│ 第三行 →→→→   │        │ 行 │ 行 │ 行 │
└──────────────┘        │ ↓  │ ↓  │ ↓  │  ← 格从上到下 = 字从左到右
                        └────┴────┴────┘
```

原图第一行（y 最小）→ 旋转后最右列（列 1）；原图行内第一个字（x 最小）→ 旋转后最上格（格 1）。
**读序逐位保持，`pNNNNcCCsSS` 单位键不用换语义**：c 就是「第几行」，s 就是「行内第几字」。

落地只有三处：

| 处 | 改动 | 说明 |
|---|---|---|
| `RunContext.raw_page` | `writing_mode == horizontal-tb` 时 `np.rot90(img, -1)` | 与 Step0 预清理一样在原图入口做，管线其余部分看到的永远是「竖排」 |
| `core/anchor.py` | 坐标空间标签加旋转（`raw_page_px@top-right;rot=90`）+ 一个 `to_original(bbox)` | 只有**面向人**的三处需要回原图：控制台叠图、金标锚点、Step9 导出。算法与产物一律留在读序空间 |
| `cell_shrink` 出字块 | 横排时字块 `np.rot90(patch, 1)` 转回正 | `char_patch` 永远是正的，Step5 之后一行不改；`char_index` 的 bbox 留在列图坐标 |

**为什么不在每个 util 里加「轴」参数**：Step2 的射影、Step3 的投影 DP、Step4 的收框都是几百行按「列竖直」写的几何代码，
加轴参数是改遍每个函数；旋转是一次性的、可逆的、零精度损失的，代价是叠图要转回去显示。
控制台叠图对横排书显示原图方向，`render/overlay.py` 在画完框后整体逆旋转即可。

**金标锚点**：新书的金标全部在读序空间收（与产物同空间），锚点里记 `rotation`。
不存在「旧金标要迁」的问题——现代书没有旧金标。

### 四.1 `line_detect`：现代模式的 Step1

在读序空间（横排已旋转）里做，输入原图，输出 `borders`（与 `border_detect` 同一种产物）+ `line_index`：

1. **去斜**：全页在 ±3° 内搜投影方差最大的角度，记进产物；
2. **找行**：沿行进方向投影，墨段之间间隙 ≥ 行距的 30% 为分行；行 = 墨段 ± 半个间隙；
3. **行分类**（`line_index.kind`）：行高相对页中位 >1.2× → `heading`；<0.85× → `footnote`；
   位于页顶/页底外侧且离正文块 > 1 行距 → `header`/`footer`；孤立短行 + 位于页底中央/外侧 → `pageno`；
   其余 `body`。**v1 只把 body 行送下游**，其他行标出但不处理——与古籍「只优化正文页」同一方针；
4. **块**：body 行沿字进方向的公共跨度 = 文本块 `[x_start, x_end]`，这是 Step3 推格数的依据；
   块内若有跨全高的宽间隙 → `two_column`，v1 整页标出不处理；
5. **写产物**：`borders.top/bottom` = 文本块两端；`verticals` = N+1 条直线（间隙中线，`slope=去斜角`）；
   `expected_cols` = N；`head_raise` 空。`line_index` 记每行 kind/高/跨度。

`page_column_windows` 拿到直线照常出窗口，`column_warp` 照跑。**`borders` 的语义在这里是「虚拟界行」**，
产物 docstring 要写明，别让后人拿它当真墨线去量。

### 四.2 Step3 刚性网格模式

现代排版的字距 `pitch` 是页级常量（全角标点也占整格），Step3 的问题从「弹性切」变成「定相位 + 等距切」：

- **字距**：页级 `pitch` 由行内投影自相关取，跨行取中位；册级 `pitch_prior` 与 `period_prior` 同一套路标定；
- **格数**：`n = round((x_end − x_start) / pitch)`，页级；短行（段末）末尾自然是 `blank`，段首两格 `blank`
  就是缩进——**现有 `blank` kind 直接表达段落结构**，Step9 靠它分段；
- **DP 收紧而不换**：`lo/hi_ratio` [0.9, 1.1]、`lam` 加大，DP 就近似刚性；候选切点仍是墨谷，
  U-Net 裁判关掉（字间是纸，规则够用）；
- **`punct`**：格内墨占比小、墨迹外接框 ≤ 0.4 em 且落在字身框固定角落（横排「。，、」在左下）→ `punct`。
  它照样进 Step5 匹配（字体里标点也是字形），kind 只是给 Step9 和归一化用；
- **`narrow`**：连续几格的墨谷落在半 pitch 处 → 半角连串，整段合成一个 `narrow` 格交 5-c OCR 按串识别，
  **不进自动放行**，人审。v1 只做到「标出来不切错」；
- **行末挤压**：行末最后一格若比 pitch 窄 ≥15% 且是 `punct` → 允许，记 `squeezed` 标记；闸3 统计比例。

### 四.3 归一化按字身框

`normalize_patch` 现在把墨迹外接框等比拉满 64×64 再质心居中——对刻本是对的（格松、字大小不一），
对现代印刷体是错的：「。」会被拉成「〇」，「一」拉成横杠占满，「、」与「丶」不分。
现代模式的字身框（em box）由刚性网格给出、误差 ±2px，**位置与大小本身就是可靠信号**，
归一化改为「以字身框为画布、只缩不放、不动位置」（`anchor=cell`）。这是 `normalize.py` 的一个模式参数，
库存储 `to_canonical` 同样加这个模式，两边一致才可比。刻本链保持 `anchor=ink` 不变。

## 五、字体：判定、渲染、库分域、许可

### 五.1 「字体判定」是标定命令，不是 Step

与 `bottom_gap`、`period_prior` 同一套路：跑一次、把数写进册 yaml、管线只读。

```
guji calibrate font <book> [--pages 1-12] [--catalog font:shs,font:iming,...]
```

1. 先跑 Step1–4 拿字块，用 5-c OCR 高置信 + 高频字凑 ~300 个「几乎确定」的样本（有整理本就用整理本）；
2. 对目录里每套字体：按标定出的 em 渲染这些字，退化参数 `(blur σ, dilate d, threshold)` 在小网格上搜，
   取平均 cov 最高的一组；
3. 算可分性 margin（§一.2 的量法）；margin 最高且 >0 的字体胜出；
4. 写回 yaml：`font: {family, size_px, degrade: {sigma, dilate}, margin, calibrated_at}`；
   全部 margin ≤0 → `family: none`，5-b 字体路退回通用候选生成，5-a 只靠书自己长的库。

### 五.2 两条路的分工

| 路 | 作用 | 精确判据？ |
|---|---|---|
| 书自己长的库 `modern:<book>` | 5-a 主力。第一轮 12 页人审后，高频字就有真实退化的刻例；一字一两例即饱和，之后人审率应远低于刻本的 1.5% | 是（same 闸按现代分布重标） |
| 字体渲染模板 `font:<family>` | 5-b 候选源（判定字体优先、其他字体兜底）；冷启动时给 Step6 出候选；**永不单独放行** | 否，直到 M0 量出 margin>0 且 `match_precision ≥0.999` 才升为 5-a 的一路 |

### 五.3 库分域与共享

- `edition_tag = modern:<book>`，`kind = print`（新增一个来源类别，与 `woodblock/scan/font` 并列）；
- 两本书同字体同印厂能不能共库：**先不共**，各长各的；需要时显式合并——与「同字不同版永不合并」的纪律一致，
  合并是人的决定；
- 字形图与刻本库同一套 `glyph_store` 格式，可再生（`kind=print` 的真源是书的扫描件 + 字块坐标）。

### 五.4 许可（一定要写清）

- `charset_and_lm.md` 的纪律「商业字体只取 cmap 不取字形」不变：商业字体档只在本机 `$GUJI_FONT_DIR`，
  渲染出来的字形图**不进 Git**（§6.4 已有的约定，`export_store` 跳过 `kind='font'`）；
- 目录里可进仓的只有自由字体：I.Ming（IPA）、Jigmo（CC0）、可再加 **思源宋体 / Noto Serif CJK（OFL）**
  ——现代出版物最常见的宋体形态，与方正书宋同源度高，是横排书最该先试的一套；
- 书自己的字形库是扫描件的裁片，不受字体许可约束；书的文本版权是另一个问题，与刻本链的整理本同一口径处理。

## 八、里程碑与验证

**越靠前的步目标越趋于完美**的原则照旧：切分线 100%，识别线看错误率与人审率。

### M0 合成页：字体已知、金标免费（先做这个，其余都以它的数为准）

- 用思源宋体 / I.Ming 渲染 20 页横排文本（真实古籍整理本文字：含标点、段首缩进、短行、少量数字），
  加扫描退化（模糊 σ 0.5～1.5、墨扩 0～2px、二值化、±1° 倾斜），每字 bbox 与字符都是已知金标；
- 跑 `modern_body` 全链（`writing_mode=horizontal-tb`）；
- **判据**：Step1 行数 20/20 页全对；Step3 格心离金标 ≤2px 的比例 = 100%（切分线目标）；
  5-a 字体模板可分性 margin > 0 且 `match_precision ≥0.999`；旋转链路：`to_original` 回原图的 bbox 与金标逐位一致；
- 顺带出**第一版阈值**：现代 same 闸、`punct` 墨占比门槛、行高分类倍数；
- 再用同一批文本渲染成竖排跑一遍 = 现代竖排的 M0，只改 `writing_mode`。

### M1 真书 12 页（一轮）

- 选一本用户手边的现代排印整理本，扫 300dpi 以上（**建议 600**：em ≥ 40px 才够分己已巳，300dpi 10.5pt 约 44px 刚够）；
- `calibrate font` → 看 margin 落在哪；跑 → 人审 → 判据 A（自动放行零错）/ B（人审率）；
- 预期：第一轮人审率高（库是空的），第二轮起应显著低于刻本的 1.5%——**这是「一书一字体」假设的直接检验**。

### M2 现代竖排真书 12 页

同 M1，`writing_mode=vertical-rl`。检验 `line_detect` 在真实无界行竖排上的行分割。

### M3 版式扩展

双栏、脚注、标题、页眉页脚从「只标不处理」升为「分类处理」；Step9 段落与标题层级输出；`narrow` 从人审升为 OCR 串自动放行（要单独的通道标定）。

## 九、风险与已知负结果

1. **字体模板可分性未验证**（§一.2）。刻本上的负结果不能外推到现代印刷体，正结果也不能想当然。M0 定。
2. **归一化模式改动会波及库**：`anchor=cell` 与 `anchor=ink` 的图不可比，现代库与刻本库必须各自用各自的模式，
   `to_canonical` 存储也要分——库表加一列 `norm_mode`，查询时过滤。
3. **常量提参数（第 8 项）是刻本链的回归风险点**：默认值必须等于现值，用 vol01/vol02 的四把尺子 + `eval_db_match` +
   产物指纹三样一起守。
4. **半角西文数字**破坏刚性网格。v1 只标 `narrow` 不切；古籍整理本里比例低，横排学术书里可能不低——M1 选书时避开。
5. **行末标点挤压 / 悬挂**在专业排版里常见，会让最后一格窄 15～50%。闸3 统计 `squeezed` 比例，比例高就要在 Step3 加「末格弹性」。
6. **不同字号混排**（标题、脚注、注码）：`line_detect` 只按行高分类，同一行内混字号（如正文里的上标注码）v1 不管，进 `narrow` 或人审。
7. **简繁与语料**：现有 LM 语料是殆知阁繁体（简转繁），简体书不能直接用；`script=simp` 时要另配语料，
   否则 Step6 会「编字」（λ 0.35 起就开始编，已有实测）。
8. **无整理本时的双信号**：只剩「形状 × 上下文」一对。OCR × 库 top 有共同盲区（已巳、人入、日曰、今全，97.1%），
   不能凑成第二路——这条纪律在现代模式下**更要守**，因为现代书大多没整理本，OCR 又准得让人想信它。
9. **分辨率**：低于 300dpi 的扫描（常见的 PDF 影印本 150～200dpi）字身 20～30px，像素级判据分不开形近字；
   M1 前先量 em 像素，低于 40 就别做像素级承诺。
10. **旋转空间对人不直观**：控制台叠图必须转回原图方向，否则审核横排书的人看到的是竖着的页。地基 3 与第 13 项一起做完再给人用。

## 十、待用户裁定

1. **M0 用哪套字体合成**：建议思源宋体（OFL，可进仓，现代宋体的主流形态）；I.Ming 已在仓里但是传承字形，与现代出版物的字形习惯有差。
2. **M1 的真书选哪本**：需要用户手边一本现代排印整理本 + 能扫 300dpi 以上；有没有对应的电子文本（哪怕质量一般）决定 5-d 开不开。

4. **第 8 项常量提参数**是刻本链也受影响的改动，是先做（一次到位）还是先在现代链里用子类硬编码、等 M1 过了再回头统一？建议先做，回归三件套守得住。
5. **旋转 vs 加轴参数**（§三）：方案选旋转；若用户更在意「产物坐标就是原图坐标」，就得走加轴参数那条重路。
