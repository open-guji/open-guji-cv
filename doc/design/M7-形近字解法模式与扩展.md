## 一、一句话与总览

形近字分两类，各用一种解法，**两类都是「把握十足才给字，其余弃权送人审」**：

| | IDS 路（异体） | 上下文路（形近不同义） |
|---|---|---|
| 区别在哪 | 部件（笔画层面） | 文意 |
| 例 | 彝彛彜彞𢑱𢑴 | 己已巳、日曰、入人八 |
| 解法 | 通用 IDS 展开 → 折线切分 → 每段二选一 → 反查定字 | L1 规则/词组 → L2 haiku 离线答案表 |
| 人要做什么 | 点切线（约一半，其余机器预画你来采纳） | 复审不一致与低置信格（不抽查） |
| 现状 | 证据已出，**未接放行** | 已接 `seed_admit`（开关缺省关），vol04 A/B 过 |

## 二、IDS 路：流程

**适用**：组内成员是同一字的异体，顶层结构相同、差别落在固定位置的一两个部件上。若不同字义不同、写法会混用（形近不同义），走上下文路。

1. **成员 IDS 表（A2）**：用 Unicode 通用 IDS（IDC 加部件），数据取 cjkvi-ids 快照，**不自造格式**；程序递归展开到停止点并压平同向嵌套，按位对齐，自动算出每个位置的可选部件（彝组：{彑,彐}／{米糸,米分}／{廾,大}）。数据本身错或歧义才在 `ids_override.tsv` 里逐字覆盖，写理由。要**完全展开**（`⿱彑𪪷` 不行，要 `⿳彑⿰米分廾`）。
2. **先认最准确的 IDS，再匹配字符**：识别出的 IDS 若没有对应码位，归最近异体并打 `nearest_variant` 旗（𢑴 的彑写法），不认识的结构弃权。同部件别名要用户定（⺕＝彐 是同一部件；彑 与 彐 必须区分）。
3. **切分**：分界用**折线**，不是直线。直线基线像素归段只有 73.6%；只在本组刻例上训的小 U-Net 五折交叉验证 98.0%（最差一格 94.4%）。中段再按竖缝切成「米｜糸/分」，用「穿过墨迹最少、靠近中段中心」的竖缝，没用 U-Net。
4. **每段二选一**：每段和该位置的两种部件比，给分数差。**只用字体渲染做模板不够**（中段 42 格里约 31 对），要用真实刻例做模板。
5. **定字与弃权**：任一段分数差（margin）低于门槛就弃权。取 0.02：38 对、4 弃权、0 错。
6. **标注**：先复用已有标注（彝组是用户 42 格上中下读法，只缺切线）。用户只标约一半（25/42）作训练，其余 17 格机器预画折线，页上有「采纳」按钮，用户判断或拖点调整。手机能点、图片固定尺寸（否则翻卡漂移）、结果自动存回页面，再用 `harvest_verdicts.py` 收回。页面生成脚本已支持预填与采纳（`research/m7/build_cutline_page.py`、`build_vcut_page.py`），新组可直接复用。
7. **验收口径**：留一/折外交叉验证，整格读对率 ≥95%，**给字的格放错 0**；与现行放行字、整理本的不一致格逐格单列，不直接算谁错。
8. **接入**：缺省只写证据（`yi_ids_vol04.json`：`id/ids/char/kind/flag/slots/margins`），不改放行；是否让它抬待审、要不要降级，看证据再定。

### IDS 路的结果（彝六字形）
- 42 格端到端交叉验证（U-Net 自动横切＋自动竖切，模板只用训练折）：margin 0.02 时 38 对／4 弃权／0 错，对率 90.5%，**零误放达标，整格 ≥95% 未达**，差在弃权。不设门槛 41 对 1 错。
- 难点是 彑/彐：笔画本来就细，三种相似度×四档模糊都停在 41/42 或 40/42，换判别法救不了，残破图只能弃权给人复审。
- vol04 的 27 格证据：16/27 与现行字一致，11 格不一致，集中在下段 廾 被认成 大（彛→𢑱、彝→𢑴 等）。是 IDS 看到了真差异，还是 42 格里「大」的样例太少，目前分不清，待人裁。

### IDS 路踩过的坑
- 手写 `ids.yaml` 被用户否决：通用 IDS 有现成数据，自造格式容易错。
- 只用一条直线切分有上下残留，用折线；标注页第一版是直线，作废重点。
- 部件同一性不能由程序替用户定：我曾把「⺕＝彐」说成「彑/彐 同一处理」，用户纠正彑、彐就是要区分的。
- 评测要排除格自身：42 格里有 vol04 的 8 格，这 8 格评测时用「不含这 8 格」训练的 U-Net 和模板库。
- 数据集标注更正直接 commit 到 main，不开 PR；yi_560 目录原先只在别的分支，要整个目录合进 main。
- 注册表和公共配置只由一条线程改；并行时别的线程要改，经协调者转，否则会撞（`context.py` 就这样撞过一次）。
- 用户标注会累：只标一半，其余机器预标、用户审，比全标快得多。

## 三、上下文路：流程

**适用**：字组成员字义不同，写法会互混，靠前后文就能判（干支、虚词、书名、固定搭配）。字形只作护栏。

1. **L1 静态规则**（`groups/ctx_l1.py`，`config/groups/<组>/rules.yaml`）：正则（`◎` 是目标位）、否决规则、词组；匹配串是「前 20 字◎后 20 字」，不分段。命中字不一致或被否决就弃权。词组来源只取外部语料纯键（n≥25、纯度≥0.99），逐条在强真值上验。**《總目》校对本不能当语料真值**（己已巳、日曰互讹严重）。运行时零模型。
2. **L2 离线大模型**（`groups/ctx_l2.py`，`prompt.md`）：每组专用提示词，批量离线跑，出 `group_clf/1` 答案表，管线只查表。**生产只用 haiku，只收 conf=high**，先走 L1，L1 弃权的格才交 haiku，其余送人审。三模型一致省不了错，只多花两倍调用。
3. **窗口**：前后各 20 字，**不按段截断**（`ctx_ver: 3`；v2 段内版作废）。邻字取整理本对位字，对位缺字用占位符不跳过。建表和运行时必须同一个函数。夹注（双行小字）要先 `sort_by_reading`（先右行再左行），否则上下文错位，表里窗口哈希对不上就弃权。
4. **金标与口径**：只数强真值（A 人裁＋B 看图）；可评格要求有字块图、前后文各 ≥8 字、金标在组内。形近字**一律按文意定**，不按刻字像哪个，上下文是更强的证据。
5. **标注**：先复用 `char-groups` 里已有的 A/B/C 档。复审只审**模型之间不一致、与金标不符、haiku 把握不高**的格，页上隐藏金标与模型答案、顺序打乱，用户点本组字、「其他字」或「拿不准」。用户明确不要抽查。
6. **验收口径**：L1 给字零错；L1＋haiku 合并后给字准确率的 Wilson 95% 下界 ≥97%。零错时下界 ≥97% 需要约 130 格。
7. **接入**：`seed_admit` 的 `m7_groups` 开关，缺省关，按册在 yaml 开（`doc/exp/m7_groups-vol04.yaml`）。答案表是这一册的数据，放在 guji-workspace 的册目录，yaml 里用相对路径。

### 上下文路的结果（强真值，按用户两轮复审改正金标）
| 组 | 给字 | 对 | Wilson 下界 |
|---|---|---|---|
| 己已巳 | 172/183 | 全对 | 0.978，达标 |
| 日曰 | 47/61 | 全对 | 0.924 |
| 入人八 | 50/57 | 全对 | 0.929 |

日曰、入人八没到 97%，是样本量不够，不是准确率问题。用户定：数据集到此为止当 starter，以后数据多了再复测。

### 上下文路踩过的坑
- 窗口取法不一致：建表漏了夹注读序，vol04 首跑把「巳」放成「已」（规则「前字为天干」看错）。修了读序、给 jys 规则加了天干前字排除，受影响的 122 格重判。
- 字外格（口、目、白、田、巴）：haiku 会硬给组内字（原始评测 12 个字外格里 5 个）。所以日曰只能「抬待审且必须等于整理本字」，不能单独放行；这类格属于按字形归组（块 B），还没做。
- 金标自己有错（「大畜卦曰」标成日、「而◎」有 1 格标成己）：复审要对金标，不只是对模型。
- L1 规则是在强真值上调的，「L1 零错」以新样本为准；现数据集不再扩，所以只能当 starter 口径。
- 模型选择：opus、sonnet、haiku、muse、gemini 都跑过。gemini 几乎不弃权、错了也标 high，无法把难格路由给人；muse 入人八比 haiku 差；haiku 配 L1 够用。
- 书名规则要写：而已、《己易》、《讀易日鈔》《黃氏日鈔》。

## 四、接入流水线与 A/B 的通用做法

1. **新行为缺省关**，按册在 yaml 开；PR 先开草稿，PR 描述写清改了哪几步的 `code_hash`（合前实算，对比合并前的 main）。
2. **单项 A/B 是合入门槛**（`guji exp`，A＝关、B＝开，上游用同一份快照，只重跑 `seed_admit`）。报告看两件事：目标组内送审→放行、放行→送审各多少、放对放错各多少；**组外格必须逐格不变**。
3. vol04 实际结果（cv#113）：组外 33899 格差异 0；己已巳 3 格送审→放行，已有强真值的那格放对；入人八 1 格放行→送审；日曰无变化。vol04 本来放行就多，空间小，只证明接线安全。
4. **跑法**（4 核实测）：只重跑 `seed_admit`；按页号分 4 路并行；先跑 A 暖缓存（A 每页约 12.5 s，B 约 1.6 s）；改开关只重跑 B。细节见 [跑实验经验](../exp/跑实验经验.md)。
5. **版本**：功能分支 `feat/*` → 集成分支 `rc/vX.Y.Z` → main，tag 请 Owen 打（云端会话推 tag 会 403）。v0.3.0 已发（main `714b0a2`）。
6. 新字组加进来，只靠注册表加 `GroupSpec`、配置目录 `config/groups/<组>/`，不改 `seed_admit`。

## 六、下一批字组候选（每类 2～3 组，由用户挑）

说明：以下按字形和字义判断，**各组在 vol02–10 的实际格数我没量过**。动手第一步统一是：量格数、查 `char-groups` 与工作区 `feedback/events` 里已有标注。

### IDS 路（异体，部件级差别）

| 候选 | 理由 | 风险 |
|---|---|---|
| **慎愼**（真/眞） | 属 `variant_tie` 已裁的 7 组之一，用户 10-07 裁过「刻形＝系统码位」，已有人裁基础。结构相同，差别只在右部一个小部件，是单段二选一，比彝组更简单，拿它验证模式能否从三段缩到一段 | 差别部件小，笔画细，可能和 彑/彐 一样难 |
| **群羣** | 异体，但**顶层结构不同**（⿰ 对 ⿱），正好测设计里「多结构各切一遍取最大」的分支，彝组没测过 | 需要新写多结构评测；切分要两种假设 |
| **點㸃 或 參㕘**（先量格数后二选一） | 同在 `variant_tie` 7 组里，已有裁决可复用；两字字形差别明确 | 部分字形库刻例少，模板不足 |

备选：𫎇蒙、𨽾隸。

### 上下文路（形近不同义，文意可判）

| 候选 | 理由 | 风险 |
|---|---|---|
| **戊戌戍** | 和己已巳最像：干支、纪年、「戍守」有强搭配，L1 规则好写，预计能直接复用 jys 的做法 | 三字在书里的实际频率未知，格数可能少 |
| **未末** | 加一笔差，字形分不开，词组很强（本末、末年、未必、未嘗），L1 友好 | 常见字，格数多但混淆是否真多要量 |
| **土士** | 研究总览点名的形近组，词组强（士人、土地） | 字形差别小但「士」本身高频，L2 提示词要写清反例 |

备选：而面、太大（注意 muse 审计里 大/太 被当异体，要小心真值污染）、七一、金全、目自。

### 排序建议
1. 先做「**慎愼** ＋ **戊戌戍**」各一组，把两条路的整套流程（含标注页、A/B）在新组上完整走一遍，验证模式可复用；
2. 再补「群羣」（验多结构）和「未末」（量大，验 L1 覆盖）；
3. 土士、點㸃等看前两轮格数再决定。

线程分配：IDS 扩展和上下文扩展各一条线程并行（用户 10-17 要求并行）；注册表和公共配置归一条线（建议 IDS 线）；A/B 与发版另开一条，等两边功能分支就绪后做。新线程各自以本文为起点，不沿用旧线程（旧线程上下文已很长）。
