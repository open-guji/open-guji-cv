# 语料库：把 CV 流程里的语料类数据收成一个带版本号的包

> 2026-10-18，Emerson。依据 sheldon 同日提议：一批产物依赖三个东西——CV 版本、字形库版本、语料库版本；指纹只算这三个号，不看内容；语料库不自动更新，定期手动重算、升版本；升级语料库默认不重跑，要重跑时知道是从哪个语料库版本起。
> 本文只写盘点与方案，不改代码，`code_hash` 不变。盘点来自对 `steps/`、`clustering/`、`groups/`、`utils/`、`core/` 的只读扫描。

### 悄悄不过期的缺口（现状的风险）
1. 形近表（`confusable_font_degraded`、`confusable_human`、`NEVER_MATCH_FAMILIES`）：glyph_match 和 seed_admit 都吃，但不在任何 `code_deps`，数据也没指纹。
2. context_decide、align_ref 用的异体表：只有 seed_admit 有 `variants_fingerprint`。
3. rare_candidates：整理本字表、异体关系图、字表、部件库都不进指纹。

这三处正是「语料库版本号」要一并补上的。

## 二、方案

### 1. 语料库＝一个带 manifest 的包
```
corpus-pack/vN/
  manifest.json      # 版本号、日期、每个文件的 sha256、由哪个 CV 版本／字形库版本算出
  groups/rules/…  groups/ids/…  groups/l2/…  groups/freq/<书>.json
  variants/…  confusable/…  charset/…  notes/…
  reference/<书>/…   # 整理本参考文本（大文件按书分目录，manifest 里只登记哈希）
```
- **版本号是递增整数 `corpus-vN`**，每个包是一个不可变快照。manifest 记每个文件的哈希，但指纹**只取版本号**。
- 谁生成：一个脚本 `guji corpus build`，把上面各项（字频表、L2、异体表、形近表…）重新算一遍，写新的 `vN+1`。**不自动运行**，定期手动跑。
- 手写文件（rules.yaml、never_group、iron_extra）也进包，改了就要出新版本，不再「改一个字就让所有书过期」。

### 2. 每册「钉」一个语料库版本（像锁文件）
- 书的 yaml 里写 `corpus: v3`。指纹用的是这个钉住的版本号，不是「最新」。
- **升级语料库默认不重跑**：出了 v4，各册还钉在 v3，指纹不变、产物不过期。
- **想用新版**：把某册（或某工作区）的钉从 v3 改成 v4，这一册的相关步骤判过期、重算；产物里记着是用 v4 算的。重跑时知道「从哪个语料库版本起」，因为产物自带版本号。

### 3. 指纹怎么改
- 语料类的内容哈希（`corpus_fingerprint`、`group_flow_fingerprint` 里的表哈希、`variants_fingerprint`…）全部换成「钉住的语料库版本号」。
- 每个 Step 在 spec 里声明自己用语料库的哪些部分是否用（`uses_corpus=True`），不用语料的 Step（版框、列切分…）指纹不含它，不会因升版过期。这样补上缺口 1–3。
- 路径参数仍留在 `path_params`；`soft_params` 照旧。

### 4. 和另外两个版本号的关系
- 指纹 = (CV 版本, 字形库版本, 语料库版本) 三样。字形库版本现在是 glyph_match 的 soft 参数，只报漂移、不判过期，这是你之前有意定的，**本方案不动**。
- **CV 版本**：现在指纹用的是各 Step 源码哈希（`code_hash`），不是版本号。改成只看 CV 版本号会让开发中改代码不让产物过期，风险大。**建议第一步只做语料库，CV 仍用 `code_hash`**；CV 改成版本号单独排期、单独定。

### 5. 不进语料库的
- 切坏图块排除名单、人裁事件：属字形库／人裁。
- 释义、`near_form_ctx_jys.json`：只被面板或评测用。
- 图像模型（rr_clf）：模型版本，另算。

## 三、第一次迁移的代价
首次接入新指纹，相关步骤（Step7 及部分上游）对所有册判过期一次。做法：先用 `guji fp-migrate` 把旧指纹改写成新指纹（前提是内容没变）；做不到的就一次性重算，并放进同一个 MINOR 发版。

## 四、分步做
1. **P0 定包布局与 manifest**，写 `guji corpus build`，用现有内容出 `v1`，各项内容一字不改。**已做（2026-10-18）**：`ops/corpus_pack.py`＋`guji corpus build|verify|list`；清单落 `<工作区>/corpus-pack/vN/manifest.json`，只登记路径与 sha256，**不搬文件**（文件仍在原位置，包的「不可变」靠 `verify` 对哈希保证；是否把文件物化进包目录留到 P1 定）。
2. **P1 书 yaml 加 `corpus:` 钉子**，Step 读包里的文件，指纹换成版本号。
3. **P2 补缺口**：形近表、异体表、rare_candidates 的字表进包。
4. **P3 `fp-migrate`＋全量验证**：对 vol04 做「迁移前后产物逐格一致」。
5. 以后：字频表、L2 表等定期重算，出 `v2、v3…`，各册自己决定何时升。
