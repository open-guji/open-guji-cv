# 字形库与语料库：哪些独立、哪些共享、哪些进中心库、归档后怎么回流

> 本文取代 cv#157 的《语料库多工作区共享方案》（原文件改名为本文件重写）。**只出方案，不改代码**；`code_hash`、殿本 `corpus-v1` 指纹都不变。
>
> **已定（sheldon 10-18）**：语料库分底库＋书库两级清单；钉子先做「承诺＋起跑前硬校验」，物化以后再说；整理本先不抽成作品级、只登记作品号；北行日錄没有字频表就弃权、不借殿本。

## 〇、一页结论

| 数据 | 独立／共享 | 真源在哪 | 进中心库 | 归档时回流到哪 |
|---|---|---|---|---|
| 字体字形（`kind=font`） | 共享 | 引擎仓 `fonts/`，确定性重建 | 不进 | — |
| **本书刻例**（instances、exemplars、admissions、evictions） | **独立**（按 `edition_tag`） | 工作区 `glyph_store/` → 中心库切换后以库为准 | 进（已在工作包 8 范围） | 本书域原样归档、只读；精选刻例升格进共享刻例库 |
| **共享刻例库**（新） | 共享，按字体族分域 | 中心库，图在 R2 | 进 | 接收各书升格 |
| 字级信息（IDS、语义字） | 共享 | 底库 | 进（底库镜像） | 本书发现的新 IDS 升格进底库 |
| 人裁事件、裁决、锚、消费台账 | 独立 | 工作区 → 中心库 | 进（已在范围） | 原样归档；从中挖升格候选 |
| 底库 A 层：字表、部首、IDS 表、泛古籍语料 | 共享 | 引擎仓（git） | 清单进；大文本进 R2 | — |
| 底库 B 层：异体表、形近表、L1 规则、夹注词表 | 共享 | 引擎仓（git，走 PR） | 清单与条目镜像进 | 接收各书升格 |
| 书库：字频表、L2 答案表、用字账 | 独立 | 工作区 → 中心库 | 进（拆成行） | 随书归档，不升格 |
| 书库：整理本参考文本 | 独立（登记作品号） | 工作区 / book-text | 清单进；文本进 R2 | 本书精校后的 1.0.0 文本就是同一作品下一个刻本的最佳整理本 |
| 产物、cache、`glyph.db` | — | 本地，可重算 | 不进 | 删 |

一句话：**本书的东西永远各归各的，共享的东西只能经「升格」进来，所有共享都靠钉版本号才生效。** 中心库承载两者，升格是唯一的连接通道，归档是触发大批升格的时点。

## 一、现状

### 1.1 三本书的字形库（guji-workspace main，10-18）

| 工作区 | `edition_tag` | 实例 | 字头 | store 体积 |
|---|---|---|---|---|
| 殿本《四庫全書總目》 | `siku-zongmu` | 18,480 | 2,932 | 96 MB |

- 每本书一个 `edition_tag` 域，`glyphs` 以 `(edition_tag, char)` 为键，**同字不同版永不合并**（`clustering/glyph_db.py` 头注）。这条是对的：刻工、字体、磨损都属于版本。
- 跨书共享**完全没有**：殿本 1.8 万刻例，第二本刻本书一个也用不上（`doc/workspace_layout.md` §3.2 待办）。`GUJI_GLYPH_STORE` 只挂一个库。
- 字形 `glyphs.ids` 列每本书各存一份，实际是字级事实，和语料库的 IDS 表重复。

### 1.2 语料库
殿本 `corpus-v1` 清单 51 份：引擎仓 40 份约 42 MB（对所有书相同），工作区 11 份约 19 MB（本书独有）。北行、全唐文尚无清单、无字频表和 L2。钉子目前只是承诺：Step 读的是引擎仓工作树。

### 1.3 中心库（工作包 8）
已实现导入与核对（`doc/datastore.md`，cv#126）：三个工作区 188,404 行、29,837 张刻例图进 Neon ci 分支，逐行核对 0 差异。范围是人裁事件、裁决、锚、消费台账、名单、`config/**`（整文件）、字形库各表；刻例图进 R2，按 sha256 内容寻址、跨工作区去重。**不含** `corpus/`、产物、`glyph.db`、字体域。写入切换（第 4 步）还没做，git 仍是真源。

### 1.4 归档
三阶段流程（ai-team `team/整理/设计/文本整理三阶段流程.md` §8）：精校完成、文本 1.0.0 后归档，事件、锚、裁决、`glyph_store/`、`corpus/` 转入 **open-guji-dataset**（公开仓），删工作区。现流程只「保存」，**没有任何一步把这本书的经验交给下一本书**。

## 二、四块共用的原则

1. **三层**：A 通用源料（与书无关、外部来、可重建）／B 共享经验（与书无关、随各书经验增长）／C 本书（只属于这本书、不可再生）。字形库和语料库按同一把尺子分。
2. **C 层不外借**：一本书的人裁证据不悄悄变成另一本书的放行依据。别的书要用，只能走升格，升格进的是 B 层。
3. **先长在本书，审过才升格**。升格有证据、有记账、可追溯到来源书和事件。
4. **共享只经钉版本生效**：B 层出了新版，已钉旧版的书不受影响；哪册改钉哪册重算。字形库与语料库都一样。
5. **每份数据只有一个真源**：裁决类与本书字形以中心库为真源（工作包 8 第 4 步之后），底库以 git 为真源（要 PR 审阅），大文件以 R2 的内容哈希为真源。其余都是导出或索引。

## 三、语料库（已定部分，保留要点）

- **底库 `bM`**＝A＋B 层，整个项目一份；**书库 `vN`**＝C 层＋`base: M`，每个工作区各自编号。
- 册 yaml 仍写 `corpus: N`，指纹仍只带 `corpus-vN`；殿本 `v1`（无 `base` 字段的自包含旧格式）照常有效，不迁移。
- 钉子：起跑前对钉住版本做 `verify`，不一致**拒绝跑**；同一时刻所有活跃书钉同一个底库，落后的册先升再跑。物化以后再做，而且有了中心库之后很便宜（见 5.3）。
- 字频表、L2、用字账、整理本属书库，不升格。用字账 `wuyingdian_zongmu.json` 从引擎仓迁到殿本工作区。
- 北行日錄、全唐文用 `guji corpus init` 接入：底库白拿，字频、文意两种判法在产物里**显式**记弃权。

## 四、字形库

### 4.1 三层

| 层 | 内容 | 域（`edition_tag`） | 匹配时的地位 |
|---|---|---|---|
| A 字体 | 字体渲染字形 | `font:<字体>` | 兜底，现状不变 |
| **B 共享刻例库（新）** | 从已归档书升格来的精选刻例 | `lib:<字体族>`，如 `lib:qing-kai-palace`（清内府/殿本楷体系） | **第二顺位**：本书域没有或不够时才用，结论降一档信任（同字体域的处理） |
| C 本书 | 本书全部刻例与台账 | 本书 tag，如 `siku-zongmu` | 第一顺位，现状不变 |

- **为什么按字体族分域，不搞一个大库**：刻本字形因版而异，殿本楷字拿去配宋刻本是误导。字体族（`sources` 里已有 `script_style`、`era` 字段）是「借得动」的边界。同一刻本的不同部（如殿本系统里的其他书）借用价值最大。
- **为什么只放精选**：共享库的作用是冷启动（新书第一轮播种、库缺字时有候选），不是代替本书的库。每字每本来源书限 k 例（建议 k=3，取 exemplars），防止一本书独占。
- **字级信息不在字形库里存**：`glyphs.ids`、`semantic` 改为引用底库 IDS 表，字形库只存形。本书发现的 IDS 修订走语料库升格。
- **独立的部分**：本书域所有实例、准入/撤库历史、exemplar 选择、`pairs`（本书形近对）。新书用共享库得出的结论，入的是**本书**域（来源记为 `lib` 借形），不回写共享库。

### 4.2 版本
- 本书域的版本＝中心库里该书相关表的 `rev`（中心库设计 §六已定，取代现在按条数推断的 `db_fingerprint`）。
- 共享刻例库单独编号 `glyphlib-vN`，像底库一样钉在册 yaml：`glyphlib: N`。没写就不挂共享库，**现有各册行为与指纹一字不变**。
- 至此 sheldon 说的「一次跑批 = CV 版本＋字形库版本＋语料库版本」落地为：`code_hash`（或 CV 版本）＋（本书 `rev`、`glyphlib-vN`）＋`corpus-vN`。

### 4.3 匹配怎么挂两个域
`GlyphDB.query(editions=[...])` 已支持按域检索。要改的只有两处，留到实现时：`glyph_db_path()` 解析时把 `lib:*` 域一并装进本地 `glyph.db`（由 `guji db pull` 生成，中心库设计 §五）；`glyph_match` 对 `lib` 命中的结论降一档（和 `font` 一样不直接放行）。这会碰 `glyph_match` 的 `code_hash`，所以和 `glyphlib:` 开关一起在一个 MINOR 里做，开关缺省关。

## 五、中心化：在工作包 8 现有范围上补什么

工作包 8 已经覆盖人裁事件、裁决和本书字形库，方向与本文一致，不用改。本文要补的是语料库和共享层：

### 5.1 新增表（建议）

| 表 | 内容 | 真源 |
|---|---|---|
| `corpus_bases` | 底库版本：`M`、`repo_commit`、日期、说明 | git（`guji corpus build-base` 写库） |
| `corpus_books` | 书库版本：工作区、`N`、`base` | 工作区清单 |
| `corpus_items` | 每个版本的文件：分组、路径、sha256、大小 | 同上 |
| `corpus_pins` | 每册钉的 `corpus`、`glyphlib`、`cv_version` | 册 yaml（`books` 表已进库，拆出这三列即可） |
| `l2_answers` | 书、页、格、组、答案、模型、置信度 | 工作区（现在整文件进 `files`，改拆成行） |
| `freq_snapshots` | 书库版本、组、字、计数 | 由 `verdicts`／`events` 算出，书库出版本时冻结一份 |
| `glyphlib_versions`、`glyphlib_members` | 共享刻例库版本；成员 = 来源书、来源实例、`patch_sha`、字体族 | 中心库 |
| `promotions` | 每次升格：数据种类、条目、来源书与事件、证据、进了哪个底库/刻例库版本、谁批的 | 中心库 |

有了 `corpus_pins`，「哪几本书还落后在旧底库/旧刻例库」一句查询就能回答。

### 5.2 不进中心库的
- `rules.yaml` 等手写规则、底库各表的**编辑**：留在 git 走 PR，中心库只存每个底库版本的镜像，方便查询。
- 产物、cache、`glyph.db`、字体域：与中心库设计 §一一致。

### 5.3 大文件进 R2，顺带解决「物化」
整理本、泛古籍语料（约 50 MB）按工作包 8 现成的规矩进 R2：`sha256/<前两位>/<sha>`，只增不改。这样语料库每个版本的每个文件都能按 sha 取回，**档③物化不再需要新建内容寻址仓**：`guji db pull` 按钉住的版本拉到本地缓存，Step 读缓存。等真有两本书要钉不同底库，再做这一步。

共享刻例库同理：升格只是在 `glyphlib_members` 里记一行引用已有的 `patch_sha`，**图一张都不用复制**。

## 六、归档时回流（新流程）

### 6.1 什么时候回流
- **主回流在归档时**（精校完成、文本 1.0.0，三阶段流程 §8）：这时人裁最全、刻例已过体检，证据最硬。
- **粗校完成（0.1.0）时可做一次预回流**，只回流语料库 B 层的候选（新异体对、新形近对、规则候选），因为它们是字级事实，不怕后面精校改单格。刻例不在粗校时升格：精校还会撤库改判。

### 6.2 回流什么

| 来源（本书） | 挖出的候选 | 去向 |
|---|---|---|
| exemplars ＋ 人裁确认数 ＋ `glyphdb-audit` 结果 | 每字 ≤k 张精选刻例 | 共享刻例库 `lib:<字体族>`，出 `glyphlib-v(N+1)` |
| 人裁里的「CV 认 A、人改 B」 | 形近对候选 | 底库 B 层形近表 |
| 人裁里的「同义异形」裁决 | 异体对候选 | 底库 B 层异体表 |
| 字组流程中人裁攒够、模式稳定的文意判断 | L1 规则候选 | 底库 B 层 `rules.yaml` |
| 本书新确认的 IDS | IDS 修订候选 | 底库 A 层 IDS 表 |
| 精校后 1.0.0 文本（book-text） | 作品级整理本 | 书库登记 `work_id`；同作品的下一个刻本建书库时直接引用 |
| 字频表、L2、用字账 | 不回流 | 随书归档 |

### 6.3 怎么回流
```
归档前（三阶段流程 §8 的核对之后、删工作区之前）：
  guji promote mine   -w <书>                 # 从中心库里该书的事件、字形挖候选，写候选清单
  人审候选清单（审阅页，按第七节门槛预勾）
  guji promote apply  --list <清单>           # 写 promotions 记账
  guji corpus build-base / guji glyphlib build  # 各出一个新版本
  对已钉旧版的其他书各跑一次 A/B（guji exp），不退步才把各书的钉子改到新版
归档：本书域在中心库标 archived（只读、仍可查），文件按 §8 转入 open-guji-dataset
```
- 归档后本书域**仍留在中心库可查**，只是只读：同一刻本的其他部、或这本书重印时，可以直接挂本书域，比共享库更准。
- open-guji-dataset 是公开仓：人裁事件里的审阅人按 GUJI-562 脱敏，这一步和现有归档一致。
- 这一步要加进三阶段流程 §8 的「归档前核对」，作为第 6 条。那份文件归整理组，本项目独立运行期间不去改，**验收后集成时提给整理组**。

## 七、升格门槛（sheldon：按每种数据逐项讨论；下面是初稿）

| 数据 | 证据从哪来 | 门槛（初稿） | 谁批 | 验证 |
|---|---|---|---|---|
| 共享刻例 | 本书 exemplars | 人裁确认 ≥2 次；`glyphdb-audit` 未标「同字不像」「形似他字」；该字本书准确率下界 ≥97%；每字每书 ≤3 张 | 自动预勾，sheldon 抽看 | 拿另一本同字体族的书跑播种 A/B |
| 形近对 | 「CV 认 A、人改 B」 | 同一对在本书出现 ≥3 次，且不是切分错引起的 | 自动预勾，sheldon 过清单 | 在已钉书上 A/B：组外格一格不变 |
| 异体对 | 人裁的同义异形 | 有字书出处（异体字典或《康熙》）＋本书 ≥1 例；无出处的只进本书 | sheldon 定 | 同上 |
| L1 规则 | 字组流程人裁 | 在来源书上命中准确率 ≥99%、命中 ≥20 例，且在另一本书上抽 20 例无反例 | sheldon 定 | A/B 不退步 |
| IDS 修订 | 本书确认 | 通用 IDS 语法、完全展开；与已有条目冲突的先给 sheldon | sheldon 定 | 语法校验器 |
| 作品级整理本 | 精校 1.0.0 文本 | 文本线达到 1.0.0 即可登记 | 自动 | — |
| 字频表、L2、用字账 | — | **不升格** | — | — |

数字都是初稿，要 sheldon 逐项改。原则是：**自动预勾 ≠ 自动合入**，每次升格都留 `promotions` 记账，出新版本后各书自己决定什么时候改钉。

## 九、要 sheldon 定的

1. **共享刻例库按字体族分域、只放精选、在匹配里排第二顺位并降一档信任**，这样行不行？（另一种是不建共享库、只允许新书显式挂某本归档书的域。更简单，但每本新书都要人去挑挂哪本。）
2. **字体族怎么划**：建议先只开一个 `lib:qing-kai-palace`（殿本系统），等有第二种刻本风格的书再加。
3. **刻例库也钉版本**（`glyphlib: N`），跟语料库一样：同不同意？
