## 一、一页结论

| 数据 | 独立／共享 | 真源 | 在中心库里 |
|---|---|---|---|
| 本书刻例（instances、exemplars、admissions、evictions） | 独立（按工作区） | 中心库 | 已在，`glyph_*` 表 |
| 人裁事件、裁决、锚、消费台账、批次 | 独立 | 中心库 | 已在 |
| 书库：字频表、L2 答案表、用字账、工作区异体补充 | 独立 | 中心库 | 已在，`files` 表（`config/**`） |
| 书库清单 `corpus-pack/vN` | 独立 | 冻结的 git → **改进中心库** | 改放 `config/corpus-pack/`，自动进 `files` 表（2.2） |
| 整理本 `corpus/*.txt` | 独立（登记作品号） | 冻结的 git → **改进中心库** | 文本进 R2，库里记 sha（2.2） |
| 底库文件：字表、IDS、异体表、形近表、L1 规则、夹注词表、泛古籍语料 | 共享 | 引擎仓 git（走 PR） | 不进；中心库只存每版清单 |
| 底库清单 `bM` | 共享 | **中心库** | 特殊工作区 `corpus-base`（2.1） |
| 共享刻例库 | 共享（按字体族） | **中心库** | 每版一个只读工作区 `glyphlib-<族>-v<N>`，刻例图引用原 sha，不复制（第三节） |
| 升格记账 | 共享 | 中心库 | 目标工作区里的事件（第四节） |
| 字体字形（`kind=font`） | 共享 | 引擎仓 `fonts/`，确定性重建 | 不进（中心库设计第一节） |
| 原图 | 独立 | guji-workspace git／IA | 不进 |
| 产物、cache、`glyph.db` | — | 本地，可重算 | 不进 |

一句话不变：**本书的东西各归各的；共享的东西只经升格进来；共享层出新版就新开一份只读的，各书靠钉版本号决定什么时候跟。** v3 的新点是：共享层全部做成中心库里的特殊工作区，几乎不用新表。

## 二、语料库

### 2.1 底库（共享）
- **文件**仍在引擎仓（字表、IDS、异体、形近、规则……），改动走 PR。每版底库靠清单里的 `repo_commit` 还原。
- **清单**放中心库的特殊工作区 `corpus-base`：`config/corpus-base/b<M>/manifest.json`。每版一个文件、路径不同，新版不覆盖旧版，这就绕开了「中心库不存旧内容」。
- `guji corpus build-base` 出新版后，用 `guji db push -w corpus-base` 推上去。

### 2.2 书库（每个工作区）
- **清单**从 `<工作区>/corpus-pack/vN/manifest.json` 挪到数据目录 `config/corpus-pack/vN/manifest.json`。挪过去就自动进 `files` 表，不用改中心库。改的只是 `core/corpus_pin.py` 里的 `pack_root`：这个文件不在任何 Step 的 `code_deps` 里，`code_hash` 不变。殿本 `v1` 原样搬过去，钉子和指纹都不变。
- **整理本**（殿本约 19 MB，泛古籍语料 30 MB 留引擎仓）照锚图的做法：文本进 R2（`sha256/…`），库里新开一类元数据行，只记路径和 sha（同 `anchor_patches_meta`）。`pull` 按 sha 拉到数据目录的 `corpus/`，`core/workspace.corpus_path()` 改成先找数据目录。这一步要改 `datastore/scope.py`、`materialize.py`、`workcopy.py`，都不在 `code_deps` 里。
- 书库清单里 `base: M` 指向 `corpus-base` 里的某版底库。册 yaml 仍写 `corpus: N`（`books` 表已在中心库）。
- 字频表由人裁算出，现在人裁在中心库，以后可以直接从 `events` 表算。v3 不改，仍是 `config/groups/freq.json` 这个文件。

### 2.3 钉子与校验（已定，不变）
`pipeline` 起跑前对钉住的版本做 `verify`，不一致就拒绝跑。清单和文件都能从中心库或 R2 按 sha 取回，所以以后真要做「物化」（钉旧版就读旧文件），不用另建存储。

## 三、字形库

### 3.1 三层
| 层 | 在哪 | 匹配时 |
|---|---|---|
| A 字体 | 引擎仓 `fonts/`，`import-font` 本地重建 | 兜底，现状不变 |
| B 共享刻例库 | 中心库工作区 `glyphlib-<族>-v<N>`，先开 `glyphlib-qkp-v1`（qkp＝清内府楷体，殿本系统） | 第二顺位，降一档信任 |
| C 本书 | 中心库里该书的工作区 | 第一顺位，现状不变 |

### 3.2 共享刻例库怎么存
- **每版一个只读工作区**：`glyphlib-qkp-v1`、`glyphlib-qkp-v2`……里面只有 `workspace.yaml` 和 `output/glyph_store/`。出了新版就开新工作区，旧版不动，钉旧版的书照样拉得到。
- 刻例行指向来源实例原来的 `patch_sha`，**R2 里一张图都不用复制**。v1 估计：殿本每字 ≤3 张，2,932 个字头，最多约 8,800 行。
- 只读靠约定，加一道 push 检查：以 `glyphlib-` 开头的工作区，已有版本拒绝再写。

### 3.3 怎么挂进一本书
- 用现成的借库：`workspace.yaml` 写 `glyph_lib.borrow: [glyphlib-qkp-v1]`。版本号写在工作区名里，**这一行就是钉子**。
- **钉在工作区级，不在册级**：v2 写的是册 yaml `glyphlib: N`。但 `glyph.db` 一个工作区只有一份，借库是在重建它的时候装进来的，同一工作区的几册没法各挂各的版本。所以改为工作区级。要按册做 A/B，就在实验分支上改这一行跑全工作区。
- 要补的代码：
  1. **`db pull` 支持借库**：先拉被借的工作区，再按 `extra_stores` 重建 `glyph.db`。现在配了借库就报错（`ops/central_glyph.py`）。
  2. **借库要进硬指纹**：`glyph_match.db_fingerprint` 是软参数，借的版本变了，产物不会判过期。给 `glyph_match` 加一个自动填的硬参数 `borrow_fingerprint`（被借工作区名的排序列表）。这会让 `glyph_match` 的 `code_hash` 变一次，所以要和第 3 条放进同一个 MINOR。
  3. **降一档信任**：`glyph_match` 对 `borrowed` 表里的命中不直接放行，和字体域一样。同样会碰 `glyph_match`。

### 3.4 要先核实的一处：借来的人裁会不会被当成本书的铁证（未实测）
读码看到两点：
- `rebuild_from_store` 借库时 `admissions.jsonl` 也照装，没有跳过（`clustering/glyph_db.py` 约 993 行）。
- `seed_admit` 人裁通道的查询 `glyph_fp.HUMAN_SQL` 只按 `provenance='human'` 和 `instance_id LIKE 'v2:%'` 过滤，不看是不是借来的。

两点合起来，**借来的人裁实例可能被当成本书的「同形人裁」铁证**，这正违反「本书的东西不外借」。全唐文现在就借殿本，可能已经受影响。这是从代码推断的，还没在全唐文的 `glyph.db` 上验证。实现第 3.3 节之前，先在全唐文上查一次：借来的实例里有多少条被计入人裁通道。若属实，修法是借库时不装 admissions，或者 `HUMAN_SQL` 排除 `borrowed` 表。修法会碰 `seed_admit` 的人裁指纹，要另开一卡报给 sheldon。

## 四、升格与回流在中心库里怎么做

### 4.1 升格记账
不新建 `promotions` 表。升格就是往目标工作区写事件，进现成的只追加 `events` 表，`changes` 自动留痕，备份也自动覆盖：
- 进刻例库：`glyphlib-qkp-v(N+1)` 的 `feedback/events/promote.jsonl`，一行一条：来源工作区、来源实例、证据、谁批的。
- 进底库：`corpus-base` 的 `feedback/events/promote.jsonl`，同样格式，加上对应的引擎仓 PR。

### 4.2 回流流程
```
本书精校完成（文本 1.0.0），归档之前：
  guji promote mine -w <书>              # 读中心库里该书的人裁、字形、glyphdb-audit 结果，出候选清单
  人审候选（审阅页，按第六节门槛预勾）
  刻例：guji glyphlib build --from glyphlib-qkp-vN --add <清单>   # 开新工作区 v(N+1)，写 promote 事件，push
  语料：引擎仓开 PR 改异体表、形近表、规则 → 合入 → guji corpus build-base → push 到 corpus-base
  其他书：在实验分支 exp/<卡号> 上改钉子（workspace.yaml 的 borrow／书库的 base），跑 A/B，不退步就 guji db import 进 main
归档：该书工作区在中心库里标为只读（不再 push），按三阶段流程 §8 导出到 open-guji-dataset
```
- 粗校完成（0.1.0）时只跑 `promote mine` 的语料部分（形近对、异体对、规则候选）。刻例要等精校结束再升格。
- 归档后，本书工作区仍在中心库可查。同一刻本的其他部可以直接借这个工作区，比借共享库更准。
- open-guji-dataset 是公开仓：导出时审阅人按 GUJI-562 脱敏，和中心库设计第九节一致。
- 「归档时回流」要加进整理组的归档流程（ai-team `team/整理/设计/文本整理三阶段流程.md` §8）。这份文件归整理组，本项目验收后集成时再提。
