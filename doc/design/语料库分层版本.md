# 语料库分层版本：全局／整套书／册，三层各一个整数，册上记一个总号

> 2026-10-20，Emerson。起点是 sheldon 的提议（下面「一」），盘点来自收口线程对殿本 v9 清单的核对（101 个文件）。
> 接在 [语料库版本化方案](语料库版本化方案.md)（钉子、`corpus-vN` 指纹）和 [字形库与语料库：共享与中心化方案](字形库与语料库-共享与中心化方案.md)（底库＋书库两级、中心库落位）之后，**不推翻它们**：现在的底库 `b<M>` 就是全局层，书库 `v<N>` 就是整套书层，要新增的只有「册层」和「总号」。

## 一、sheldon 的想法（原样提炼）

1. 语料库分三层：**global**（所有人共享）、**book-id**（一套书，比如四库总目，下面各册共用）、**册**（单册自己用）。
2. 每层各有一个整数版本，从 1 往上涨。
3. 册配置里的语料版本号是三层版本的**组合**；任何一层变了，总号就升。例：vol1 起始 `v1 = {global: 10, book-id-xxx: 8, vol-set: 1}`；book 升到 9 → 总号 v2；册层升到 2 → 总号 v3。
4. 大静态文件不放进某层的语料库，存 R2，层的配置里只记哈希做索引。
5. （10-20 另定）平时在 dev 上随便改，攒到发版才升版本号；不另开 git 仓。

## 二、现状（为什么要改）

殿本 `corpus: 9` 钉的是「书库 v9 ＋ 底库 b1」，清单登记 101 个文件，但放的地方和性质混在一起：

| 类 | 个数 | 现在放哪 | 性质 | 该归哪 |
|---|---|---|---|---|
| 字频表、文意表 12 组、本书异体表 2、整理本 5 | 20 | 中心库（工作区级） | 按书的数据 | **整套书层** |
| 字集／康熙、异体字典、形近、IDS、夹注、殆知阁两部（各约 15MB） | 35 | CV 仓 | 通用字典 | **全局层** |
| 各字组 `prompt.md`、`rules.yaml`、`ids_bank.json`、覆盖表 | 46 | CV 仓 | **其实是数据**（词组规则、书名词例、从殿本人裁挖的字形库）；读它们的代码才是逻辑 | **留在语料库**，逐个判全局层还是整套书层（4.1） |
| （册层） | 0 | — | 目前没有 | 见 4.3 |

三个问题：
- 改一条 prompt 就要出新语料库版本、各册改钉，两个节奏被绑死。
- 钉的是「一个号」，看不出是哪一层变了；底库和书库各自编号，册 yaml 里只写一个书库号，底库号藏在书库清单的 `base` 里。
- 清单只登记哈希，不存内容，旧版本想还原只能靠 git 提交（底库）或根本还原不了（书库，中心库不存旧内容）。

## 三、方案

### 3.1 三层
| 层 | 内容 | 版本号叫 | 清单放哪 | 现状对应 |
|---|---|---|---|---|
| 全局 G | 通用字典、外部参考文本 | `b<N>`（P1 沿用现名） | 中心库 `corpus-base`：`config/corpus-base/b<N>/manifest.json` | 现在的底库 `b<M>`，不变 |
| 整套书 B | 字频表、文意表、本书异体表、整理本 | `v<N>` | 工作区的 `config/corpus-pack/v<N>/manifest.json` | 现在的书库 `v<N>`，不变 |
| 册 V | 单册私有语料 | `v<N>` | `config/corpus-pack/vol/<册>/v<N>/manifest.json` | 新增，初期为空（4.3） |

每层各自：一个整数，从 1 起，**只增不改**，旧版本清单不可覆盖（现有行为，沿用）。

### 3.2 总号
- 册 yaml 仍写 `corpus: <N>`（整数，**与现在的写法完全兼容**）。
- N 对应的三层组合记在**该册自己的钉子账**里：`config/corpus-pack/pins/<册>.json`，只追加：

```json
{"rows": [
  {"n": 9, "global": 1, "book": 9, "vol": null, "date": "2026-10-20", "note": "迁移：原 corpus: 9"},
  {"n": 10, "global": 2, "book": 9, "vol": null, "date": "...", "note": "全局 g2：补异体字典"},
  {"n": 11, "global": 2, "book": 9, "vol": 1, "date": "...", "note": "册层首版"}
]}
```
- 新命令 `guji corpus pin -w <ws> --vol <册> [--global-ver M] [--book-ver N] [--vol-ver K] [--from-n 现在的 corpus:] --note ...`：把三层里要换的换掉、没写的沿用最新一行；**组合与最新一行相同就拒绝**（不空升）；否则追加 `n = 最大 n + 1`，打印新总号。**命令只写账，不改册 yaml、不推中心库**，新总号由收口线程写进册 yaml（册配置归它统一改）。任何一层变了总号必升，是账的结构保证的，不靠人记。
- 册层清单：`guji corpus build -w <ws> --vol <册>` 出 `vol/<册>/v<K>`；内容和上一版相同拒绝。`guji corpus verify --vol <册>` 按钉子账最新总号三层一起对。
- **指纹不含版本号，取内容**（sheldon 10-21）：指纹串 = `corpus-` + 该总号三层清单所有条目（根、路径、sha256）排序后的哈希。好处：升了版本号但这册用到的文件没变，指纹不变，不白重算；开发中取工作副本当前内容，发版时清单就是那一刻的文件，指纹不变，不用 `fp-migrate`。
- **兼容**：还没有钉子账的册（殿本十册现在的 `corpus: 9`）仍用旧写法 `corpus-v9`，已有产物不过期。第一次 `pin` 登记的迁移首行（账里 `legacy_token: true`，n 沿用原 `corpus:` 号）仍是旧写法 `corpus-v9`，**迁移本身不改任何指纹、不需要 `fp-migrate`**；之后新升的总号（比如 10）才用内容哈希，指向新内容的册自然重算（M8 的事）。
- 总号是**每册自己的**账（对应 sheldon 例子里 vol1 的 v1→v2→v3）；两册三层组合相同，总号也可以不同，这没关系，指纹本来就是每册的。
- 兼容：册 yaml 写 `corpus: 9` 但没有钉子账 → 当作 `{global: 书库 v9 清单里写的 base，book: 9, vol: null}`，和现在行为一致。钉子账只在第一次 `guji corpus pin` 时生成（首行就是上面这行迁移行，n 沿用 9）。

### 3.3 校验
`require_pin_clean`／`push_problems`／`guji corpus verify` 改成：按 N 查出三层版本，三份清单**并起来**对当前文件（现有两级合并，加一层）。条目根的规矩沿用并加一条：G 只放引擎仓文件，B 和 V 只放工作区文件，V 只能在 `config/corpus-vol/<册>/` 下。

### 3.4 大文件进 R2，层配置里只记哈希
- 清单条目加可选字段 `blob`：`{"sha256": ..., "size": ...}`，表示这个文件的内容在 R2 按哈希存（桶 `guji-assets`，公开域名 `blob.open-guji.com`，现有整理本已是这样，沿用 `corpus_files`）。
- **门槛**：单文件 ≥ 1MB 必须走 `blob`（殆知阁两部、整理本）；小文件（字典、表）直接登记哈希，内容仍在 git／中心库。
- 好处：全局层从此不必把 30MB 外部文本放进 CV 仓；任何一层的任何一版，只要清单在，大文件就能按哈希取回，旧版本可还原。

### 3.5 「平时随便改、发版才升」：版本号先升，再用 `corpus_dev: true` 跳过校验（sheldon 10-21 定）
- 要改语料时：`guji corpus pin --dev`（各层版本号可以指向还没出的清单）追加新总号，册 yaml 写 `corpus: <新总号>` 并加 `corpus_dev: true`。开发中：**不核对清单、不拒绝起跑**；指纹取工作副本当前内容（3.2），所以改了表产物自动判过期，不会悄悄用旧结果。
- **只在本机用，不进中心库**：普通 `guji db push／sync` 发现册 yaml 带 `corpus_dev: true` 就拒绝（`push_problems`），中心库只收正式版本号。
- 改定了：各层出新版（`guji corpus build`、`build --vol`，版本号要和账里写的一致），`guji corpus release --vol <册> --version <总号>` 检查三层清单都出齐、去掉账里的 dev，再把册 yaml 的 `corpus_dev` 去掉，之后进入钉死状态：清单里的文件不许再改，要改就再 `pin --dev` 升新总号。
- 发版前后指纹不变（内容哈希），不需要 `fp-migrate`；没有快照读，不需要改读语料的 Step，也不需要给每个文件在 R2 存快照（原方案 A，取消）。
- 已知缺口（同未钉的册）：形近表、`NEVER_MATCH_FAMILIES`、异体表、rare_candidates 的字表本来没有进 `PIN_FIELDS` 的内容指纹；`CORPUS_STEPS` 的整步 `corpus` 键现在带的就是上面的内容哈希，已覆盖这几处文件（清单里登记的都算）。`NEVER_MATCH_FAMILIES` 是代码常量，随 `code_hash`。

### 3.6 不动的
- 一次跑批指纹＝CV 版本＋字形库版本＋语料库版本；字形库钉子（`glyph_pin`）、`cv_version` 护栏不动。
- `code_hash`：这次只改 `core/corpus_pin.py`、`core/engine.py` 的起跑前校验、`core/book.py`（新字段）、`ops/corpus_pack.py`、CLI，不在任何 Step 的 `code_deps` 里，**17 步 code_hash 不变**；没写 `corpus:` 的册和没有钉子账的已钉册（殿本）指纹逐位不变。

## 四、各层放什么

### 4.1 逻辑和数据彻底分开（sheldon 10-20 补充，取代原先「算法配置出语料库」）
原则：**逻辑在 CV 仓；数据在语料库；配置按影响范围分：整条流程的开关在 CV，一套书或一册书的配置在 guji-workspace（中心库 `config/`）。**
对 `config/groups/<组>/` 下 46 个文件逐类核过（读了实际内容）：
| 文件 | 实际是什么 | 归哪 |
|---|---|---|
| `rules.yaml`（23 个） | L1 词组正则，如「綱目、條目、目睹」：古汉语用字知识，手写，注释里偶有殿本用例 | 数据。通用的进**全局层**；只对本书有效的进**整套书层**（逐组判，见下） |
| `prompt.md`（23 个） | 提示词，第一行就写「《四庫全書總目》殿本刻本」，后面是该字组的用法词例 | 数据＋模板混在一起：**拆成「通用模板」（逻辑，CV 仓）＋「书名／词例」（数据，整套书层）**。P3 拆 |
| `ids_bank.json`（10 个，共约 1.4MB，`zheng` 一个 640KB） | 字形模板库，来源写着 vol01…vol10 的切图，是从殿本人裁里挖出来的 | 数据，**整套书层**（≥1MB 的走 R2 哈希） |
| `ids_override.tsv`（3 个） | 人工覆盖表 | 数据，整套书层 |
| 读这些文件的代码（`groups/ctx_l1.py`、`flow.py`、`ids_online.py`、`registry.py`） | 加载器、判法 | 逻辑，留 CV |
注意：判法**参数**（阈值、窗口大小）现在写在代码里或 Step 参数里，不是文件，不在清单里；真要搬到册配置是另一件事。

### 4.2 通用字典、参考文本
- 35 个通用字典（字集、康熙码表、异体字典、形近、IDS、夹注词表）归全局层，不变。
- **殆知阁两部**：我读了内容。`daizhige_ru_yi.txt` 开头是《春秋左傳正義》，`daizhige_zhaoling.txt` 开头是《淳熙玉堂雜記》《金坡遺事》，是殆知阁网站上抓的**泛古籍文本**，不是《四库总目》，也不是任何一册的整理本。它们在 `context_decide` 里当「泛古籍 n-gram 语料」（参数名 `general_corpus_dir`），谁的书都用，所以放**全局层**；各约 15MB，走 R2 哈希。你问的「如果是四库总目就该在书层」——这两部不是，书层的是 5 个整理本（殿本、文渊阁、维基文库本等）。
- 本书异体表在 CV 仓和中心库各有一份重复：整套书层留一份，全局层只留通用的，去重时先比内容。

### 4.3 册层放什么
现在没有册私有语料。预留位置 `config/corpus-vol/<册>/**`，候选：册级固定用字补充、册级整理本分段、册内人工确认的异体。先不放，等有第一个需求（比如彝组之后的册专有表）再出 `v1`。**没有册层 = 钉子账里 `vol: null`**，总号只随 G、B 变。

## 六、会碰到的坑
- 全局层叫 `b<M>`，中心库里已有 `corpus-base/b1`、北行钉 `base: 1`。**P1 不改叫法**，免得动已推的路径；要改名另议。
- 钉子账是只追加文件，推中心库走 `files` 表的乐观锁，两个线程同时 `pin` 同一册会冲突；册的钉子账有收口线程独占（项目规矩），不加锁。
- 回退：钉子账允许新增一行指向更旧的层版本（回退），总号仍然单调。

- 殿本 `corpus: 9` 在没有钉子账时 `params_for` 指纹与改前逐位相同（测试里对一个自造册断言）。

**一键脚本**：`python scripts/migrate_corpus_layers.py prepare -w <殿本工作区>`（本机和 R2，已用殿本真数据完整跑通：b2、v10、十册钉子账、verify 全干净、上传 R2）；`... push -w <殿本工作区>` 缺省演练，加 `--yes` 真推（要 sheldon 一句同意）。下面是它做的事：
