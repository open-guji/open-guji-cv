## 一、目标

在本机就能查的「字＋关系边＋部件＋字形向量」离线库，按版本钉住。
一句话：**`audit alt` 和控制台「以字找字」不再联网等字统网，族至少不比现在小，排序照旧按字块图。**

## 二、不做什么

- 不做字形演化（甲骨、金文、简帛）。需求 §9-1 的建议，用户未反对，按默认走。
- 不整站抓字统网，不全文照抄任何一部词典（见第三节许可立场）。
- 本期不做 HTTP 服务（B6 只留接口位，等用户定）。
- 本期不改任何 Step 的 `code_deps`：`variants.json` 照旧是 5-b 读的那份；新库导出一份兼容的，换不换另做决定（B3）。
- 不碰正文以外的页型、不碰放行判据：库只出候选。

## 三、用户 10-19 晚的定调（许可）

> 不用太刻意地管许可。字与字之间的关系不属于创作内容，没有严格的版权限制。
> 开源资料里不确定的地方，可以上网有针对性地查。只要不全文照抄别人的词典，只是有针对性地参考、研究，最后得出我们自己的事实结论，就没有侵权风险。用户已反复确认。

落到设计上：

1. **关系边是事实**：「A 是 B 的异体」「A 通 B」这类结论，来自哪里都可以收进库，按来源标注。
   部件檢索 rt（非商业）、cjkvi（无 LICENSE）照收，不再当阻塞项。
2. **字统网**：可以**按需、有针对性**地查（一次一个字，低频、缓存），把查到的**关系事实**（谁和谁、什么关系、出自哪部字典）收进库，来源标 `zi:<前缀>`。
   不存整页、不存它的图和释义原文，不整站爬。需求 §9-2 按此答复。
3. **教育部《異體字字典》等网站同理**：疑难字可以针对性地查，把结论（例如「某字是正字」）作为 `web:<站名>` 来源的事实边记下，附查询日期。不申请授权（需求 §9-4）。
4. 许可字段**照留**（`sources.license`），只用来标出处和日后对外打包时可以一键过滤，**不挡任何导入**。
5. **字形图另说**：字体文件和扫描图是作品，照旧按各自许可（I.Ming、Jigmo、康熙公版、GlyphWiki）。天珩全字库照旧不用。

## 六、共用契约（B0）

### 6.1 产物形态（B7 定稿，10-19 晚用户定「核心包进 git，部件包先按 txt 传 R2」）

| 包 | 内容 | 放哪 | 大小 |
|---|---|---|---|
| 核心包 | `sources`、`edges`、`forms` 三张 tsv；形近对不另存，灌库时直接读 `config/ids/` 的两张表 | **git**：`config/hanzi/core/` | 4.9 MB |
| 部件包 | `chars`、`ids`（只留主套 yibai lv1）、`comps`（只存直接部件，多层查询时现算） | **R2 正式桶**，按 sha、txt 后缀 | 10.3 MB 文本 |
| 清单 | 版本、每个文件的 sha／行数／属哪个包、原始资料的 sha、统计 | **git**：`config/hanzi/manifest.json`（当前版）＋ `versions/<版本>.json`（历次） | 几 KB |
| 向量包（B2） | 全字表字体模板向量，float32 分片 `vectors-NN.npy`＋`chars.txt`＋`failed.txt`；版本号由模型、字体、渲染代码、额外图源四样指纹算出 | **R2**，按 sha；清单 `config/hanzi/emb/<版本>.json` 进 **git** | 约 105 MB（4 片） |
| 原始资料 | Unihan 四个文本、cjkvi、yitizi、部件檢索、yi-bai lv1、字统网派生族 `zi-families.jsonl` | **R2**，按 sha（上游会变，存一份才能原样重建） | 约 20 MB |

- **sqlite 不分发**：各机由 `pack.Pack.ensure()` 灌到 `$GUJI_DATA_HOME/_shared/hanzi/<版本>/{core,parts}.sqlite`，同版本只灌一次。核心库 1 秒；部件库约 3 秒，外加第一次下载。
- **取文件**：按清单的 sha 认，先看仓里、再看本机 blob 缓存，都没有就从 `https://blob.open-guji.com/sha256/<2>/<sha>.txt` 下载，不要令牌，下完核 sha。
  所以云会话克隆完就能查族、形近；第一次用部件检索时才拉部件包。
- **旧版本**：`HanziDB.open(version=…)` 读 `versions/<版本>.json`。仓里的核心包已经换了版，就按 sha 从 R2 取那一版。
- **内容指纹** `content_sha`：清单 `files` 里各文件的 sha 按键排序再 sha256，取前 12 位。版本名 `hanzi-<content_sha>`。
  清单里不写时间戳，同一份原始资料＋同一 commit ⇒ 清单逐字节相同（验收 A3）。
- **构建与发布**：`scripts/build_hanzi_db.py [--fetch] [--zi-dir …]` 构建并发布到 `config/hanzi/`，约 10 秒。
  `--upload` 用正式令牌经 guji-data Worker 把清单里的文件和原始资料传进 R2（按 sha，已有跳过）。
- **和中心库的关系**：原计划把清单放中心库的共享工作区、经 `guji db pull` 拉。改成清单进 git 后读取不要令牌，也不用改 `db pull`；版本和代码一起走，更简单（见 §11）。

### 6.2 表

| 表 | 主键 | 列 |
|---|---|---|
| `sources` | `src` | `name`、`url`、`sha256`、`license`、`tier`（`open`／`nc`／`unclear`／`own`／`fact-ref`）、`note` |
| `chars` | `ch` | `cp`、`block`、`rs`（kRSUnicode）、`strokes`、`kangxi`（kIRGKangXi）、`def`（kDefinition，英文，只作提示） |
| `forms` | `key` | 未编码形：`key`＝IDS 串（不造 PUA），`src`、`ref`、`regular`（归属的正字，可空） |
| `edges` | (`a`,`b`,`rel`,`src`,`sense`) | `a`、`b`、`rel`、`directed`、`src`、`sense`、`ref`、`note` |
| `ids` | (`ch`,`src`,`seq`) | `ch`、`src`（现只收 `yibai:lv1`）、`seq`、`regions` |
| `comps` | (`ch`,`part`) | 主 IDS（`yibai:lv1`）的**直接**部件（depth=1）；`vt` 折叠后的部件另记一行 `folded=1`；多层由查询逐层现算 |
| `near` | (`a`,`b`,`src`) | 形近对：`kind`、`score`、`detail`（本仓两张形近对表原样进） |
| `emb`（B2） | (`ch`,`style`) | fp16 向量 blob＋`ckpt`（checkpoint 指纹） |

**边的约定**（需求 §3.3）：

- `directed=1` 时 **`a` 是正字、`b` 是异体／简体／借字**；`directed=0` 时按码位 `a<b` 存一行。
- `rel` 取值，**不混成一个「异体」**：

  | `rel` | 含义 | 来源举例 | 当不当异体 |
  |---|---|---|---|
  | `variant` | 来源说是异体 | twedu、hydzd、dypytz、yitizi、kSemanticVariant、charcomp rt 的 `~` 段、zi | 候选；最终归类看本书用字账 |
  | `variant_partial` | 只在部分义项同 | kSpecializedSemanticVariant | T2 先验 |
  | `z` | 字形微差、同字 | kZVariant | 当异体 |
  | `simp` | 简繁（a 繁 b 简） | cjkvi-simplified、kSimplified/TraditionalVariant、hydzd/simplified | 只作关系证据，不当桥 |
  | `borrow` | 通假（a 本字 b 借字） | hydzd-borrowed | **永不当异体** |
  | `spoof` | 形近易混（防钓鱼） | kSpoofingVariant | **永不当异体** |
  | `distinct` | 人审定「永不并组」 | `never_group.json` | 负边：查族时把对方剔掉 |

- `src` 沿用现役标签（`twedu`、`hydzd`、`unihan:kSemanticVariant`、`local:keben` …），新来源用 `charcomp:rt`、`zi:GHZR`、`web:moe` 这种前缀式。
- `sense`：义项。开放源没有就空串；字统网边填它的节点 id。
- 同一对字、同一 `rel`、不同 `src` 各一行：**来源不合并**，溯源靠这一点。

### 6.3 查询 API（`open_guji_cv.hanzi`）

| 函数 | 说明 |
|---|---|
| `HanziDB.open(version=None, parts=None)` | 按 git 里的清单灌本机库；`parts=None` 时部件库等第一次部件查询再拉，`True` 立刻备好，`False` 不要 |
| `family(c, rels=FAMILY_RELS, srcs=None, depth=1)` | 以 c 为中心的星形族，`{字: [Edge…]}`；`distinct` 边上的字剔掉；depth=2 只从 c 的一跳成员再走一跳，不做连通分量 |
| `edges(a, b)` / `variants_of(c)` | 两字之间的全部边；兼容现役 `variants.variants_of` 的 `[(字, (标签…))]` |
| `near(c, k)` | 形近，按分数降序 |
| `by_components(parts)` / `by_ids(seq)` | 部件组字、IDS 反查 |
| `info(c)` | 码位属性＋各套 IDS |
| `pool(pivots, near_k=5)` | 与 `family_pool` 同形的输出（`{字: {"p", "src"}}`），`src` 简写 `v`／`rt`／`zi`／`near`／`piv`，B3 直接替换 |
| `export_variants_json()` | 按现役格式导出 `variants.json`（`pairs`＋`directed`），B3 换表前对照用 |

### 附：「永不并组」去留分析（10-20，用户问「是不是太人工、去掉会怎样」）

`config/variants/never_group.json` 54 对，管两处：
- 用字账分组：`scripts/build_book_variants.py:build_groups`；
- 语义自动表：`clustering/variants.VariantMap._drop_never`，match_replace 按「语义相同」放行时读它。

它在 Step7 `seed_admit` 的指纹里，改动会让各书 Step7 判过期。逐对核（关系表＋殿本整理本参考文本）：

| 去掉后 | 对数 | 后果 |
|---|---|---|
| 语义表重新把两字算同一个字 | 5（沙砂、僕仆、冶治、咸鹹、嘗嚐） | match_replace 静默放错（qtw v010:73:2:21「沙」存成「砂」那类） |
| 用字账重新并组 | 45 | 首选形改字或压人审（注註 97% 那类） |
| 本来就有别的机制挡 | 4 | 无影响 |

- **形近字组替代不了它**：形近字组判「这一格是组内哪个字」；永不并组挡的是「字典说可互换、本书里是两个词」。名单里大多数对字形并不像（州洲、中仲、乾干）。
- **可规则化的部分**：分组时不认「只有 hydzd／yitizi 背书」的异体边，能盖住其中 25 对。代价是全库 41,178 对可分组的异体里有 15,514 对只靠这两家，得先用 `guji exp` 在几册上量人审率与放行错。
- **剩下 29 对**有 twedu／Unihan 背书（雲云、準准、沙砂、祐佑），是书一级的分工，字典规则判不出。建议改成「从人裁挖候选、人只点头」，套路同 `guji promote mine`。
