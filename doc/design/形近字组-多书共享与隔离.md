# 形近字／异体字组：多书之间怎么隔离、怎么共享

> 2026-11-03，A24。起因是 sheldon 11-03 的问题：以前只整理一本书，以后会有很多本书，形近字下面的各种东西怎么在多本书之间保持独立、又让一部分可以共享；同时要逐步把**逻辑、参数、数据／模型**分开，并且能扩展到几万本书。
> 本文**只出方案，不改代码**。第 2 轮重跑冻结期间，下面任何一步都不合会改产物的 PR。

> 本文接在下面三份已定的设计之后，**不推翻它们**，只补上「字组」这一块：
> - [语料库分层版本](语料库分层版本.md)：全局 G／整套书 B／册 V 三层，册上记一个总号。
> - [字形库与语料库：共享与中心化方案](字形库与语料库-共享与中心化方案.md)：本书的各归各，共享的只经升格进来；共享层做成中心库只读工作区；刻例库按字体族分域、`glyph_lib.borrow` 借用。

## 〇、一页结论

1. **判据只有一条：是「知识」还是「事实」。**
   - **知识**跟具体哪本书无关，例如：两个字是不是异体、某个词组用哪个字、IDS 怎么拆。知识放全局层，大家共享。
   - **事实**是「这一次雕版是怎么刻的、这个整理本是怎么录的」，例如：殿本 祿禄 只有一种刻法、全唐文整理本 天 大 可信、门族在殿本刻成什么样。事实只属于一本书，**不能继承，只能借鉴**：复制过来当候选，在本书重新看图核过才生效。
   - 两者之间还有第三种东西：**能力**，也就是从某本书的事实训练出来的模型和模板（ids_bank、U-Net、整字 HOG、L2 小头）。它按**字体族**共享，比如殿本系、写本系。新书拿来当初始值，用之前必须在本书上按册留出重测。
2. **加一层「字体族」。** 现有三层是 全局／书／册。字形相关的东西天然是按刻风共享的，所以在全局和书之间补一层「族」。几万本书扩展的杠杆就在这里：新书挂到一个族上，模型和模板直接借来用，只需要补书级事实。族的数量是几十个，不是几万个。
3. **三种共享机制，各管一类东西。**
   - **继承**：参数用。下层自动拿到上层的值，可以覆盖。
   - **借用**：模型和数据用。只读、钉版本，不复制；结果留痕「借自谁」；**借来的不能当本书的证据**。现成的例子是 `glyph_lib.borrow`。
   - **抄录**：书级事实用。复制一份进本书，标成「候选」；本书看图核过才生效。现在全唐文的 `follow_ref_seen` 14 对就是这么来的。
   - 反方向是**升格**：书级的东西要升到族或全局，需要至少两本书的证据一致。
4. **字组逻辑不按书分叉代码。** 切分可以按套书分叉，用 `seg_set` 的 OVERRIDES。字组不一样：一律用「代码＋书级方案文件」，书和书之间的差别全部写成数据。
5. **几万本书靠「按例外配置」。** 新书默认什么都不写，全部继承族的配置。字频、`form_freq` 等统计从本书的放行结果自动生成。只有送审多的字组才开书级方案。书级文件是稀疏的，没写就等于继承。

### 2.1 五层（从共享到私有）

| 层 | 键 | 放什么 | 真源 | 版本 |
|---|---|---|---|---|
| **C 代码** | — | 方法实现、加载器、合并规则 | cv 仓（PR） | cv 版本号 |
| **G 全局知识** | — | 组定义（成员、同义还是不同义）；异体字典、IDS、edge_pair 通则；L1 通用规则；提示词模板；基座模型；L2 小头（待验）；跨书文意缓存（见 4.3） | cv 仓（文件），清单放 `corpus-base` | `b<N>` |
| **F 字体族** | 族 id，例如 `qkp`（四库殿本系刻本）、`skxb`（四库写本系） | 组方案缺省值（族 profile：开哪些组、阈值）；ids_bank、U-Net、整字 HOG；共享刻例库 | 中心库只读工作区 `groupkit-<族>-v<N>`、`glyphlib-<族>-v<N>` | 每版一份，只增不改 |
| **B 书** | 书 ID，例如 `96mid1ogzk` | 码位结局 `codepoints.yaml`、参照策略（`reference_trust`、`follow_ref*`）、白名单、`cp_*` 组、字频、form_freq、L2 答案表、人裁、刻例库、`book_prompt`、书级组方案覆盖 | 书的工作区（中心库 `files` 表，≥1MB 走 R2） | 书库 `v<N>` ＋ 中心库 rev |
| **V 册** | 册 | 实测版式先验、册级例外 | 册 yaml | 总号 |
| （运行） | 任务单 | 实验覆盖 | 不落库，记进 manifest | — |

和已定设计的对应关系：G＝底库 `b<N>`，B＝书库 `v<N>`，V＝册层。**F 是新加的**。字形库方案里的「刻例库按字体族分域」已经在 F 层，这里把模板库和模型也放进去。

### 2.2 三种机制

| 机制 | 用于 | 怎么做 | 留痕 |
|---|---|---|---|
| **继承** | 参数（组方案、开关、阈值） | Step 默认 → 管线 yaml `params:` →（新）族 profile → 书 `book_defaults` → 册 yaml → `--override`／`--params`。按「写没写」深合并，`null` 表示删除。这一顺序 cv#903（11-03）已经在 `Engine.__init__` 落实；族 profile 是本文要新插的一层，位置在管线 yaml 和 `book_defaults` 之间 | `guji book show --effective` 已能逐字段列出来源层（含管线 yaml，cv#903），族层上线后多列一层 |
| **借用** | 模型、模板、刻例、缓存 | 书级配置写 `borrow: {groupkit: qkp-v3}`，只读、钉版本；本书有同名文件时本书优先（`ids_online` 现在已经这样） | 判定证据记 `via=borrow:<来源>@<版本>`；**借来的东西不当本书的人裁证据**（字形库 3.4 节已经核实过这条） |
| **抄录** | 书级事实（码位候选、白名单、L1 规则里的书级词例） | `guji groups adopt --from <书> --what follow_ref_seen` 生成候选文件，状态是 `candidate`；本书看图页核过以后才转成 `active` | 每条记来源书和核对人。没核的不生效 |
| **升格**（反方向） | 书 → 族，族 → 全局 | 至少两本书的证据一致，出族或全局的新版本 | 升格事件记在目标工作区 |

### 2.3 什么能共享：判断表

| 问一句 | 是 → | 否 → |
|---|---|---|
| 换一本内容完全不同的书，它还成立吗？ | G 全局 | 往下问 |
| 它是从图像、刻风上学来的吗？ | F 族（借用，用前在本书留出重测） | 往下问 |
| 它是「这一次雕版、这一个整理本」的事实吗？ | B 书（只能抄录） | 往下问 |
| 它只对某一册成立吗？ | V 册 | 改成书级 |

## 四、扩展到几万本书

### 4.1 新书零配置起步
- 新书立档时只填一项：**族**。族可以从 book-index 的版本元数据自动建议（四库写本、殿本刻本、明刻、清刻……），立档人确认。
- 其余全部继承：组方案、`group_flow`、阈值取族 profile；模板、U-Net 借族库；L1 规则、提示词模板、L2 小头取全局。
- 自动生成的书级统计：首跑以后由 `guji groups bootstrap <书>` 从放行结果出字频、form_freq，进书库。字频照旧只认人裁，不够就弃权。
- 参照策略是唯一必须人定的书级开关：整理本或参校本可不可信，也就是开不开 `follow_ref_variants`。可以按族给建议值。

### 4.2 只按例外配置
- 一本书的书级文件，只有送审绝对数排在前面的字组才写。其余字组「什么都不写」。
- 判断要不要写书级方案，用 `pending-stats --book <书ID>`。同一个字组在同一族的好几本书里都有问题，就改族 profile，不在每本书里各改一遍。
- 码位候选的看图页**按族合批**：同族几本书的同一对放在一页里一起看，sheldon 一次定一批书。定下的结论仍然逐书写进各书的 `codepoints.yaml`，因为码位是书级事实。

### 4.3 文意缓存跨书复用
- 裁定的键本来就是窗口内容，不是格号。同一段文字在《史記》和《全唐文》里出现，问一次就够。
- 做法：各书照旧在自己的 `feedback/rulings` 记原件。另有一个全局只读汇总库 `rulings-global-v<N>`，由各书已核过的裁定定期合并而成。书配置 `borrow` 它；问 L3 之前先查本书，再查全局。
- 前提：`prompt_ver` 要包含书的类别（`book_desc` 的哈希或文体类别），保证不同提示词不会互相命中。还要做一次跨书抽样：同一窗口在两本书里的人裁一致率，证明「跟书无关」真的成立。
- 成本随书数**次线性**增长：书越多，命中率越高。这是几万本书时文意 L3 花得起的前提（10-27 sheldon 提的扩展性问题）。

### 4.4 共享层的升级节奏
- 族库、全局库每出一版就是一份新的只读工作区，书钉版本号。升级就是改书的钉子，走 A31 的轮次：冻结、统一重跑、标 main。
- 族库升级之前，用同族已经成熟的几本书做按册留出，0 错才能出新版本。改一次族库，影响面是整族；`guji db diff` 列出受影响的书。

### 4.5 命名空间
- 一切书级数据都带书 ID：dataset 格 id、状态报告路径、看板、`pending-stats` 的分组、裁定原件的 `cell`。
- 字组 id 全局唯一，各书共用同一个 id。组方案按 (书, 组) 覆盖。
- 证据留痕统一写 `via`：`self`（本书人裁、本书模型）、`borrow:<来源>@<版本>`、`adopt:<来源书>`。抽检出错的时候，可以一次性找出「借自同一来源」的全部格。

### 4.6 代码保持一份
- 字组代码不像切分那样按套书复制模块。书和书之间的差别全部写进 plan、`book_defaults`、借用清单。
- 要是真有一本书需要新的判法，就加进全局的方法库，再在那本书的 plan 里打开。不要写书专用分支。

## 六、要 sheldon 定的点

1. **要不要加「字体族」这一层**。推荐加：模板和模型按刻风共享，比全局更准，又比一书一份更省。不加的话，几万本书要么各训各的，要么全用殿本的。
2. **新书 `group_flow` 的缺省**：全开（现状），还是族 profile。推荐族 profile：全开等于默认让新书继承殿本的码位组。
3. **组方案（FlowSpec 开关）从代码挪到书级数据文件**。推荐挪：只挪「覆盖」，代码里的缺省不动，殿本逐字节不变。
4. **文意裁定缓存跨书共享**。推荐做，但要先过「同一窗口两书人裁一致」的抽样。
5. **dataset 格 id 加书 ID 的格式**。推荐 `<书ID>/<册>:页:列:格`，与字形库的 edition 一致。
