## 〇、结论

1. **形近字不另起一套。** 形近字用到的东西，全部按新规划放进字形、语料、模型三个系统，外加参数。每样东西归哪一层，用 sheldon 定的规矩判：**按从哪里来**。在哪本书的数据上做出来的，就归那本书；别的书要用，就按 sha 引用，不复制。第一版的「字体族」层取消，改用各系统自己声明的 group。
2. **形近字在三系统里各占的位置：**
   - **字形**：刻例和人裁，已经是书级，不用动。
   - **语料**：组定义、L1 规则、码位结论、白名单、字频、L2 答案表、裁定缓存。
   - **模型**：IDS 模板库、U-Net、L2 小头、刻形二选一、近邻库。
   - **参数**：组方案的开关和阈值、`group_flow`、参照策略。
3. **按新规矩对照，现状有 6 处要改**（第二节）。最大的一处：**73 份 `ids_bank.json` 是殿本人裁挖出来的模板库，现在却记在 cv 自带的 global 语料表里。** 按「从哪里来」，它们应该和 11-04 挪走的 `ids_unet` 一样，进模型系统，归殿本 book 层。
4. **长期计划要的两个结论：**
   - **M3（本书重训模板）**：新书自己训的模板放进本书的模型清单（`ids_model`，本书数据目录 `config/groups/ids/`，现成）。没有自己的就引用殿本的，在模型卡上写明。刻本书攒够两本以上、模板一致了，再考虑训一份挂到字形或模型的 `keben` group。
   - **M6（文意缓存跨书）**：11-04 实测不同作品之间窗口几乎不重合（殿本 601 条，史記 1 条、全唐文 0 条），现在 3 本书没有收益。只补前提（汇总时给裁定盖 `domain`＝书名提示词哈希，不改现有键），等有同作品多版本的书再建汇总。

### 1.2 group 怎么用（按三系统设计「各系统自己声明、用到才建」）

形近字只在下面三处用得上 group。其余一律是 book 层，或者从 book 按 sha 引用。

| 系统 | group | 放什么 | 什么时候建 |
|---|---|---|---|
| 字形 | `keben` | 丛书或刻本共用的刻例库（现在借殿本的库） | 跟字形第三步 |
| 模型 | `keben` | 用两本以上刻本书人裁训出来的模板、U-Net | 有第二本刻本书的人裁模板、和殿本合训过留出 0 错以后再建。在这之前，全唐文引用殿本 book 层的模型 |
| 语料 | `wyd`、`wyg` | 丛书用字账、参校本合集；同一版本系统共用的码位候选 | 有第二本武英殿或文渊阁的书再建 |

**码位结论不进 group。** 码位是「这一次雕版」的事实，同一版本系统里的另一部书也要重新看图核。group 里最多放「候选」：新书立档时抄一份到本书，标成待核，本书看图页核过才转正。现在全唐文、史記的 `follow_ref_seen` 字对就是这样逐对核出来的。

### 1.3 文意裁定缓存跨书（M6）

- **键与书无关**：裁定的键是 `(组, 前后各 20 字窗口的哈希, prompt_ver)`（`feedback/rulings.py`、`groups/ctx_llm.py`），不含格号和书。同一段文字在两本书里出现，答案应该一样，原则上能复用。
- **11-04 实测，收益比预想小得多**：
  - 殿本已有 601 条文意裁定（`llm-ctx-20261028`）。拿这 601 个窗口去史記整理本（127 万字）、全唐文整理本（974 万字）里找：前后各 4 字的窗口，史記只命中 1 条，全唐文 0 条；前后各 10、20 字都是 0。
  - 史記、全唐文自己的中心库里**还没有一条文意裁定事件**（只有人裁 `confirm`），所以「同一窗口两书人裁是否一致」现在没法抽样，只能等它们跑出裁定。
  - 结论：**不同的书之间几乎不会碰到同一个窗口**。只有同一部作品的不同版本（殿本四库提要和别的刻本、同一文献的多个整理本）才会大量重合。几万本书里这样的书很多，所以要做，但不是现在的 3 本书能受益的事。
- **所以 M6 改成两步**：
  1. **现在只补前提，不建汇总**：`prompt_ver` 现在只取提示词 frontmatter 里的 `ver`（如 `ry-l2-2`，`seed_admit._l3_online`），**不含书名提示词 `book_desc`**；各书的裁定库互相独立所以没出问题，但任何跨书汇总都会让不同书名的提示词互相命中。汇总时给每条裁定盖一个 `domain`＝`book_desc` 哈希（从各书的 `book_prompt.json` 补盖，不改现有键，现有缓存不失效）。
  2. **等有同作品多版本的书再建汇总**：汇总放 global 语料（来自几本书、没有共同 group，按规矩归 global），清单记 sha、内容放 R2。到时先在两个版本上抽样核一致率，再开。
- **成本**：现在 3 本书各问各的。几万本书时，同作品多版本这一类才能次线性。

## 二、按新规矩对照，要改的 6 处

1. **ids_bank 等 74 个文件记错了系统和层。（A1 已做，cv#1037，11-04）**
   - `config/corpus-registry.json` 的 136 项里，有 73 份 `config/groups/*/ids_bank.json`、1 份 `can/whole_bank.json`。`ids_override.tsv`、`ids_fine.tsv` 是手写的 IDS 规则（别名、停止点），不是训出来的，仍算语料，留在 global。
   - 组卡和 `ids_online` 的说明都写着，这些是从殿本 vol01… 的人裁切图挖出来的，按「从哪里来」归**模型系统、殿本 book 层**。
   - 做法同 11-04 的 `ids_unet`：`model_pack.KINDS` 加 `ids_bank`、`ids_whole_bank`（root=repo，path `config/groups/*/ids_bank.json`、`*/whole_bank.json`），`corpus_pin._not_corpus` 不再把它们算语料，老清单里登记过的核对时跳过。
   - **影响**：钉了 `model:` 的殿本、史記要出新模型号；文件内容不变，`ids_online.fingerprint` 本来就按内容哈希算，seed_admit 的产物不应过期。上线前用 `guji status` 对账。
2. **`form_freq.tsv` 和 `edge_pair_exclude.tsv` 不在任何清单里。**
   - `corpus_pin.ITEMS` 只收 `config/variants/*.json`，这两个 `.tsv` 漏了。`groups/edge_pairs.py` 直接从 cv 仓读它们。
   - 看起来也不在 seed_admit 的指纹里，所以改了它们产物不过期，rc 时 `git rm` 语料表也带不走它们（需核）。
   - 应该进清单：`form_freq` 是殿本放行统计，进殿本 book 语料；排除表进 global 语料，书级补充进 book。
   - 别的书没有 form_freq 时，edge_pair 只用通则，不拿殿本的字频。
3. **组方案和码位组写死在全局代码里。**
   - registry 的 `FlowSpec` 开关，注释里写的全是殿本的证据。`cp_*` 是殿本的码位结论。`seed_admit.group_flow` 缺省是全部组，所以新书默认把殿本的码位组也跑上了。
   - 改法：
     - 代码只留通用缺省。
     - 书级覆盖走现有的参数五层（基础配置 `params.seed_admit.group_plan: {组: {字段: 值}}`，按「写没写」深合并，`book show --effective` 列出来源）。
     - `cp_*` 的成员挪进殿本 book 语料。
     - `group_flow` 缺省改成「不含 `cp_*` 的通用组」；殿本在基础配置里写全集，逐字节不变。
4. **用字账缺省是殿本的。** `params.seed_admit.edition` 缺省 `wuyingdian_zongmu`。新书不写，就用上了殿本的用字账。应该改成缺省取书 ID，没有账就弃权；丛书的账以后放语料 `wyd` group。需要先核史記、全唐文现在实际读到的是哪本账。
5. **人工标注的格 id 不带书 ID。** dataset `char-groups/labels/unified.jsonl` 的 id 是 `册:页:列:格`，史記 vol05 和殿本 vol05 会撞键。改成 `<书ID>/<册>:页:列:格`，与字形库的 edition 一致；旧行补 `96mid1ogzk/`，可以重建。状态报告的路径也加一级书：`status/<书ID>/<轮>`。
6. **组卡只写了殿本。** `doc/字组/<组>.md` 分成两段：「字形差别、怎么判」是通用知识；「各书现状」按书各写一节。

## 三、扩到几万本书

- **新书立档只填两样**：每个系统的 `groups`（例如 `{glyph: [keben], corpus: [wyd], model: [keben]}`），以及参照策略（开不开 `follow_ref_variants`）。其余全部取 global 和 group 的最新版。
- **书级的东西靠自动生成，不靠手写**：首跑以后，从放行结果自动统计字频、form_freq，进本书语料。只有送审绝对数排在前面的字组才写书级 `group_plan`。
- **码位候选按版本 group 合批看图**：同一个 group 里几本书的同一对放在一页里一起看，结论仍然逐书写进各书的 `codepoints.yaml`。
- **模型先引用、后重训**：新书先按 sha 引用殿本或 group 的模板和小头。在本书按册留出测，不够 0 错的组才训本书的 `ids_model`。重训的成本只花在拖后腿的组上。
- **代码只有一份**：字组逻辑不像切分那样按套书复制模块，书和书之间的差别全部写成参数、语料和模型。

## 六、M3 本书重训模板（11-05，已做：`groups/ids_retrain.py`）

- 一条命令：`python -m open_guji_cv.groups.ids_retrain <组…> --ws <工作区>`（自动取各册最新产物包与原图、重训、写进本书数据目录 `config/groups/ids/<组>.json`），已有数据时用 `--prod --imgs --out`。之后 `guji db sync` 推中心库，用本书模板的册从 seed_admit 起重跑。
- 做法：本书已放行格＋人裁当标签 → 按册留出去离群标签（去掉的全进报告，人裁格只标不去）→ 按册留出定门槛 → **独立审计**（不进训练的通道放行格拿最终库判，判成另一组员字的 margin 抬高门槛）→ 写库。门槛写进模板库文件的 `spec.min_margin`，`ids_online.judge` 读到就覆盖 `SPECS`（文件内容进指纹）。
- 为什么要独立审计：训练格全是别的通道已放行的容易格，只做按册留出会高估（全唐文 xjz 首跑门槛 0.67 留出 0 错，审计里 徧→偏 1.07、冷→令 1.07 判错；抬到 1.45 后 0 错）。
- 全唐文首跑（005–015 册）：men 门槛 1.2、给字 688/943（殿本模板同格 254、错 9）；chuo 0.78、1516/2086（殿本 83、错 4）；xjz 1.45、866/1906（殿本 224）；审计各 0 错。
- 模板标签里整理本标错的格（滎→榮、閉→閑、違）在报告 `audit_diff_cells`；要进一步放宽门槛，须逐格看图把整理本标错的格填进 `--audit-ok`。
