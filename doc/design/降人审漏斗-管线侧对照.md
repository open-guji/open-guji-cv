# 降人审漏斗：管线侧对照（A20，2026-11-05）

> 依据：guji-manager `doc/02-粗校/降人审迭代框架.md`（执行版）与 `人审页模板.md`（manager #106，sheldon 11-05 定）；设计依据 ai-team `domain/CV/质检/迭代降人审框架/新书降人审迭代框架-2026-11-05.md`。
> 本文只回答架构侧的三件事：①漏斗每一层落在管线的哪块代码、数据放在哪；②「D 轮／S 轮」两档在步骤与指纹上怎么对应；③现行代码与 11-05 四条决定还有哪些出入（**只列，不在本文改**）。流程本身以 manager 执行版为准。

## 一、11-05 定下、管线侧要守的四条

1. 待审格按 `pending_reason` 走五层：L0 配置 → L1 算法 → L2 大模型只读文意 → L3 独立复核 → L4 人审批量页。
2. 大模型**只读文意**可以参与放行；字形侧的「图一致证人」由算法出（库字形分、字体渲染分、book_knn 等）。大模型**看图只给人审页预标注，不放行**。
3. 越过参校本（整理本）放行：**按书、按组**抽 30 格金标定白名单，不继承殿本名单。
4. 节奏目标是一天左右做完一本书：决策层小轮（D 轮）只从 `seed_admit` 起跑，结构层（S 轮）攒批。

## 三、两档轮在步骤与指纹上的对应

### 3.1 按改动落在哪一步分档

| 改动 | 最早受影响的步 | 档 |
|---|---|---|
| 新裁定（`ctx_ruling`）、白名单、码位结局（`codepoints`）、`seed_admit` 参数与放行规则、书级字组模型／近邻库 | `seed_admit` | **D 轮** |
| 字形库换快照（改 `glyph_pin`） | `glyph_match`（`guji recheck --glyph-diff` 可只算受影响的格） | S 轮 |
| 语料换号（改 `corpus`）、勘误层 | `align_ref`（及之后） | S 轮 |
| 页型、图源、`border_detect`／`row_segment`／`cell_shrink` 参数或代码 | 最早那一步 | S 轮 |

判断起跑步：看 PR 里登记的 `code_hash` 变了哪几步、册配置改了哪些步的参数（`guji status <册> --pages all` 会点名过期原因）。**一轮里只要有一项是 S 档，这一轮就是 S 轮**；换语料、换借库仍各自单独一轮（执行版第八节）。

### 3.2 D 轮为什么不动格号

格号由切分各步（到 `cell_shrink`／`char_index`）决定。D 轮只重跑 `seed_admit`，上游产物原样复用，格号不变，标点锚点、人裁绑定都不受影响。

裁定库的键是**窗口内容**，不是格号：`(组, prompt_ver, sha256(前文末 20 字 | 后文首 20 字))`，窗口按 `seed_admit._clf_ctx` 取（读序见 `utils/jiazhu_order.sort_by_reading`）；`_vis_ruling_pass` 另要求整理本对位字与裁定记的一致。所以 S 轮重切后，只要前后文没变，裁定照样命中；前后文变了的格就要重问。（执行版写成「格号＋上下文哈希」，实际只认内容，格号只记在 `payload.cell` 给人看。）

### 3.3 D 轮必须强制重跑 `seed_admit`

裁定库的**内容**不进 `seed_admit` 的指纹（`code_deps` 里有 `feedback.rulings` 只管代码）。新写一批裁定后 `guji status` 不会报过期，不强制就吃不到：

- 走任务库：`guji_jobs submit … --from seed_admit` 缺省 `force=true`，直接可用；
- 本机：`guji step seed_admit <册> --pages all --force`，或 `guji pipeline … --pages all --from seed_admit --force`。

同理，「白名单只写在判读脚本里」的那部分也不进指纹（见第四节第 4 条）。

### 3.4 版本钉

每轮发一个正式 PATCH 再钉（用户 11-04 定），D 轮一天里可以发多次；D 轮只换 `cv_version`，不碰 `corpus`、`glyph_pin`。细则见 [版本号规矩](../版本号规矩.md) 第七节。
