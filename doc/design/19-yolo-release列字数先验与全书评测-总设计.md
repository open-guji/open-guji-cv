# 项目总计划：殿本逐列字数金标、Step3 列字数先验与 YOLO 并格闸

> 状态：**执行中**（用户 2026-10-19 基本同意，三条意见已并入）｜依据：[doc/research/yolo_release_comparison.md](../research/yolo_release_comparison.md)
> 分支：`feat/yolo-colcount-prior`（从 main 开出）。cv 正在做 v0.4.0 大改，本项目做完后**并到 `rc/v0.4.1`**；那条待发分支开出来之前，本分支只跟 main。
> 新行为一律**缺省关**，关着时各步输出逐字节不变（[版本号规矩](../版本号规矩.md) §三.3）。

## 一、目标

1. **全书评测金标**：殿本 vol01–vol10 每一列的「字数 + 字落在哪几格」，切分可以按整册算逐列全对率。现在的列切人裁只有 60 页。
2. **Step3 列字数先验**（殿本专用）：金标里的格位喂给 Step3。纯算法逐列全对现在是 96.6%，目标 ≥98%。
3. **原生 YOLO 并格闸**（通用，新书也能用）：用 yolo-tool 原生字框抓「一个字被切成两格」，自动并格。

## 二、不做什么

- 用户 10-19 定的不做：
  - 不拿 release 的字或图训字形和识别（和直接匹配整理本差不多）；
  - 不给对方提改流程的建议。
- 不改 yolo_tool，不重训它的模型。今后只有原生输出，模型可能小幅更新。
- **release 和人工修补都不会再有**，所以第 1、2 条只对殿本成立，不写成通用机制的前提。
- 原生 YOLO 的字数不当先验：逐列全对只有 64–84%，只当并格这一种第二意见。
- 不处理 Step1 整页列错位（vol05 p55、p123），另立卡。

## 三、金标怎么能信（用户问：release 也可能有错）

**金标不是 release 本身。** 它是两份**互相独立**的来源对同一列给出同一答案时的那个答案：

| 来源 | 怎么来的 | 它会怎么错 |
|---|---|---|
| **daizhige 逐列本** | 维基文库人工逐列校对，每列记了首字格位 `start`（−1 是出格抬头）、正文、夹注两行各自的格位；`page_map.jsonl` 已经把我们 vol01–10 的 1,707 页一页一页对到它的半叶上（人读锚点 + DP，09-28 P 道） | 校对漏字、多字、抬错格；页对应错一页 |
| **release** | 另一份印本扫描图上，YOLO 框加人工修框；每个框一个字 | 框漏、多，人工修框时为凑文字而改框 |

规则：

1. **两边一致才进金标**：这一列的字数相同、列边界对得上。vol01–10 对应 release ch1–24 共 15,050 列，**一致 14,926 列（99.2%）**。
2. **不一致的 124 列不当金标**，出审查页给人裁。裁过的进金标，记 `label_origin: human`。
3. **抽检量残错**：在一致列里随机抽 300 列出拼图，人看。0 错时残错率 <1%（95% 置信，3/300）。两份独立来源同时在同一列错成同一个数，概率是两边错率之积量级，预期远低于此。
4. **用法纪律**：
   - 评测报「与金标一致率」时，**凡是要据此下结论的改动，把前后翻转的列全部出图人看**，通常只有几十列；
   - 金标残错只要不偏向改动的那一边，就不影响比较；
   - 发现金标错，改金标，记进 `history`。
5. 我们自己的切分是第三份独立来源。抽看过的「我们与两份来源都不一致」的列都是我们错（研究文档 §二），这反过来说明那两份来源一致时基本可信。

## 五、契约

**A 的行格式**（一列一行；B、C 共用）：

```json
{"vol":"vol04","page":12,"col":7,
 "dzg":{"half":"0001-0141h1","start":2,"n_main":19,"note":null,"text":"…"},
 "release":{"ch":10,"p":10,"n":19},
 "agree":true,"label_origin":"consensus"}
```

- `col` 用我们的口径：右起，从 1 开始，与 daizhige `no % 9 + 1` 一一对应。
- `note` 是夹注：`{"start":k,"r":n_r,"l":n_l}`。
- `agree=false` 的行也写，B 和 C 都只用 `agree=true` 或人裁过的行。

**模型文件**：yolo-tool 的 `model/type/best.onnx` 和 `model/slide/best.onnx` 不进 cv 仓（104 MB + 12 MB）。放 `_shared/models/yolo_tool/<sha8>/`，册 yaml 写 sha；`yolo_boxes` 指纹带 sha，模型一换就判过期。

## 六、验收标准

1. **A**：
   - vol01–10 正文页 100% 有表行，空白页、牌记页除外；
   - 一致率 ≥99%，不一致列数报出来；
   - 抽检 300 列 0 错，最多容 1 错；
   - 命令：`python scripts/dzg_import.py colgold --ws <ws> --release <dir>`。
2. **B**：
   - `guji eval run column_counts` 在 vol04/05 那 100 页上复现纯算法 96.6%（±0.1）；
   - vol01–10 各出一份报告，正文列、夹注列、抬头列分开报。
3. **C**：
   - 开关关着时，vol01–10 的 Step3 产物与 main 逐字节相同；
   - 开着时，金标正文列逐列全对 ≥99%；
   - 翻转的列全部出图，确认是改对；原来对的列新错 ≤0.1%；
   - 人裁 `column-slots` 列的结果不变；
   - `tests/` 有自造数据单测，全量测试通过。
4. **D**：
   - 关着时输出逐字节不变；
   - 开着时 vol01–10 抓到多切列 ≥60%，误并 ≤1 列/100 页；
   - 北行日錄抽 50 页，人看全部触发列，误并 ≤2；
   - 换模型 sha 后跑 B 复测，再决定沿用阈值。
5. 合进 `rc/v0.4.1` 时：CHANGELOG 待发节加行，写明 `row_segment` 的 code_hash 变化、新增 `yolo_boxes` 步。

## 七、风险

| 风险 | 应对 |
|---|---|
| page_map 某段错一页，整页先验全错 | C 在整页 ≥3 列与算法冲突时整页不套，记旗送审；A 报每册冲突热点 |
| daizhige 第 0005 册仅 OCR（卷 186 起） | vol01–10 不涉及；以后扩到别册要先量 |
| 格位语义：我们 21 格从哪格起算、抬头负格 | C 的分块设计先用 vol01 字形库 instances 已核的「idx = daizhige 格位 + 1」（910 列 900 符合）定死换算，再写代码 |
| D 的阈值只在 100 页上定过，模型更新会漂 | 用 B 在 vol01–10 全册重标；模型 sha 进指纹 |
| 与 v0.4.0 大改冲突 | 只加开关和新步、不改既有逻辑；rc/v0.4.1 开出后 rebase，再跑全量测试 |
