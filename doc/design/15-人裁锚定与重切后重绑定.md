# 人裁锚定与重切后自动重绑定（设计，2026-09-25）

- **触发**：vol02 人裁清查（[../Step7-放行判定/08-影子放行模型-计划.md](../Step7-放行判定/08-影子放行模型-计划.md) 末节）：
  1,417 条人裁里约 270 条在重切后挂错格或失效，其中一部分**已经被当成人裁写进了文本**（`151:9:20` 等），整段跟着错且不报错。
  这是第三次栽在同一个坑上（09-17 vol02 撤 65 条、09-20 bxgb、09-25 vol02 撤 250 条）。
- **用户要求**（2026-09-25）：「怎么让上游重切之后，这里尽量少地重做，而且能及时更新信息。」
- **状态**：**P1、P2 已做，P3 看板列已做（2026-09-26）**；P3「还是同一个字吗」卡按用户定的「对不上就撤销」**不急做**；P4 的排除名单/切线裁决/逐列字数裁决未做。见 §七。

## 一、病根

人裁（以及排除名单、切线裁决、逐列字数裁决）都用**字位编号** `book:page:col:slot`（第几页、第几列、列内第几格）当主键。

**多数重切只是挪动格的上下边界，编号不变、字也还是那个字**——这时裁决本来就是对的。出事的是少数情况：
- 列内某处**多切或少切了一格**（一个字被切成两格、两格并成一格、空白格判法变了、抬头格数变了），
  **这一处以下整列的格号都顺移一位**；
- Step1/2 **多认或少认了一条界行**，这一处以后**整页的列号都顺移**；
- 夹注 a/b 的判法变了。

这些情况下，编号没变，但它指向的已经是**相邻的另一个字**。一处改动，会让一整串裁决同时挂错。而下游一律**按编号直接读**，
没有任何一步核对「现在这一格还是不是当初看的那一格」。

vol02 实测（1,417 条人裁）：1,122 条编号和字都没变（多数情况）；约 220 条出了问题，其中能在附近找到原字的——
**同列顺移 ±1～2 格 68 条、挪到相邻列 15 条**，其余是格已不出字或已不存在。

后果分三种，全都静默：
1. **挂错格并被采信**：人裁「一票定案」，错字压过所有自动证据写进文本（最坏）；
2. **挂错格未采信**：不改文本，但污染训练标签、下次重跑可能被采信；
3. **失效**：指向的格没了或不出字，这一处人裁白做，同一个字要再审一遍。

## 二、目标

1. **绝不把裁决用到另一个字上**（准确率第一）；
2. **能跟过去的自动跟过去**：只是编号变了、字还是那个字的，自动改绑，人不用重审（少重做）；
3. **跟不过去的立刻冒出来**：切开了、合并了、形状变了的，马上回到待审队列并在看板上显示（及时）。

## 三、设计

### 1. 锚：裁决记「看的是哪块图」，而不只是编号

人裁时把这些一并写进事件的 `target.anchor`（字段早就有，一直是空的）：

| 锚 | 内容 | 用途 |
|---|---|---|
| **原图坐标框** | `quad_page`：这一格在**原始扫描页**上的四角（Step3 产物里现成） | 主锚。原图不会变，重切只是换了一种切法，框在原图上的位置可比 |
| **图块指纹** | 裁决时那块字块图（存一份小图，或哈希 + 存档路径） | 核对「现在这一格和当初看的是不是同一个字」 |
| **上下文** | 前后各 2 个字（当时的定字） | 辅助：框对上了但前后文全变，说明整列错位 |
| **产物版本** | 当时 Step3/Step4 产物的指纹 | 判断这条裁决是按哪一版切分做的，不用每次都重核 |

字形库入库的人裁本来就存了当时的图块（这次漂移检查就是靠它），但「字形不入库」的人裁、排除名单、切线裁决都没有，要统一补上。

### 2. 绑定表：裁决与「现在哪一格」的对应，单独一张、可重算

- **事件日志不改**：它是历史，只追加。
- 新增**绑定表**：`裁决事件 id → 当前字位编号 + 状态 + 证据（框重叠度、图块相似度）+ 算它时的 Step3/4 产物指纹`。
- **所有下游只通过绑定表读人裁**，不再按编号直接读：seed_admit 的人裁通道、`human_chars`、字形库人裁字形、训练标签、看板。
  这是关键的一刀：以后改了切分，只要重算绑定表，所有下游自然跟着对。

### 3. 重绑定：切分一变就自动重算，按页、很便宜

Step3/Step4 某页产物的指纹变了 → 该页的绑定自动过期 → 下次任何下游读它之前重算（或 Step4 跑完立刻重算）。逐条裁决：

| 情况 | 判法 | 处置 |
|---|---|---|
| 编号没变、边界微调（最常见） | 同编号新格与锚框重叠度 ≥ 0.8，图块相似度高 | **确认仍有效**，不打扰人 |
| 字没动、编号顺移了（列内多切/少切一格、列号顺移） | 锚框落在**另一个编号**的新格上，重叠度高、图块相似 | **自动改绑**到新编号，记一笔——整列顺移的一串裁决一次改完，人不用重做 |
| 框被切开 / 两格合并 | 锚框与两个新格各重叠一部分，或一个新格盖住两个旧锚 | **待重审**：出卡，并排放「当时看的图」和「现在的图」，问「还是同一个字吗」 |
| 框对上了但图变了 | 重叠度高但图块相似度低（切法改了、带进了邻字残笔） | 待重审 |
| 找不到对应格 | 锚框处没有格了 | **作废**，记原因 |

作废与待重审都**不删事件**，状态落在绑定表里，可追溯、可恢复。

### 4. 及时冒出来

- 进度看板（9.0）加一列「人裁待重核」：按页显示。
- 定字台出卡：「当时裁的是左图（X），现在这一格是右图，还是 X 吗？」——一键「是」即改绑确认，「不是」进正常定字。
- 重绑定汇总写进 Step4 的运行日志：「本次重切：自动改绑 N，待重核 M，作废 K」。

### 5. 不只人裁

同一个坑还在这些地方：**排除名单**（`crop_exclusions.jsonl` 按 instance_id）、**切线裁决**（按 `page,col,slot_above`）、
**逐列字数裁决**、**字形库实例 id**。它们都应走同一套锚 + 绑定表。字形库实例本身不用改——那块图的标签对那块图永远是对的，
变的只是「它对应现在哪一格」，这正是绑定表管的事。

## 四、存量迁移（老裁决没有锚）

老事件没存框，但可以补：
1. **从备份产物补框**：vol02 有 `row_segment.bak-20260919` 等备份，按「事件时间 ≤ 备份时间」找当时那一版切分，读出当时的原图框。

3. 补完后跑一次重绑定，结果分三堆给人看：自动改绑（抽查即可）、待重核（逐个）、作废（不用看）。
   这次 vol02 手工做的漂移清查，就是这个流程的第一次人工版本。

## 五、分期

| 期 | 做什么 | 效果 |
|---|---|---|
| P1 | 定字台、切线台等所有出裁决的地方，写事件时带上锚（原图框 + 图块指纹 + 上下文 + 产物指纹） | **从今天起的新裁决不再丢位置**，改动小 |
| P2 | 绑定表 + 重绑定逻辑；下游（seed_admit 人裁通道、`human_chars`、训练标签）改为读绑定表 | 重切后自动改绑，跟不过去的冒出来 |
| P3 | 看板列 + 定字台「还是同一个字吗」卡 | 及时、人审成本低 |
| P4 | 存量迁移（四庫各册、bxgb），排除名单与切线裁决并入同一机制 | 清掉历史隐患 |

**P1 最急**：它不依赖别的，而且每多拖一天，就多一批没有锚的裁决要靠 P4 去补。

## 九、老裁决补锚落成持久档（2026-09-28，H 道 overview#152）

**起因**：vol02 09-27 在云端整书重跑、以快照导入之后，产物里不再有「裁决当时那一版」Step3（快照不带 `.bak-*`，`_prev/` 是 09-27 的上一版）。
§四 的现场补锚因此补不出框，4439 条老裁决全部 `unanchored`，`human_chars(vol02)` 绑定后只剩 2 条（D #59 报）。
另查出 `_prev/` 起点被写死为 −∞：只要有 `_prev`，老裁决就被当成「按它裁的」。拿 09-27 的两版互比，4441 条全判 valid，是**假有效**。

**做法**（cv `feedback/anchor_backfill.py`、`scripts/backfill_anchors.py`；工作区 `feedback/anchors/<book>.jsonl`）：
- 补锚写成**跟事件同级的持久档**，不再每次从产物历史里现找；`bindings.compute_page` 的取锚顺序是：live 锚 → 补锚档 → 老的现场补锚。
- **墨框锚**：字形库入库时存的当时字块图，拿到**原图**上做模板匹配找回墨框（NCC ≥0.60、比第二峰高 ≥0.15）。绑定时按「墨框 ≥80% 落在某一现格、第二格 <20%」判。原图不变，所以以后再重切也照样找得回。
- **上下文锚**（没有图块的）：整理本 `align_char` 在同列 ±2 格内只有一处是裁的字，且落在同编号；或者顺移 d 格，同时有旁证（墨框邻格也顺移 d，或同列 ≥3 个字位一致顺移 d）。单条顺移、没有旁证的不绑。
- `_prev/` 起点改为从 manifest 历史里反查「头一次写出这份内容」的时间，查不到就不用。

**vol02 实测**：带字老事件锚上 3502/3658（1352 位）；`human_chars` 2 → 1336；Step7 人裁通道可采信格 9 → 1345。另有 36 位改绑到整列顺移后的新编号。目检 30 条：29 条锚对，1 条跨格进了 review。
无字裁决（seg_defect／not_a_char／skip）783 条没有补：没有字可核，锚不上就不硬绑。
**做别的书时**：先跑 `scripts/backfill_anchors.py <book> -w <ws>`（不带 `--write` 只看数），确认后再 `--write`。
