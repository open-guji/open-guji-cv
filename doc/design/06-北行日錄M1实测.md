## 一、两栏的裁定：先裁

每张扫描页 = **两页原书上下拼成**（上栏一页、下栏一页，各带书口栏线、卷次小字、页码
一八三四／一八三五；栏间一条横线；末页只有上栏）。裁成逻辑页（扫描页 k → 2k−1 / 2k）之后，
九步的「一页一块」不变量全部保住，原书页码结构也回来了；「顺序编号列」等于在 Step1 里表达
两个块，要改产物模型、闸和单位键，不值。分页是 Step0 的显式命令 `guji split`，与预清理同一
套路：扫描页永不改写，逻辑页落成产物，manifest 记来源矩形。

分页踩了三个坑（都已修）：扫描页 4 没印横线只有淡断线（先找淡线再找白带，顺序反了每列多一项）；
末页首列比别的列高一字（跨度门槛按 0.1 页宽会切掉它）；影印本页码离正文 240px（按 0.02 会裹进来）。
现在：实线 → 淡线（最长连续墨段 ≥ 0.1 页宽）→ 白带；强正文行段 + 紧挨的弱段。

## 二、这本书推翻了方案里的一个假设

方案 §四.2 假设现代排版是**刚性网格**。实测不是：列高固定，但每列 14～16 汉字 + 2～4 标点
（17～19 项），标点占 0.35～0.7 格，字距随列在 111～132px 之间调整撑满列长——**标点挤压 +
撑满**。所以 Step3 没走「收紧的弹性 DP」，改成**墨段 + 字身盒模型 DP**（`row_segment_runs`）：
按纯白缝切墨段，DP 把墨段合成项，代价 = 相邻项中心距偏离本列 pitch。`一`、`二`、`六`、`文`
这类分离笔画靠 pitch 一致性并对；标点靠「小于 0.55 em 且靠列右半」认。

## 五之二、五例「真错」的根因与训练/测试切分（2026-09-15）

用户追问「我以为匹配算法是 100% 准的，为什么 4 个匹配成不同的字」。**根子不在匹配器，
在播种闸把正确的字整批拒了**：重播前库里 `字`/`宣`/`旦` 各 0 个样本，书上的 `字` 只能去配
`宇`。两个 bug 叠加，都已修：

1. **播种与匹配用的不是同一把尺子**——播种走库检索（不归一笔宽，量的是粗细：书块 4.6px vs
   字体 2.7px），Step5-a 走笔宽归一 3px。不归一时全书每个 `字` 的字体 top-1 都是 `宇`、
   每个 `旦` 都是 `且`，两套字体一致地反，于是一个都没进库。
2. **字体模板本身被毁了**——归一化里有条为刻本写的规则「贴边细线 = 版框/界行，删掉」，
   门槛 11.5px；字体渲染的宋体横笔只有 7px，于是 `旦` 的底横、`宣` 的宝盖和底横被当版框删了，
   库里的字体 `旦` 是个「日」、`宣` 是个「亘」。I.Ming 全字表 2091 字有 84 个中招，
   书上的字块抽 3000 个一个没中——只有字体这一路坏。

修后播种的拒绝数从 971 掉到 213，入库字头 1,978 → 2,010。另两例改判：`吴/吳` 是校對本把
同一个人名录成两种码（书上同一个字形，互比 0.9993），归到校對本错那一类；`揚/楊` 是留一法
协议的产物（全书只有 1 个 `揚`，摘掉自己库里就空了）。

**这把尺子的天花板要记住**：骨架 3px + 弹性覆盖对「差一笔」的字对分辨率只有千分之一到
千分之五（字/宇 0.994、宣/直 0.991、旦/且 0.998，而同字自比 0.9992～0.9997，same 门槛 0.996）。
**门槛分不开，只有排序能分开**——所以「库缺字 = 必错，而且高分、看起来很自信」是这条链的
结构性风险，形近字护栏与 Step6 上下文不能省，播种的拒绝名单要当一等公民盯。

**训练 / 测试切分（用户定）**：逻辑页 21–80（扫描页 11–40）= 训练集，人裁结果可回流；
逻辑页 1–20 = 测试集，**不做任何人工干预**。界线划在人工干预、不在库成员——库照旧全书播种、
留一法摘自证，只要 1–20 没人看过没人据它改过，它的数字就是真实上线水平。
规模：Step4 字位 训练 16,662 / 测试 5,519；证人标签 训练 13,196 / 测试 4,193。

**修完后的全书结果**（库重播 + Step5-a 全书重跑）：播种入库 17,153 个字块 / 2,010 字头，
字体不认 213（修前 971）；库里 `宣` 0→30、`字` 0→6、`旦` 0→5 个样本，**五例「真形近误判」
全部消失**。
