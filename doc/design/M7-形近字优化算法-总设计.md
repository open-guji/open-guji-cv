## 一、目标（一句话）

**每个形近字组都由注册表指定自己的解法（IDS 拆分、上下文两层，或两者都用），先按字形把格归进字组，再由该组的解法给出 pick；异体字组以「彝」六字形为第一个落地组，形近不同义组以 日曰、己已巳 为第一批落地组。**

为什么：现在四个字组四套做法（研究总览 §1.2），几何匹配在形近对上只有 0.643（低于多数类基线 0.760），日曰字形路失败，彝组没有读字器。用户的判断是：异体字的差别在**部件**，要从 IDS 下手；形近不同义字的差别在**文意**，要从上下文下手。

## 六、共用契约

### 6.1 注册表扩展（`groups/registry.py`，只加字段，旧字段不动）

```python
@dataclass(frozen=True)
class GroupSpec:
    ...                                    # 现有字段不动
    kind: str = "near_form"                # "variant"（异体）| "near_form"（形近不同义）
    solvers: tuple = ()                    # 有序："ids" | "ctx_l1" | "ctx_l2" | "image"，可多个
    config_dir: str | None = None          # config/groups/<id>/
```

### 6.2 每组配置（`config/groups/<组>/`）

- **IDS 用 Unicode 通用 IDS 语法**（描述字符 ⿰⿱⿲⿳⿴⿵⿶⿷⿸⿹⿺⿻ 加部件），**不手写自定义结构**。数据源：cjkvi-ids（`ids.txt`，来自 CHISE／Unicode，已核对能取到这六字：彝 `⿳彑⿰米糸廾`、彞 `⿳彐⿰米糸廾`、𢑴 `⿳彐⿰米糸大`、彜 `⿱彑𪪷`、彛 `⿱彐𪪷`、𢑱 `⿱彑𡙢`；𪪷＝`⿱粉廾`、𡙢＝`⿱粉大`）。仓里放一份固定版本的快照 `config/ids/ids_snapshot.tsv`（只含各组成员与递归展开到部件所需的行，记来源 commit），不运行时联网。
- **结构是算出来的，不是配出来的**：`groups/ids.py` 递归展开各成员的 IDS，把同向嵌套压平（`⿱彑⿱粉廾` → `⿳彑粉廾`），得到每个成员的**扁平结构**（如 彝彞 `⿳·⿰米糸·`、彜彛 `⿳·粉·`），再在同一结构下按位对齐，**自动**求出每个位置上有哪几种可选部件；只有当 IDS 数据本身有错或有歧义时，才在 `config/groups/<组>/ids_override.tsv` 里按字覆盖（每条带理由）。
- 注意 Unicode 的写法里中段有两种：`⿰米糸`（彝彞𢑴）和 `粉`（彜彛𢑱，即米+分），所以中段二选一在 IDS 里是「⿰米糸 vs 粉」，和用户说的「米+糸 / 米+分」一致；上段 彑／彐（标注文件里写作 ⺕，U+2E95，与 彐 U+5F50 是否同一部件**待核对**，核对结果写进 override）、下段 廾／大。
- 新字组加 IDS 路的成本：给出成员列表即可，其余自动；若组内成员**顶层结构不同**（如一个 ⿰、一个 ⿱），`ids.py` 会列出所有不同的扁平结构，切分时每种各试一遍（§6.5 第 4 条）。
- `rules.yaml`（L1 用）：词组表（`phrase → char`，带支持数、来源册）和正则（`pattern → char`，带说明与反例）。
- `prompt.md`（L2 用）：该组专用提示词；版本号进答案表的 `ver`。

### 6.3 输出与合并

- 每个解法都出 `GroupVerdict`（`protocol.py` 已有：`char`、`conf`、`why`、`via`、`extra`）；`via` 新增 `ids`、`ctx_l1`、`ctx_l2`。
- **组内合并规则**（缺省，可在注册表里按组改）：按 `solvers` 顺序取第一个**不弃权**的 pick；后面的解法若给了不同的字，记 `why=disagree:<via>` 并**弃权**（不让两条路打架时硬选一个）。`image` 只能否决不能给字。
- 终版写成 `group_clf/1` 表（格式已在 main，`group_decide.lookup` 在读），`ctx` 键改用新窗口，表头 `ctx_ver: 3`。

### 6.4 上下文窗口（块 A，用户第 4 条）

- 前后**各 20 字**，训练集与实际判读用同一个函数。
- **不按段截断，简单上下各取 20 字**（用户 10-17 改：缺上下文的字太多，按段截取易误判；v2 的遇段即停作废）。只有撞到全文首／尾才会短。
- 邻字取**整理本对位字**（和 PR2 `ctx_window` 同口径：键不随放行态漂移）；对位缺字的位置记占位符，不跳过。
- 现有表按 30 字窗口取键：旧表照旧可读（`ctx_ver` 缺省＝1），新表用 `ctx_ver: 3`（v2＝段内窗口作废），三者不混。

### 6.5 IDS 路的切分（块 C，用户第 3 条）

1. **结构已知**：从 `groups/ids.py` 取该组所有扁平结构（yi_560 压平后只有 `⿳` 上中下一种；中段部件不同但位置相同）。
2. **切分**：**分界是折线，不是直线**（用户 10-17 看图后指出：只用一条直线会有上下残留）。C2 标注每格两条折线（上/中、中/下），折线两侧的像素就是三段掩码。先用水平投影谷底给一个直线基线（只作对照）；再用**只在本组刻例上训**的小 U-Net 出每个像素属于哪一段（⿱⿱ 是三类），训练标注来自 C2 的折线掩码加字体渲染的合成样本。上中下不均匀、边界不平，所以不用等分、也不用直线。评测用「像素归段准确率」和「按段切出的部件图再做二选一的准确率」两个数，基线直线版对照它们。
3. **每段二选一**：每段只和该位置的两种部件比（字体渲染部件＋已标刻例），给出两选项的分数差。
4. **多结构**：组里成员结构不同（如一个 ⿰、一个 ⿱）时，每种结构各切一遍、各判一遍，取「各段分数差之和」最大的结构；差距不够就弃权。
5. **定字**：三段读法按 IDS 对齐查成员表（`ids.py` 反查，不再手写表）；任一段分数差不足就弃权，送人裁。

## 七、项目验收标准

1. **yi_560**：42 格用户三段标注上，留一册交叉验证，三段读法全对率 ≥ 95%，给字的格放错 0；13 格分歧格的 IDS 结论与用户的最终裁决（`disagree_13.jsonl` 里已有的看图结论为参考）逐格比对，不一致的逐格列出原因。命令：`python -m open_guji_cv.eval.groups yi_560 --dataset <char-groups> --backend ids`。
