# 5a 规则框架：判决规则的顺序、参数与加法

2026-11-06 起。Step5-a（`glyph_match`）一格从「查库」到「落判决」要过的每一条规则，按执行顺序登记在
`open_guji_cv/steps/glyph_rules.py` 的 `RULES` 里；判决层由 `glyph_rules.decide()` 按序执行，
`steps/glyph_match.py` 只调它，不再内联判决逻辑。缘起：Sheldon「把几条规则是个什么顺序、都有哪些参数抽象出来，
做成一个框架，方便后面加规则、改参数」。

这次只是搬家：缺省参数下各书产物逐字节不变，已登记 `core/code_equiv.py`（ENTRIES 一行＋SPLITS 一项），不让各书过期。
证据：测试样页 3 页 `scripts/code_equiv.py check` 与 origin/dev 逐字节相同；殿本 1500 格、史記 800 格（含真借库）
真匹配结果分别喂给改前内联逻辑与 `decide()`，18 组参数 × 2 种借库 × 近形开关共 24.8 万次判决 0 差。

## 一、两层

| 层 | 是什么 | 规则代码在哪 |
|---|---|---|
| 匹配器层（`stage="matcher"`） | `clustering.match.GlyphMatcher` 和外面几层包装（`_FontTier`、`_with_same_gate`、近形决胜）。给出 `MatchResult`：verdict／char／candidates／guard／near_shape | 原地不动（有金标与负结果记录）。表里只登记顺序、参数、常数、实现位置 |
| 判决层（`stage="step"`） | 拿到 `MatchResult` 后在格上再改判：借库降档、共识升档、近形升档 | `glyph_rules.rule_*` 函数，`decide()` 按 order 执行 |

「写死的常数」改了就是改算法，产物过期，要重新标定。

## 三、判决层的不变式

现行三条判决层规则都守下面几条，新加的升档规则也应守：

1. 只改 `unsure` 档；
2. 匹配器判了护栏（`guard` 非空：`never_match`／`conflict`；超时格记 `timeout` 后直接落盘，不进判决层）的格不动；
3. 借库降档降下来的格（`Decision.lent` 非空）后面的升档一律不碰，因为它们看的 cov 正是借来的条目给的；
4. 每次改判都写 `via`（前缀＝规则名对应的通道），出了错能按通道归因、按通道统计精度。

前三条合在 `glyph_rules._promotable()` 里，升档类规则直接调它。

候选试切（`cand_variants`）只走 `cand_variants=True` 的规则（现行只有借库降档），入口是 `decide_variant()`。

## 四、加一条判决层规则

1. 在 `glyph_rules.py` 写 `rule_xxx(m, d, state) -> Decision`：`m` 是匹配器结果（只读），`d` 是前面规则改过的判决，
   `state`（`StepState`）是本页共用的东西：参数、人裁例数、借库 id、近形配置。不适用就 `return d`。
2. 在 `GlyphMatchParams` 加开关，缺省关，并在 `_drop_unset_near_shape` 里让缺省值不进 `model_dump`。
   否则参数哈希变，全部现役产物判过期。
3. 在 `Rule` 加成员、在 `RULE_LABELS` 配一两个英文词的短名（有新改判通道就在 `Via` 加前缀），再在 `RULES` 里按位置插一条 `RuleSpec`（`order` 取两条之间的数，写清 `params`／`constants`／`via`／`summary`）。
4. 跑 `tests/test_glyph_rules.py`（顺序唯一递增、登记的参数都在 `GlyphMatchParams` 里、表里每条都能生成文档行），
   再用上面的命令重新生成第二节的表贴回来。
5. 先用比对基准 `guji eval run match_bench`（及 `_shiji`／`_qtw`）量开关前后，再按 `doc/exp_framework.md` 做 A/B 才改缺省。
6. 改 `glyph_rules.py` 的代码本身会让 glyph_match 产物过期（它是 code_dep）。开关缺省关、产物不变时，
   用 `scripts/code_equiv.py check` 证明后登记 ENTRIES（模块 `open_guji_cv.steps.glyph_rules`）。
