## 一、两级

| 级 | 放哪 | 版本 | 谁改 |
|---|---|---|---|
| global | 本仓：`seg/` 原语、Step 壳、引擎、指纹、三条版式的缺省实现（现 `impl/keben`、`impl/modern`、`impl/free`） | `vX.Y.Z`（`doc/版本号规矩.md`） | 改原语、壳、指纹找切分架构维护人（A22） |
| 书 | 各书工作区仓根 `code/`（GitHub 组织 `guji-workspace`，一书一仓） | 整数 `k<N>` | 书的负责人自己发，不等 cv 发版 |

没有 group 级；两本书要同一段代码，各拷一份。**书的 `code/` 为空也能跑**：全走缺省实现，指纹与没有 `code/` 时逐位相同。

## 二、书仓 `code/`

```
code/
  code.yaml        name（＝册的 seg_set）、base（keben/modern/free）、cv 兼容段、overrides
  defaults.yaml    这套代码配套的参数缺省（params: {step: {字段: 值}}），取代 books/<套书>/defaults.yaml
  samples.yaml     样页单
  equiv.yaml       本书登记的代码等价（moved / forked / entries），只许登本书模块
  *.py             本书模块：只许 import open_guji_cv.seg、open_guji_cv.book_api 与本书模块（guji code check 查）
  releases/k<N>.json   每版文件清单（路径 → sha256），只增不改
```

`overrides` 写 `keben.row_boundaries: row_boundaries`（缺省模块短名 → 本书模块）。cv 在 `core/book_code.py` 把 `code/`
挂成包 `guji_book.<name>`，`core/seg_set.resolve()` 先查书仓覆盖、再查 cv 内置的 `OVERRIDES`（2026-11-09 第 3 步后已空，只为兼容留着）。

已搬：史記 shiji_wyg → 988g3f0wsu 书仓 `code/`、全唐文 quantangwen → 995ejelvk0 书仓 `code/`（各 `k1`）。这两个名字已从
`seg_set.SEG_SETS` 删掉：工作区不是带 `code/` 的书仓就报错。书仓 `code/tests/` 放本书测试（`conftest.py` 借 cv 仓 `tests/helpers`），
不进指纹、`guji code check` 不查其 import。

## 三、版本号：字母＋整数

| 字母 | 库 | 册配置键 | 层 |
|---|---|---|---|
| `cv` | 引擎 | `cv_version` | global |
| `c` | 语料库总号 | `corpus` | 册（钉子账，下分底库 b、书库 v、册层） |
| `g` | 字形库 | `glyph_pin` | 书 |
| `m` | 模型库 | `model` | 书 |
| `k` | 书级代码 | `code` | 书 |

- 册配置可写简写 `pin: c31-g19-m2-k3`（`core/lib_pins.py`，逐层展开成分开的键，同层两种写法不一致报错）。
- 产物包标签：`cv0.7.0-c31-g19[-m2][-k3]-<改动名>`（guji-manager `datastore/packs.version_label`）；没有模型、书级代码的册标签与以前相同。

## 四、指纹与钉版本

- **版本号不进指纹**；指纹照旧按每个模块去注释后的代码算。书级模块进指纹的名字是 `guji_book.<name>.<模块>`。
- 从 cv 搬进书仓的模块登 `code_equiv.MOVED`；只改了 import 路径的另登 `ENTRIES`（或书仓 `equiv.yaml` 的 entries）。
  `engine._fingerprint_name` 沿 MOVED／FORKED 链走到头，所以「书仓模块 →搬自→ cv 套书副本 →分叉自→ 殿本模块」也认。
- `guji code release -w <书仓>` 写 `code/releases/k<N+1>.json`（内容没变不出）；书仓里提交、推 main，再打 tag `k<N>`，书配置写 `code: N`。
  云端会话推不了书仓的 tag，走中转站（ai-team `process/tag.py`，2026-11-09 白名单加了 guji-workspace，tag 名认 `k<N>`，只给 main 上的提交打）：
  `python3 process/tag.py guji-workspace/<书仓> <40 位提交号> k<N> "说明"`。tag 只是方便查找，钉版本按 `releases/k<N>.json` 核对。
- 钉了 `code: N` 的册起跑前比工作副本与 `k<N>.json`，不符拒跑（`GUJI_CODE_DRIFT=warn` 只告警）；`code.yaml` 的 `cv:` 段不含当前正式版也拒跑。

## 五、和 cv 发版的关系

- 只动一本书的代码：书仓提交、出 `k<N+1>`，不碰 cv。
- 改 `seg/`、`book_api`：加东西 PATCH；改签名或删 = MINOR（各书要跟着出新 `k`、改 `cv:` 段）。
- 改缺省实现：照 cv 规矩；改完用 `scripts/seg_samples.py` 比各书样页。
- 只给一本书用的新行为不再往共用 Step 里加「缺省关、按书开」的开关：拷缺省模块进书仓再改；要改的地方不在可覆盖模块里，找 A22 开钩子点。
- **钩子模块**（2026-11-10，第 4 步，Sheldon 定「先搬自成一块的，其余留着」）：共用 Step 在固定位置调一个缺省「什么都不做」的
  `impl/keben/<钩子>`，书仓覆盖它就生效，不再用开关。现有：`jiazhu_step`（雙行小注逐步切 `page_note_runs`／`apply`、两行字数可不等
  `free_split`）、`seal_ink`（大印下剔印泥 `inkcut`、表中间空格位记空 `GAP_SLOTS_EMPTY`）。原 `row_segment` 开关 `jiazhu_free_split`／
  `jiazhu_step_split`／`seal_gap_slots_empty`／`seal_inkcut` 删掉，书配置里留着 false 或删掉照常；写 true 而工作区 code/ 没覆盖对应钩子就拒跑
  （`row_segment._RETIRED`，防止还钉着 k1 的史記悄悄当关）。史記 k2 起覆盖这两个钩子。
  2026-11-13 加 C1 进库准入的 `follow_ref_hooks.rival_skip`（`seed_admit` 照录整理本异体对算领先差时，哪些字不当对手；
  史記同族第三形 吴／呉／吳、嵗／歳／歲，SJ 请求、A24 定规则），签名与 `facts` 字段见该模块头。cv 不加开关，书仓覆盖即生效。
- **留在 cv、冻结**：其余单书开关（史記的 row_pitch／layout_*／coord_dp*／alt_*／ref_topk_follow、全唐文的 frame_line_grow／
  ink_blob_empty／tail_one_abs 等）嵌在 Step 主循环里，搬它们得把 Step 内部开成书级接口，先不动；以后不再新加这类开关。
- **什么算「单书开关」**（2026-11-10，A20 判 cv #1388）：写死某本书的版式、字、页的分支（史記写本的 row_pitch、全唐文的列端
  一字逃生口这类）。通用机制按书调参、别的书配上自己的数据也能开的（按本书码位表归一 `solo_cal_5b_canon`、按本书两字刻形模型判
  `group_flow_pair_shape_nm_5b` 这类判决层旋钮）不算，照常进 cv、缺省关按书开。
- **剩下的怎么搬：改到哪个搬哪个**（Sheldon 2026-11-10 定，不再成批搬）。某本书要**改**自己的某个单书开关（改行为、改缺省、加分支）时，
  就在这次一起搬：书的线程（SJ／QTW…）找 A22 在共用 Step 那个位置开钩子（`impl/<版式>/<钩子>`，缺省什么都不做），实现进书仓 `code/`、
  删掉 cv 里的开关并登 `row_segment._RETIRED` 那样的拒跑表，书仓出新 k；本来就要验的这一轮顺带用 `scripts/code_equiv.py check`
  核别的书不变、登等价。只改数值的开关（值写在书仓 `code/defaults.yaml`）不用搬。只是用、不改的开关原地不动。
