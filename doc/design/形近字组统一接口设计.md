# 形近字组：模块化现状评估与统一接口／流程设计（草案）

> 2026-10-17，Emerson。用户问：形近字这一小块的模块化做得够不够好？怎么做得更好，让不同字组有**统一的接口和流程**？
> **状态：研究草案，没有改任何代码。** 与已有设计的关系见第三节：本文不推翻 B1（Ethan）的 `group_clf/1`、Evan 的 PR2 `ctx_window`，而是把它们**没覆盖到的部分**补成一套。
> 事实来源：代码均为 main `76d1f2f` 上实读；overview 设计档 `项目进展/CV形近字分组/计划/`（`总计划.md`、`分块-B1接口与放行闸-Ethan.md`、`Step6b-PR1/PR2-*.md`、`PR2合并清单-Evan.md`）；字组数据在 open-guji-dataset 的 `char-groups/`。

## 一、结论

**够不够好：只做到了一半。**

- **做得好的**：数据侧已统一——`char-groups` 测试集有统一契约（`groups.json`、真值分档 A/B/C、`items.jsonl`、`baseline.json`）；离线答案表有统一格式 `group_clf/1`；产物种类 `group_decision` 与 `group_decide` 步已有；`seed_admit` 的各遍有了固定次序（B1 §3.1）。
- **没做好的**：**代码侧一组一套**。同样是「判这个格是不是组内某个字，再决定抬升或降级」，现在有 4 种判别后端（规则、语料决策表、离线答案表、图像模型）、6 个入口函数签名、17 个扁平参数、4 套证据键和 6 个疑问码、3 份窗口取法、9 处字组成员常量；接入逻辑全部在 `seed_admit.py`（2720 行）里手写拼接。
- **后果**：新加一个组（例如 #560 彝彛彜彞𢑱𢑴）要同时改 `seed_admit` 的参数区、`__init__` 里的指纹填充、`model_dump` 里的「关时不进 dump」清单、`code_deps`、一个新的 `_xxx_pass`、证据键与疑问码约定——**每加一组都改 `seed_admit`，都让十册 `seed_admit` 过期**。B1 为了不付这个代价，明确选了「旧开关不重命名」，所以统一只做到了表格式与证据键，没做到代码。

## 四、目标设计：三个抽象＋一条流程

### 4.1 字组注册表（单一真源，在代码里）

```python
# open_guji_cv/groups/registry.py （新，低层，不依赖 steps/）
@dataclass(frozen=True)
class GroupSpec:
    id: str                       # "jys" | "ry" | "rr" | "yi_560" …，与 dataset groups.json 的 id 一致
    members: frozenset[str]       # 组内字；所有 FAMILY／CLASSES／GROUP_MEMBERS 由它派生
    backends: tuple[str, ...]     # 判别后端名，按优先级："rule" | "table" | "image" | "ctx_table"
    policy: GroupPolicy           # 见 4.3
GROUPS: dict[str, GroupSpec]
```

- 旧常量保留为**派生别名**（`ji_yi_si_clf.FAMILY = GROUPS["jys"].members`），不改外部 import。
- 加一组＝在这里加一项＋配后端，不碰 `seed_admit`。
- 测试：`tests/test_groups_registry.py` 校验每组 `members` 互不重叠、后端名都已注册；dataset `groups.json` 与它的一致性由 `research/char_groups` 的建集脚本断言（测试不读 dataset）。

### 4.2 判别后端协议（统一入口）

**判别输入与决策输入必须拆开**（Ethan 评审 ①c）：现行放行字 `admit_char` 要等 `seed_admit` 的全部通道跑完才定，`group_decide` 阶段根本不存在。所以后端**只吃判别输入、只出 pick**，「抬／降」由 `seed_admit` 拿 pick 与放行状态比。

```python
@dataclass
class JudgeInput:                  # 判别输入：group_decide 阶段就有的全部东西（只读）
    id: str
    ref: str | None                # 整理本对位字
    left: str; right: str          # **只许由 ctx_window（PR2）给**，适配器内不得再取一份窗口
    patch: Callable[[], np.ndarray]  # 惰性读字块缓存（图像后端才调）；缺图抛 PatchUnavailable

@dataclass
class GroupVerdict:                # 判别输出：就是 group_decision 里的一条
    char: str | None               # pick；弃权＝None，语义同 group_clf/1
    conf: float | None
    why: str                       # **直接复用 group_clf/1 的取值**：agree／abstain:<来源>／disagree／veto:<来源>，
                                   # 及缺格／ctx 不符／ver 不符的原因码，不另起一套
    via: str                       # "rule"|"table"|"image"|"ctx_table"
    extra: dict                    # 原样保留：表后端的 votes、规则命中文本、图像后端的四类概率、patch_missing

@dataclass
class DecideInput:                 # 决策输入：只在 seed_admit 里存在
    admit_char: str | None; channel: str | None; doubts: list[str]; is_human: bool

class GroupBackend(Protocol):
    name: str
    fingerprint: str               # 表／模型／规则版本的内容哈希
    def judge(self, spec: GroupSpec, cell: JudgeInput) -> GroupVerdict: ...   # 不读 DecideInput
```

四个适配器，**包住**现有函数，不改其算法：

| 适配器 | 包住 | 说明 |
|---|---|---|
| `RuleBackend` | `ji_yi_si_clf.classify`、`ji_yi_si.resolve` | 纯函数，无指纹（版本号即规则版本） |
| `CtxTableBackend` | `near_form_ctx.decide` | 语料决策表，指纹＝表文件哈希 |
| `TableBackend` | `group_decide.lookup`（W4 的 `utils/group_clf.py` 合入后改包它）、`ry_group.decide`、`ji_yi_si_clf.suggest` | **包 `lookup`，原样返回 `votes` 进 `extra`，不重定义弃权语义**（Ethan ①a） |
| `ImageBackend` | `rr_clf.classify` | numpy 模型，指纹＝`model_fingerprint`；**缺图不静默弃权**，见第七节 |

新增「大 vs 廾」读字器、或其它字组的图像模型，只需再写一个适配器。

### 4.3 策略：一次声明，一个函数执行

三个 `_pass` 的差别其实只有几个**可声明的旋钮**：

```python
@dataclass(frozen=True)
class GroupPolicy:
    lift: bool            # 待审格：判决字＝整理本字 → 抬为放行（通道名 <组>_group 或沿用 legacy）
    demote: bool          # 已放行（非人裁）格：判决字≠放行字 → 退回待审（疑问码 <组>_disagree 或沿用 legacy）
    conflict_with_strong: str   # "demote"（jys：强通道放行与规则冲突两边都不信）| "ignore"
    skip_doubts: frozenset[str] # occluded／glyph_timeout／seal… 这些格一律不碰
    strong_channels: frozenset[str]
    legacy: LegacyNames   # 旧证据键、旧疑问码、旧通道名（保证旧产物逐字节不变）
```

`apply_group_verdicts(records, verdicts, spec)`（**在 `seed_admit` 里调用**，拿 pick 与 `DecideInput` 比）：**唯一**的升降执行函数，把 `_ry_group_pass`／`_rr_clf_pass`／`_ji_yi_si_clf_cell` 里重复的「跳过人裁位／写证据／改 admit／记 doubts／记 `demoted_from`」合成一份。

### 4.4 流程（证据与决定分离，一条线）

```
Step6b group_decide      对每个整理本字落在某组的格：逐后端 judge() 出 GroupVerdict（只含 pick，不含抬／降）→ group_decision 产物
        │                （所有组、所有后端，唯一的证据出口；图像后端在这里读字块）
        ▼
Step7  seed_admit        读 group_decision，按各组 GroupPolicy 一次 apply：先升后降，降压过升，人裁位不动
```

这正是 Step6b PR1→PR2 原计划的方向（「PR1 只出证据，PR2 才让 `seed_admit` 改读」）。当前 PR2 只做了窗口口径；**本文建议把「seed_admit 改读 group_decision」也并进去**，这样：

- 一格只查一次表、只用一种窗口；
- `seed_admit` 里字组相关的 218 行（`_resolve_ji_yi_si` 等）收成一次调用；
- `group_decision` 同时就是审阅界面、评测、`char-groups` 基线的**统一数据源**。

### 4.5 参数：一块 `groups` 配置取代 17 个扁平键

```yaml
seed_admit:
  groups:
    jys: {lift: true, demote: true, backends: [rule, table], table: <路径>}
    ry:  {lift: true, backends: [table], table: <路径>}
    rr:  {demote: true, backends: [image], p: 0.5}
```

兼容：旧的 17 个键保留为**别名**，由 `model_validator` 翻成新结构；**关闭时不进 dump**，所以 `params_hash` 与现在逐位相同（这是 PR2 已验证过的做法：`ctx_align_ref` 缺省不进 dump、有测试钉着）。

## 七、风险与未决

**最可能出错的一处**：jys 的行为等价。`_resolve_ji_yi_si` 有 112 行，含「干支／时辰永远最先」、`use_ref="all"`、`clf > ctx_rule > review_gate` 的 if 链、对 `strong_channels` 的冲突处理，且 vol04／vol05 和其它册开的开关不同。统一时若悄悄改了优先级，会让真书放行结果变。对策：S2 先对拍、不通过不合，且 jys 的 4 套机制**先原样迁移，不趁机退役**。

**缺图不能静默弃权**（Ethan ②i，刚在字形库重放上踩过同一个坑）：`rr_clf` 现在靠 `patch_missing=skip` 静默跳过缺图格并记 `evidence.patch_missing`。`rr_clf` 前移到 `group_decide` 后，读的仍是**缓存**（缓存不是产物，不进 `consumes`），但缓存状态会改变产物。所以 `group_decide` 必须把 `patch_missing` 写进 `group_decision`，`seed_admit` 读到后保持 **skip／raise 同语义**，不能默默当弃权。

**两个 hash 都要核**（Ethan ②ii）：`group_decide` 要读缓存、走模型，成本上升；它的 `code_deps`（现只有 `ji_yi_si_clf`、`ry_group`）S2 会并入 `rr_clf`、注册表、适配器，`code_hash` 一次性大变，与「窗口后同批」的安排一致。

其余：
- **时机**：S2 必须并进窗口后的统一重跑；窗口甲前不碰 `steps/`、`core/`、`code_deps`（Mila 规矩）。
