# 跑批耗时统计（2026-11-03，A20）

回答「哪一步慢、慢在哪、改了有没有变快」。方案与分期见 Claude Doc《CV 管线性能统计方案》（https://claude.ai/artifact/KsR2RKgb3PRtAEChHwLhNn）。

## 记了什么

`guji pipeline`／`guji step`（凡走 `Engine.run()` 的）每次运行写一份 `<产物根>/../perf/<册>/<run_id>.jsonl`，一行一条：

| 行 | 内容 |
|---|---|
| `run` | 册、管线、步、页数、`--jobs`、cv 版本与 commit、命令行、任务库单号（`GUJI_JOB_ID`）、机器（主机、核数、内存、类别、云端容器号） |
| `page` | 真跑的每一页：计算耗时 `elapsed`，主进程开销 `overhead`（`check` 算指纹、`cache_invalidate`、`land` 落盘），步内分段 `spans`、计数 `counts`。新鲜跳过的页不写，只在 step 行计数 |
| `step` | 每步：跑／跳过／失败页数、墙钟、计算合计、p50／p90／max、并行效率、CPU 秒、峰值内存、开销合计、分段合计、最慢 20 页 |
| `end` | 墙钟、是否中断 |

放在产物根**外面**：产物包、冻结登记、部署检查都把产物根下的目录当步／册扫。`GUJI_PERF=0` 关掉，`GUJI_PERF_DIR` 换目录。

## 怎么看

```
guji perf top [--days 7] [--book 册] -w $WS     # 各步合计，按墙钟排
guji perf show <册> [--run ID] -w $WS           # 一次运行（缺省最新）各步明细、分段、最慢的页
guji perf pages <册> <步> [--slowest 20] -w $WS  # 某步最慢的页及其分段
```
都可加 `--json`。

## 全队汇总（美国机任务库）

设了 `JOBSDB_TOKEN`／`JOBSDB_PASSWORD`（任务库走美国机，见 `jobs/jobsdb.py`）时，每次运行写完自动把 run 一行、每步一行
（含最慢 20 页）推到美国机任务库 `jobs.perf_run`／`jobs.perf_step`，一次约 15 KB。**只推美国机，不推 Neon**
（Neon 存储与出流量都按量计费，Sheldon 11-03 定）；没设令牌就只落本地。每页明细不上传。

```
guji perf top --remote [--days 7] [--book 册] [--by host|cv_version|book]   # 在库里聚合好再回，几 KB
guji perf job <单号>                  # 一条任务单的各次运行、各步（执行方经 GUJI_JOB_ID 带单号）
guji perf push [--book 册]            # 补推没推上的本机记录（推过的旁边有 .pushed）
```

`guji pipeline` 缺省每步一个子进程、各写一份记录，用 `GUJI_PERF_GROUP` 同一个组号串起来（表里 `grp` 列）。

## 在 Step 里打点

```python
from ..core import perf

with perf.span("读模板表"):
    ...
perf.count("字块缓存未命中")

@perf.timed("cnn前向")
def forward(...): ...
```
嵌套的 span 记成 `外/内`。**Step 模块和它的 `code_deps` 进产物指纹**：在里面加 span 会让各册这步判过期。
只加计时、产物逐字节不变的，用 `scripts/code_equiv.py check` 证明后登记进 `core/code_equiv.py`，同一个 PR 提交。

### 不改 Step 源码的分段计时（2026-11-04）

`cli_perf.PERF_HOOKS` 点名一批函数／方法（现为 glyph_match 与 seed_admit 的各道关、匹配器 `GlyphMatcher._match` 等），
`guji step`／`pipeline` 起跑时 `install_hooks()` 把它们换成计时薄壳（`perf.timed`），分段记进每页的 `spans`，
随步级汇总推到任务库（`jobs.perf_step.spans`）。壳只调原函数、原样返回，Step 源码不动，**指纹不变、不用登记代码等价**。
限制：只换按名字查的调用点（模块全局、类方法、函数里现 import 的）；别处 `from x import f` 早拿走的引用不计；
拿函数身份做判断的（如 `GlyphMatcher._verify is verify_pair_elastic`）不换。并行时子进程 fork 继承；Windows（spawn）
子进程里不计。`GUJI_PERF=0` 不换。函数改名了 `tests/test_perf_hooks.py` 会红，把名单跟着改。
