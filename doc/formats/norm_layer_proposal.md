# 规范层（norm：异体 → 通行字）方案调研

> F2 道（任务卡 open-guji-core/overview#381），2026-10-02。用户 10-02 对 #361·4 的原话：「再仔细研究，提供方案」。
> 本文只出方案与演示，**不改 v0.2 的 `norm` 字段**（v0.2 照 v0.1：稀疏、只记异体、`why` 只许「异体」）。拍板后进 v0.3。
> 演示：`scripts/demo_norm_layer.py`，数据与输出在 `doc/formats/samples/norm_demo/`（四庫 vol03 p3、p53、p78、p107 的真实 CV 产物）。

## 〇、结论先行

**推荐方案 C「共享归一表 + 页上逐位例外，简体档派生不存」**：

1. **规范层只存一档：繁体通行字。** 简体不存——由繁体通行档过网站现成的 `t2cn` 派生。一字多义（云/雲、后/後、余/餘）在
   「繁 → 简」方向是多对一，**派生时自然合并，根本不用判**；它们只在「简 → 繁」方向才难，而我们的原样层是刻本繁体字形，永远不走那个方向。
2. **无条件的纯字形异体**（㫖→旨、葢→蓋、彚→彙、𠮓→變、歴→歷……）**进一张共享归一表**，就是网站 #350 已经做出来的 bim
   `variant-chars.json`（753 条，教育部正字口径，只收「转简后与正字相同、不改字义」的字形异体）——**一张表，网站繁简转换与本格式规范层共用**，
   本格式不另维护一份。页上 `norm` 里这类条目只是表的物化缓存，`by` 指向表的版本，表一升级可整批重算。
3. **要看上下文才定的**（証→證：「証」本義諫也，「互証」才是證；乾 在人名「王象乾」里不能简成「干」）**逐位记在页上**，
   `by` 记来历（整理本对齐 / 人裁），这是规范层里真正需要人判断、也真正需要存的部分；页上也可记「此位不归一」的例外。
4. **校勘（讹、脱、衍、倒）不进 `norm`**，另起一层「校勘记」，用稳定字框 `id` 锚定、按 guji-markdown 校勘三式（改/补/删）导出，
   结构草案见 §五。
5. **`variants.json` 不能直接拿来填 `norm`**（演示：p3 若照它的有向边填，会提 44 位，真该归一的只 2 位——欽→撳、全→痊、易→蜴、士→土 全是噪声）；
   它与本书用字账只当「候选来源」，进表要过人裁或 muse 批次（可并入 #372）。

待拍板的事列在 §七，每条附推荐。

## 三、「通行字」以什么为准

### 3.1 分两档，只存一档

| 档 | 内容 | 存不存 | 怎么得到 |
|---|---|---|---|
| 原样 | 刻本字形（`text`） | 存（真源） | CV 照录 |
| **繁体通行** | 异体 → 繁体正字；其余照原样 | **存**（`norm` 稀疏） | 共享表 + 逐位条目（§四） |
| 简体 | 繁体通行档转简 | **不存** | 网站 `t2cn`（与 book-text 简体模式同一个转换器、同一张归一表） |

为什么只存繁体通行一档：

- **繁 → 简是多对一**：雲/云 → 云、後/后 → 后、餘/余 → 余、於/于 → 于。原样层在繁体一侧，往简体走只是合并，不需要判断。
  演示 p78「題歸雲别集」→ 简体档「题归云别集」，`t2s` 直接对。用户举的 云/雲、后/後、余/餘 在**繁体通行档里本来就不归一**——
  它们在繁体里是不同的字（云＝言說，雲＝雲氣；后＝君后，後＝先後；余＝我，餘＝剩餘），刻本写哪个就是哪个，`norm` 不该碰。
- **简 → 繁才是一对多**，那是 OpenCC `s2t` 要靠词组表（STPhrases）解决的难题；我们不走这个方向。
- 简体档仍有少数「繁 → 简」也要看上下文的字：乾（乾坤、乾隆不简）、著/着、藉/借、瞭/了、夥/伙、覆/复、鍾/钟……演示 p78 的人名
  「王象乾」被 Python `t2s` 转成了「王象干」——**这是转换器词组表的事**，修法是给 `t2cn` 补词组，或在页上逐位记一个简体覆盖（§七·5），
  不是规范层（异体→通行）的事。

### 3.2 繁体通行字的口径

推荐：**以共享归一表的目标字为准**，即「教育部《異體字字典》的正字；被归一的字本身不是 Big5 常用繁体字、也不是通用规范字」——这是按 #350 R11 回报归纳的 bim 表收字口径（确切规则以 bim `ui/scripts/variant-chars/` 生成脚本为准，F2 没有读到该仓）。
后果是两条，要说清楚：

1. **只归一「标准转换器不认得」的字形异体**。#350 原话：「Big5 里的「异体」多半另有字义（如「抬」「雰」「妳」「祐」），一律不收」。
   所以爲、羣、峯 这类 Big5 里有码位的写法（是否算异体各家不一）按此口径不进表；它们在繁体通行档里**保持原样**，简体档由 `t2cn` 正常转换（爲→为、羣→群）。所以「繁体通行」≈「刻本字形去掉生僻异写」，
   不等于「台湾教育部标准字形」。要台湾标准字形，可以在网站再派生一档（繁体通行档过 OpenCC `t2tw`），也不存。
2. **新旧字形不归一**（宫/宮、温/溫 这类只差一笔的）——是否收进表由表的维护者定。演示表收了「宫→宮」（用字账 single、twedu 有边），
   bim 表若不收，就以 bim 为准。

### 3.3 一张表，两处用：怎么共用不漂移

- **真源**：bim `ui/scripts/variant-chars/` 生成的 `variant-chars.json`（已经是网站、检索边缘函数共用的那一份）。规范层**引用它的版本**，不复制。
- **本格式这一侧**：页上 `producers.norm_table = {"tool": "bim variant-chars", "version": "<bim 版本>", "sha256": "…"}`；
  表里的字物化成 `norm` 条目时 `by: "table:<version>"`。表升级 → 按版本整批重算这些条目（逐位条目不动）。
- **CV 这一侧要补进表的字**（刻本里有、bim 统计因 ≥1000 次门槛没收的，如 𠮓→變、彚→彙）：走 bim 那边的生成脚本加白名单，
  或另起一张「刻本补充表」由生成脚本合并——**不要**在 cv 仓另立一份。CV 的 `local_edges.json`（local:keben，㫖—旨 首例）就是天然的补充来源。
- 表的条目要多一个字段 `cond`（默认 false）：false = 无条件、可物化；true = 只当候选、不自动套（§四·3）。bim 现表全是 false。

## 四、谁来填、怎么填

### 4.1 三个来源，各自的可信度（vol03 实测）

| 来源 | 能给什么 | 实测 | 用法 |
|---|---|---|---|
| **共享归一表**（bim + 刻本补充） | 无条件的字形异体 | 演示表 11 条，vol03 四页物化 14 条，逐条看全对 | **直接物化**进 `norm`，`by: table:<版本>`、`review: auto` |
| **整理本对齐**（CV Step5-d `align_ref`、book-text 入库对齐） | 整理本在这一位用的字；与原样不同且两字互为异体 → 整理者做过归一 | vol03 四页样张里，非阙文位的 `cand.ref` 与 `text` **一位都没有不同**——这批整理本（维基）本身照录了刻本字形（㫖、葢、彚 都原样在） | 有差异时当**逐位候选**；对齐上的是另一个本子时还可能是异文，要过人裁 |
| **`variants.json` 有向边** | 「哪边是正字」的先验 | **不能直接用**：p3 会提 44 位、真该归一的 2 位；p53 87/6、p78 85/5、p107 74/1。噪声是 hydzd/twedu 收的古文、通假、分化字（欽→撳、全→痊、士→土、傳→傅、大→太） | 只作**候选过滤**：表外的字要进表，至少要有 T1 来源 |
| **本书用字账**（`books/wuyingdian_zongmu.json`） | 本书出现过的异体组、跨书统一键 `canonical` | 95 组里 `ref_policy=single` 的 54 条，看下来至少 2 条错（卞→其、籕→抽），五/伍（T2、通假）也混在 multi 组里 | 候选来源；进表前人裁 |
| **人工**（校对模式、muse 批次） | 逐对裁决（进不进表）与逐位裁决（这一处归不归一） | — | 逐对的并入 #372 那类 muse 批次；逐位的在网站校对模式点 |

### 4.2 一字多义、要看上下文的映射

先分清三类，只有第三类是规范层的难题：

| 类 | 例 | 规范层怎么办 |
|---|---|---|
| 繁体里本是两个字（简化时才合并） | 云/雲、后/後、余/餘、于/於、干/乾/幹、谷/穀 | **不归一**。刻本写哪个就是哪个；简体档由 `t2cn` 合并 |
| 古今字、通假（不同的词借用） | 說/悅、蚤/早、女/汝、知/智、内/納 | **不进 `norm`**（`why` 只许「异体」把它挡在外面）。这是训诂注释，不是字形规范；要做另开注释层 |
| **同一个字形在不同语境下是不同字的异体** | 証（諫也；又作 證 的俗写）、脩（乾肉；又同 修）、彊（姓、地名；又同 強）、閒（同 間、同 閑） | **逐位记**：`norm` 条目 `by: "align"/"human"`，不进共享表（或进表但 `cond: true`，只出候选）。演示：p53「多証以史事」、p107「互証」→ 證，F2 手填 |

`cond: true` 的表条目由导出器**只生成候选**、不物化：网站校对模式把候选列给人点；整理本对齐那一路若在这一位给了正字，自动采信并记 `by: "align"`。

### 4.3 整页 / 整册统一，还是逐字

- **规则在册（书）级，结果在页级。** 共享表是全局的；「这本书里 X 一律归 Y」「这本书里 X 一律不归」这类本书决定写进书级规则
  （`layout/norm_rules.json`：`{"keep": ["爲"], "add": {"𠮓": "變"}}`，只放与共享表不同的部分），由它和共享表一起物化。
- **页上 `norm` 是物化结果**——一页拿出来自己就能出规范层（网站、检索、luatex-cn 都不用再查表），这一点保留 v0.1 的设计。
- 逐位条目只给「上下文才能定」的位与例外（「此位不归一」：`t` 等于原字、`why: "保留"`，见 §七·3）。

## 五、和校勘层的边界

**口径**：规范层回答「这个字形的通行写法是什么」（同一个字，换个写法）；校勘回答「底本这里对不对、该读成什么」（不同的字或字数变了）。
讹（误字）、脫、衍、倒都改变了**读法**，与异体无关，不进 `norm`——这也是 TEI 把 `<orig>/<reg>` 与 `<sic>/<corr>` 分成两对的原因（§二）。

**挂在哪**：不挂在页文件里。页文件的 `text` 是底本原样，校勘是跨本子的判断（一处校记要引他本、引文义，可能跨页跨列），
所以另起**校勘记**，每书（或每卷）一个 `layout/collation.jsonl`，一行一条，用**稳定字框 `id`** 锚定（规范 v0.2 §六：重切后按 IoU 承接，
文本区间下标会随重切变，`id` 不会）。

**结构草案**（一行一条）：

```jsonc
{"id": "k7f3…",                              // 校记自己的稳定 ID
 "page_id": "96mid1ogzk/3/107",
 "anchor": {"glyphs": ["gab12…", "gcd34…"]},  // 被校的字框（连续若干个）；脱文锚在「前一字框之后」：{"after": "gab12…"}
 "op": "gz",                                  // gz 改（讹）| bz 补（脫）| sz 删（衍）| yi 乙（倒，等价于对一段「改」成颠倒的顺序）
 "orig": "己",                                // 底本读法（= 锚定字框在原样层的字，冗余存一份方便核对）
 "reading": "已",                             // 定本读法；sz 为空；bz 为补入的字
 "src": "據文淵閣本",                         // 依据（guji-markdown §4 的 src 属性）
 "witness": ["文淵閣本"],                      // 引了哪些本子
 "note": "…",
 "by": "human", "review": "human"}
```

导出 guji-markdown 定本层时按校勘三式写：`gz` → `[已]{{己}}`、`bz` → `((字))`、`sz` → `{{字}}`、`yi` → 对整段写一次 `[乙甲]{{甲乙}}`；
原样层导出不受影响。**异体归一与校勘可以叠在同一位**（底本「㫖」是讹字、定本作「肯」）：先校勘定读法，再对定本读法套规范层——
所以导出顺序是 原样 → 校勘 → 规范，规范层只对「校勘后仍是底本那个字」的位生效。

这层现在没有数据（CV 不产校勘），先定结构，等文本一侧第一批自校文本入库时再落 schema。

## 六、方案对比

| | A 页上逐位、全量物化（v0.1 现状照填） | B 只存规则（共享表 + 书级规则），页上不存 | **C 共享表 + 书级规则为真源，页上存物化结果与逐位例外（推荐）** | D 不要规范层，网站运行时查表归一（#350 做法延伸） |
|---|---|---|---|---|
| 存储 | 每页 `norm` 全量 | 页上零条；一张表 + 每书一个小文件 | 页上 `norm`（表的物化 + 逐位）；表引用版本 | 零 |
| 维护成本 | 高：表一改要逐页改，谁改的分不清 | 低 | 低：表条目 `by: table:<版本>` 可整批重算，逐位条目不动 | 最低 |
| 上下文相关 | 能（逐位） | **不能**（规则只能按字） | 能（逐位条目） | 不能 |
| 与 #350 共表 | 不共（内容抄过来） | 共 | 共 | 共 |
| 阅读模式（繁体通行 / 简体） | 页文件自足 | 要带表才能出 | 页文件自足；简体由 `t2cn` 派生 | 简体可以；**繁体通行档没有**（#350 繁体模式不动） |
| 校对模式 | 看得到每位怎么来的，但表条目与人裁混在一起 | 看不到逐位 | 每条 `by` 分得清「表/对齐/人裁」，人裁的单独可审 | 无记录 |
| 检索（通行字检索原样字） | 可 | 要查表 | 可 | 要查表 |
| md 导出（`layer="norm"`） | 可 | 要带表 | 可 | 不可 |

**推荐 C**。B、D 都做不了上下文相关的位，也做不了「此位不归一」；A 的问题是表与人裁混在一起、表一改无从重算。C 只比 A 多一个约定：
表条目带版本、可重算。

不推荐、也不在对比里的做法：

- **把规范字塞进原样层**（直接改 `text`）——丢原貌，与 TEI、CBETA 的做法都相反（§二）。
- **用 IVS（异体字选择符）表示异体**——IVS 表示的是**同一个字**在字形上的变体（字形库层面），不是「异体字 → 正字」的映射；
  而且注册的集合（IVD）以日本的为主，中文古籍的异体大部分本身就有独立码位（㫖、葢、彚 都是）。可以在原样层里出现（照录带 IVS 的序列，字元数组已经支持），
  但不是规范层的机制。

| 5 | 简体档的逐位覆盖（王象乾 这类） | 先给网站 `t2cn` 补词组（人名进词组表）；页上**暂不**加字段 | `norm[].s` 记简体档覆盖 |
| 6 | 刻本补充字（𠮓→變、彚→彙）进哪张表 | 进 bim 生成脚本的白名单（cv `local_edges.json` 当来源），**只维护一处** | cv 另立补充表、bim 生成时合并 |
| 7 | `cond: true`（上下文才定）的表条目 | 加，导出器只出候选不物化；校对模式点 | 不加，上下文相关一律逐位人工 |
| 8 | 进表的逐对裁决谁做 | 拆成 muse 批次并入 #372（schema 已有「同字异形」一档），人抽检 | 全人工 |
| 9 | 校勘层 | 结构按 §五 草案先定，等第一批自校文本入库再落 schema；`op` 用校勘三式 + `yi` | 现在就做 schema |
| 10 | 什么时候填 | 共享表那部分**现在就可以**由 CV 导出器按表物化（零人工）；逐位那部分等入库对齐 | 照 v0.1：全部等入库对齐时文本一侧填 |

## 八、演示（`doc/formats/samples/norm_demo/`）

```bash
python scripts/demo_norm_layer.py --table doc/formats/samples/norm_demo/demo_norm_table.json \
    --overrides doc/formats/samples/norm_demo/demo_overrides.json --out doc/formats/samples/norm_demo \
    doc/formats/samples/norm_demo/p00{03,53,78}.guji-page.json doc/formats/samples/norm_demo/p0107.guji-page.json
```

- 输入：v0.2 样张 p3、p107，外加 vol03 **p53**（爻變、卽、葢、「多証」）与 **p78**（葢、彚×3、萬歴、人名王象乾）——
  按本书用字账在 vol03 110 页里数「表内异体」出现次数挑的（p53 6 处、p78 5 处，用字最杂）。全部由快照
  `snap/96mid1ogzk/vol03/20260928T1708-full` 的真实产物导出。
- `demo_norm_table.json`：共享归一表草样 11 条（从用字账 `single` 组挑、F2 逐条看过、剔了 卞→其 与 籕→抽；**未经人审，不是正式表**）。
- `demo_overrides.json`：逐位条目 2 条（証→證，上下文才定）。
- 输出：每页 `*.norm.guji-page.json`（填好 `norm`、过 `check()`）与四份 md：`orig`（原样）、`norm`（繁体通行）、`simp`（繁体通行档 → `t2s`）、
  `simp_without_norm`（不经规范层直接 `t2s`，对照用）；运行记录 `demo_run.txt`。

| 页 | norm（表 / 逐位） | 内容 | variants.json 有向边直接填会提 | 不经规范层直接转简体漏下的异体 |
|---|---|---|---|---|
| p3 | 2 / 0 | 㫖→旨、葢→蓋 | 44 位（在表里的 2） | 㫖、葢 |
| p53 | 6 / 1 | 𠮓→變 ×4、卽→即、葢→蓋；証→證（逐位） | 87 位（6） | 葢、𠮓 |
| p78 | 5 / 0 | 葢→蓋、彚→彙 ×3、歴→歷 | 85 位（5） | 彚、歴、葢 |
| p107 | 1 / 1 | 彚→彙；証→證（逐位） | 74 位（1） | 彚 |

看点：

1. **简体模式的漏字正是 #350 的病**：㫖、葢、彚、𠮓、歴 `t2s` 都不认得、原样留在简体里；过了规范层再转就干净（p78 简体档「往为汇解」「万历」）。
   网站 #350 的归一表解决的就是这一步——所以规范层与网站共表是顺理成章的。
2. **云/雲 不用判**：p78「題歸雲别集」繁体通行档照原样，简体档自然成「归云」。
3. **简体档的上下文问题在转换器**：p78「王象乾」被 `t2s` 转成「王象干」，与规范层无关（规范层没碰它），要给 `t2cn` 补词组（§七·5）。
4. **表外的字形异体**还有：p53「以决進退」的「决」（決）、p78「别集」的「别」（別）、「鈎解」的「鈎」（鉤）——都是 Big5 外或 Big5 内的异写，
   按 §3.2 口径要不要收由表的维护者定，演示表没收，繁体通行档照原样、简体档 `t2s` 也照样对。
5. **整理本对齐这一路在这批页上没有信号**：维基整理本照录了刻本字形，`cand.ref` 与原样没有一位不同，所以这批页的规范层只能靠表与人裁。
   换一个做过归一的整理本（如识典、中华书局点校本）才会有差异。
