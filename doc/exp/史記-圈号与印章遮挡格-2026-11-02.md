# 史記文淵閣本：圈号 ○ 与卷端印章遮挡格（2026-11-02）

口径：01–10 册正文待审 3,519 格里的 C 类（参校本此格空）484、A 类（印章遮挡）432、D 类 3。cv 代码取 claude/shiji-run（ba2b739），册 yaml 同线上。

## C 类：圈号 ○（做成了）
- 478 格是段末/篇末的圈号 ○，整理本不录，坐标对位（`coord_relaxed`）说这一位是空格；图上是清清楚楚的圆圈，库 cov 0.977–0.999。
- 原因：`symbol_review` 对符号一律送审，除非本书库里同一符号人裁 ≥ `symbol_min_human`（3）条；本书没有人裁过 ○。
- 做法：书级开关 `seed_admit.symbol_ref_blank: "○"`（缺省空＝关，不进参数 dump），条件＝库首位是名单符号 ∧ cov≥0.97 ∧ 坐标对位说空格 ∧ 非遮挡/排除/人裁格。
- 结果（01–10）：484 格里 461 格放行；仍待审的是旧人裁（02:208:6:5 人裁判成「困」，绑定后不采信）等；其余格逐格对比 0 变化。

## A 类：卷端第 2 页印章遮挡（只做成一小半）
- 267 格机器没给字，全在各册第 2 页「欽定四庫全書／史記卷N／漢太史令司馬遷撰／宋中郎外兵曹參軍裴駰集解／唐國子博士…索隱／唐諸王侍讀…正義」列和小注列。
- 原因：这些标题列被大印压着。`row_segment._header_columns` 对大印压着的列**不改**（印泥斑点会被按字数重切成字），格网切在这几列乱切（一字两三格、空位切出多余格），格数与整理本字数对不上 → 坐标对位失败 → `occluded.via=none` → 无默认字、`lane_seal` 无从放行。
- 失败的试验（别再试）：
  1. 放开 `_header_columns` 的印下不改（试加书级开关 header_under_seal）：03 册 p2 实测，列 3、4 格数反而更少（4<8、4<12），印文被当成字，第 6 列整列读成乱字 → 回退。
  2. 按「有大块墨的连续格」成簇数对整理本字数：相邻字（令司馬遷）连成一簇，簇数与字数不等，不可用。
- 做成的：放开 `lane_seal_title_marks` 里的「四庫全書」（册 yaml 改成 `書總目`）。第 1 列「欽定四庫全書」坐标对位本来就对（via=coord），原来被标题串拦掉；放开后 8 册放行 47 格（另 2 册第 1 列对位本身冲突，不放）。
- 剩下约 220 格要靠格位表给格号（layout_slots：漢太史令司馬遷撰 在列内格位 [3,6,9,12,13,14,15,17]，要把格位表映到实际格网上），属切分工作，交职名页切分线程一并看。
