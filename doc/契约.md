# pipeline ⇄ manager 契约（v1，2026-10-27）

> 设计与背景：[design/拆分-pipeline与manager.md](design/拆分-pipeline与manager.md)。本文是两边都要守的接口，改它要加 `CONTRACT_VERSION`（`open_guji_cv/core/contract.py`）。

## 一、谁能 import 什么

manager 只许 import `open_guji_cv.api`（转发层）与 `open_guji_cv.products.kinds`（产物 schema）。其余内部（`clustering` `utils` `steps` `core.*`…）不许碰。方向守卫见 `tests/test_architecture.py`（pipeline 不许 import manager）。

## 二、命令行（`guji-cv`，也是 `guji` 的子集）

| 命令 | 用途 | `--json` |
|---|---|---|
| `version` | 装着的 cv 版本、commit、契约版本、Step 清单 | `{"cv_version","cv_commit","contract_version","steps":[…]}` |
| `pipeline <册> <管线> …` | 跑整条或一段 | 有（已有） |
| `step <册> <步> …` | 只跑一步 | 有 |
| `rerun --stale …` | 重跑显式失效的页 | — |
| `status <册>` | 各步各页新鲜／过期／缺失 | 有 |
| `book show <册>` | 合并后的生效册配置与来源层 | — |

退出码：0 成功；1 有页失败（`--stop-on-error`）；2 参数错误；3 册被别的跑批锁着。

> M2 起 `pipeline` 加 `--no-prep`、`--no-pack`，manager 显式 prep → 跑 → pack；过渡期缺省行为不变。

## 三、磁盘契约（pipeline 定义，manager 只读）

| 对象 | 约定 |
|---|---|
| 册配置 `books/<册>.yaml`、`config/book_defaults.yaml` | 字段集合与五层覆盖规则见 [design/册配置分层与运行覆盖.md](design/册配置分层与运行覆盖.md)。manager 只改身份、图源、钉版类字段，其余原样透传 |
| 产物 `products/<册>/<步>/`、`_manifest.jsonl` | 条目字段见 `products/manifest.py::ManifestEntry`；新增字段只加可选。`contract_version`、`manager_version` 两项**不进指纹**、不参与过期判定 |
| 人裁事件、裁决表 | 格式归 `feedback.events` / `feedback.lookup`；生产在 manager |
| 工作区布局 | `core/workspace.py`（`doc/workspace_layout.md`） |

## 四、输入物化

pipeline 不联网、不读令牌。跑之前原图、语料包、字形库、生僻字索引、字体包必须已在工作区；缺了应报错并提示先 `prep`。现状有 5 处例外（见设计第四节），M2/M3 清掉。

## 五、版本

- `contract_version`：整数，当前 1；0 = 契约成文前（manifest 无该字段的老条目）。
- manager 调用 pipeline 的子进程里设 `GUJI_MANAGER_VERSION=<manager 版本>`，pipeline 记进 manifest 供审计。
- manager 启动时先 `guji-cv version --json`，契约版本不在自己支持范围就拒跑。
