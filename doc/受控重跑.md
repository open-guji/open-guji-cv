# 受控重跑：钉住、只跑受影响的、看前后对比

> 2026-10-19 起（rc/v0.4.7）。方法论（什么改动重跑什么、在哪跑、怎么验收）在 ai-team
> `domain/CV/规范/受控重跑方法论.md`；本文只讲命令。三样新东西都是**缺省关**：不钉、不用就和原来逐位相同，
> 不进任何 Step 的 `code_deps`，17 步 `code_hash` 不变。

## 一、钉字形库：别处的人裁不让本册过期

```yaml
# 中心库数据目录 books/vol04.yaml
glyph_pin: 1        # 或 g1
```

- 钉了之后 seed_admit 的 `human_fingerprint`、`approx_fingerprint` 在 `params_for` 里换成 `glyph-g1`
  （`core/glyph_pin.py`）。别的对话 `guji db sync` 推上来的人裁不再让本册 seed_admit 判过期。
- **第一次写上 `glyph_pin` 本身会让本册 seed_admit 过期一次**（指纹从内容哈希换成钉号）。挑本来就要重跑 seed_admit 的时候写。
- 要让新人裁落地：号加一（`glyph_pin: 2`），本册 seed_admit 整册过期一次，重跑时读当时的库。
- 钉的是指纹，不是库内容：因别的原因重跑的页（切分改了、`guji recheck` 点名的格）照常读**当前**的库。
- `guji status` 在册名下提示「字形库钉在 gN」。
- 同类的钉子还有语料库 `corpus: N`（`core/corpus_pin.py`，见 [语料库版本化方案](design/语料库版本化方案.md)）。

## 二、前后对比：`guji products diff`

```bash
guji products diff vol04 --a <前的产物根> [--b <后的产物根，缺省本机 products>] \
     [--pages 10-60] [--out diff-vol04] [--images 40] -w $WS
```

- 产物根是含 `<册>/<步>/p0001.json` 的那一层：`products/`、`guji snapshot make` 出的目录、`guji products pack fetch --to` 解出的目录、实验变体目录。
- 按**位置**对齐（同一页同一列，`bbox_page` IoU ≥ 0.5 算同一格），切分变了、格号漂了也能比。格的状态取 seed_admit（口径同 `exp/compare.cell_state`）；没有 seed_admit 就只比切分。
- 出 `report.md`（两边格数、送审数、人审率、变了的列分类、逐格翻转）、`columns.tsv`（每个变了的列两边的字，送审格写 `[字]`）、`summary.json`；`--images N` 再出 `index.html`：前 N 个变了的列，原图上 A 红框、B 绿框并排，粗框是送审格。
- 列分类：`cells`（切分变了）> `text`（字变了）> `state`（只状态变）> `geom`（只框动了 >2px）。
- **「放行字变」**（两边都放行、字不同）是重跑最要看的风险，报告单列，逐个看图。
- 和 `guji exp report` 分工：exp 按格 id 比 seed_admit、要标签、算错率与置信区间，回答「开关开不开」；这里不要标签，回答「这次重跑改了什么、人审格多了还是少了」。

## 三、产物包与索引：`guji products pack`

products 不进中心库，新会话原来只能整册从 Step1 重算才有「前」的那份。现在存进 R2（guji-data Worker `/v1/packs`，R2 下载不收费，不走 Neon）。

```bash
export GUJI_DATA_TOKEN=$GUJI_DATA_TOKEN_PROD        # 存、标 main 要正式令牌；取、列读令牌就够
guji products pack push vol04 [--change layout] [--main] [--steps a,b] [--note "谁、为什么"] -w $WS
guji products pack promote vol04 --label cv0.4.7-c1-g2-layout -w $WS     # 把已存的包标成该册 main
guji products pack list [vol04] -w $WS              # ★ = main；列出每份的 cv／语料／字形库版本
guji products pack fetch vol04 [--label …] [--to /tmp/base] [--force] -w $WS   # 缺省取 main（没标过就取最新）
guji products pack push-index        # 本机 models/*/emb_*.npz 里 R2 还没有的存上去
guji products pack fetch-index       # R2 里有、本机没有的取下来（键按内容算，各机器通用）
```

- **一份结果由三样版本共同决定**：cv、语料库（册 yaml `corpus: N`）、字形库（`glyph_pin: N`）。标签缺省按这三样拼：
  `cv0.4.7-c1-g2-<改动名>`（`--change` 给改动名，不给用 UTC 时刻）；字形库没钉的写 `g-` 加人裁内容指纹前 6 位
  （如 `g-82293e`），语料库没钉写 `c-`。三样的完整值（含 cv 提交号、人裁指纹）另记在包的 `manifest.json` 的 `versions`。
  `--label` 给了就整个用它。标签只能用 ASCII 字母、数字和 `_.-`，中文会被拒。
- 包名 `products/<ws>/<册>/<标签>`，只增不改，同名拒绝：不同版本、不同开关的结果各存一份并存，任意两份都能取回 `products diff`。包里不带 `_prev/`。
- **main** = 这册当前的正式结果。`pack push --main` 或 `pack promote` 追加一条指针（`products/<ws>/<册>/main-ptr/<时刻>-<标签>.json`，只增不改，最新一条为准）；`fetch` 不给标签取 main。实验、试跑的包不标 main。
- `fetch` 目标已有该册产物时拒绝，`--force` 才覆盖，且先核完全部段的 sha256 才动本机产物。
- 取回的产物照常由引擎按指纹判新鲜：代码、参数、库变了的步照样过期，只重跑那些。
- 实验分支（`GUJI_DATA_BRANCH=exp/…`）上存取的是实验桶。

## 四、已有的、配合着用的

| 要做的 | 命令 |
|---|---|
| 看哪些步过期、为什么 | `guji status <册> --pages all`（过期原因：代码／参数／册配置／上游） |
| 只跑某些页 | `guji pipeline … --pages 3-6,9 --from <步> --to <步>` |
| 只重算点名的格（Step5-a 起） | `guji recheck <册> --chars 巳,已 | --verdicts unsure` 再 `guji pipeline … --from glyph_match` |
| 只跑显式失效的页 | `guji rerun <册> --stale [--dry-run]` |
| 重跑前留一份「前」 | `guji snapshot make <册> [--steps …]`（本机拷贝）或 `guji products pack push`（存 R2） |
| 不动正式产物试参数 | `export GUJI_PRODUCTS_DIR=$SCRATCH/products`（沙箱），或 `guji exp run`（[exp_framework.md](exp_framework.md)） |
| 试会写库的功能 | 中心库实验分支（[datastore.md](datastore.md) 第六节） |
| 关掉格级复用（排查用） | `GUJI_NO_REUSE=1` |
