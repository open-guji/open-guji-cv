# 受控重跑：钉住、只跑受影响的、看前后对比

> 2026-10-19 起（rc/v0.4.7）。方法论（什么改动重跑什么、在哪跑、怎么验收）在 ai-team
> `domain/CV/规范/受控重跑方法论.md`；本文只讲命令。三样新东西都是**缺省关**：不钉、不用就和原来逐位相同，
> 不进任何 Step 的 `code_deps`，17 步 `code_hash` 不变。

## 一、钉字形库：别处的人裁不让本册过期

```yaml
# 中心库数据目录 books/vol04.yaml
glyph_pin: 1        # 或 g1
```

- 钉了之后 seed_admit 的 `human_fingerprint`、`approx_fingerprint` 在 `params_for` 里换成 `glyph-g1`
  （`core/glyph_pin.py`）。别的对话 `guji db sync` 推上来的人裁不再让本册 seed_admit 判过期。
- **第一次写上 `glyph_pin` 本身会让本册 seed_admit 过期一次**（指纹从内容哈希换成钉号）。挑本来就要重跑 seed_admit 的时候写。
- 要让新人裁落地：号加一（`glyph_pin: 2`），本册 seed_admit 整册过期一次，重跑时读当时的库。
- 钉的是指纹，不是库内容：因别的原因重跑的页（切分改了、`guji recheck` 点名的格）照常读**当前**的库。
- `guji status` 在册名下提示「字形库钉在 gN」。
- 同类的钉子还有语料库 `corpus: N`（`core/corpus_pin.py`，见 [语料库版本化方案](design/语料库版本化方案.md)）。

## 二、前后对比：`guji products diff`

```bash
guji products diff vol04 --a <前的产物根> [--b <后的产物根，缺省本机 products>] \
     [--pages 10-60] [--out diff-vol04] [--images 40] -w $WS
```

- 产物根是含 `<册>/<步>/p0001.json` 的那一层：`products/`、`guji snapshot make` 出的目录、`guji products pack fetch --to` 解出的目录、实验变体目录。
- 按**位置**对齐（同一页同一列，`bbox_page` IoU ≥ 0.5 算同一格），切分变了、格号漂了也能比。格的状态取 seed_admit（口径同 `exp/compare.cell_state`）；没有 seed_admit 就只比切分。
- 出 `report.md`（两边格数、送审数、人审率、变了的列分类、逐格翻转）、`columns.tsv`（每个变了的列两边的字，送审格写 `[字]`）、`summary.json`；`--images N` 再出 `index.html`：前 N 个变了的列，原图上 A 红框、B 绿框并排，粗框是送审格。
- 列分类：`cells`（切分变了）> `text`（字变了）> `state`（只状态变）> `geom`（只框动了 >2px）。
- **「放行字变」**（两边都放行、字不同）是重跑最要看的风险，报告单列，逐个看图。
- 和 `guji exp report` 分工：exp 按格 id 比 seed_admit、要标签、算错率与置信区间，回答「开关开不开」；这里不要标签，回答「这次重跑改了什么、人审格多了还是少了」。

- **重切过就顺手核排除清单**：`config/crop_exclusions.jsonl` 按格号记，不带框，切分一变可能落到别的格上。
  `guji products exclusions <册> --a <重切前产物根> [--b <重切后>] [--apply] -w $WS`：拿重切前这个号的框，到重切后找框重合
  （IoU ≥ 0.85）的格——没动不改、顺移改号（记 `rekey_from`）、找不到撤到 `crop_exclusions_retired.jsonl`（那格回流程，多半送人审）。
  缺省只报计划；`--apply` 改本机名单，再 `guji db sync`。名单一变各册 seed_admit 都过期（名单向来如此），所以先报、看过再改。

## 三、产物包与索引：`guji products pack`

products 不进中心库，新会话原来只能整册从 Step1 重算才有「前」的那份。现在存进 R2（guji-data Worker `/v1/packs`，R2 下载不收费，不走 Neon）。

```bash
export GUJI_DATA_TOKEN=$GUJI_DATA_TOKEN_PROD        # 存、标 main 要正式令牌；取、列读令牌就够
guji products pack push vol04 [--change layout] [--main] [--report diff-vol04] [--summary "目的、改了什么、结论"] [--steps a,b] [--note "谁、为什么"] -w $WS
guji products pack promote vol04 --label cv0.4.7-c1-g2-layout -w $WS     # 把已存的包标成该册 main
guji products pack list [vol04] -w $WS              # ★ = main；列出每份的 cv／语料／字形库版本
guji products pack fetch vol04 [--label …] [--to /tmp/base] [--force] -w $WS   # 缺省取 main（没标过就取最新）
guji products pack push-index        # 本机 models/*/emb_*.npz 与训好的语言模型（cache/general_lm/*.json）里 R2 还没有的存上去
guji products pack fetch-index       # 生僻字索引：R2 里有、本机没有的取下来（键按内容算，各机器通用）
```

- **一份结果由三样版本共同决定**：cv、语料库（册 yaml `corpus: N`）、字形库（`glyph_pin: N`）。标签缺省按这三样拼：
  `cv0.4.7-c1-g2-<改动名>`（`--change` 给改动名，不给用 UTC 时刻）；字形库没钉的写 `g-` 加人裁内容指纹前 6 位
  （如 `g-82293e`），语料库没钉写 `c-`。三样的完整值（含 cv 提交号、人裁指纹）另记在包的 `manifest.json` 的 `versions`。
  `--label` 给了就整个用它。标签只能用 ASCII 字母、数字和 `_.-`，中文会被拒。
- 包名 `products/<ws>/<册>/<标签>`，只增不改，同名拒绝：不同版本、不同开关的结果各存一份并存，任意两份都能取回 `products diff`。包里不带 `_prev/`。
- **main** = 这册当前的正式结果。`pack push --main` 或 `pack promote` 追加一条指针（`products/<ws>/<册>/main-ptr/<时刻>-<标签>.json`，只增不改，最新一条为准）；`fetch` 不给标签取 main。实验、试跑的包不标 main。
- `fetch` 目标已有该册产物时拒绝，`--force` 才覆盖，且先核完全部段的 sha256 才动本机产物。
- 取回的产物照常由引擎按指纹判新鲜：代码、参数、库变了的步照样过期，只重跑那些。
- 实验分支（`GUJI_DATA_BRANCH=exp/…`）上存取的是实验桶。
- **字形库内容版本靠中心库 rev 追**：`glyph_pin` 只钉指纹，不钉字形库内容。所以每条产物 manifest 另记跑时本机数据对应的中心库版本
  `db_rev`（`<工作区>@<分支>:<rev>`，取自数据目录的 `.central-state.json`，不进指纹）；存包时 `versions` 里记
  `db_rev`（存包时）和 `db_revs`（seed_admit 各页跑时的 rev 及页数），另记语料库底库号 `corpus_base`。要精确复现某份包读的库，
  从那个 rev 开 Neon 实验分支。拉过之后本机又裁了、还没推的改动不在 rev 里，正式重跑前先 `guji db sync`。
- **没存包会提醒**：`guji pipeline`／`step` 跑完、`guji status`、`guji close-check` 末尾，本机这册产物与最后一次存／取的包对不上时
  印一行「本册产物还没存进产物包」（只提醒，不挡；比的是各步 `_manifest.jsonl` 的摘要，记在 `<产物根>/<册>/.pack.json`，只打几步的包不算）。
- **实验记录写进工作区仓**（用户 10-20 定：工作区仓记录跑过哪些实验，配置和最终报告按标签分开积累，clone 的人都能看到；数据在中心库和 R2）：
  `pack push` 在 `<工作区>/experiments/<册>/<标签>.md` 写一页——基线（存包时的 main）、三样版本与中心库 rev、存包时的册 yaml、
  `--report <diff 目录>` 给的前后对比报告；开头是「摘要」：`--summary` 写的目的／改动／结论、自动的结果一行、各步最后一轮的起止时刻与耗时（每次存包都写，sheldon 10-20）；`promote`／`--main` 往页尾追「★ 标为 main」。只写文件不提交，跑实验的人提交到 guji-workspace。
  试存、测试加 `--no-record`。
- **训好的语言模型**（2026-10-20）：Step6 本机缓存没命中时**自动**去 R2 取 `derived/lm/<同名文件>`（要 `GUJI_DATA_TOKEN`，读令牌就够；核 sha256、原子落盘；没令牌、没这份、网络出错都接着现训，`GUJI_DERIVED_FETCH=0` 关掉）。推是**手动**的：`push-index` 顺带推（正式令牌）。文件名就是缓存键（语料内容 sha256 + 训练参数 + lm.py 代码指纹），所以取回的一定是同一份输入训出来的，不会拿错。

## 四、已有的、配合着用的

| 要做的 | 命令 |
|---|---|
| 看哪些步过期、为什么 | `guji status <册> --pages all`（过期原因：代码／参数／册配置／上游） |
| 只跑某些页 | `guji pipeline … --pages 3-6,9 --from <步> --to <步>` |
| 只重算点名的格（Step5-a 起） | `guji recheck <册> --chars 巳,已 | --verdicts unsure` 再 `guji pipeline … --from glyph_match` |
| 换了字形库版本，只重算受影响的格 | `guji recheck <册> --glyph-diff <旧号> [--dry-run --list]` 再 `guji pipeline … --from glyph_match`（见下第五节） |
| 只跑显式失效的页 | `guji rerun <册> --stale [--dry-run]` |
| 重跑前留一份「前」 | `guji snapshot make <册> [--steps …]`（本机拷贝）或 `guji products pack push`（存 R2） |
| 不动正式产物试参数 | `export GUJI_PRODUCTS_DIR=$SCRATCH/products`（沙箱），或 `guji exp run`（[exp_framework.md](exp_framework.md)） |
| 试会写库的功能 | 中心库实验分支（[datastore.md](datastore.md) 第六节） |
| 关掉格级复用（排查用） | `GUJI_NO_REUSE=1` |

## 五、换字形库版本后只重算受影响的格：`guji recheck --glyph-diff`

2026-10-24 起（A23）。改钉（`glyph_pin: N` → `N+1`）后 glyph_match 不判过期（库指纹是软参数），要吃新库得点名。
`--chars` 太粗（每格记了前 10 个候选，常用字一进新刻例就牵进三成的格），`--glyph-diff` 只点名判决可能变的格：

```bash
# 册 yaml 已改钉 g2；旧号给 1（或旧库文件路径）。先看点名多少
guji recheck vol08 --glyph-diff 1 --dry-run [--list] -w $WS
guji recheck vol08 --glyph-diff 1 -w $WS
guji pipeline keben_body_v2 vol08 --from glyph_match --to glyph_match -w $WS
```

- 判法（`ops/glyph_diff.py` 模块头）：本格及候选试切在旧库、新库里的 HOG 前 k 邻居（刻本库、整库各一份，连条目 id、字头、
  归一图、顺序）一样，命中条目没撤没改，候选字的人裁例数没跨共识门槛（已按共识升档的格例数不许变），近形决胜、形区分四对
  用到的那几个字的刻例没变——五条都满足就照搬旧记录，否则点名。差分只做粗排、不做弹性精验，比整册 5a 便宜得多。
- 新库不是册 yaml 指的那份（沙箱试验）：`--params '{"glyph_match": {"db_path": "…/new.db"}}'`，之后的 pipeline 也带同样的 `--params`。
- 实测（殿本 vol08，69 页 10,681 格；旧库 g1，新库＝g1 之后的中心库加 vol08 的 62 条人裁）：点名 716 格（6.7%，按字点名是 32%），
  其中 428 格重算后确实变了（判决或字变 17 格）；「点名格重算＋其余照搬」与「整册 5a 不复用全算」**逐格逐字节相同**。
- 前提：上一版 glyph_match 产物是对旧库判的，几何也没动（切分变了的格本来就由格级复用那套重算）。

## 六、字形库更新：谁做、怎么做

2026-10-24 起（Sheldon 定，A23）。起因：控制台裁一格当场就落进字形库，可批量补标、网站审校收割、各线程用脚本写的事件推进中心库后
没人跑落库消费者——10-22 到 10-24 攒了 967 条人裁确认，g1 快照里一条都没有，靠 A23 手工补落才出了 g2。分三步，各有主人：

| 步 | 做什么 | 谁 | 何时 |
|---|---|---|---|
| 1. 落库 | 人裁进字形库真源（中心库） | `guji db sync` 自动（下面）；A23 每天扫一遍落不成的 | 谁 sync 谁落 |
| 2. 出快照 | `guji glyph-db snapshot` 出 `g<N>`，推清单、`pin-verify` | A23 | 大波重跑之前，或攒够新刻例（约 500 条以上、或进了库里原来没有的字） |
| 3. 改钉 | 册 yaml `glyph_pin` 改到新号，`guji recheck --glyph-diff <旧号>` 只重算受影响的格 | 跑这本书的线程；冻结册由 Sheldon 定 | 跟 cv 升版、整册重跑一起换；审到一半的册不换；冻结册不跟 |

- **落库**：`guji db sync` 拉完合完，对未记账的人裁只跑 `glyphdb_admit`、`glyph_audit`（`feedback/auto_admit.py`），落了再推。
  逐条记账：消费者报错的（取不到字块、字形乱码、库里没有要改的条目）不记账，下次再试；绑定不可用、印章遮挡、`no_glyph_lib`
  照消费者口径记账。sync 输出里有 `left` 就是还有落不成的，多半是本机没有那一页的产物和字块缓存——到有产物的机器上 sync，
  或留给 A23 扫尾。A23 扫尾时报错的逐条看：乱码字形、改判冲突（如 A24 改判与 Sheldon 裁决相反）就问清楚再补事件。
- **出快照提速**（2026-10-25）：`snapshot-upload`、`pin-verify` 缺省只处理相对上一版新增或改动的条目（g3 实测 20,813 条里只核 143 条，2 分钟→5 秒），`--full` 全量。
- **出快照**：出之前在一两册上看 5a/5b 前后（`--glyph-diff` 点名比例、判决变了多少），写进 ai-team `domain/CV/经验.md`；
  出完不用挨个通知，跑书线程改钉时自己用。
- **改钉**：库指纹是软参数，改钉不让 5a 判过期，所以改钉和「要不要重算」分开定；改了就用第五节的 `--glyph-diff`，别整册重跑 5a。


## 七、新字快速确认：`scripts/build_newchar_review.py`

2026-10-25（A23）。大批重跑新书后待审格很多，其中**整理本字的字头在字形库里一例都没有**的格（新字），库没机会自己认出来。
人看一眼「整理本字对不对」、点一下，落库后这个字头就有了第一批刻例，之后别的页、别的册自动匹配。

```bash
guji source pull volNN -w $WS                   # 要有原图才出字块图（没有就加 --no-images）
python scripts/build_newchar_review.py collect --books vol06,vol07 --products-root <产物根> -w $WS --out /tmp/newchar
#   → cards.jsonl（卡冻结）、review.html（带图确认页，按 review-artifact 流程发布、点、收回）、summary.tsv、crops/
python scripts/build_newchar_review.py apply --cards /tmp/newchar/cards.jsonl --verdicts verdicts.jsonl --out /tmp/newchar -w $WS
#   缺省 dry-run，只写 events.jsonl 与 seg_issues/unclear/other.tsv；--execute 追加本机事件日志（带锚）；再加 --admit 本机落 glyph.db
```

- 「新字」＝ 整理本字在 `glyph.db` 的有效刻例数 < `--min-count`（缺省 1）；上下文护栏顶上来的格（`ctx_guard_ref`）黄底置顶，整理本字未必对。
- 卡上按钮：整理本字对／库首选／5b 候选（各写 `confirm`，`shape`＝所选字）；**切分有问题、看不清、另有其字不写事件**，分别列进 tsv 转切分线或回头补。
- 口径：只收意思相同的字，形近异义字（个/今、己/已/巳）不并，拆不开点「看不清」；脚本从不做归一。
- 推中心库（`guji db sync`）与出 `g<N>` 不在脚本里，要 Sheldon 点头；改钉归跑书的线程（见第六节）。
