# 3b 形近字组分析 `glyph_near`（事实与 schema）

只对触发了形近字组的格，按书配置挂的看图方法给组内各字一个**原始分**（`sims`）＋证据。不定字、不放行、不改 3a。
分 → p 在收尾 `glyph_analyzer` 按方法的校准表做（见 [收尾产物.md](收尾产物.md)）。代码：`steps/glyph_near.py`（触发、读图、落产物）、
`groups/near_methods/`（一方法一模块，2026-11-28 结构拆分 C5；对外名字一律从包根 `groups.near_methods` 导入）。

## 书配置

`params.glyph_near.groups.<组>`：`{ref?, chars?, fold?, trigger, delta?, topk?, gap?, methods: {方法名: 写法}}`。
`ref` 指登记表 `config/near_groups/v2.json` 的组（成员从表里来）；每组能挂哪些方法由登记表 `handling.methods` 管
（[形近字组登记表.md](形近字组登记表.md) 第三节；过渡期挂了不许的方法警告、跳过并计入 `PageNear.skipped_methods`）。

## 触发（`NearRec.trigger`）

| trigger | 什么格跑 |
|---|---|
| `member` | 3a 首位字在组里 |
| `close`（缺省） | 首位在组里，且组内另一字在 3a 前 `topk`（3）名、分差 ≤ `delta`（0.03） |
| `cands` | 3a 首位或前 `topk`（5）名里有组内任一字 |
| `guard`／`near_form`／`gap` | 只给保留伪组 `_guard`（near_knn）：3a 护栏 conflict／never_match、手工形近表字、没判 same（`gap: true`） |

一格可触发几个组，每组一条 `NearRec`（同格 id、`group` 不同）。读口：`PageNear.get(格, 组)`、`by_id_all()`；`by_id()` 只给按组 id 排第一条（旧行为，待 B5 去掉）。

各方法的 `evidence` 键、指纹算法、与原出处逐键对应的约定写在各自模块头（`groups/near_methods/<方法>.py`）。共同约定：
- `evidence` 一律以 `method` 开头，其余键＝原判法的返回值原样（同键同值同舍入）；读不到图 → `{error: "patch_missing", detail}`、`sims: {}`。
- 指纹：`method_fingerprint(方法, 写法)`＝`<方法>=<短哈希>`，进 `methods_sha`（`<组>:<方法>=…` 用 `;` 连）；4d 比对模型版本调同一个函数。
  `PageNear.models["方法:组"]`＝`model_sha`（方法的模型版本），收尾抄进 `near[组].methods[方法].model`。
- 方法的 `score` 声明了 `ctx`／`cells` 才传；`cells[]`＝`{id, page, col, slot, sub, patch_key, char, candidates, punct}`。

## 产物 `PageNear`

`{page, methods_sha, columns: [{col, chars: [NearRec]}], models: {方法:组: 版本}, skipped_methods?: [组:方法]}`；
`NearRec`＝`{id, slot, sub, group, trigger, methods: [{method: "方法:组", sims, evidence}]}`。
