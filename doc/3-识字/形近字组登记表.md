## 二、合并规则

- 注册字组表每组一条，组 id 照旧；
- 字对来源 1–4、6 按无序对去重，`src` 记全部来源。两个字同在某个注册组里的对挂到那个组（同在几个组就挂几个）的 `pairs` 下；
  其余每对单立一组，id 为 `p:<两字按码位序>`；
- 剔除名单里、又没有手工／人裁／刻形（shape）来源的对不收（同 `build_near_groups.py merge`）；
- 每组的处理方式 `handling` 先按缺省规则（＝现役行为）生成，再拿人定表 `config/near_groups/handling.json` 逐键盖（见第三节）；
- 仓里的表只用仓内来源（1–5）。书级来源（6、书配置里的 3b 组）用 `--pair-clf <书>=<文件>`、`--glyph-near <书>=<册配置>` 生成书级版本，
  放数据目录，不提交。

现版（仓内来源）：**620 组**＝注册 185 ＋ 单立字对 435；字对 573（手工 20、人裁 42、字体 78 全在 `near_groups.json` 的 572 里，另加刻形 1 对 之矣）；
按类型 near 298、variant 322（2026-11-28 起只分两类；组内带异体归并的 6 组 guan、hou、kgc、tsh、xz、zh 原先另记一类，现归 near）。带全唐文 pair_clf 的书级版本：669 组（多出 50 对没别处登记的）。

### 类型：只有 `variant` 与 `near` 两类（2026-11-28 Sheldon 定）

| 类 | 含义 | 例 |
|---|---|---|
| `variant` | 异体，同义异码 | 侣侶、寇𡨥、冊册 |
| `near` | 形近异义 | 凊淸、人入八、日曰、己已巳、官宫宮 |

注册组 kind=variant → `variant`，其余 → `near`（原先带 `families` 的 near_form 组另记一类，现归 `near`；组内异体归并照旧写在
`fold` 字段，3b 触发与 `glyph_near_spec` 读的就是它）。单立字对：`near_groups.json` 的 src 里有 `variant` → `variant`，否则 `near`。
人定覆盖：`config/near_groups/type_override.json`（`{对: {type, note}}`，只管单立字对组；2026-11-28 Sheldon 定 pair_clf 来的 侣侶＝variant、凊淸＝near）。
旧版书级表里的类型 `fold`，读口读成 `near`。
只改 `type`；现役读口（`NEVER_MATCH_FAMILIES`、`partners()` 等）按 src 派生、3b `expand_refs` 只取 chars／fold／books，都不读 type
（类型改两类前后取值逐项相同：`tests/test_near_registry.py::test_type_and_handling_feed_no_current_reader`）。
相似度口径不归本表：3a 里己已巳、日曰在相似度上折叠（同码即同形、异码即异形）是 3a 的事，不读本表的类型。

### 处理方式 `handling`（2026-11-28 Sheldon 定「每组自定」）

| 键 | 取值 | 含义 | 谁拥有 |
|---|---|---|---|
| `methods` | 方法名列表 | 本组**允许**用的 3b 看图方法（`groups/near_methods.METHODS` 的名字：cnn_small、rr_shape、wu_shape、hou_shape、part_shape、pair_shape、book_knn、near_knn、stroke_veto、flow_shape）；`[]`＝不做字形区分 | CV3 |
| `context` | true／false | 收尾走不走文意判断 | CV4 |
| `aspect` | true／false | 4d 宽高比（原 `fold_aspect` 窄宽判）一路开不开 | CV4 |
| `action` | `admit`／`evidence` | 看图结论（过门槛）可放行或改字，还是只出证据（送审）；文意一路由 `context` 管 | CV4 |
| `threshold` | null 或数 | 组门槛，缺省 null（CV4 填） | CV4 |

人定值写在**输入文件** `config/near_groups/handling.json`（`{"groups": {组 id: {要盖的键…, note}}}`，只写要盖的键；组 id 不在表里、
方法名不认识、取值不对，生成脚本报错），v2.json 是生成物不手改。没列的组按**缺省规则**生成（＝现役行为，`build_near_groups_v2.default_handling`）：

- `methods`：注册组里有 5a.2 字形方法（`shape_stage.shape_methods` 非空，80 组）→ `[flow_shape]`（结构拆分 A4，11-28），其余 `[]`；
- `context`：第四步 group_flow 的方法（`methods`／`review_methods`／`form_methods`）里有文意 `ctx` → true，否则 false；
- `aspect`：false（现役宽高比只有 seed_admit `_fold_pass` 对日曰一组，日曰在人定表里写 true）；
- `action`：group_flow 有看图解法（`groups/flow.IMG_SOLVERS`：ids、rr_img、yr_bars、bars、ss_bars、ry_shape、zy_strokes，外加读 3b 校准 p 的
  `near_p`），或 `methods` 里有现役第四步会因它放行／改字的 3b 方法（除 stroke_veto 只降审、near_knn 挂伪组外都算）→ `admit`，否则 `evidence`；
- `threshold`：null。

表里一组没写 `handling`（旧版书级表）时，读口给 `near_registry.DEFAULT_HANDLING`＝`{methods: [], context: false, aspect: false,
action: evidence, threshold: null}`（不配看图方法、不走文意、只出证据）。

## 四、读口

`near_registry.load(path=None)`；`reg.get(组)`、`reg.groups_of(字, types=None)`（注册组在前）、`reg.by_type(*类型)`（只认 near／variant）；
`reg.handling_of(组)`／`near_registry.handling_of(组)` → `{methods, context, aspect, action, threshold}`（收尾与 4d 读）；
`reg.resolve(groups, book)`／`near_registry.resolve(…)` → (展开 `ref`、去掉 handling 以外方法的 groups, 跳过的 [(书配置组, 登记表组, 方法)])；
