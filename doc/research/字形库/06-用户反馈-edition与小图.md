# 06 用户反馈：edition 与图太小（2026-09-25）

## 反馈一：「v2 这个是什么？应该是整个四库目录，是整一个新的 edition」

- 原来 `v2` / `vol01` / `bxgb` 各当一个 edition。其实它们只是**实例 id 前缀**，也就是字位坐标的命名空间：旧管线从 0 数、新管线从 1 数，人裁一律加 `v2:`。
- 改为**一本书一个 edition**：`glyph-db set-edition --edition X --apply`，把库里刻本字形并到一行一字。
  - 四庫 → `siku-zongmu`：523 个字原来在两个 edition 各一行，已合并。
  - 北行 → `beixing-guben`：139 个字合并。
  - 声明写进新的 `meta` 表，随 store 导出（`meta.jsonl`）。之后 `admit_instance` 新进的刻例自动归这个 edition；字体 `font:*` 与现代链 `modern:*` 不动。
  - 实例 id 与 `source_id` 没改。
- 总账页「来源（edition）」改成「版本与实例来源」：先写本书 edition，再逐个说明每个实例前缀是什么、有多少刻例、来路是什么。

## 反馈二：很多图里的字特别小（例：北行 歧）

有两个原因，都处理了：

1. **显示**：库里的 canonical 图，字本来只占画布三到四成（四庫 0.44、北行 0.30）。刻例图和字体图接口改为默认裁到墨迹外接正方形、四周留白（`?crop=0` 可取原图）。只改显示，不动库。
2. **数据坏了**：北行 09-20 00:25 那批 194 条人裁刻例，字高只有画布 0.16，笔画被啃掉，歧 的「止」旁几乎全没了。
   - 原因：09-19 已修了人裁进库时二值化的「纸缘留白」问题（`e75894d183`），但这批是修复后仍由旧代码进库的。
   - 用现成的 `scripts/repair_glyphdb_canonical.py` 从字块缓存重抽，修后字高中位 0.26，歧 字形完整。
   - 四庫同一检查只有 4 条偏小，看着是本来就小的字，没动。
