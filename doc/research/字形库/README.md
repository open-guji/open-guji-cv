## 二、分几层：三层，而且**没有跨书公用库**

**直接回答用户的问题**：
- 「公用库 + 每本书单独库」——**目前只有每本书自己一个 glyph.db**。字体字形（B 层）是「公用的料、各书各导一份」；
  **刻例的跨书共享库不存在**（cv-workspace-env 已记：要独立仓 + 升格命令 + 多 store 挂载，用户定「本书整理完才谈升格」）。
- 一个 glyph.db 里存什么：`sources`（来源/套元数据）、`instances`（每个字位的图块 PNG + 定的字 + 来路 `label_status`）、
  `glyphs`（每书每字一行：char / semantic / unicode_cp / **ids（全空）** / sparse|stable / 确认数）、`exemplars`（字→实例）、
  `admissions`（准入审计：provenance + 证据）、`derived`（特征缓存）；`pairs`、`events` 两表全空。

## 四、摸底时顺手发现的问题（都是只读查出来的，未改）

1. **四庫真源漂移**：db 里 v2 人裁 2,096 例，`glyph_store` 只导出了 1,276——**820 条人裁只在不进 git 的 db 里**（db 最后更新 09-16）。
2. **北行刻本没有真源**：1 GB 的 glyph.db 是唯一真源，无 `glyph_store/`（已知风险，导出一直是待办）。
3. **同一本书被拆成两套**：人裁进 `v2`、自动放行进 `vol01`/`bxgb`，是两个 edition_tag；四庫两套在 528 字、北行在 136 字上重叠。
   根子是 `edition_tag` 同时当「来源」和「套」用（roadmap §5.1 的 G8，未解）。北行还有 `sources.edition_tag='modern:bxgb'` 而 `glyphs.edition_tag='bxgb'` 对不上。
4. **`semantic` 字段脏数据**：四庫 v2 里 麗/袤/虞/墀/頌/耶/衷 的 semantic 是单个拉丁字母（l/m/y/x/s/y/z），像拼音首字母误写；
   `曰` 的 semantic 记成 `日`（两个不同的字）。
5. **码位缺失与正异并存**：眞 / 戸 / 别 / 別 / 竒 的 `unicode_cp` 为空；vol01 用 `别`、v2 用 `別`，同字两形分落两套，没有关系记录。
6. `ids` 字段全库为空；没有任何字段表达「这个刻例与所选 Unicode 字形完全一致，还是只是最接近」。
7. 已有体检（`audit.py`）只在四庫 vol01 跑过一次（2026-09-06，标出 635 例），`glyphdb_audit/audit_ok.json` 有白名单；北行从没跑过；跑出的 HTML 没进控制台。

### 原问题

2. 人裁（`v2`）与自动放行（`vol01`/`bxgb`）要不要并成一套、用 provenance 区分？**建议并**（01 卡详述），否则「本书字形总账」永远要两套拼。
3. 可信度分级的档位（04 卡给了三档草案）。
