## 〇、结论

1. **release 是「YOLO 粗切 + 大量人工整理」的成品，不是算法原始输出，质量很高。**
   - 全书 204 卷（卷首四 + 二百卷）16,516 个半叶，2,608,930 个字框，每框带一个字，其中夹注小字 86,266 个。
   - 文本是按刻本字形录的，卽、戸、彚等异体照录，114 种 PUA 码共 2,932 处。
   - 和 daizhige 逐列本比，**147,345 列里 99.39% 的列边界对得上**。逐字错位（多字或少字）只有 0.14%，而且大半集中在卷首二一卷；那一卷尾部的对齐分数很低，是 release 缺页还是评测定位不准，还没细查。
   - 拿 repo 里的模型直接跑 release 自己的底图：0/150 页和 release 完全一致；加了去版心、去碎框、去重这些轻清理，也只有 15/150 页一致。
   - 所以 release 是**人工修过的结果**，算法本身没这么准。
2. **同一批图上对比：列结构（每列切几个字）我们明显更准；单字框和整页召回两边打平；夹注、粘连字各有输赢。**

   | 指标（纯算法、不带人裁） | CV（我们） | YOLO 原生 | YOLO 轻清理 |
   |---|---|---|---|
   | **A. release 底图 150 页**（每卷抽 1 页）逐列字数全对 | **97.3%**（123/150 页整页全对） | 53.0%（0 页） | 73.3%（17 页） |
   | A. 单字框 P / R（IoU≥0.3，对 release 框） | 99.0% / 99.0% | 94.3% / 99.4% | 98.9% / 98.9% |
   | A. 夹注小字召回（IoU≥0.3） | **98.2%** | 95.2% | 91.8% |
   | **B. 我们 CADAL 底图 vol04/05 100 页**逐列字数全对 | **96.6%**（85 页） | 64.4%（1 页） | 83.6%（23 页） |
   | B. ＋release 列字数先验（§四-1 实验） | **98.2%（94 页）** | — | — |

   - 上表 IoU 按 0.3 算，是有意为之。release 框本身就是 YOLO 框修出来的，IoU 卡 0.5 时对 YOLO 有偏：我们 P/R 97.9/97.9，YOLO 轻清理 98.8/98.75。
   - 我们与 YOLO 的框口径本来就不同：CV 是格内墨迹紧框，YOLO 是整字大框。按 0.3 量，两边打平。
3. **两边的错几乎不重叠，这是能合并的根据。**
   - **我们剩下的错**：最多的一类是多切 1 字，占 B 组 31 个错列里的 13 个，抽看的几例都是横画字被拦腰切开（三→一+二、二→一+一）；其次是 Step1 整页列错位（vol04 p25、vol05 p55、p123）；还有夹注列的字数。
   - **YOLO 的错**：
     - 版心被当成正文列；
     - 碎框（框线、印泥）；
     - 版面框重叠后同一个字出两次；
     - 漏掉扁字、疏字（一、二、十、人、八）；
     - 列尾字漏检，B 组 47 个漏字里有 20 个是列尾字；
     - 低分辨率底图上的夹注。
   - YOLO 从不把「三」切成两半；我们的几何链从不漏「一」。
4. **合并机会**（详见 §四），按性价比排：
   - ① **用 release 的逐列字数当我们 Step3 的列字数先验**。在 B 组实测，全对列从 96.6% 升到 98.2%，整页全对从 85 页升到 94 页。现成的 `column-slots` 回流通道就能用，全书 14.7 万列都有这个数。
   - ② **release 当全书评测金标**。我们的切分金标现在只有 14–60 页，有了它可以扩到全书逐列字数，并且能对每册自动出报告。
   - ③ **release 当字形和识别的训练数据**。260 万个带字标签的字框、8,798 个字种，我们现在的字形库是 1.8 万条刻例。
   - ④ **YOLO 当 Step3 的第二意见**，专门复核「两格落进同一个 YOLO 字框」的情况，正好对上我们最多的那类错。这一条是 10-02 那篇第三节建议之外新增的。
   - ⑤ **反过来给对方用**：
     - 用我们的 Step1–4 出列、格、抬头、夹注结构，替掉他们大部分人工清理；
     - 用我们的整理本对齐替掉 yolo_tool 的线性灌字；
     - 用 release 重训他们的 YOLO（训练数据从 57 页扩到 1.6 万页，并且要分出独立的验证集）。

## 一、两边是什么

| | yolo_tool（对方） | open-guji-cv（我们） |
|---|---|---|
| 切分 | 两个 YOLOv8 检测：版面（v8m，6 类）→ 每个版面框裁条 → 单字（v8n）；几十行排序启发式 | 纯几何：版框/界行（含三段折线）→ 单列射影 → 弹性 DP 切格（格数 = 21+抬头）+ 缝切 + U-Net 判官 → 收框 |
| 训练/标定 | 57 页版面 + 109 根字条，多书混训，**val = train** | 四库 vol01–03 上标定的几何常数 + 人裁回流 |
| 先验 | 无（不知道每列多少字） | 每页 9 列、每列 21 格（硬约束），`period_prior` 等书级参数 |
| 语义 | 只有阅读序；夹注配对只在批量推理里有 | 格位 slot、抬头级数（负 slot）、夹注 a/b、留白格、读序 |
| 文本 | 「分配整书文本」按框数线性灌字，没有对齐 | Step5-d 整理本对齐 + 库匹配 + 上下文定字 |
| 本书覆盖 | **全书 204 卷 16,516 半叶**（release） | vol01–vol10（卷首一～卷二十，1,707 页），vol01–05 跑过全链 |
| 速度（本次 4 核 CPU） | 0.8 s/页 | 约 3.8 s/页（Step0–4，Step1 4 进程） |

两边底图不是同一份扫描：
- 我们的是浙大 CADAL 600dpi 版，约 2400×3085，1-bit。
- release 是另一份印本的扫描，像维基文库文渊阁四库全书 0001–0005 册用的影像：1298×1920，二值，噪点多，字距约 78.5px，我们是 115px。
- 逐字比对过，**两份是同一副版片**：字形、版心、鱼尾全同，只是印次和扫描不同，所以版式和列内字数应当完全一致。

## 二、release 数据本身

格式（`format_version: 2`）：

- 每卷一个目录：`<卷序>/pages/NNN.png`，加一个 `text.jsonl.gz`。
- `text.jsonl.gz` 首行是卷头 `{h,b,c,t,ps}`；之后每页一行，字段是 `x[] y[] w[] hgt[] c s`。
- `x,y` 是**左上角**坐标，`c` 是逐框的字，`s` 是 `[起点,长度]` 的小字段（夹注、小字「臣」之类）。
- 全书有 99 个空页，都是卷末空叶。

| 检查 | 结果 |
|---|---|
| 与 daizhige 逐列本（文渊阁本整理本，逐列校对）比列边界 | 147,345 列中 146,450 列吻合（99.39%）。不吻合的 895 列里，303 页是同页两列互换一个字（多在夹注列，部分是本评测按 x 聚列的口径误差），所以真实列准确率 ≥99.4% |
| 字级对齐 | 插入 3,622（其中 2,932 在卷首二：daizhige 那一段比 release 多出约 2.9k 字，卷尾对齐分数只有 48，是 release 缺页还是评测定位不准，未细查）；删除 45；替换 4,753（0.18%，多为异体和 PUA） |
| 每列大字数分布 | 众数 19（19 格正文 + 2 格抬头位 = 21 格）；20/21/22 分别是单抬、双抬、三抬（「聖祖仁皇帝」等）。抽查 22 字的列全是三抬，没有错 |
| 字↔框对应 | 抽看卷四十六 p9（夹注满页）、卷七 p62 等，逐框正确；夹注两行分得清 |
| 和我们 vol04/05 整册报告逐列对（401 页、3,510 列） | 列字数一致 97.3%；不一致的抽看下来**几乎全是我们错**：横画字切开、抬头首字漏、整页列错位、列尾「一」被当噪点。只有 release 列尾的「一」那几处起初疑似 release 错，看图证实是真字 |

**release 怎么来的**：
- 用 repo 里的两份权重跑 release 自己的 150 页，和 release 框的中位 IoU 是 0.904，可以断定框是 YOLO 出的。
- 但原生输出每页约多 10 个框：版心 571，框线和印泥碎段约 240，重叠版面框带出的重复字约 160。另外还有约 1 个漏框，多是单字列、夹注、扁字。
- 这些在 release 里都没有，可见每页都经过人工或另一套更好的后处理修整。
- 文字和 daizhige 几乎逐字相同，含 PUA，可见是「整理本按框灌字 + 人工修框，直到两边对齐」。
- **对我们来说，它就是一份全书规模、按列核过的切分金标。**

## 三、同图对比的细节

### 测试 A：release 底图 150 页（每卷抽一页，正文页，≥120 字）

- CV：图放大 1.465 倍到 period≈115，重新二值化，册配置只给 `expected_cols: 9`、`chars_per_line: 21`、`period_prior: 115`。**不带任何人裁，不调参。** 150 页全部过闸，Step3 没有拒列。
- YOLO：原图（1920 高，正是 yolo_tool 自己渲染的尺寸）原生喂法，参数照 GUI（conf 0.25，iou 0.45）。
- 「轻清理」是本评测替使用者做的最小人工：
  - 删掉版心列（midText，以及贴页边、宽度小于中位列宽 0.7 倍的窄条）；
  - 删掉 conf<0.4 的框，和面积不到全页中位面积 0.25 的碎框；
  - 跨条做 NMS（IoU>0.5）。
- 夹注列与正文列分开看：
  - CV 错 37 列，其中正文列 19 个（共 1,241 列），夹注列 14 个（共 113 列）。
  - YOLO 轻清理错 362 列，其中正文 301 个、夹注 61 个。
  - YOLO 的列是用它自己的版面框按水平重叠聚出来的，夹注列上可能吃一点口径亏；按框计的夹注召回不受这个影响，同样是 91.8% 对 98.2%。

### 测试 B：我们 CADAL 底图 vol04/05 各 50 页（与 release 页面文本匹配度 ≥0.9 的正文页）

- 真值：同一页 release 的逐列字数。两份是同一副版片，列内字数一致。
- 页面对应靠全文对齐，`cmp_md.py` 401 页全部对上。
- CV 错 31 列，分布如下：
  - 正文列多 1 字 13 个，抽看 4 个都是三、二被切开；
  - 列错位或列数不符 3 页，vol04 p25、vol05 p55、p123；
  - vol04 p216 是登记过的拆页缺陷页；
  - 夹注列 6 个。
- YOLO 轻清理的错以「少 1 字」为主，正文列 59 个。47 个漏字的去处：
  - 列尾 20、列首 12、列中 15；
  - 漏的多是一、二、十、人、八这类扁、疏的字；
  - 47 个里有 15 个是轻清理的面积阈值删掉的「一」；原生输出里在，但原生输出同时带着几百个碎框。

## 四、合并机会（按性价比）

| # | 做什么 | 依据 / 实测 | 代价与风险 |
|---|---|---|---|
| 1 | **release 逐列字数 → Step3 列字数先验** | B 组把 21 个错列的字数写成 `column-slots` 裁决（n_slots = 现格数 − 多出的字数），重跑 Step3–4：**15/21 列修好，抽图证实「三」「卷三」「十三」整字成框**。列准确率 96.6%→98.2%，整页全对 85→94。没修好的 6 列是列错位页（先验救不了）和夹注列（夹注两小字占一格，字数换格数不能这么简单相减） | ① 要有页对齐：全文对齐已现成，401/401 页对上；② release 自身约 0.6% 列不准，只采信与 daizhige 列边界一致的列；③ 不该冒充 `human` 裁决，应另起 `label_origin`（例如 witness），并定好与人裁的优先级；④ 夹注列要按格算，不能按字算 |
| 2 | **release 当全书评测金标** | `evaluate.py test-a/test-b` 已经能对任意一册给出逐列字数报告。现在切分金标只有 14 页边框、60 页列切、几百条粘连裁决 | 做成 `guji eval` 的一个指标，数据放 open-guji-dataset；注意 release 底图与我们底图分辨率不同 |
| 3 | **release 当字形 / 识别训练数据** | 260 万带字字框、8,798 字种、夹注 8.6 万；字形库现有 1.8 万条刻例。两条路：① 直接用 release 底图裁片训 CNN 候选，字距 78px、噪点多，可当增强；② 在两边列字数一致的列（约 97%）按格序把 release 的字转到我们的格上，大批量给字形库播种 | ① 是不同扫描，要先量跨扫描的效果；② 走 seed_admit 的准入闸，不能直接进库；PUA 要配码表（release 用 U+F10xx 私用区，daizhige 记作〓） |
| 4 | **YOLO 当 Step3/Step4 的第二意见** | 同列相邻两格同落进一个高置信 YOLO 字框，就标「疑似横画字切开」送审或自动并格，正对我们最多的错。10-02 那篇的列探测、夹注旁证、收框复核三条闸照样成立 | 要 onnxruntime 或 torch；印章页关掉；先在 vol01–05 量召回和误报 |

| 6 | **用 release 重训 YOLO** | 现模型只训了 57 页 / 109 条，而且 val=train；release 有 1.6 万页现成标注 | 对方的事。训出来的四库专用模型，对第 4 条也更有用 |
| 7 | **格式打通** | yolo_tool 的工程 JSON 已并进 guji-page v0 §九；release 的 `format_version 2`（逐卷 jsonl.gz）还没有导入器 | 小活：写一个 release v2 → guji-page / 我们产物格式的导入器 |

### 四-4′ 补测：原生 YOLO 并格闸（10-19，用户定「今后只有原生输出」之后）

**闸**：同列相邻两个正文格的紧框，各有 ≥cover 的面积落进同一个 YOLO 字框（conf≥conf），这一列就标「疑似多切」。
- YOLO 用原生输出，不做任何清理；
- 加一个条件：YOLO 框高 ≤1.3 × 本页 YOLO 字框中位高。YOLO 偶尔把两字并成一个约两倍高的框，「三」被我们切开时它给的是一个正常高的框。

| 设置（测试 B，CADAL 底图 100 页，纯算法基线） | 抓到多切列 | 误报列 |
|---|---|---|
| cover≥0.6、conf≥0.5，不限框高 | 12/19 | 7（1 个其实是我们的错：「二」切成一+一，但列字数碰巧对上；6 个是 YOLO 两字并一框） |
| cover≥0.6、conf≥0.5、框高≤1.3×中位 | 12/19 | **0** |
| cover≥0.5、conf≥0.25、框高≤1.3×中位 | **13/19** | **0** |
| 同上，测试 A（release 低分辨率底图 150 页） | 3/23 | 0 |

**自动并格**：触发几对就把该列格数减几，写成 `column-slots` 后重跑 Step3–4。
- 逐列全对 96.6% → **98.0%**，整页全对 85 → **93**；
- 13 列修好，**原来对的列新错 0**；
- 和 release 字数先验（98.2%、94 页）几乎一样好，而且**不依赖 release，新书也能用**。

局限：只在殿本 100 页上量过；测试 A 的低分辨率底图上只抓到 3/23，说明对扫描质量敏感；模型更新后阈值要重标。脚本：`research/yolo_release_compare/gate_merge.py`。

## 五、口径与局限

- release 框是 YOLO 框修出来的，**拿它当框金标对 YOLO 有利**。所以框级同时报 IoU 0.5 和 0.3，结论以逐列字数为主，逐列字数与框口径无关。
- 测试 A 把 release 底图放大 1.465 倍喂 CV，是「同一书、换扫描、只调一个尺度」的情形，几何常数一个没改。YOLO 用原尺寸，是它自己的工作尺寸。
- YOLO 的「轻清理」规则和阈值是本评测定的，代表一个勤快的使用者大致会做的事，不是 yolo_tool 的功能；原生和清理后两列都报了。
- 第 1 条实验只给**已经错的列**写了先验。真正上线要全书写，对的列写进去应当不变，这一点未验证。另外这次用的是 release 的数，所以是「先验来源可靠」的上限。
- 文本层面 release 和 daizhige 同源，比文字准确率是循环论证，本篇只用它比列边界和字数。
- 测试 B 每卷只有 50 页，夹注列只有 70 列，夹注那一行的数字置信区间很宽。

## 六、复现

```bash
# release：file_archive release siku-qiefen 的 96mid1ogzk.zip 解压
export SIKU_RELEASE=.../96mid1ogzk GUJI_WS96=.../guji-workspace/96mid1ogzk-欽定四庫全書總目武英殿刻本 YOLO_TOOL=.../yolo_tool

python evaluate.py dzg                      # §二 release/ours 对 daizhige
python evaluate.py make-ws-a /tmp/wsA       # 测试 A 工作区（150 页，种子固定）
guji pipeline keben_body_v2 A --to cell_shrink --pages all -w /tmp/wsA
python run_yolo.py /tmp/wsA/yolo_items.json yA.jsonl   # 或直接用 results/yA.jsonl.gz
python evaluate.py test-a /tmp/wsA yA.jsonl
python evaluate.py make-ws-b /tmp/wsB       # 测试 B（不带 feedback = 纯算法）

python run_yolo.py /tmp/wsB/yolo_items.json yB.jsonl
python evaluate.py test-b /tmp/wsB yB.jsonl errB.json

```
