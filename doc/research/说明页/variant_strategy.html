§0一頁結論

骨架已經對了，缺的是三樣東西。對的部分：AdmitRec 分 char（刻本形）/ reading（文意）兩欄，整理本字永遠不覆蓋 char；準入十條通道全部在 vmap.semantic() 空間比較；人裁事件帶 shape / reading / conversion；關係圖 config/variants/variants.json（47,935 字、47,181 邊、12 個來源）已入庫；釋義表 gloss.json 69,835 字；_char_hint.std 已會「在異體組裡找整理本實際用的那個」。

語義層默認表只有 21 行

VariantMap 讀 config/dicts/variants.tsv（手工 21 行）；2,727 條自動表在 config/charset/ 沒接、只用 Unihan、比關係圖舊。

後果：髪/髮 䙝/褻 㕔/廳 鍾/鐘 與已解決的 卽/即 㫖/旨 彚/彙 同一機制，卻仍在燒人審——剩 7 條人審裡 4 條是它。

沒有「本書用字賬」這一層

字形套方案層 4 寫了設計，未落地；E5 是手算的 6 組。

後果：同一異體每次出現都當新問題；無法量「這本書用哪個形」。

義定了、形沒定時會靜默歸一

_pick_char：庫 unsure + 文本兩路一致 → char = align_char。刻 髪、OCR 讀 髮（字典偏通行字）、整理本 髮 → 存 髮，字形庫錯標一例，後續 髪 實例繼承錯。

現在沒發生只因語義表小；一擴表這個洞就打開，所以擴表必須與新狀態同時上。

方案一句話：三層表（關係層 → 本書用字賬 → 語義層派生）+ 準入加一個狀態「義定形未定」+ 按組審閱。人審率預期從 1.1% 再降（4/7 異體橋消失），字形保真率變成可量的數。

§1原則與邊界

1.1 三種關係必須分開，這是全文的基礎

T1 · 純異體
髪髮 卽即 㫖旨 彚彙 㕔廳 无無
同一個詞的不同寫法，任何語境可互換。語義層可合併；準入可橋。
T2 · 互通 / 一對多
鍾鐘 注註 后後 于於 囘→回迴
各自是正字，只在某些義項互通，或一形對多個正字。不可全局合併；可橋但 reading 取整理本字。
T3 · 形近 / 通假 / 古文
己已巳 人入 日曰 上二 王玉
不同的詞；或字典收錄但刻本不會用的關係。永不橋。界面紅色「形近·非異體」。

關係圖裡的來源標籤不能直接對應到這三類——twedu 既給 㕔~廳（T1）也給 上~二（T3 古文），unihan:kSemanticVariant 既給 䙝~褻（T1）也給 子~只（T3）。來源白名單只是第一道粗篩，真正的分類器是本書語料（§3）。

1.2 Unicode 邊界

  • 現階段只記 Unicode 已收字（含擴展區，𠮓 U+20B93、𨽾 都已在庫）。
  • 未收字三條出路：① IDS 文本錨（字形套方案層 5 已定，唯一對口的通用機制）；② IVS（Unicode 官方「同碼位異形」機制，IVD 登記很重，私用 IVS 互操作差）；③ 字形庫原型本身——圖像就是最忠實的記錄，glyph.db 已在做。建議：未收字 = 圖像 + IDS，不造 PUA。
  • IRG 的 UCV（可認同部件變體）決定了哪些差異不會有獨立碼位（者有無點、辶一點二點）。這類差異只能活在字形庫的圖像層，碼點層不可能「忠於刻本」到這一級——這是邊界，不是缺陷。
  • 不做 NFC/NFKC 歸一：兼容區（U+F900–FAFF）會被折疊到統一區。待核：全倉 grep unicodedata.normalize。

2.2 一對一 vs 一對多：沒有現成的乾淨表，只能自己算

  1. 沒有任何公開資料庫直接標「一對多」。要自己算：一個形在 T1/T2 邊下連到 ≥2 個整理本用字，就是一對多。本書實測：字形庫 18 個整理本沒有的形裡，2 個一對多（囘→回/迴、蓋→葢/盖）；整理本自身多形的組 362 個。
  2. 一對多有三種來路，處理各不同：簡化合併（发→發/髮、后→後/后）與繁體刻本無關，但簡繁邊把它帶進了圖，必須排除出準入橋；義項互通（鍾/鐘、注/註）兩邊都是正字，整理本 注 748 / 註 526 並用，說明它在區分，這時整理本字是形的證據；古文/篆文異體（上/二、人/几、王/玉）字典真有、刻本不會用，只有本書語料能過濾。
  3. 「明確的規範化繁體字」有兩個候選，建議都存：canonical——跨書統一鍵，取教育部正字（twedu 方向），沒有時取整理本用形裡碼位最小的；reading——本書文意字，取整理本實際用形。兩者常不同（教育部正字 蓋，本書整理本 葢 ×791、蓋 ×0）。
  4. 方向信息原始文件裡有，現在的構建把它丟了。twedu、hydzd 都是正字在前；build_variants.py 只存 ord(a)<ord(b) 一側的無向邊。重建時保留每條邊的 (正字, 異體) 方向與來源。

2.3 關係圖現狀的兩個問題（實測）

  • HIGH_CONFIDENCE_SOURCES 對準入橋過寬。用它給字形庫 1,958 字種分組，「本書刻了 ≥2 種形」的組有 99 個，大半是假的：四×86/肆×6、二×40/上×40（twedu 古文）、人×69/几×1、王×18/玉×10、子/祇/祗/只、後/后、乾/干（簡繁）、來/勅、某/私、藝/芸（只有 yitizi）。真異體組（卽/即 18/15、彚/彙 11/4、畧/略 15/1、歷/厯 14/1、註/注 12/6、鑒/鑑 11/7、製/制 10/7、抄/鈔 13/4、迹/跡/蹟）混在裡面。
  • 自動表 config/charset/variants.tsv（2,727 條，只用 Unihan，語料限定）對本書 12 個可橋的刻本特有形只覆蓋 7 個，漏 彚 㓂 㕔 厯 𠮓——它建於關係圖之前。應改為從關係圖派生（§3.4）。

  1. 保留方向：邊存 (正字, 異體, 來源)，ord 排序只做去重。

五個用處：(a) 準入先驗（§4）；(b) 候選排序（本書常用 卽 就把 卽 排前）；(c) 默認 reading；(d) 新書按時代/版本繼承最近的賬當初值；(e) 直接導出為研究數據——「武英殿本《四庫總目》異體用字表」本身就是可發布的成果，每冊跑完自動更新。

規模感：字形庫 1,958 字種裡只有 18 種是整理本沒有的（59 例），60 頁挖出 21 個異體組，整冊估 100–200 組。賬本很短、很尖，這決定了 §4 的人審成本是 O(組數) 而不是 O(字次)。

3.3 整理本作為校驗器

整理本不是全歸一的，是半歸一的。對刻本用到的 1,851 個組：整理本只用 1 種形的 1,489 組，用 ≥2 種形的 362 組（注/註 748/526、於/于 3055/171、无/無 41/1370、攷/考 31/1256、疎/疏/踈/䟽、弁/辨/辯、据/據 17/541、鑒/鑑…）。這個劃分決定了整理本字能當什麼證據：

組的 ref_policy整理本字能證明什麼形從哪來準入要求
single（1,489 組）只證明語義；整理本自己不區分形，髪/髮 一律印 髮只能來自圖像（庫 same / 組內定形器）語義兩路一致即可橋；形另定（§4.2）
multi（362 組）語義 + 形（它在區分，印 註 就是 註）整理本字兼作形證據要求精確一致；不一致時只有賬本裡有人確認過的轉換對才橋
  1. 確認我們的異體判斷：橋放行的每一對進賬本；賬本裡出現關係圖裡沒有的對 → 三選一（新異體 / OCR 錯 / 整理本錯）進審隊列。現役 38 條裡 㫖→旨 就是「關係圖沒有」（UCV 認同形），靠手工表兜的。
  2. 推斷整理本的凡例：ref_policy 就是整理本對每組的取捨，可導出成表，反過來給整理本做校勘（无/無 41:1370 多半是漏改）。
  3. 分層報數：align 金標與整理本同源，驗異體橋必須用 human 層（273 條）單獨報。

3.4 語義層派生

config/dicts/variants.tsv 改為生成物：從關係層取 T1 邊 + 賬本裡人確認過的 T2 對，方向 = 整理本用形（single 組）或不派生（multi 組：注/註 各算各的）；一對多形（囘、蓋）不派生；手工 21 行留作 override。LM 收益小但方向正確：髪/髮 等計數合併，n-gram 不再被同詞分票。glyph_layer_immutability 硬斷言不動。

§4準入：保留異體的同時提高自動率

4.1 現役唯一的系統性漏洞：首例靜默歸一

_pick_char：庫 same → char = 庫形（對）；庫 unsure 且整理本通道放行 → char = align_char。註釋裡的理由成立（unsure 時庫 top1 不可信，敷/數 那 8 條實錘），但它默認「整理本形 = 刻本形」。對 single 組這個假設必然錯在首例上：

刻本刻 髪（庫裡還沒有 髪）→ 庫 unsure
OCR 讀 髮（字典 15,907 字含 髪，但模型偏通行字）
整理本 髮
→ dual 放行，char = 髮        ← 字形庫多一個錯標的 髮，下一個 髪 實例繼承它
現在沒發生，只因為 VariantMap 太小、這些位都落人審了。把語義表擴大而不補這一步，等於把人審換成靜默錯標——這是保真最要防的事，也是本文所有改動必須一起上的原因。

4.2 新狀態「義定形未定」（semantic-fixed, form-open）

進入條件現有通道判「語義兩路一致、可放行」（dual / match_ref / match_replace / match_margin / match_ref_weak）且 庫 ≠ same 且 組內候選形 ≥ 2（組 ∩ (賬本 book_forms ∪ OCR 字典 ∪ 字體模板集)）
處理組內定形器：現成的三源檢索（HOG 0.5 / CNN 分類頭 1 / embedding 3，第五輪 checkpoint）限定在組內 2–4 個形之間。closed-set 比開放集容易得多；本書原型（glyph.db exemplar）優先於字體模板
自動放行margin ≥ τ 且 該形在賬本 book_forms 裡已有人確認 ≥ 1 次 → 放行，channel = variant_form，reading = 整理本字，產物打 form_auto 標記可審計
人審（一次）該形是本書首次出現 → 組視圖人審；確認後賬本 +1，之後同形自動
人審margin < τ → 組視圖人審

multiunsure—現役行為（整理本字兼作形證據，精確一致才放）
任意涉及 己已巳—always_review 不變
任意對在 T3 / NEVER_MATCH / 借用—不橋，走現役形近路徑

4.4 護欄一條不動

己已巳 always_review；NEVER_MATCH_FAMILIES（手工 20 對，每對有案底）；SEMANTIC_MERGED_PAIRS 只有 (已,巳)；kSpoofingVariant / hydzd-borrowed 永不進；OCR 永不投票；match_precision ≥ 0.999；glyph_layer_immutability。新通道 variant_form 是第三路證據（形狀）補在文本兩路之上，不是替代。

§5審閱界面

現有卡片已有：圖塊、庫/OCR/上下文三路、候選按鈕 1-3、shape/reading 雙值（只對己已巳顯示 reading 框）、「查候選」（字體模板 + CNN 融合 10 個，帶釋義與整理本對應字）、dwell 計時。下面都是增量。

5.1 組視圖（新頁「異體」）——首例確認與保真抽審都在這裡

一組一屏：列 = 形，格 = 圖塊縮略圖。頂欄：語義字 · 釋義 · 整理本用形與頻次 · 本書各形計數 · 關係徽記。每格默認在系統判的那一列。操作：Enter 整組照準；點格 → 換列；N 非此字；1–4 把焦點格移到第 k 列。輸出沿用 confirm 事件協議，不新造。組按「含首例形」「待審數」排序。

一個 5×10 的網格人眼幾秒就能掃出異類，比逐卡快一個量級；這也是 §4.5 字形保真率的抽審台。

5.2 單卡增強（只在「義定形未定」時變樣）

  • 候選只列組內形（2–4 個大按鈕），每個帶：本書原型縮略圖（glyph.db exemplar；沒有就字體渲染）、本書計數「髪 ×17」、整理本字徽記、釋義、關係徽記（異體 互通 形近·非異體）。
  • 默認焦點 = 本書慣用形，Enter 接受；reading 默認整理本字，非己已巳折疊顯示、不強制填。
  • 去掉拼音/碼點（用戶 2026-09-05 已定）。
  • 形近對卡上明寫「形近·看字形」，異體對寫「異體·同義·本書慣用 X」——兩類問題人要用的判斷完全不同，界面必須先告訴人是哪一類。

5.3 卡片 API 加字段

/api/review/cards 每張卡加：align_char、reading、state（semantic_fixed 等）、group: {canonical, forms: [{ch, book_n, ref_n, exemplar_url, tier}]}。數據全部來自賬本 + glyph.db，不新增計算。

5.4 計時

dwell 已有；組視圖按組計時，報「每組秒數」與「每格秒數」。UI 改動唯一的驗收指標是它。

§7風險與口徑

  • 組內定形器對只差一筆的形（髪/髮、鑒/鑑）分辨力要實測，closed-set 容易但不是免費的；沒數字之前 τ 取高，寧可多進組視圖。
  • 整理本自己的錯（漏改、誤改）會進賬本；賬本按 human / auto 分列來源，報數分層。
  • 一對多形（囘、蓋）：LM 不歸一、reading 按整理本、char 按圖。
  • 賬本是先驗不是規則：本書 髪 ×17 不禁止第 18 次刻 髮，只是讓它進組視圖而不是自動放行。
  • 報數紀律照 step5_step6_benchmark §4：成對報、帶基線、align/human 分層、語料挖洞。
