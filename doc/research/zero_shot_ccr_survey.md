## 二、逐篇核心内容

### 2.1 RAN（Zhang, Zhu, Du, Dai；中科大；ICME 2018；arXiv 1711.01889）

- **问题**：汉字 >2 万类且持续新增，整字分类器只覆盖约 4 千常用字。GB13000.1 的
  20,902 字只由 560 个部首构成 → 把分类改成"生成部首序列"，天然能认没见过的字。
- **方法**：cjk-decomp 拆出前缀式 caption（如 `a { stl { 尸 d { 龷 八 } } d { 几 又 } }`），
  词表约 390。全卷积 VGG14 编码；两层 GRU + **覆盖注意力**（累积注意力图过 5×5 卷积
  喂回能量函数，抑制部首重复/漏解码）逐 token 生成；beam=10，与真值精确匹配。
- **数字**：宋体 26,079 字，训练 2k 字 → 未见字 55.3%，5k → 77.3%，10k → 85.1%（5k 后
  每千字只涨约 1 点）。少样本字体：测试类只在 1 种新字体上见过时，RAN 80.7% vs
  整字分类 23.4%。无基线、无消融。
- **局限**：单一宋体干净图；生成的序列可能对应不存在的字；一字多种合法分解没处理；
  部首粒度由 cjk-decomp 决定（龷、丆 这类非直觉构件）。
- **对我们的意义**：奠基了"部件共享 → 未见字可认"的思想；其"训练子集必须覆盖目标
  字全部部首与结构"的前提，正是我们 §四要量的东西。生成式路线本身不用再走。

### 2.2 CCR-CLIP（Yu, Wang, Li, Xue；复旦；ICCV 2023 Oral；arXiv 2309.01083）

- **问题**：文本行识别里零样本字不可避免；FC 分类头遇到新字要改字表重训；RAN 系
  序列解码太慢（567–1666 ms）塞不进文本行模型。
- **方法**：文本侧 IDS 递归展开到叶节点（仓库表 27,533 字、976 token，含 CDP 私用区
  部件），12 层 Transformer 编码取 END 位置；图像侧 ResNet-50 全局池化；双向 InfoNCE
  对齐，另加**同 IDS 标签图像互为正样本的图-图对比 L_I**（压字体风格差异，λ=1；
  公开代码没实现）。推理：候选字表全部预编码成矩阵 P，一次点积。文本行阶段只把
  P 当冻结分类矩阵换掉 FC 头，再加原型正则 β‖p_y − f‖²。
- **数字**：HWDB 字零样本 21.79 → 72.98（m=500 → 2755），比当时最好的 CUE 平均高
  28 点；加印刷模板 93.80 → 95.73。**部件零样本只有 11–17%**。分解粒度消融：字 /
  部件 / 笔画 = 96.83 / **97.18** / 92.74（笔画"过细难感知"）。
- **局限**：零样本只对"已知部件的新组合"有效；候选字表必须预先给定，**IDS 表覆盖
  不到的字进不来**；竖排要旋转；字体数、参数量未报。
- **对我们的意义**：核心可搬的是"**文本侧编码器把 IDS 变成向量，作为没有任何图像
  的字的锚**"——这是六篇里唯一能处理"没字体、只有拆字"的机制。

### 2.3 Hi-GITA（Zhu, Yu, Wang 等；复旦同组；arXiv 2505.24837，2025-05；未收录，无代码）

- **问题**：CCR-CLIP 只用部首、只用 [CLS] 全局相似 → 部首零样本做不了。例：臀 认成
  臂；团 里的 大 vs 才 手写形似，但笔画序列（横撇捺 vs 横竖撇）能分。
- **方法**：文本侧两条序列——401 部首 + 12 结构符的 IDS，和 **5 类笔画**（横竖撇捺折）
  序列（最长 50，来自 RSST）；各 3 层 Transformer 独立编码后做对称交叉注意 + 拼接
  自注意。图像侧 ResNet-50 三尺度（1/8 笔画、1/16 部首、1/32 结构）互加。对齐用
  token 级单向匹配（FCC-M），结构 token 单独对结构图；四粒度四项对比损失，笔画权重
  1、部首 0.1；InfoNCE **排除 batch 内同字重复正例**。推理只用 refined stroke。
- **数字**：HWDB 字零样本 45.34 → 85.38（比 CCR-CLIP 均值 +18.9）；部首零样本 31.13
  → 44.18（CCR-CLIP 11–16）。消融里最大一步是 token 级匹配（+11.8 / +16.2），其次是
  文本侧交叉注意（+9.6）；**去掉结构 token −11 点，只留结构 token 1.3%**。
- **局限**：没有"单部首 vs 双粒度"的直接消融；5 类笔画很粗，碰撞未讨论；无代码、无
  速度；测试仍限 3,755 常用字，**没碰真正的生僻字/异体字**；笔画序列来源没写。
- **对我们的意义**：两条实证——结构 token 值 11 点、token 级对齐值 12 点——比"笔画"
  本身更有用。笔画序列需要额外数据源，且未编码异体字得手工写笔顺，门槛高。

### 2.4 CoLa（Shi, Yu, Li, Xue；复旦同组；arXiv 2506.03798，2025-06；Under review，无代码）

- **问题**：对人工分解的批评——同一视觉特征在不同字里被拆到不同部首；笔画法过细；
  CCR-CLIP 仍"通过人工定义的表示学特征"。最有说服力的证据是 Figure 4：**刻本字
  陽 被 IDS 拆成 6 个以上元素，與 的 IDS 含两个无 Unicode 编码的 CDP 部件**，而
  CoLa 只给 3 块粗区域；瀕 的第一块整体对应 頻（层级停止）。
- **方法**：3 个 Slot Attention 潜在组件（128 维高斯），重建目标不是像素而是冻结
  DINOv2 教师特征；损失 = 重建 + λ·潜空间原型分类（每类 10 张字体渲染的 slot 均值）。
  **训练完全不用 IDS**。推理：欧氏最近原型，9 ms。输入 80×80。
- **数字**：HWDB 字零样本 **68.59** → 82.71（m=500 时比 CCR-CLIP +46.8）；部首零样本
  70.40 → 75.78（CCR-CLIP 11–16）；**历史文献扫描 57.37 vs CCR-CLIP 22.36**。无消融。
- **局限**：缺最关键对照——去掉 slot、直接用教师特征做图-图模板最近邻。CCR-CLIP 是
  图 ↔ 文（IDS）匹配，CoLa 是图 ↔ 图（字体渲染）匹配，**增益多少来自"组件"、多少
  来自"换成图像模板 + 强预训练教师"分不开**。历史文献数据集不可复现。
- **对我们的意义**：CoLa 的设定就是我们现在的设定（锚 = 字体渲染图）。它的大幅领先
  与其说证明了"潜在组件"，不如说证明了"图-图模板检索 + 好的视觉表征"这条路对——
  这正是我们 embedding 检索比分类头高 8 点的原因。它无法处理"没图只有 IDS"的字。

### 2.5 GL-HPN（Cao, Xu 吉林大学；Diao UCL；arXiv 2605.08814，2026-05；无代码）

- **问题**：CCR-CLIP 整图整句一个向量，局部部件差异被平均掉。直接套 FILIP 的 patch
  级匹配又有两个新问题：IDS 里的**结构算符 token 没有视觉实体**（热图空间散乱），
  引入噪声；细粒度交互随候选数线性增长，3,755 类做不起。
- **方法**：共享 ResNet-50，两个投影头。全局分支 = CLIP（算符保留）；局部分支 =
  FILIP 式 patch ↔ token 最大响应，**结构算符硬掩码剔除（SFM）**。推理两级：全局
  向量取 Top-K（K=50），只对 Top-K 算局部分数，两者 softmax 后**相乘**。损失课程式：
  前 25% epoch 全局局部等权，之后全局降到 0.2、局部升到 2。
- **数字**：HWDB m=500 时 36.19（CCR-CLIP 21.79，FILIP 基线 34.54），m=2755 时 80.04
  略低于 GRSTR 80.62。消融：加全局分支但不掩码算符**反降** 0.35，加掩码 +2.0。
  层级推理 K=30 起与全量同分，13 倍提速——**省算力不提精度**。
- **局限**：只测手写；+14 点的大头来自 FILIP 局部对齐，双分支 + 掩码本身只 +1.65；
  硬掩码让局部分支完全丢掉空间关系。
- **对我们的意义**：两条工程模式——"粗召回 → Top-K 精排 → 后验相乘"，以及
  "结构算符只进全局、不进局部"。前者跟我们 RRF 三源融合是同一思路的升级。

### 2.6 EASA（Luo 等；深圳大学；arXiv 2602.03913，2026-02；README 称 PR 录用；开源无 license）

- **问题**：IDS 扁平序列每个部件等权，口/亻/日 这类高频部件淹没稀有判别部件
  （货/贷 混淆）；cosine 对齐丢层级拓扑（呆/杏 同部件不同布局）。
- **方法**：部件自信息 H(r) = −ln P(r)（训练语料频率，约 2–9 nats）**乘进位置嵌入**；
  IDS 解析成二叉树，节点按深度和分支位生成正弦嵌入，父视角（根到节点路径）、子视角
  （子节点均值）两路聚合；五个向量全部离线预计算成字典。匹配用候选原型为 Query 的
  4 头交叉注意力 + Top-5 邻居原型融合。输入只有 32×32。
- **数字**：24.54 → 67.96（自家表里 CCR-CLIP 21.03 → 62.59，**比 CCR-CLIP 自报低**，
  测试集口径不同）。消融 m=500：无树 16.53 → 加树 23.23（+6.7）→ 加熵 24.54
  （**+0.9**）。小样本：每个未见类给 1 张真实样本 → 92.41%，5 张 → 97.93%（无基线）。
- **局限**：标题卖点"熵"是消融里最小的一项；对比口径存疑；小样本无协议无基线；
  代码与论文有出入；32×32 只剩 4 个视觉 token。
- **对我们的意义**：(1) 树结构位置嵌入是这篇真正值钱的部分，离线零成本；(2) 熵权
  = IDF，能搬但别指望；(3) 小样本那张图是六篇里对我们最有用的一个数字——
  **一张真刻例把 24% 变成 92%**，说明人裁回流成模板比任何算法改进都值钱。

## 三、横向看，这条线解决了什么、没解决什么

| 痛点 | 谁解决了 | 怎么解决 | 代价 |
|---|---|---|---|
| 慢（序列解码） | CCR-CLIP | 检索替代生成 | 候选字表要预先给定 |

## 四、对照我们现在的方案

我们的现役方案（`glyph_cnn_explained.md`）：小 ResNet，分类头 4,636 类 + IDS 部件
多标签头（一层展开、出现 ≥3 字的约 750 个部件），unseen 类只喂字体渲染 + 退化增广；
推理三源 RRF（HOG 字体检索 / 分类头 / embedding 对字体模板检索，权重 0.5 / 1 / 3）。
unseen 1,327 条 top-1 / 5 / 10 = 95.0 / 98.6 / 99.0，rare-char 21 条 81.0 / 100 / 100。

按文献的坐标系定位：

1. **我们走的是 CoLa 那条路（图 ↔ 图模板检索），不是 CCR-CLIP 那条（图 ↔ IDS 文本）。**
   锚是字体渲染图；部件头只是弱监督正则，推理时不用 IDS。
2. **我们的 unseen 协议等于文献的"加印刷模板"设定**，可比对象是 CCR-CLIP 的 93.8–95.7
   和 CoLa 的 78–93（印刷），不是 21–68 那些。我们 95.0 与之相当，没有明显落后。
   文献里"不许用模板"的分数对 Unicode 已编码字对我们没有意义——Jigmo 能渲染全部
   十万字，任何编码字都有模板。
3. **文献的"部首零样本"在我们这里是真实存在的**。unseen 1,022 个字种里：

   | 部件与 seen 真刻例的关系 | 字种 |
   |---|---|
   | 全部部件在 seen 类真刻例里出现过 | 413 |
   | 部分部件出现过 | 560 |
   | 一个都没出现过 | 47 |
   | 含"不进部件头"的罕见部件（整理本 <3 字用到） | 257 |

   但因为有字体模板，这些字目前照样 95%——**部件没见过在我们这里不致命，字体
   模板兜住了**。真正没兜住的是下一条。
4. **我们真正的空白 = 没有字体的字**：未编码异体字、刻工写法（如 CoLa 图 4 里 與 的
   两个 CDP 部件）。这种字既没模板也没分类头，现在只能人去字统网翻。文献里唯一
   对口的机制是 CCR-CLIP 的 **IDS 文本编码器**——给一串 IDS 就能生成锚向量。
5. 我们已经做过的负结果与文献一致：手工按 IDS 切图（§2.3 台账）输给整字，对应
   CoLa 对"人工分解不一致"的批评；IDS 护栏进放行净亏，对应 EASA 熵权只值 0.9 点。

## 五、能进项目的技术，按性价比排序

每条给：机制 → 解决我们哪个痛点 → 数据前提 → 预期与验收。验收沿用冻结集
（unseen 95.0 / 98.6 / 99.0，rare 81.0 / 100 / 100），**两边都不掉才换**。

### A. 真刻例原型进模板库（EASA 小样本；CoLa 甲骨文实验）—— 最高杠杆，一天

- 机制：`cnn_candidates._emb_index` 现在只用 4 套字体渲染的均值向量当模板。把
  **glyph.db 里人裁过的真刻例** embedding 均值也加进模板矩阵（同一字：字体模板 +
  真刻例原型两条，或加权合并）。
- 解决：生僻字第一次人裁之后，第二次出现就该稳稳排第一；现在第二次仍在用字体模板。
- 前提：无。人裁回流已经在跑。
- 验收：unseen 集不动（它们定义上无真刻例）；用 seen_test 里每类只留 1 个真刻例做
  原型、测其余样本，对照纯字体模板——EASA 报的是 24 → 92，我们应看到 emb 单源在
  seen_test 上逼近分类头。**这也是"换数据来源"三条里最便宜的一条。**

### B. IDS 文本编码器作为第二种锚（CCR-CLIP 核心）—— 补真正的空白，一周

- 机制：小 Transformer（3 层够，Hi-GITA 用 3 层）吃 IDS 序列（我们的 lv1 表递归
  展开到叶，结构符保留），输出 256 维，与现役 CNN 的 embedding 做对比对齐（CNN 冻结
  或联训）。推理时任何有 IDS 的字都能生成模板向量，**和字体模板向量并列进 RRF**。
- 解决：§四.4 的空白——未编码异体字、GlyphWiki 里只有 KAGE 部件描述的字、
  用户手写一条 IDS 就能查。
- 前提：IDS 表已有（yi-bai/ids lv1，10 万字，MIT）。未编码异体字的 IDS 来源要单独
  找（GlyphWiki 的 KAGE 数据可机械转 IDS，许可待核实；zi.tools 无许可只能链接）。
- 验收：**新建"无模板零样本"切分**——从 unseen 里抽 200 类，训练时既无真刻例也
  **不给字体渲染**，测试只允许 IDS 锚。CCR-CLIP 在手写上是 22–73%，我们的刻本更
  规整、字体预训练更多，目标 top-10 ≥ 80% 才值得上线；同时 unseen / rare 两套不掉。
- 顺带收益：IDS 编码器给的向量可当分类头的**语义先验**（CCR-CLIP 的 matching head），
  让 4,636 类之外的字也有"分类头"。

### C. 结构感知的部件目标（EASA 树嵌入 +6.7；Hi-GITA 结构 token −11）—— 半天，一次训练

- 机制：现在部件头是"袋子"（含哪些部件，不管在哪）。改成 **部件 × 位置槽** 多标签：
  按 IDS 一层结构给每个部件一个槽（⿰ 左/右、⿱ 上/下、⿴ 外/内……），标签变成
  "言@左""俞@右"；再加一个 12 类结构符头。等价于把 EASA 的深度-分支位嵌入
  离散化成标签，零推理成本。
- 解决：論/諭、呆/杏 这类"同部件不同布局"或"同布局差一个部件"的形近字；也是
  用户最初提的"结构 + 部件"路线的正确打开方式（不是切图）。
- 前提：IDS 表已有。
- 验收：unseen top-1 ≥ 95.0，rare ≥ 81.0；另看 seen_test 里形近对（論/諭 等）的
  混淆是否下降。

### D. 同字图-图对比项 + 批内去重（CCR-CLIP L_I；Hi-GITA）—— 半天，一次训练

- 机制：训练损失加一项 supervised-contrastive：同一字的真刻例与字体渲染互为正样本，
  batch 内其他字为负；同一 batch 里同字样本不当负例。
- 解决：embedding 检索是我们最强单源，但它是分类头的副产物，没有被直接优化过；
  这一项直接把"刻本样式 ↔ 字体样式"拉近，磨损鲁棒性也应受益。
- 前提：无。
- 验收：emb 单源 unseen top-1（现 94.5）为主指标；rrf 两套不掉。

### E. 粗召回 → Top-K 精排（GL-HPN 层级推理；EASA Top-K 邻居）—— 半天

- 机制：RRF 给出 Top-30 后，用部件头对候选做一次一致性重排：候选字的 IDS 部件被
  部件头预测为"存在"的比例（C 做完就是"部件@槽"的一致性）作为第四路信号，只在
  Top-30 内起作用。与之前失败的"IDS 护栏进放行"不同——这里只重排候选，不拦放行。
- 解决：rare-char 上 top-1 81% → 提高把正确答案顶到第一的概率，减少人点第二个。
- 前提：无。
- 验收：rare top-1；unseen top-1。GL-HPN 的教训：K ≥ 30 才不丢召回。

### F. 部件 IDF 权重（EASA 熵）—— 一行代码，附在 C 里做

- 机制：部件多标签 BCE 按 −ln P(部件) 加权，或 E 的一致性打分按 IDF 加权。
- 预期：EASA 自己只有 +0.9，我们此前"频率加权"是负结果。作为 C 的一个开关顺手
  试，不单独立项。

### G. 笔画序列（Hi-GITA）—— 暂不做

- 需要每字的笔画序列数据源（Make Me a Hanzi 约 9.5 千字，覆盖不到我们的生僻字；
  未编码异体字要手写笔顺）；CCR-CLIP 消融里笔画级单独用是最差的；Hi-GITA 的收益
  主要来自 token 级对齐和结构 token，不是笔画本身。等 B、C 做完再看是否还有形近
  混淆需要它。

### H. Slot Attention / DINOv2 教师（CoLa）—— 暂不做，但留一个便宜实验

- 潜在组件本身不建议做（无消融、无代码、增益来源不清）。便宜的是它的教师：
  **DINOv2-S 冻结特征直接做字体模板检索**当第四源，零训练，一个下午能出结果。
  若它在 wear 模拟下比我们 CNN 稳，再考虑蒸馏。

### I. 不搬的

- RAN 系生成式解码：慢，且我们不需要开放词表生成。
- FILIP 式 patch ↔ token 局部对齐：推理成本随候选数线性涨，我们的候选是两级字表
  （4,636 + 扩展），且 GL-HPN 证明大头收益可由更便宜的手段拿到。
- 交叉注意力打分（EASA +2.7）：同上，先做 E 的免费版。

## 六、建议顺序与验收

| 序 | 项 | 工作量 | 主指标 | 通过线 |
|---|---|---|---|---|
| 1 | A 真刻例原型进模板 | 1 天 | seen_test 单原型 emb top-1 | 明显高于纯字体模板；unseen/rare 不变 |
| 2 | C（+F 开关）结构感知部件头 | 1 次训练（1 h） | unseen / rare top-1 | ≥ 95.0 / ≥ 81.0 |
| 3 | D 同字对比项 | 1 次训练 | emb 单源 unseen top-1 | > 94.5 |
| 4 | E Top-30 部件一致性重排 | 半天 | rare top-1 | > 81.0，unseen 不掉 |
| 5 | H′ DINOv2 第四源 | 半天 | wear 模拟下单源 top-1 | 比 CNN 稳才留 |
| 6 | B IDS 编码器 + 无模板零样本切分 | 1 周 | 新切分 top-10 | ≥ 80% 才上线 |

1–4 每一步都是"一次训练 + 三源评测"，沿用 `eval_zero_shot_fusion.py`；6 需要先
建新切分和新脚本。B 是唯一能碰"没字体的字"的项，工作量最大，放最后但不是最不
重要——它是这条线里唯一对我们的空白有解的机制。
