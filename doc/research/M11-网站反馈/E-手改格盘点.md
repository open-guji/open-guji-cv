## 2. 逐格清单怎么读（`E-手改格逐格清单.tsv`）

列：`册 PR 日期 页:列 格号(改后) 旧格号 旧字 新字 类型 细类 变的字段 cord_id(改后) id来源 HEAD现状 处置 事件线索`。

- **配对办法**：先按 cord id 把新旧两版的格对上，再按格号对；剩下对不上的就是增、删。
- **类型**：
  - `A`：只改字。
  - `B`：涉及 □ 或 lacuna。
  - `C`：增删格，或格号、框、id 变了。
  - `D`：整页漏切后补字。
  - `F`：只改了 lane 字段。
- **id来源**：
  - `CV 原 id`：id 在 CV 首版里出现过（001 取 #150、#151、#172 三版的并集，002／003 取 #22，cv-proof 取 #167）。
  - `手造 id`：id 不在 CV 首版里。
  - `无 id`：没有 cord id。
- **HEAD现状**：看这一格在当前 main（fd8f15d7）里还在不在，格号和字有没有被后面的提交再改。
- 「每次改动一行」：同一格被几次提交改过，就占几行。例如 190:1:8 先被 #179 改成「自」，又被 #194 改回「目」；95:3:16 先被 #179 改成「琦」，又被 #194 改成「𤦺」。

**核数**：拿 HEAD 和 CV 首版 id 集合直接比，001 有 175 格 id 不是 CV 的，另有 5 格是 CV id 但改了框，合计 180，和清单里 001「人工格、HEAD 里还在」的 180 一致。002 是 4＋2＝6，003 是 7＋1＝8，也都一致。
