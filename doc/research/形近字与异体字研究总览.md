## 0. 先分清三件事

| 概念 | 含义 | 处理原则 |
|---|---|---|
| **形近字** | 不同的字，长得像（己已巳、日曰、入人八、土士、而面…） | 永不当同字；几何相似度分不开，靠上下文、规则、分类器、护栏 |
| **异体字** | 同一个字的不同写法（卽即、髪髮、彝𢑴…） | 字形层忠于刻本，语义层可合并；分 T1／T2／T3（见 §3） |
| **稀见字／生僻字识别** | 字不在分类头里（零样本、IDS 拆分） | 见 §4 文献调研；本项目走「字体模板 + 少量真刻例 + 只出候选」 |

## 1. 形近字：各字组的进展、算法、效果

### 1.1 两条线

1. **几何匹配线**：判「是不是同一个字」。形近字在任何全局相似度下与同字分布重合，调阈值无解，靠 never-match 护栏降档。
2. **字组专项线**（2026-10 起）：对已知易混组各自做判别器。判别器不靠通用相似度，靠各组自己的特点。

### 1.4 几何匹配栈（通用线）现状

详见 `doc/design/glyph_match_stack.md`、`doc/research/g3g4_error_analysis.md`。

- 现用 **elastic 判据**：软覆盖（`exp(-(d/1.5)²)`）＋16×16 分块弹性对齐（±1px）；**不做笔宽归一**（撤除后 hard 0.684→0.7632）；归一化补回了被误删的点和短横。
- 基线（2026-08-26 重键后）：eval_db_match 覆盖 35.9% / 44.8% / 54.8%（闸 0.97），三协议 `match_precision` 全 1.0000；triplets control 1.0000、nearmiss 1.0000、hard 0.5143。
- **闸能从 0.996 放到 0.97，靠的是形近护栏把异字上尾摘出去，不是判据变准了。** 实测字形层在形近对上只有 0.643，低于多数类基线 0.760；n-gram 0.955，大模型 0.987——所以形近交给上下文和语言模型。
- 仍排反的三族：加一笔／减一笔（面/而、日/曰、已/巳、七/一、金/全、目/自、太/大）、偏旁替换（諭/論、識/議、傳/傅）、部件包含（庶/廣、難/離、遠/還）。
- **死路（已测已否，别再走）**：密度自适应半径、骨架失配否决、部件失配否决、墨芯加权残差、提高归一分辨率（96/128/192/256，360× 代价换噪声）、降二值化阈值救细笔（反而粘连）。
- 聚类侧用不上 never-match 护栏（无监督拿不到字标签），脏簇全是形近家族（而/面、七/一、彖/象）。

## 3. 异体字研究

### 3.1 主档：`doc/design/variant_strategy.md`（约 1,540 行，2026-09-05 至 09-08）

- **原则**：字形层忠于刻本；归一到通行字只为方便理解和积累异体数据。
- **三类关系（基础）**：
  - **T1 纯异体**（髪/髮、卽/即）：可合并、可桥。
  - **T2 互通／一对多**（鍾/鐘、注/註、后/後）：不可全局合并，只按本书用法定向；可桥但 `reading` 取整理本字。
  - **T3 形近／通假／古文**（己已巳、人入、上/二）：**永不桥**。
- **公开资料库盘点**：Unihan、教育部异体字字典（经 cjkvi 抽取）、汉大、dypytz、yitizi、OpenCC、CHISE、GlyphWiki 等 13 个来源，逐个评估格式、授权、方向、分型。结论：没有现成的「一对多」干净表，只能自己算；原始文件有方向，旧构建把它丢了（后已保留 `directed`）。
- **三层表**：关系层（`config/variants/variants.json`，有向、带来源）→ 本书用字账（`config/variants/books/wuyingdian_zongmu.json`，只由脚本从产物派生）→ 语义层（派生的 `config/dicts/variants.auto.tsv`）。
- **准入新状态「义定形未定」**：组内定形器＋`variant_form` 通道，堵住「首例静默归一」的洞（刻 髪、OCR 读 髮、整理本 髮 → 静默存 髮）。**扩语义表必须与此同时上线。**
- **判据 E 字形保真率**：自动放行里 `char` 是否等于实刻形；第一次亮红就抓到两条「产物落后于人裁」。
- **审阅界面**：组视图（列＝形，格＝缩略图）、`O` 组外／`N` 非字／`T` 字形不完整／`C` 有噪声。
- **落地数字（2026-09）**：用字账 87 组，后拆组（`never_group` 补到 49 对）到 76 组；58 页人审率 0.84%，对整理本 9,458/9,458、对人裁 167/167。
- **差点犯的错**：「v1 idx = v2 slot − 1」**不是普遍规律**，单格改判要靠独立证据，绝不能批量按该规律改。
- 不做：PUA 造字；把关系图连通分量当等价；把 twedu 古文边当刻本异体；用 dypytz 定方向。

### 3.4 Y1 `variant_tie`（cv 引擎侧）

- 开关 `seed_admit.variant_tie`（默认关）：库候选里 top1 与另一个候选是同一字的两个码位且并列，因 margin 不足被送审 → 在口径 A（忠实原刻，不归并、不改字）下放行 top1。条件：top1 cov ≥ `variant_tie_cov`、无护栏、top-3 里 cov 差 <0.03 的候选**全是**直接异体。
- `variant_tie_extra` 给了组表就只认组表。用户 10-07 字组页裁决：7 组「刻形＝系统码位」（𫎇蒙、㸃點、㕘參、䜟讖識、𨽾隸、慎愼、㫖旨）。**去掉 㫖 组后** 27 放行、0 放错（vol04 待审 487→469，vol05 348→339）。
- **𢑴／彝／𢑱／異 一组当时裁为「拿不准（样例含不同字形）」，处理是「按字形拆开」**——这正是 §5 三段规则的起点；所以彝不在 `variant_tie` 组表里。
- `variant_indirect_guard`（overview#178）：`𢑴→彝`（hydzd）与 `彞→彝`（twedu）经共同正字「彝」间接相连，会把 𢑴／彞 误判同义；此闸专拦这类间接路径。

### 3.5 muse 异体关系标注

- 试点（`research/muse_variant_pilot/报告.md`，2026-09-27）：**按七分类口径放量闸不过**（形近易混／无关分界不清）。但「是不是同一个字」二分口径：50 对人工对照 43/43 一致，校准集 74/87（85%）。三类自动真值（通假、形近、简繁）本身靠不住。全量交 Claude 约 4 美元。
- 复核（`research/muse_variant_audit/README.md`）：`variants.json` 47,182 条边里 22,454 条单来源，大/太、戊/戌、增/憎 被当异体；对两字都在书里出现的 1,957 条单来源边审一遍，目的是**把 muse 判「否」的单来源边降级**（不删边）。

## 5. 彝彛彜彞𢑱𢑴（#560 yi_560）：三段规则

数据与方案在 `open-guji-dataset` 仓 `claude/Evan-1011` 分支 `char-groups/variant/yi_560/`（`plan_step3.md`、`plan_step4.md`、`rule_assign.jsonl`、`disagree_13.jsonl`、`user_parts_labels.jsonl`、`sheets/`）；分块设计在 overview `项目进展/CV形近字分组/计划/分块-B5异体-Evan.md`。总计划把它登记为「**异体里第一个落地的字组**」，并写明「异体是项目的正式一半，不是样板」（Mila 10-12）。

### 5.1 策略

**不看以往机器和人的判断，每个字拆成上／中／下三段，按三段读法查规则表定字**（用户 2026-10-12 定）。理由：模型与整理本在异体上系统性偏向通行字；证人＝放行＝对位在异体上不可信（有三方一致仍错的反例）。

| 段 | 两种写法 |
|---|---|
| 上 | 彑 或 ⺕ |
| 中 | 米+分 或 米+糸 |
| 下 | 大 或 廾 |

| 下 | 中 | 上 | 字 | 备注 |
|---|---|---|---|---|
| 廾 | 米+糸 | 彑 | 彝 U+5F5D | |
| 廾 | 米+糸 | ⺕ | 彞 U+5F5E | |
| 廾 | 米+分 | 彑 | 彜 U+5F5C | |
| 廾 | 米+分 | ⺕ | 彛 U+5F5B | |
| 大 | 米+糸 | ⺕ | 𢑴 U+22474 | 精确 |
| 大 | 米+糸 | 彑 | 𢑴 | **最近异体**（Unicode 无此码位），字形库打 `nearest_variant` 旗 |
| 大 | 米+分 | ⺕ | 𢑱 U+22471 | 精确 |
| 大 | 米+分 | 彑 | 𢑱 | **精确，不打旗**（官方拆法变体，Mila／Eliot 10-12 定） |

下为「大」时，上段不决定是哪个字，只决定是否打旗。

一句话笔画差：𢑴 vs 𢑱＝中段糸对分；彝 vs 彞、彜 vs 彛＝上段彑对⺕；彝彞 vs 彜彛＝中段糸对分；大类 vs 廾类＝下段大（三笔）对廾（双竖加横）。

### 5.2 数据与发现

- 42 格点单（每码位最多 8 格，彜只有 2 格放行）；用户标三段 → `rule_assign.jsonl`：𢑴 13（精确 7、旗 6）、𢑱 11、彞 9、彝 4、彛 3、彜 2。七册现有定字：彝 50／彛 9／彜 2／彞 41／𢑱 9／𢑴 46（共 157 格）。
- **13 格与引擎放行不一致**：引擎判彝的 3 格（vol04:133:7:18、vol03:45:2:10、vol07:31:1:17）、判彛的 5 格，下段其实是「大」，应是 𢑴／𢑱——方向都是**引擎把大类当廾类放行**。
