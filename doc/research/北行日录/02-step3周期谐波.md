## 一、现象

Step3 `row_segment` 在 dev_set 上跑完，**p20 的 18 列里 16 列报「弹性 DP 无解」**，
只切出 2 列 42 格。而 p20 恰恰是全书**列距最干净**的一页
（gaps 114~127 无离群，`01-step2界行识别.md` 里当反例的那张好页）。

## 二、根因（已量实）

`utils/row_boundaries.estimate_period` 的搜索窗口**写死** `lag_lo=70, lag_hi=160`：

```python
def estimate_period(curve, lag_lo: int = 70, lag_hi: int = 160) -> int:
```

这套数是给《四庫全書總目》标的（period ~113~115，稳稳落在窗口中间）。
**本书字格高真值 70.6px，正顶在 `lag_lo=70` 这条下界上**——窗口能勉强表示真值，
却对 2 倍谐波 141px 敞开。自相关在 70 和 141 两处都有峰，逐列各自锁哪个看运气。

逐列实测（默认窗口）：

```
p20 逐列 = [70,142,141,142,71,70,72,142,143,72,70,143,143,144,142,71,71,72]
           ^^ 9 列锁真值 70~72，9 列锁 2x 谐波 141~144
           中位 = 106.5  ← 没有任何一列估出过这个数，是两堆的中点
```

`estimate_shared_period` 取的是**逐列中位数**。两堆各半时中位落进中间的空档，
给出一个物理上不存在的 106.5，DP 拿它当先验自然无解。

## 三、这不是 3 页的问题，是全书 30% 的列

全书 53 页 884 列普查（默认窗口）：

| 项 | 值 |
|---|---|
| 锁到 2x 谐波（>100px）的列 | **269 / 884 = 30.4%** |
| 页级中位已经翻车的页 | 3（p20 106.5、p27 139.0、p38 125.5） |
| 谐波列占比 ≥35%、**随时会翻车**的页 | **17** |

其中 p21/p24/p28/p32/p45/p52 的谐波列占比已到 0.44——**再翻一列中位就过半**。
所以现在「只坏 3 页」是运气，不是稳。这批页的产物现在看着是对的，
不能因为数字好看就当没事。

## 四、修法（已验证，未落地）

**窗口由 `Book.period_prior` 派生**，别再写死：

```python
lag_lo, lag_hi = int(prior * 0.7), int(prior * 1.4)
# bxgb  prior=70.6  -> [49, 98]   （2x 谐波 141 被关在窗外）
# zongmu prior=115  -> [80, 161]  （与现默认 70–160 几乎重合）
```

没配 `period_prior` 的册**保留现默认 70–160**，行为逐位不变。

### 离线验证结果

| 对象 | 结果 |
|---|---|
| bxgb 884 列 | 锁谐波 **30.4% → 0.0%** |
| bxgb 54 页页级中位 | **偏离 >10px 的页 0**（改前 3） |
| zongmu vol01 抽 12 页 | 中位**逐页相同**（prior=115 → 窗口 [80,161]） |
| zongmu vol02 抽 12 页 | 中位**逐页相同**（prior=113 → 窗口 [79,158]） |

### ⚠️ 一条死路：别用固定窄窗

先试过把窗口改成固定 `[55,100]`，bxgb 是好了，**四庫總目当场全毁**——
115 被 `lag_hi=100` 截成 99：

```
vol01 p3 默认=115.0  窄窗=73.0
vol01 p4 默认=115.0  窄窗=99.0   ← 顶在新上界上
vol02 p4 默认=117.0  窄窗=99.0
```

抽的 12 页里 **10 页中位都变了**。窗口必须跟着书走，不能换一组写死的数。

## 五、已落地（2026-09-16）与回归实测

**改法**：`estimate_shared_period` 新增 `period_prior` 参数，由它派生自相关窗口
`[0.7×prior, 1.4×prior]`（常数 `PERIOD_WINDOW_LO/HI`，上界 1.4 < 2.0 保证 2x 谐波一定
被关在窗外）；不给 prior 时沿用 `estimate_period` 缺省 70–160，逐位不变。
`column_gate` 1.7→1.8，并补 `book_deps=("period_prior","expected_cols","chars_per_line")`
——以前这道闸**没有 book_deps**，改 yaml 里这几个数产物照报「新鲜」（与 `leaf_layout`
当初踩的是同一个坑）。`estimate_period` docstring 写明窗口的两个硬条件与两条死路。

**回归（全是重跑真产物，不是离线估算）**：

| 对象 | 结果 |
|---|---|
| bxgb 54 页 | 谐波页（period>100）**5 → 0**；period 中位 **71.0**（真值 70.6） |
| bxgb Step3 | **952/1026 列过**；**932 列恰好 21 格**；char 格 **18,162** vs 校對本 18,321（**差 0.9%**） |
| zongmu vol01 body | 108 页，**3 页动了 1~2px**（116→117 / 114→116 / 112→113），坏页 **0 → 0** |
| zongmu vol02 body | 186 页，10 页微动，坏页 **0 → 0** |
| zongmu vol03 | 105 页，5 页微动，坏页 **1 → 1** |
| tests | **586 passed**（`test_route_snapshot` 那条是本机临时目录快照过期，与本改动无关） |

**18,162 vs 18,321 这条是独立佐证**：字格总数与证人字数差 0.9%，说明格数在全书尺度上是准的，
不只是抽查的几页好看。

⚠️ 顺手修了一条**测试自身的漏洞**：`test_prior_never_overrides_a_page_that_can_estimate`
原本传 `period_prior=999` 来证明「兜底不得插手」。`period_prior` 现在还派生窗口，999 会把窗口
推到 [699,1398]，估出来是个 720 的假数——**即使兜底逻辑坏了这条也会通过**。改成传真周期本身
（60），让 `period_from_prior` 这个标志来区分「估出来的」和「顶上来的」。

**还没做**：`column-split`（60 页人裁）那份金标没跑——它判的是**界行位置**，本改动只动纵向
周期、不碰竖线，按理无关；但没实测过，留个记录。
