## 三、真根因：三层，一层一层剥出来的

### 1. `expected_cols: 20` 写错了（用户发现）

19 列 → 20 条线，yaml 写 20 → 探测器**每页被迫多收 1 条**，只能拿页边（x≈2798）或字身假峰凑。
这也是 README 里「被拒的那 1 列是页边假列」的来历——不是探测器聪明，是它被逼的。

### 2. 界行没印全，且这本是灰度扫描（回答「为什么四庫總目没事」）

- 四庫總目十册全是 **1-bit 双色**扫描（`np.unique` 只有 {0,255}），界行条条实黑、
  半高宽 3~5px、**从不缺线**——自由模式按分数取前 N 条，永远取得对，14 页金标中位误差 0.05px。
- 本书 **254 级灰度**，界行是淡线（沿线 min gray 中位 ~130，局部淡到 186）而且**有的半叶
  根本没印出来**：p41 左半叶整片空白（`step1_grid_p41.png（已删，留底见 9f97524e）` 蓝线那一片），粗量 972 个槽位
  里 120 个（12.3%）用整页投影找不到线，54 页里只有 15 页齐全。
- 自由模式在缺线槽位**只能拿别的东西凑**：字身竖向对齐的假峰（半高宽 50+px、分数 ~10）。
  这就是 p41 列距出现 60/69/212 的来历。

**不是「半个筒子页 vs 整个筒子页」的差别**，是「界行齐 vs 界行缺」+「双色 vs 灰度」的差别。

### 3. 折线拟合把对的直线掰弯了（修完 1、2 之后闸2 才暴露出来）

网格模式给出的直线全在缝里，但闸2 p41 只过 **1/19**、p46 11/19。追下去：
`fit_vlines_polyline` 的判弯量 w80（装下 80% 墨的最窄 x 跨度）在**淡而断**的界行上量的是
「线有多断」不是「线有多弯」——平直页 w80 中位 **41**，阈值 7，整页被判成弯页。折点得分在
淡线上是噪声，某条线找到一个假最优，失败的邻居再照抄它的位移，**全页 20 条线齐刷刷平移
33~39px 落到空白纸上**（p40：直线 1 条可疑 → 折线 14 条穿字；`step1_polyline_bends_p46.png（已删，留底见 9f97524e）`）。
四庫總目界行实黑 w80 3~6，从没触发过这条路。

## 四、修法（三个开关 + 一个新函数，默认全关、四庫總目逐位不变）

```yaml
expected_cols: 19        # 9 + 版心 + 9
column_grid: true        # 竖线走网格模式
col_pitch: 119.0         # 列距先验（不是 pitch_prior——那是现代链的字距）
vline_polyline: false    # 只量 w80、不拟合折线
```

**网格模式 `find_vertical_lines_grid(mask, n_lines, col_pitch)`**：
1. 候选池沿用原有粗筛 → 逐窗联合精搜 → 去重（抽成 `_vline_pool`，自由模式共用、逐位不变）；
2. **版框对**：池里两两配对，隐含列距 (b−a)/(N−1) 与 `col_pitch` 差 ≤8%，按「多少槽位落着细线」
   排、同分按投影和——页边那条假线列距不对、支持数低，选不上；
3. **逐槽验线**：`a + k·pitch ± 18px` 里做位置+角度联合精搜（两翼都要干净），
   分数 ≥20 且半高宽 ≤12 才算探到。**阈值余量 >10 倍**：全书探到的线最低 29.6 分，
   被拒的槽位最高 2.8 分且半高宽 ≥140；
4. **缺槽插值**：相邻已验线（含版框）之间线性插值位置和斜率，`borders.vline_filled` 标 True，
   `line_index` 该列位加 `rule_interpolated` 旗标。

每条线要么是验过的细线、要么是几何插值——**不可能落在字上**。逐槽联合精搜比整页投影灵敏得多：
粗量 120 个「空槽」里最后只有 **7 个**真的没线要插（p41×6、p56×1）。
