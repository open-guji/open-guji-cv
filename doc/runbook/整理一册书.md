# 整理一册书：标准流程（runbook）

> 状态：**v0 骨架（2026-10-06）**，随 cv 大清理（overview#413）同步补全。
> 读者：**没有任何上下文的模型会话**。照本文从上往下做，就能把一册刻本古籍整理成交付文本；
> 做不下去的地方，本文会明确写「停下来问人」。
> 维护：整理总管。每次试跑后，把卡住的地方补进本文对应一步的「坑」。
>
> 标 ⏳ 的命令还没做成，会在 C2（入口规范化）里补上。在此之前按括号里的临时做法操作。

## 〇、先读这一节

### 0.1 你要交付什么

一册书交付，指下面 14 项全部达标，见第四节。核心产物是三份文件：

| 文件 | 是什么 |
|---|---|
| `NNN.lines.md` | 原刻逐列分行的正文，原字，不加任何记号 |
| `NNN.pages.json` | 每个字在原图上的坐标和锚点 |
| `NNN.norm.json` | 规范层：转换表版本，加逐位例外 |

三份推到 `open-guji/book-text` 的 `wip/siku-volNN` 分支。另写一份收尾记录。

### 0.2 七条不能违反的规矩

1. **不改 `open-guji-cv` 的代码**。引擎有问题，开 `[整理→CV]` 卡，自己先做下一件事。
2. **人裁只能经控制台或 `guji` 命令写**，不手改 `feedback/events/` 下的文件。
3. **不加 `--force`，不从上游起跑**，除非本文明确写了要这样做。只从受影响的最上游一步起跑。
4. **审期间不整册重算**。发现问题先记下，等这一册审完再统一重算；重算必须出差异单。
5. **整理本和证人都不是标准答案**。己、已、巳在殿本里三字同形，只能按文意判。
6. **提交只 add 具体文件**，不 add `products*`、`cache/`；不强推；book-text 的产物不进 main。
7. **问人要省**：能自己判的自己判；必须问人的，攒成一张请审单一次问，见第三节。

### 0.3 名词

| 词 | 意思 |
|---|---|
| 册 | `vol04` 这样的 book id，对应书 yaml `books/vol04.yaml` |
| 工作区（ws） | `guji-workspace` 里这部书的目录，下文记作 `$WS` |
| 格 | 一个字位，id 形如 `vol04:12:3:7`（页:列:格），夹注加 a/b |
| 放行 | Step7 自动定字（admit=True）；没放行的格进待审队列 |
| 证人 | 现成整理本，用来对齐和对勘，**不是真值** |
| 人裁 | 人在控制台给的裁决，写成事件 |

## 一、开工前

### S1 环境自检
- 做：建 Python 3.12 虚拟环境，装依赖，自检。
- 命令：
  ```bash
  cd <cv仓> && uv venv .venv --python 3.12 && uv pip install -e ".[console,torch,dev]"
  .venv/Scripts/python -c "import torch, scipy, cv2; print(torch.cuda.is_available())"
  ```
- 环境变量：`PYTHONIOENCODING=utf-8`；`GUJI_WORKSPACE=$WS`。
- 验收：torch、scipy、cv2 都能 import；`guji status <册> -w $WS` 能出表。
- 坑：
  - 缺 torch 或 scipy **不报错，只悄悄降级**：切点判官、CNN 候选失效，截条图出空白。所以必须自检。
  - 不要跑全量测试，它会卡在 rare 冷启动。

### S2 仓与资源
- 要的仓：`open-guji-cv`、`guji-workspace`、`overview`；入测试集时还要 `open-guji-dataset`。都 `git pull`。
- **一册书钉一个 cv 提交跑到底**。在任务卡上记下 cv 和 ws 的提交号。
- 资源清单：

  | 资源 | 位置 |
  |---|---|
  | 原图 | `$WS/data_full/<册>/` |
  | 字形库真源 | `$WS/output/glyph_store/`，加上 `$WS/feedback/events/` |
  | 字形库索引 | `$WS/output/glyph.db`，可重建 |
  | 模型权重 | cv `models/` |
  | 字体 | cv `fonts/` |
  | 合扫拆页裁剪表 | overview `项目进展/新书整理/书/四庫合扫拆页-裁剪框.json` |
  | 证人整理本 | 书 yaml 的 witness 段 |

### S3 书 yaml
- 做：写或核对 `$WS/books/<册>.yaml`。内容包括版面先验 `bottom_gap`、`period_prior`，`params:`，`iron_gate`，`codepoints`。
- 命令：`guji calibrate <册> -w $WS --pages all --with-bottom-gap`，把实测值抄进 yaml。
- 坑：
  - calibrate 必须在 Step2（column_gate）的产物出来之后再跑，早跑测出来的值是错的。
  - 缺 `period_prior` 会被闸 2、闸 3 拦下。

## 二、算

### S4 Step0 预检与拆页
- 命令：`guji survey <册> -w $WS`。宽或高超过本册中位的 1.3 倍、或不到 0.7 倍的页列为异常；版心用 `guji locate-gutter`。
- 异常页逐页看图，三选一：拆页顺移、标非正文、保留。**拿不准就停下问人，附图。**
- 坑：
  - 顺移页号之前，先在 `feedback/events`、`verdicts`、`glyph_store/instances` 三处 grep 这几页，**有命中就停手问人**；
  - 同一册有多处拆页时，合成一张顺移表；
  - 改过页面的册，在 `Commons修图记录.md` 加一行。

### S5 Step1–7 管线
- 命令：`guji pipeline keben_body_v2 <册> --pages all -w $WS`；跑完 `guji status <册> --pages all -w $WS`。
- 验收：全部新鲜，失败 0。记下人审率：待审格数 ÷ 总格数。
- 坑：
  - 一条命令控制在 9 分钟内，按页分块跑；
  - status 报「过期」时先查原因，不要上来就 `--force`；
  - 换过字形库后，glyph_match 不会自动判过期，此时要 `--from glyph_match --force`。这是本文唯一允许 `--force` 的地方。

### S6 字形库重建
- 命令：`guji-cv glyph-db rebuild -w $WS --no-borrow`。⏳ 以后并进 `guji`。
- 坑：已经有本书人裁之后就不再借别书的库，只有冷启动时才借。

### S7 缓存校验
- 命令：`guji cache verify --book <册> -w $WS`，有错位就加 `--fix`。
- 验收：错位为 0。
- 坑：从别处换进产物、或更新字形库之后，必须先校验缓存，否则重算会读到错位的字块，而状态仍显示「新鲜」。

## 三、定版检查与请审

### S8 放行错穷举（请审之前必须做完）
- 做：列出「已放行、不是人裁、和证人不同」的格，分系统类和非系统类，非系统类逐格看图。
- 命令：⏳ `guji audit admitted <册>`（临时做法：从 `guji collate` 的 JSON 按字位比三个证人）。
- 产出：`书/<册>/放行错穷举-vN.md`。
- 坑：context 通道是放行错的大头；iron_gate 要单独统计。

### S9 多证人对勘
- 命令：`guji collate <册> --console "" -w $WS`，产出 `$WS/reports/<册>/collation_*.{html,json}`。
- 坑：两个证人可能同源，差异逐条相同时只算一份信息。

### S10 己/已/巳 按文意判
- 做：这一族全册逐格按文意定。
  - 干支用「己」；
  - 「並已」「時已」「而已」这类用「已」；
  - 拿不准的进请审单。
- 命令：⏳ `guji audit jys <册>`，导出这一族的格和上下文（临时做法：从 collate JSON 取）。
- 坑：
  - **不能拿证人当真值**，证人在这一族上常讹；
  - split_ref 通道对这一族全部放行，错率过半。

### S11 请审（问人）
- 请审单的格式（⏳ `guji review-sheet <册>` 生成）：
  - 在哪：控制台地址 → 册 → 步 → 标签；
  - 一共几格，预计几分钟；
  - 每格：字位、现在是什么字、建议是什么字、理由；
  - 不审时默认怎么处理。
- **一次只给一类活**：待审队列、按字位改判、看原图，三类分开问。超过 30 分钟拆成几次。
- 控制台：`guji console --no-auth`，打开 http://127.0.0.1:8640/。

### S12 人裁核数（用户审完当场做）
- 命令：⏳ `guji review-count <册> --since <时间>`（临时做法：`GET /api/review/cards`，看 `class_counts`，再 grep 事件）。
- 验收：审过的条数和请审单对得上，没漏，没重复，事件都带锚点。

### S13 收尾闸
- 命令：`guji status <册> --pages all -w $WS --json`，看 `closure_gaps` 和 `closure_mismatches` 两个字段。
- 验收：
  - `closure_gaps` = 0；
  - `closure_mismatches` 逐格扫一眼，真错的进请审单。
- 坑：「待审队列为 0」不等于真清零。失效的老人裁会回到队列并预勾，要用户确认。

## 四、收尾与交付

### S14 字形库导出入真源
- 顺序：`git fetch` → `guji-cv glyph-db export -w $WS` → `git diff --numstat` 检查**没有成片删除** → 只 add `$WS/{feedback,config,review,output/glyph_store}` → commit → `pull --rebase` → push。
- ⏳ 做成一条 `guji store commit <册>`，自带「没有成片删除」检查。
- 坑：`scripts/glyph_store_sync.py` 在 Windows 上跑不了，因为用了 `fcntl`。

### S15 入测试集
- 命令：`guji gold import <分片> --book <册> --ids <清单> --dry-run`，确认 updated = 0 后，去掉 `--dry-run` 再跑一遍。
- 坑：曾有缓存错位的页里的格要排除。

### S16 Step9 导出
- 命令：
  - `python scripts/render_guji_markdown.py <册> <页号…> --out $WS/reports/<册>/<册>.md`。页号只能逐个列，不认范围。
  - `guji collate`，见 S9。
- ⏳ 并成 `guji export md <册>`。

### S17 出 lines、pages、norm
- 先只从 seed_admit 起重跑，让新人裁进文本，再导出：
  ```bash
  python scripts/export_guji_format.py --products $WS/products --book <册> --chapter NNN \
    --meta <meta.json> [--split-table <拆页表>] --out <dir>
  ```
- ⏳ 并成 `guji export format <册>`；meta 从书 yaml 生成，不再手写。
- 验收：lines 的字数 = Step7 定字格数 − 非字格数，差为 0；与 Step9 的 md 逐字一致。以导出器的口径为准，不要自己数。

### S18 pages.json 抽检
- 命令：`python scripts/check_pages_json_boxes.py --pages-json NNN.pages.json --images <图=页号…> --n 20 --out x.png`。
- 验收：抽 20 字以上，合扫拆页必抽，**目测**每个框都落在字上。脚本的自动判据太严，只作参考。

### S19 推 book-text
- 在官方仓 `open-guji/book-text` 的 `wip/siku-volNN` 分支上，先 pull，再只替换 lines、pages、norm 三个文件。不碰别人的 punct、entity、rich 层，不强推。
- 推完在任务卡上告诉文本总管。

### S20 收尾记录
- 先跑体检：
  ```bash
  guji close-check <册> -w $WS --export-dir <S17 的输出目录> --notes <overview>/项目进展/新书整理/书/<册>
  ```
  机器能判的项逐项给出 ✓/✗ 和数字，退出码 0 表示机器项全过；标「·」的是要人或会话按本文确认的项。
- 再写 `overview/项目进展/新书整理/书/<册>/收尾记录.md`：把体检输出贴进去，人工项逐条补上说明。

## 五、交付标准（14 项）

`guji close-check` 判「能」的项；「部分」的项它只查得到一半，剩下靠人。

| # | 项 | 标准 | 能否机器判 |
|---|---|---|---|
| 1 | 产物新鲜 | status 全新鲜，失败 0，cache verify 无错位 | 能 |
| 2 | 待审清零 | 队列内待审 = 0 | 能 |
| 3 | 队列外改判清零 | 穷举列出的每格都有人裁，或写明原因 | 部分 |
| 4 | 切分问题有着落 | 修好的已重算复审；没修好的标存疑并列出 | 部分 |
| 5 | 己/已/巳 | 全族逐格按文意定，不拿证人当真值 | 部分 |
| 6 | 对勘 | 存疑逐条有人裁或说明，html 已出 | 部分 |
| 7 | 避諱改字表 | 有 | 能（有无） |
| 8 | 字形库 | 已导出并推送，没有成片删除，store 落后 db = 0 | 能 |
| 9 | 测试集 | 已导入，dry-run updated = 0 | 能 |
| 10 | lines.md | 字数 = 定字字数，差为 0 | 能 |
| 11 | pages.json | 每个字都有框，抽检全对 | 部分（抽检要目测） |
| 12 | Step9 | md、对勘 html、体检表已出 | 能 |
| 13 | 收尾记录 | 已写 | 能（有无） |
| 14 | 修图记录 | 改过页面的册已记一行 | 能 |

## 六、度量（每册必记，用来比较流程和模型）

人审率、问人次数和总分钟数、放行错率（按页分层抽 300 格看图）、总耗时、花费、本册新开的 CV 卡。

## 七、停下来问人的情况（判准表）

| 情况 | 怎么办 |
|---|---|
| 拆页、顺移页号时命中已有人裁 | 停，附图问 |
| 引擎报错，或产物明显是垃圾，例如整页认成乱码 | 停，回滚，开 `[整理→CV]` 卡 |
| 己、已、巳 按文意判不了 | 进请审单 |
| 证人之间、证人与图互相矛盾，看图也定不了 | 进请审单 |
| 需要改 cv 代码才能继续 | 开卡，先做别的 |
| 本文没覆盖的情况 | 停，问人，问完把答案补进本文 |
