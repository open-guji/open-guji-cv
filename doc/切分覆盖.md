# 切分覆盖：人定切分的 15 种写法、优先级与怎么选（2026-11-12）

> A22，Sheldon 11-12 定（方案 Claude Doc《切分三方向：覆盖接口、去重、快检》）。本页是**唯一总表**：
> 想让某页、某列、某格「按人说的切」，先在这里找该写哪一种、写在哪、写完从哪步重跑。
> 细节（字段含义、来历）在各条链接的代码 docstring 里；runbook、《人裁事件规范》、《切分代码结构》只指到这里。
> 代码依据：cv dev 4d7b6f8（`steps/row_segment.py`、`steps/border_detect.py`、`feedback/lookup.py`、`core/page_kinds.py`）。

## 一、先判层（口诀）

别的书也会有 → 改公用算法（找 A22）；只这套书 → 书仓 `code/`（出新 k）；只某类页 → 页型 `page_kinds`＋书级代码分支；
只这一册这一页的几何 → 册 yaml `params`（第二节 1–5）；只这一列的格数／格线 → 格位表或列级人裁（7–9）；
这一列算法怎么也切不对 → **整列写定 manual-cells**（10）；只差一条线、一格的属性 → 切线／格级人裁（11–15）。

能在下层修的不动上层：为一列改公用算法或书级参数，几乎必然在别处回退（三书 11-10 经验一致）。

## 三、同一列上几条都写了，谁说了算

按 `RowSegmentStep.run_page` 的实际顺序：

1. **manual-cells（10）最后套、整列替换**：算法照常切完，再把整列换成钉子格（职名页分支也认，在 `_run_roster` 之后套）。
   同列写了别的什么都不算数。列旗 `roster`＋`manual_cells`，Step3 闸不按版式格数拦、Step4 不按格线裁。
2. **抬头（7）先于格数**：裁决级数盖过闸给的 `n_raised_hint`；格位表的级数不同时，表的字按先后整体挪到裁决格号上（`_reraise`）。
   Step1 也读同一张表补／去抬头框，所以要从 border_detect 重跑。
3. **列上有任一条 8、11、12、13、14、15 → 这一列整列不用格位表（9），连 `cuts` 一起失效。**
   理由：这些人裁都按格号记，格位表一改格数或抬头级数，格号就对不上，所以人裁为终裁。
   **坑**：只想改一格的小注属性，却让整列失去了格位表的格网和夹注先验。这时宁可把小注写进格位表，或者整列写 manual-cells。
4. 没有 3 的列：格位表（9）定抬头级数、每格有无、小注；表里有 `cuts` 且列图高与 `col_h` 差 ≤4px 时格线照表，格数＝线数−1−抬头级数
   （列图高变了就不套，打旗 `layout_cuts`）。
5. 格数（8）盖过 `effective_body_slots`；`uniform: false` 放宽等距先验。
6. 切线（11、12）在 DP 里收敛候选／钉线；小注（13–15）在夹注判据里强制。

页级 1–5 先于以上一切：它们决定版框、界行、列窗，列图本身就从这里来。改了 2、3、7，列图会变，**同页的 manual-cells、`cuts` 是列图坐标，要核**
（`cuts` 有 `col_h` 自检；manual-cells 没有，用 `scripts/seg_pins_check.py` 核）。

## 四、整列写定（manual-cells）

什么时候用：算法在这一列上怎么也切不对（职名页雙行相位不齐、压扁密排、挤成半高的卷题、漏格／并格／多格的长尾单列），而格位表的 `cuts` 表达不了
（要定 x 范围、夹注 a/b、只此一列）。

一行一列：

```json
{"id": "vol01:88:4", "anchor": {"book": "vol01", "page": 88, "col": 4}, "status": "active", "label_origin": "human",
 "expected": {"cells": [{"slot": 1, "sub": null, "kind": "char", "x0": 3, "x1": 118, "y0": 12, "y1": 140}, …]},
 "input": {}, "source_events": [],
 "history": [{"ts": "2026-11-12T00:00:00Z", "change": "created", "why": "閣領并格拆开"}]}
```

- `expected.cells` 是**整列**新格表（不是只写改的格），列图坐标（`cache/<册>/column_image/pPPPPcCC.png`），slot 从 1 顺排；
  `kind` 只许 `char`／`jiazhu_a`／`jiazhu_b`，夹注要写 `sub: a|b`，同 slot 的 a/b 共一个格位。
- 同一列只能有一行 active；要改就改那一行、加一条 history。
- 写完：`python scripts/zhengli/check_manual_cells.py <items.jsonl>`（格式）→ `scripts/seg_pins_check.py --book … --items …`
  （沙箱从 row_segment 跑到 cell_shrink：有没有静默丢字、人裁会不会失锚，出补锚草稿）→ `guji db pull --force` 后推库 →
  交单 `--from row_segment --pages …` → 出包后格号有变的按格号对照表 `guji swap run` 换进 book-text。
- 退役：`scripts/seg_pins_retire.py` 每轮列出算法已能自己切对的钉子；为下游钉的写 `expected.keep_for`，一律判留。
- 来历与实例：ai-team `domain/CV/质检/格子手工修复流程-manual-cells.md`（ZM 11-12）、`domain/CV/A22/史記切分经验-2026-11-10.md` 第三节。

## 五、各书怎么 customize

| 想改的范围 | 写哪 |
|---|---|
| 这套书所有册的 Step 参数缺省 | 书仓 `code/defaults.yaml` 的 `params:`（无书仓的走 `impl/<版式>/defaults.yaml`） |
| 这部书（一个工作区）共用的版本钉、书级共性 | 中心库 `config/book_defaults.yaml` |
| 一册一页的几何（第二节 1–5） | 册 yaml |
| 一列（第二节 7–10） | 格位表或 verdicts |
| 一类列的新切法 | 书仓 `code/` 覆盖 `impl/keben` 的模块或钩子（`doc/切分代码结构.md` 第三节），不要在书仓里放逐列坐标表 |

`guji book show --effective` 逐字段列参数来自哪一层（参数层见 `doc/design/册配置分层与运行覆盖.md`）。
