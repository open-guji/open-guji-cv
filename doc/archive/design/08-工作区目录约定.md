  归进 `source/`；两仓都补 `README.md` 与 `.gitignore`（照抄 zongmu 那份，删掉它专有的行）。

### 三.2 没做，留给用户裁（都是有代价的）

1. **bxrl 的 294 MB `glyph.db` 没有备份，也没进 git。** 它是播种长出来的、可以重跑重建，
   但重建要重跑一遍播种（上一次 25 分钟起步）；而且**人裁回流的那部分改判不在重建路径里**。
   > **09-26 实测更正**（本地道盘点）：北行日錄现代排印本的 db 里 `human` = 0、`events` = 0，24,884 条全是 align 播种＋字体渲染，可重建；那本书的两轮人裁落在 cv `config/confusable_human.json` 与 overview `报告/北行日錄校對本订正清单.md`，都在 git。store 已导出（20,683 条 align），db 与 store 备份在本机 `C:\guji-backup\beixingrilu-workspace\20260927\`；工作区仍不进仓（无 book-index ID）。
   两条路：① 补一次 `glyph_store` 导出，按 zongmu 那样 store 进 git、db 不进；
   ② 认定它可再生、只把播种脚本与人裁事件进 git。**建议 ①**，理由是记忆里那条
   「字形库是不可再生的人工产出」——第二轮人裁的 32 条已经在里面了。
2. **两个工作区要不要 `git init`。** zongmu 有 git，另两个没有。没 git 就没有
   「改坏了退回去」，而这两本书的 `books/*.yaml`、校對本订正、人裁事件都是人的产出。
3. **`bench/` 该不该是工作区的一部分**：它现在只服务北行日錄（样本写死逻辑页 9–18），
   放这里合理；但 `score.py` 是通用打分器，将来第二本书要评测就得复制一份。

### 三.3 yiwenzhi 没有证人语料——这件事要先说

北行日錄那条链的所有精度数字（same 覆盖 82.2%、精度 99.77%）都是**拿校對本当证人**量出来的，
播种也靠它（校對本列级对齐 20,852 个标签）。**考補萃編这本没有对应的电子文本**，于是：

- 播种没有免费标签，只能靠「字体 top-1 + 上下文」或人裁冷启动；
- 精度也没有免费的量法，`same` 档对不对只能抽样人看。

这正是方案 §九.8 那条纪律的现场：没有整理本时只剩「形状 × 上下文」一对，OCR 不能凑第二路。
**但这本书有一个别的书没有的便宜货**：它的内容就是本项目在整理的正史艺文志，
`open-guji/zhengshi-yiwenzhi` 私有仓 Releases 里有 27 卷的收藏（记忆 `project_kaobu_cuibian_status`），
其中若有第 20 卷的文本，就能当证人。**这件事要先查**，查到了整条链的成本结构完全不同。
