## 一、先说现状里已经有的、和真正缺的

### 1. 三态其实已经存在，只是没有名字

每个交接闸（Step1→2 `border_detect_gate`、Step2→3 `column_gate`、Step3→4 `row_segment_gate`）
逐列产出 `GateColumn{admitted, reject[], flags[]}`，这就是用户说的三态：

| 用户的说法 | 闸产物里的样子 | 现在谁消费 |
|---|---|---|
| **通过** | `admitted=True, flags=[]` | 下一步照跑 |
| **可疑** | `admitted=True, flags=[…]`；Step3 内部还有切点 `escalate=True`（多候选没人裁） | 切线裁决台按 `cut_pending` 出卡；其余 flag **没人看** |
| **失败** | `admitted=False, reject=[…]` | 下一步跳过这一列；控制台各步页面能看到；**没有"待办"的身份** |

「可疑经人裁 → 通过就记录、可考虑进测试集」也已经有：切线/逐列字数/抬头/边框裁决 →
`gold_add` 进 `open-guji-dataset` 分片，`resolved_cuts` / `resolved_slots` 回流 Step3 覆盖判定。

### 2. 真正缺的是三件事

1. **打回没有账**。Step7 审查卡上点「有噪声 / 字形不完整」，事件只落 `char-segmentation/instances`
   金标（给切分评测用），**没有任何东西把它记成"Step3 欠这一格一次重切"**。于是：
   - Step3 的页面不知道自己欠了什么；
   - Step7 台上它还在（或者靠 `skip_decided` 藏起来，但那是"已裁"不是"已修"）；
   - 第九步只能报一个笼统的"待审"。
2. **打回不撤下游**。人说这格切坏了，Step5–7 的识别结果照旧在产物里、9.1 照旧出字。
   `product_invalidate` 是**页级**的（把整页 `seed_admit` 标 stale），没有格级的"这一格的下游
   结果作废"。
3. **没有单一真相源**。看板、裁决台、各步页面各自从产物里数，口径各写一遍——今天「待审 73 vs
   卡 31」就是这么来的：73 里 42 个是**已裁过但机器没采信**的（复核页放出来的 seg_defect 格，
   库里没这个字形），看板把它们和真待裁的 31 个加在一起。

## 二、设计：一张打回台账 + 一个单元状态函数，产物一个字段不改

### 1. 单元（unit）与它的状态

单元是 `book:page[:col[:slot[a|b]]]`——页、列、格三级，打回可以落在任一级（Step7 说"这一列
整个歪了"就是列级）。**状态不存产物里**，是从四样东西现算出来的：

```
闸产物（各步 GateColumn）      → gate:  pass | flag | reject   （按步）
打回台账（本设计新增）          → returns: 落在本单元（含祖先：页打回覆盖它的列和格）的未结打回
事件日志（已有）               → decided: 人裁过 / 没裁过
Step7 产物（已有）             → admit:  放行 / 未放行
```

```
unit_status(book, page) -> [{unit, gate:{step: pass|flag|reject|-}, returns:[…], decided, admit}]
```

放 `report/unit_status.py`，**看板、各步"本步待办"卡、裁决台 `cards()`、9.1 全部改吃它**。
口径只写一遍，三处数字必然一致——这是这份设计里唯一不能省的东西。

### 2. 打回台账（returns ledger）

`<workspace>/feedback/returns/<book>.jsonl`，一行一条，只追加，状态变更追加副本（与
`_manifest.jsonl`、`crop_exclusions.jsonl` 同一纪律：可逆、可审计）：

```json
{"id": "ret_…", "unit": "bxgb:33:19:17", "level": "cell",
 "from_step": "seed_admit", "to_step": "row_segment",
 "reason": "seg_noise",                 // 枚举，见 §二·3
 "by": "human", "source_event": "evt_…", "note": "界行残留",
 "ts": "…", "status": "open",           // open | fixed | wontfix | superseded
 "retract": ["glyph_match","ocr_candidates","rare_candidates","context_decide","seed_admit"],
 "resolved_ts": null, "resolved_by": null, "geom_at_open": {"bbox_page":[…]}}
```

- `to_step` 是**打回给谁**——这一条就成了那一步的待办。
- `retract` 记打回时**撤了哪些下游步骤的结果**（§二·4）。
- `geom_at_open` 记打回那一刻的几何键（与 `core/reuse.py` 同一把尺）：目标步重跑后几何变了
  → 自动转 `needs_recheck`（还是 open，但多一个标记：图变了，值得再看一眼）；没变 → 照旧 open。
  **机器不自动结案**——"重切了"不等于"切对了"，结案要人看。

### 3. 谁产生打回、打回给谁、撤什么

打回是**事件的一个新去处**，不是新事件。现有事件按下表路由到新消费者 `return_to_step`：

| 来源事件 | 触发条件 | to_step | reason | retract |
|---|---|---|---|---|
| `confirm v=seg_defect quality=contaminated` | Step7 卡「有噪声」 | `row_segment` | `seg_noise` | Step5–7 该格 |
| `confirm v=seg_defect quality=truncated` | Step7 卡「字形不完整」 | `cell_shrink`（首/末格）/ `row_segment`（中）| `seg_truncated` | Step5–7 该格 |
| `confirm v=seg_defect defect=jiazhu_*` | 夹注面板段级缺陷 | `row_segment` | `jiazhu_split` | Step5–7 该段 |
| `cutline verdict=overlap/idk` | 切线裁不出来 | `row_segment` | `cut_unresolvable` | Step5–7 上下两格 |
| `n_body_slots` 与产物不符 | 逐列字数人裁 | `row_segment` | `slot_count` | Step5–7 整列 |
| `border_class` = glued/none 且人改判 | 边框裁决 | `border_detect` / `column_warp` | `border_wrong` | 整页 Step2 起（页级） |
| 新增按钮：Step7 卡「整列有问题」 | 人工 | `column_warp` | `column_window` | 整列 Step3 起 |
| 闸 `reject` | 自动 | 本闸挂的那一步 | `gate_reject:<reason>` | —（下游本来就没跑） |

最后一行是关键：**闸拒绝也进台账**（`by: "gate"`）。这样"失败"不再只是产物里一个
`admitted=False`，而是本步待办里一条有名有姓的账，人裁后关掉（`fixed`）或标 `wontfix`
（等算法）。闸重跑时按 `(unit, reason)` 去重，不重复开账。

**reason 用固定枚举**（`feedback/returns.py::REASONS`），别让人自由填——第九步要按它分桶。

### 4. 打回的下游效果：撤回，但不删产物

用户要求「最好把后面的 step 结果撤回」。做法与排除名单同构，**不改产物文件**：

- `seed_admit` 读台账（像读 `crop_exclusions.jsonl` 一样）：落在 open 打回范围内的格，
  `admit=False, doubts=["returned:<to_step>:<reason>"]`，字形层不进库（`glyphdb_admit` 同样看）；
- `report/slots.py`：`returned` 的格文本层出阙文 `[[]]`（占位，和 seg_defect 同一条理由：字在，
  只是现在这块图不能信）；
- `review/cards.py`：`returned` 的格**不出定字卡**——它现在是 Step3 的事，不是 Step7 的。
  这就是用户说的「不需要出现在 Step7 的未裁部分」；
- Step5 三步（glyph_match/ocr/rare）**照跑**——它们便宜且逐格复用，撤回发生在采信层（Step7）
  而不是计算层。这样打回结案后不用再跑 Step5。

页级/列级打回同理，范围按前缀展开。

### 5. 结案

目标步的页面加一块「本步待办」（§三），每条 open 打回一张卡：当前图块 + 打回时的图块
（`geom_at_open` 能重裁出来）+ 原因 + 来源。人三选一：

- **已修**（`fixed`）→ 下游采信层恢复，这一格回到 Step7 待审（若尚未人裁）；
- **不是问题**（`wontfix`，注明原因）→ 同上恢复，且这条进测试集当负例（用户：可考虑加入测试集）；
- **等算法**（保持 open，标 `blocked_on: algorithm`）→ 继续撤回，第九步单列一桶「等算法」。

自动辅助：目标步重跑后该单元几何变了 → 标 `needs_recheck` 并把卡排到最前；没变 → 卡上写
「重跑过一次，图没变」——人一眼知道这轮修没修到它。

### 6. 「可疑」怎么进这套

闸的 `flags`（可疑）与切点 `escalate` 现在只有切线那一类出卡。统一成：可疑 = **本步待办里
一张"复核"卡**（不是打回，是本步自己的），人裁 → 通过就 `gold_add` 进对应分片（已有），
不通过就转成一条 `by: "human"` 的打回（对本步自己，reason 取 flag 名）。这样"可疑→人裁→
失败→撤下游"这条链闭合，且每一步都走同一个形状。

## 三、各步页面与第九步看板长什么样

**每步页面顶部一张「本步待办」卡**（与 Step9 的看板同一个组件、同一个数据源）：

```
Step3 本步待办 · 页 3–56
  闸拦下（失败）  4 列     可疑待复核  8 切点     打回待处理  12 格（Step7 打回 11 · 逐列字数 1）
  等算法 2 · 重跑后图已变、待复看 3
  [列表：单元 · 来源 · 原因 · 状态 · 打开裁决台]
```

**第九步看板**改成按"谁的活"分列，不再一个笼统的「待审」：

| 页 | 过期 | Step1–4 待办 | 其中等算法 | Step7 待人裁 | 已裁未放行 | 阙文 | 坏列 |
|---|---|---|---|---|---|---|---|

- **Step1–4 待办** = 各步 open 打回 + 闸拒绝 + 可疑待复核（点开按步展开）；
- **Step7 待人裁** = 未放行 ∧ 未裁过 ∧ 不在打回范围——**与裁决台出卡数逐条相等**（同一函数）；
- **已裁未放行** = 未放行 ∧ 已裁过——人做完了、机器没采信的那一档，单独列，别再混进待办。

## 四、与现有机制的边界（不做什么）

- **不改产物 schema、不改指纹**。台账在 `feedback/` 下，与裁决表、排除名单同级；
  Step7/9.1/cards 读它的方式与读排除名单一样。
- **不做自动结案**。几何变了只标 `needs_recheck`。
- **不回溯造账**：接上 `return_to_step` 那一刻起的事件才进台账；历史 seg_defect 事件（bxgb
  1,150 条已裁里的那批）用一次性脚本按上表回填，且只回填**现在仍未放行**的格——已经放行且
  与整理本一致的，说明后来修好了，不欠账。
- **闸的判据本身不动**。这份设计只给闸的输出一个"待办"的身份，不改它怎么判。

## 五、数据一致性的验收

写完要过这三条，缺一条就是没做完：

1. `guji progress` 的「Step7 待人裁」== 裁决台 `cards(pages=all, only=review)` 的卡数，**逐 id 相等**；
2. 每一条 open 打回，在 `to_step` 的页面看得见、在 Step7 台上看不见、在 9.1 里是 `[[]]`；
3. 结案（fixed/wontfix）后 Step7 台上重新出现（若未人裁）、9.1 出字，**不需要重跑任何步**。

## 八、当天已落地的部分（2026-09-20 傍晚，§六 第 1 行 + 两个顺手查出的死角）

拆看板时把「待审 73」拆开一查，发现的不是一个数、是三个 bug，都修了：

1. **看板拆列**（`report/progress.py`、`ProgressBoard`）：`review` → `review_new`（Step7 待人裁 =
   未放行 ∧ 未裁过 ∧ 不在名单）+ `review_decided`（已裁未放行）。验收 §五·1 过：**看板 62 ==
   裁决台 62，逐 id 相等**。
2. **`decided_cells` 把 seg_defect 当"裁过"**（`review/verdict_view.py`）：人点「有噪声」只是说这块图
   先别用，没定字。42 个「已裁未放行」里 **31 个从没定过字**——排除名单撤了之后它们回到待审，
   `skip_decided` 却把它们永远藏起来。现在 seg_defect 不算裁过；`cards()` 同时显式跳过名单上的格
   （此前靠这个误算顺带藏住）。
3. **人勾「字形不入库」的定字，Step7 当没裁过**（`feedback/lookup.human_chars` + `seed_admit` 1.7）：
   Step7 只从字形库拿人裁，不入库的裁决根本不在库里——5 个（一/吏/邢/太/伋）人定了字、
   文本却一直出阙文、台上又不出卡。现在文本采信走事件日志，进库才看字形库，两条路分开。
   另 6 个是裁了之后 Step7 没重跑（confirm 路由缺 `product_invalidate`，当天上午已补）。

重跑 Step7 后：**已裁未放行 42 → 0**，Step7 待人裁 31 → 62（那 31 个被藏起来的回来了）。
这正是 §一·3 说的「单一真相源」缺席的代价：三个消费者各自解释"裁过"，各错一处。§六 第 2 行
（`unit_status`）做完之前，这类不一致还会再出现。
