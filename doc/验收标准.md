# 四大步、小步的验收标准

2026-11-28 用户定（审查与来由见 Claude Doc《CV 四大步审查与验收标准》https://claude.ai/artifact/GfWY5oYGTF3V5yp4NXe14v ）。
这一期**不定分数门槛**，只要求四件事：接口清楚、文档清楚、按 book-id 和册可控、可测试。
各线合 PR 时按本页验收：新增或改动的小步要满足下面 12 条；做不到的条目写进该小步文档的「已知缺口」，写明缺什么、谁补。

## 一、每个小步（S1–S12）

| 编号 | 维度 | 要求 | 怎么验 |
|---|---|---|---|
| S1 | 接口 | 一个小步对应一个 Step id（或明写「逻辑分组，代码在 X」）；在骨架 `stages:` 里只归一个大步；编号（2a…2e、3a…3e、4a…4d）与 Step 显示名一致，显示名不再用 Step3、Step5-a、C1 这类旧号 | 大步 README 小步表与骨架对得上（`tests/test_stage_docs.py`） |
| S2 | 接口 | 输入只有三类：`consumes` 声明的产物、声明的配置键（`params`、`book_deps`）、声明的钉子（corpus、glyph_pin、model、code、pua_table_pin）。不靠环境变量改产物，不读别的小步的内存结果 | 代码审；指纹覆盖守卫 |
| S3 | 接口 | 输出产物每个字段写明类型、含义、坐标系、空值含义，写到格级；小步关闭时产物缺席、下游怎么退回也写明 | 产物类字段注释，生成进 `步骤与产物.md` |
| S4 | 接口 | 改产物格式、改名、拆步：PR 写明 L0–L3 与影响哪几步，先通知 GM2–GM4，新旧名并认一段时间。改了步骤、新加步骤，或改了产物键、步名、参数的 PR，合进 dev 前请 GM2 拿该分支跑 manager 全套测试，全绿才合（总管 11-28 定，见 [版本号规矩.md](版本号规矩.md) 第三节第 8 条、ai-team `domain/通用/规范/cv改步骤先跑manager全套.md`） | PR 描述写「manager 全套：GM2 已跑，全绿」 |
| S5 | 文档 | 大步目录下有本小步一节：做什么、不做什么、输入、输出、开关、代码入口、benchmark、测试集、已知缺口（样板：[4-定字/子步.md](4-定字/子步.md)）。参数表用生成的，边界手写 | 人审 |
| S6 | 文档 | 写明从哪个 cv 版本起有、哪些补丁线没有（殿本 0.7.x 线、史記线等） | 小步文档或生成表 |
| S7 | 可控 | 每个参数有推荐层级：全局（代码缺省）／组／书（`book_defaults`）／册（册 yaml）／页（页段表）。新行为缺省关，用 `params.<步>.enabled` 按书或按册开 | 参数说明 |
| S8 | 可控 | 生效值全部进指纹；`book show --effective` 能显示每个值来自哪层 | 指纹覆盖守卫 |
| S9 | 可控 | 只给一部书用的行为放书仓 `code/`（k<N>），不在 cv 加单书开关 | 代码审 |
| S10 | 可测试 | `tests/` 有自造数据的单元测试；缺省关时产物逐字节不变有一条测试 | CI |
| S11 | 可测试 | 有一条「只跑本小步」的 benchmark：冻结上游输入，写明主指标和必须为 0 的护栏，按书报分，带翻转清单。脚本住在跟版本走的仓（cv `eval/` 或 manager 评测器）并在 [bench登记表.md](bench登记表.md) 登记 | 干净环境能跑 |
| S12 | 可测试 | open-guji-dataset 有分片（items.jsonl 信封、`label_origin`、按书子目录），金标挂在不随切分变的键上；随机页与难例分开；写明覆盖了哪几部书、缺哪部 | 登记表「覆盖」列 |

## 二、每个大步（B1–B6）

| 编号 | 要求 |
|---|---|
| B1 | README 的小步表与骨架 `stages:` 一一对应，由测试守住 |
| B2 | 写明本大步交给下一大步的产物（大步契约）；有收尾的，收尾是唯一出口；出口 gate 只检测、不改产物 |
| B3 | 有整步验收表：动哪个小步跑哪个 bench、什么算回退（样板：CV4 第四步设计第五节） |
| B4 | 有按书的基线报告：各小步主指标＋整步指标，注明 cv 提交与数据钉子，放仓里（cv `doc/` 或 dataset），不只在 Claude Doc |
| B5 | Wiki 有对应页：这一大步做什么、怎么按书开关、典型例子截图。新增小步、改大步划分时，即使发 PATCH 也要改 Wiki |
| B6 | 每部在用的书有一段本大步的生效配置摘录（`book show --effective` 节选），放各书登记文档 |

## 三、各大步的契约与护栏

不定分数，但每个大步有「必须为 0（或不增）」的护栏，改动不能让它变坏。

| 大步 | 交给下一步 | 主指标（按书） | 护栏 | 测试集至少覆盖 |
|---|---|---|---|---|
| 1 版面 | `borders`、`seals`、页型闸 | 框线、界行位置误差；列数；页型 | 正文页判成非正文；印章漏认压字 | 殿本、史記、全唐文、脉经，各有随机页＋难例页 |
| 2 切字 | `cells`、`char_index`、`char_patch`、`cut_gate` | 列字数全对、列全对、格 F1 | 好列被改坏；字身墨被切掉（2e） | 同上＋朱楓林集、汉书 |
| 3 识字 | `glyph_analyzer`（候选＋p＋证据） | 未定格前 1、前 10 命中；校准 p 的 ECE | 库外字误认成 same；形近字组内误判 | 殿本、史記、全唐文＋至少一部新书 |
| 4 定字 | `char_decide`（放行、送审与 `pending_reason`）、`decide_gate` | 放行率；拦住·首选对率 | 放错字；4c 漏字；4d 判定格错字 | decide-bench small／large＋史記＋脉经 |

## 四、配置层级

1. 只有六层可以改产物：全局（cv 代码与仓内登记表）、组（一套丛书或一种版刻字体；字形、语料、模型各有各的组）、书（中心库 `config/` 与书仓 `code/`）、册（`books/<册>.yaml`）、页（册 yaml 里的页段表）、本次运行（`--override`，只记 manifest）。环境变量只管路径、缓存、调试、密钥。组这一层还在设计中。
2. 每个配置键登记推荐层与禁止层，写错层报错或警告（现在只对身份、实测先验做了）。
3. 权威说明只有一份（guji-manager `doc/参考/册配置.md`），cv 侧只放链接；字段释义从 `BookSpec` 注释生成。

## 五、适用范围

古籍默认链（刻本与自由版式）都按本页验收；现代排印链另定。链条分类的调整见后续设计。
