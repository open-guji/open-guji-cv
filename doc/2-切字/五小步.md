# 2 切字的五小步（2a–2e）

> 2026-11-25 用户定：第二步分五小步。2a `column_warp`、2b `column_band`、2c `column_end` 已拆成独立 Step（cv #1869），2d `row_segment`、2e `cell_shrink` 原本就是独立 Step；另有 `column_geometry`（列几何）和出口闸 `cut_gate`（cv #1872）。拆步方案见 [../design/2-切字-五小步拆成独立Step.md](../design/2-切字-五小步拆成独立Step.md)。验收按 [../验收标准.md](../验收标准.md)。

坐标约定：「页」坐标是原图（右上角原点、y 向下的新坐标系）；「列图」是拉直后的竖直矩形（左上角原点），列内坐标一律用列图的像素。

## 一、五小步的输入输出

| 小步 | 做什么 | 输入 | 输出 |
|---|---|---|---|
| **2a 拉直** | 用左右两条界行线（可为三段折线）把每列做射影变换，拉成完整矩形；去孤立小墨点 | `raw_page`；第一步的 `borders`（上下版框、内框线、每列左右界行线）、页型闸 | 每列的 `column_windows`（窗口、上下界、`border_*_in_column`）、去噪后的列图 `column_raw` |
| **2b 定字带左右边** | 竖直墨量投影找左右两端：旧算法按 240 行横条判带、抹界行；再用新切点（只取上下边框之间、各让 60 行，认出框线后在框线内侧 15% 列宽内取第一个够低处、往里缩 2px）把切点外整列抹白（不裁，坐标不变；`column_band.side_cut`，缺省开） | `column_raw` | 每列文字带 `band`（旧算法）；两侧已抹的列图（切点不进产物） |
| **2c 列端字** | 首、尾紧挨着上下版框的格：判是否只有框线、剥框线、按内框线位置切（列端曲线切边） | `column_banded`、`column_bands`、`column_windows`（`border_*_in_column`）、`borders` 的内框线 | `column_ends`（`trim_top`／`trim_bottom`、首尾格类别）；列图 `column_image`（上下端已抹版框墨） |
| **2d 字间切分** | 沿竖直方向找字缝：整列等距格网先验＋U-Net 选缝，字数来自先验（整理本、版式格数） | 清理后的列图 `column_image`、`band`、版式先验、人定切分（`切分覆盖.md`） | `cells`：每格的上下界、类型、读序 |
| **2e 字框压缩** | 每格里取字身连通体，收成紧框；剥格内残余界行竖条、框线 | 每格 `cells`、列图、`band` | `char_index`（紧框＋flags）、`char_patch`（字块图） |

## 二、每小步的边界（便于分析）

- 2a 只管几何：不判墨、不找界行；折线按折点分带，每带一个矩阵；`ruled_warp` 是逐行插值的另一种拉法（缺省关）。
- 2b 只用墨量投影，对象是列图的**左右两端**。旧算法分横条（240 行）各找一次，写本用 `tight_rule_band`、全唐文用 `inner_bar_span`；2026-11-25 起再整列一次投影定左右切点，切点外整列抹白（`side_cut`）。**2d 仍用旧算法的 `band` 宽度**：字带窄 1～3px 史記切线就大片挪动（测试集列全对 287→264／274），2d 改成不依赖带宽之前不换。新切点的短处：点线、双线里的细内线（墨占比 < 0.3）认不出，靠旧算法那一遍抹。
- 2c 是唯一同时用上下版框坐标和字墨的一步：先处理首、尾紧挨版框的格，再交给 2d 切字间的缝（2026-11-25 用户定：先切收尾和边框连接处，再切字与字）。
- 2d 只在字带内切缝，不看版框；列端已由 2c 处理。
- 2e 只改框，不改 2d 的格线；不能丢字身墨。

## 三、五小步与现有代码的对应

| 小步 | 现在在哪个 Step 里 | 入口函数 |
|---|---|---|
| 2a | `column_warp` | `seg/warp.py`：`page_column_windows`、`warp_column`；`seg/profile.denoise_column` |
| 2b | `column_band` | 旧算法 `seg/profile.column_text_band`、`impl/keben/column.strip_column_rules`；切点 `seg/side_cut.side_cut_points` |
| 2c | 主体在 `column_end`（`column_border_trim`，列图上下端抹框）；另有两处散在 `row_segment`（列端判空 `frame_only_edge_cells`）、`cell_shrink`（`strip_frame_line`、列端曲线切边） | 同左 |
| 2d | `row_segment` | `impl/keben/row_boundaries`、`row_grid`、`seg/seam`（U-Net 选缝） |
| 2e | `cell_shrink` | `clustering/extractor`：`strip_side_rule`、`strip_frame_line` |

所以：**2a–2e 各有自己的 Step，只有 2c 的判据还有一部分散在 `row_segment`、`cell_shrink`。** 分析某一小步的问题时，先按这张表找代码，不要只按 Step 名找。

## 四、已知缺口（待定）

- 2b 的输出原本只是「抹掉界行」。2026-11-25 起 `side_cut` 定出左右切点并抹白，但 2d 对字带宽度太敏感，还在用旧 `band`；切点还没进产物给 2c、2d、2e 共用。
- 2c 的逻辑散在三个 Step，各用各的判据（见 `doc/经验/切分四步-研发记录.md`）。
