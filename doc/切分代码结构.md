## 二、原语库 `seg/` 有什么

| 模块 | 内容 |
|---|---|
| `lines` | 投影、半高宽找峰、倾斜投影、位置＋角度联合搜一条直线；整页找竖线 `find_vertical_lines`、上下框线 `find_horizontal_border` |
| `grid` | 网格模式：列数已知、列距均匀时逐槽验线、缺槽插值（`find_vertical_lines_grid`、`grid_thresholds`） |
| `polyline` | 界行按弯度拟直线或三段折线（`fit_vlines_polyline`） |
| `frame_types` | 边框结果的数据类型（右上原点的 HLine／VLine／HeadRaiseBorder／BorderDetectionResult） |
| `warp` | 单列射影矫正（`warp_column`）、列窗口（`page_column_windows`） |
| `profile` | 列图去噪、横纵投影、文字带（`denoise_column`、`column_profile`、`column_row_profile`、`column_text_band`） |
| `seam` | 最省墨走缝、缝上墨量、缝外抹白 |
| `cut_select` | U-Net 切点裁判与引导缝 |
| `locate_gutter` | 找书口 |

## 三、各书怎么做自己的切分（书仓 `code/`）

1. **代码放书仓 `code/`**，挂成 `guji_book.<name>`。只 import `open_guji_cv.seg`、`open_guji_cv.book_api` 和本书模块
   （`guji code check -w <书仓>` 查）；书之间不互相 import，要用就复制。
2. **改刻本缺省实现里的某个模块**：把 `impl/keben/<模块>.py` 复制进 `code/`，在 `code/code.yaml` 的 `overrides` 写
   `keben.<模块>: <本书模块>`。指纹跟着换，只这本书的产物过期。
3. **参数缺省**写 `code/defaults.yaml` 的 `params:`；个别册的细调照旧写册 yaml。
4. **样页单** `code/samples.yaml`；本书测试放 `code/tests/`（`conftest.py` 借 cv 仓 `tests/helpers`，不进指纹）。
5. **发版**：`guji code release -w <书仓>` 出 `code/releases/k<N>.json` → 提交、推 main → 打 tag `k<N>`（云端走中转站
   `python3 process/tag.py guji-workspace/<书仓> <提交> k<N>`）→ 书配置写 `code: N`。钉了 `code: N` 的册起跑前比对清单，
   `code/` 下改了任何代码文件就拒跑（`*.md` 不算），所以改完先出新版再交单。
6. **新书**：像哪条版式就在书配置写 `seg_set:`（走缺省实现，不用建 `code/`）；要改代码再建 `code/`，`name` 就是新的 seg_set。
7. **只给一本书用的新行为不再往共用 Step 里加「缺省关、按书开」的开关**：复制模块进书仓再改；要改的地方不在可覆盖模块里，
   找架构维护人开钩子点。

样页对比（cv 改动牵动哪几套书；`GUJI_WORKSPACE` 指向书仓时也认它的 `code/` 样页单）：

```
python scripts/seg_samples.py affected --base origin/dev
python scripts/seg_samples.py local --set <套书> --ws <册>=<工作区>
```

## 四、什么时候找架构维护人

- 改 `seg/` 里任何函数的行为（修原语的 bug 也算）——要跑**全部**套书的样页、每个变化点名；
- 往 `seg/` 加新原语（两套书以上要用、或明显通用的看图操作）——原语参数写在签名上、带自造数据的单测、**只加不改**；
- 改 Step 壳、`core/seg_set.py`、`core/book_code.py`、`book_api`（书级代码的公开面，改签名或删是 MINOR）、产物指纹（`core/engine.py`、`core/code_equiv.py`）、`tests/test_architecture.py`；
- 搬家、拆模块（要登记 `code_equiv` 的 MOVED／SPLITS 才不让各书产物过期，工具 `scripts/seg_move.py`）。
- 书仓里的副本会和缺省实现各走各的：改 `impl/keben` 的模块后，告诉覆盖了同名模块的书（史記、全唐文）看要不要跟。
  `scripts/seg_fork_drift.py` 只认 cv 里的副本，书仓版待做。
- 书仓搬家、只改 import 时想让产物不过期，在书仓 `code/equiv.yaml` 登 moved／forked／entries（见 `core/book_code.py`）。

其余——在书仓 `code/` 里改算法、调参数、加页型分支、改样页单、出新版——各书自己做，不用等 cv 发版。

## 四之一、各书通用的切分检查工具（只出报告，2026-11-10）

各书清切分时用，都只读产物、不改指纹（设计：Claude Doc《切分框架改进详细设计（F1–F8）》；口径：ai-team `domain/CV/A22/切分清零口径.md`）。

| 命令 | 做什么 | 什么时候用 |
|---|---|---|
| `scripts/seg_screen.py --books …` | 列首列尾漏墨、端格只有版框线、整页列网错（列宽比、外框到页边距离离群）、格位表整页错一列（格号挪一列、一页 ≥2 列退回几何切）、表写 `pitch: free` 没生效；`--seal-blank` 列出 seed_admit 会按印框记空的格 | 每轮出包后，找要看图的列 |
| `scripts/seg_pins_check.py --book … --items <新钉子>` | 沙箱里用新钉子从 row_segment 跑到 cell_shrink：钉子格有没有静默丢字、照执行机条件人裁会不会失锚，出补锚草稿 | 推 manual-cells 之前 |
| `scripts/seg_pins_retire.py --books …` | 本册钉子全拿掉在沙箱里重切，列出算法已能自己切对的钉子（只比几何；为下游钉的在 item 写 `expected.keep_for`，一律判留） | 每轮或算法改进后 |

**格级钉子（manual-cells）与格位表 `cuts` 的分工**：`cuts`（第 5 层）只定整列 y 格线，格号、夹注照表，进语料版本、跟指纹走；
manual-cells（第 6 层）每格框都定（含夹注 a/b、x 范围），正文页、职名页都认（职名页在 `_run_roster` 之后套），不进指纹，
推了要交单从 row_segment 重跑涉及页；同列两者都有时钉子赢。书仓 `code/` 只放「一类列」的新切法，不再放逐列坐标表。

## 四之二、套书的缺省参数与选管线（2026-11-03，管线重组方案 B 第一期）

- 基础配置里 `row_segment.layout_prior` 可以写 `{book}` 占位（`core/book_config.BOOK_PLACEHOLDER_FIELDS`，2026-11-06），按册 id 展开，展开后的值与逐册写死相同、指纹不变。
- 册 yaml 写 `seg_set:` 就够了：走哪条管线由 `core/seg_set.SEG_SET_PIPELINE` 推（旧写法 `pipeline:` 仍认，且优先）。
- 同一步在这套书下的缺省参数写 `impl/<版式>/defaults.yaml`（缺省实现）或书仓 `code/defaults.yaml` 的 `params:`（形状同册配置 `params:`）。
  参数层（低 → 高）：Step 默认 < 管线 yaml `params:`（现已搬空）< 套书缺省 < 基础配置 `book_defaults.yaml` < 册 yaml < 运行覆盖。
  `guji book show --effective` 逐字段列来源层。
- **骨架＋槽位**（第二期）：步骤顺序只在 `pipelines/_skeleton.yaml` 写一遍（Step0、`layout`／`seals`／`columns`／`cells`／`recognition` 五个槽位）；
  各链 yaml（`keben_body_v2`、`modern_body`、`keben_free`）只写槽位里放哪几步，`core/pipeline.load_pipeline` 按骨架展开。展开结果与改动前的 `steps:` 逐项相同，步骤 id、产物目录、指纹都没动。
  新增共用 Step 改骨架一处；新增一套书的链 = 新建一个只写槽位的 yaml（`layout`、`columns`、`cells` 必填）。链里写错槽位名会报错，不会悄悄不生效。
- Step 壳按套书拆开的现状没变：`border_detect` 是殿本的 Step1、`line_detect` 是北行的、`block_detect` 是幼學的，各自 import 自己套书的代码。
- 幼學 Step4 以后（`free_cells` → `cells`、列图）还没接：本书没有语料与字形库，先把切分做对；要接时在这里补转换。
