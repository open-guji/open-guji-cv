# cv 仓版本号规矩

> 来源：GUJI-491b 第 6 步；Mila 2026-10-16 初定。2026-10-17 据用户意见定稿（去 `cv-` 前缀、MINOR／PATCH 口径、滚动发版；同日再据用户更正，Step `code_hash` 变化本身不算 MINOR），依据 ai-team `team/CV/Mila决定-10-14.md` 末节「版本规矩定稿」。
> 时间一律洛杉矶时间。

## 一、格式

- 版本号 `MAJOR.MINOR.PATCH`（语义化版本的子集），git tag 写作 `vX.Y.Z`，如 `v0.2.0`。
- 基线 `cv-v0.1.0` = 重写后 main `26657f84`（2026-10-16），**旧 tag 保留作历史，不动**；此后的版本一律不带 `cv-` 前缀。重写前的历史不再编号。
- 只用 **annotated tag**；tag 一经推送不改、不删、不挪。要修正就发新 PATCH。
- 预发布用 `vX.Y.Z-rc.N`；rc 只用于验收，正式版本不得以 rc 为依据。
- **rc 打在 `rc/vX.Y.Z` 分支上，不打在 main 上**（用户 2026-10-17 定）：从 main 开 `rc/vX.Y.Z`，发版准备（CHANGELOG／RELEASES／版本号）与要验的改动先进这条分支，在其上打 `-rc.N` 做实验；验收通过后才把分支合进 main，并在 main 的合并提交上打正式 `vX.Y.Z`。不通过就在分支上修、出 `rc.N+1`，main 不受影响。
- 旧的 `release.yml`（exe 打包／自动公开发布）已停用，移至 `doc/archive/release.yml.legacy`，推 tag 不再触发构建。GitHub Release 页由 Owen 手动建（目前无发布物）。

## 二、怎么升版（0.x 阶段）

| 档 | 条件 |
|---|---|
| **MINOR**（0.X.0） | 只有两类：① 新增对外能力：新 Step、CLI 命令、导出或交换格式及其版本（如 guji-proof 0.2）、公开接口模块；② 重大性能提升、算法改进 |
| **PATCH**（0.x.Y） | 其余一切：bug 修复、小调参、重构、测试、文档、依赖／打包／CI、未被任何 Step 引用的内部模块；**包括 Step 的 `code_hash` 变了但不属上面两类的改动** |
| **MAJOR** | 近期不升；到格式与流程稳定、定 1.0 再议 |

- `code_hash` 变化**不决定档位**，但**必须登记**：它会让各册已有产物判为过期，PR 描述和 `RELEASES.md` 的影响清单要写明哪几个 Step 的 `code_hash` 变了（合前实算，对比合并前的 main），便于判断是否重算。
- 拿不准时往大的升，并在 PR 描述里写明理由。同一个 PR 含多类改动时，按最大的一类升。

## 三、发版节奏与谁打 tag

- **不攒批**：动代码的 PR 合入后，由合并人按上表判档并告诉 Owen，Owen 在 **main** 上打 `vX.Y.Z` annotated tag；正式 tag 不打在分支上（rc 例外，见第一节）。同一档内多个 PR 可合并为一次发版。
- 打 tag 前：CI 绿、PR 已合并、`code_hash` 已按窗口规矩核过（如有窗口在跑）。

## 四、记录分工：CHANGELOG、Release note、内部跟踪（用户 2026-10-17 定）

- **`CHANGELOG.md`（仓根）＝完整记录，含 PATCH**：Keep a Changelog 风格，每个版本一节（PATCH 也有）。动代码的 PR 在 `## [Unreleased]` 下加一行；打 tag 时把 Unreleased 改成该版本节。
- **`RELEASES.md` 小节＋GitHub Release＝仅 MINOR**：release note 按 **Added／Changed／Fixed／Removed** 分条，每条一行，不写内部票号长文，影响清单写明哪几步 `code_hash` 变了。

| 档 | 打 tag | `CHANGELOG.md` | `RELEASES.md` 小节 | GitHub Release | 内部跟踪 |
|---|---|---|---|---|---|
| **MINOR** | 打 | 写 | 写一节 | 建（Owen 手建，正文即 release note） | 登记 |
| **PATCH** | 打（版本号照升） | 写 | **不写** | **不建** | 登记 |

- **内部跟踪**登记在 ai-team `team/CV/各册产物cv版本登记.md` 和台账：版本、sha、`code_hash` 是否变、哪些步指纹变、产物是否过期。

## 五、产物如何记录版本（manifest，窗口甲后再加）

- manifest 新增两个字段（**窗口甲后再加，本次不改**）：
  - `cv_version`：生成产物的代码所对应的最近一个 tag 的版本号（去掉 `v`／`cv-v` 前缀），如 `"0.2.0"`。
  - `cv_commit`：生成产物时的完整 commit sha。
- 非 tag 版本生成的产物，`cv_version` 写 **`最近 tag+N`** 形式，如 `"0.2.0+12"`。
- 有 `cv_version` 的产物，才能被视为可对比、可复现。
