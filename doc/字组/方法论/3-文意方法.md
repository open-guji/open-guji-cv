# 3. 文意方法

[← 总览](README.md)

文意方法是不同义组的主力。它分三级，后面再加两种强化：二审小组、图像＋文意 L4。层级的叫法是 sheldon 10-28 定的：L1 规则、L2 训练好的模型、L3 大模型。

## 3.1 先验证文意有没有区分力

上线文意路之前，要先在**已放行格**上验证文意能不能区分这几个字。

- 两个字放进句子里都说得通的对子，文意路无效。宋朱未、各名、心必 上已放行格的不一致 21 格全是文意错，所以这几组改走整字 HOG。
- 入人八、戊戌 的字形本身判不了，必须读上下文。

## 3.2 三级与两种强化

方法数组里，文意是一个子数组 `Chain`：L1 固定搭配 → L3 答案表 → L2 模型 → L3 在线，第一个给出字的说了算。表排在模型前面，因为表里读过的格有多家 strong 票；模型只补表里没有的格。L3 在线只问前面都给不出字的格。

| 级 | 是什么 | 放行条件 | 用在哪 | 成本 |
|---|---|---|---|---|
| **L1** | 固定搭配规则（`config/groups/<组>/rules.yaml`，前后各 20 字的词组或正则） | 规则命中 | 所有文意组，最先跑 | 0 |
| **L2** | SikuRoBERTa 冻结编码器取目标位向量，加逻辑回归小头（`config/groups/l2model/*.json`），再加「其他字」护栏 | 中档门槛 p≥0.99。按册留出覆盖 ry 87%（错 5/8,668）、rm 83%（错 1）、jys 84%（错 0） | ry rm jys | 本地 CPU |
| **L3** | Claude 在线（`groups/ctx_llm.py`），只收 conf=high；结果按上下文哈希缓存进裁定库 `feedback/rulings` | high | L2 没过门槛的格 | 约 1.7 美元／600 格 |
| **二审小组** | Opus-high 和 Fable-high 两家各自独立读同一格（`ctx_llm.panel_verdict`） | 两家同字、都不低于 mid、至少一家 high，才记 strong | ry rm mz jys | 只问 L3 没定的格 |
| **图像＋文意 L4** | 字块图加前后文，问一次大模型（`groups/vis_llm`） | high＋组员＋另有一个证人同字；**整理本在组里说另一字时不越过** | zy yz men wj guanm chuo yh xuan | 约 370 次调用／276 格 |

### L1 规则

- 规则是从已知册的整理本里挖出来的，所以在这些册上零冲突是必然的。**一定要拿没见过的册回测**（己已巳 的 L1 在册外回测时修了 8 处）。
- 殿本的书名规则：「而已」→已；《己易》（楊簡）→己；《讀易日鈔》《黃氏日鈔》→日；「寶巴」的 巴 是字外字。
- 干支：右字是 丑卯巳未酉亥 时只许 己。

### L2 模型

- 选择过程（10-27）：纯 n 元组逻辑回归在零错时只覆盖 30–40%；SikuRoBERTa 不训练直接 [MASK] 填空，日曰 与表一致 99%，己已巳 只有 90%；冻结编码器加小头最好；微调后 4 层反而更差（零错覆盖 67%）。
- **「其他字」护栏**：模型对组外形近字（自臼白田口甘旦四百、目、曰；jys 的 巴乙且旨）的填空分，与所判字的分差要小于 d 才给字。门槛：ry d=−1、rm d=0、jys d=1。
- **模型可以跨书**：表里已有答案的格，模型在零错门槛下复现 ry 80%、rm 87%、jys 80%，0 格判反。新书不建表也能先放八成。
- 不要再按格存表（[分篇 6](6-人审边界与负结果.md)）。表只当标注库用。

### L3 大模型

- 管线直接调 Claude（变量 `GUJI_ANTHROPIC_API_KEY`），统计 token 用量。
- 没有 key 的机器，或没装 `anthropic` 的机器，**只读缓存、不报错**，缓存没命中就弃权（cv#779）。有 key 的地方先把要问的格预跑一遍写进裁定库，别的机器就直接命中缓存。殿本预跑了 42,890 条。
- 提示词里的书名要按书改（`book_desc`）。提示词版本进缓存键，改提示词等于全部重问。

### 二审小组

- 单个模型用 high effort 也有 0.5–1% 读反的情况，所以要两家同字。两家都只有 mid 的格不收。
- 什么时候问：首问不是「组内字、high」；或首问的字与整理本不同；或前面各层没给出字；或文意与字形冲突；或补放被坐标对位拦住。
- 小组确认的字可以越过整理本补放（`strong_over_ref`），复核时也可以改字（`review_fix_strong`）。别的组的 strong 语义没验证过，不要随便开。
- 验证：己已巳 金标 215 格 0 错；日曰 金标 108 格错 3 格，按文意读都是小组对、金标是按刻字定的旧标。回放 414 格降到约 134 格。细节见 [文意二审小组.md](../文意二审小组.md)。

### 图像＋文意 L4

- 用途：整理本与文意各错一半、哪一路都不能单信的组（门辶、于千子干）。抽 14 格看图，整理本错 7 格，文意错 7 格。
- 规则：图像加文意判 A，但整理本在组里说的是另一个字 B 时，**不越过整理本**。反例 vol35:152:2:4「干文傳」，图像和 L3 一起错成了 于。
- 验证：留出 360 个已放行格，high 307 格里 303 格与放行字相同；276 格回放降到 173 格，看图 0 明确错。

### 文意组的字形第二路

文意弃权时，可以用字形补放（cv#429）。适用于 11 个文意组：入人八、土士、論諭、問間、曾會、遺還、圓圖、甲申、而面、傅傳、一二。

- 门槛要同时满足两个条件：人裁 0 错，放行异议 ≤0.2%；再乘 1.1，最低 0.4。
- 训练字块必须用线上同款的 `char_patch`。
- 大太、未末、王玉、目自、千干、十卜、戊戌戍、木本 不上字形第二路：差别只在一小笔，或者次形样本不够。

### 已到天花板的组

己已巳 抽样下界 0.978；日曰 从 0.924 升到 0.991（加了字形）；入人八 从 0.929 升到 0.991。这几组不要再单独优化 jys 的整体准确率，剩下的格按[分篇 6](6-人审边界与负结果.md) 留人审，或者交给二审小组。

## 3.3 整理本在文意组上可信到什么程度

- 殿本整理本把 曰 录成 日、把 已 录成 巳 是常态。**己已巳 完全不参考整理本**。
- 日曰 只在宽高比明显偏向一边时才参考字形（≤0.68 日、≥0.88 曰）。
- 文意置信度很高时可以覆盖整理本，但必须是 strong（L1 命中，或二审小组确认）。
- 整理本字在组外的格（自、旨、巴、元、白、昌 等）属于「整理本字复核」问题，不是字组问题。

## 3.4 联合判与窗口

- 窗口取上下各 20 字，不按段截。
- 窗口里邻格的同组字是识别出来的字，常常是错的，例如「王制日春…夏日禘」，会把模型带偏。所以联合判 `decide_joint` 要保留：两个共字组（日曰 与 日目）一起表态。
- 页首页尾的格上下文会被截断（目前一页一串，不跨页连读），这类格要多留一些人审。

## 3.5 留痕与备注

- 靠较复杂文意判断定下的字，要写备注：依据、原标注与事件 id、是否看过刻形、线程 id。备注写进数据集（`by: "claude-ctx"`，`card_note`/`note`）和中心库事件的 `payload.note`。
- 文意判定放 `review/<名>_verdicts.jsonl`（kind=reading），刻形更正放 `variant/pair_review/labels_*.jsonl`。
- 以后所有大模型分析都按情况写备注。
