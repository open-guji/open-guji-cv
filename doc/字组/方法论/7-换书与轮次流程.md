# 7. 换书与轮次流程

[← 总览](README.md)

## 7.1 哪些能带走，哪些不能

**方法和模型可以带走，码位结论和书级表带不走。**殿本「每对只有一种刻法」是这一次雕版的事实，换书要重新看图。

| 东西 | 换书时 |
|---|---|
| 字组注册、方法数组、护栏、edge_pair 通则 | 直接用 |
| L1 规则、L2 模型、L3 提示词 | 直接用。L2 不建表也能先放八成。规则要拿新书回测；提示词里的书名（`book_desc`）要改 |
| HOG 模板库、U-Net 权重 | 当初始值用，在新书上按册留出重测；刻风差得远就重训 |
| `codepoints.yaml`（照录刻形、真归一、暂归一） | **不带**。新书重新看图、逐对请 sheldon 定 |
| `follow_ref` 白名单 | **不带**。白名单是逐对核过的本书事实 |
| 字频表、`form_freq.tsv`、L2 答案表 | 用新书的放行重新统计 |
| 边表 `variants`、`edge_pair_exclude.tsv` | 直接用，排除表按新书补 |

语料分三层：全局（底库、通用规则、提示词模板）→ 套书（L2 表、字频表、ids_bank、book_prompt.json）→ 册。换书要新建套书层。细节见 `doc/design/语料库分层版本.md`。

## 7.2 开工步骤

1. **登记册配置**：册 yaml 写全 `group_flow`，并补上 `period_prior`。vol51–99 曾经缺这一项，O 类送审暴涨，那一批产物和待审单只好作废重跑。
2. **定参照策略**：整理本或参校本整体可信（四库系书），就开 `seed_admit.follow_ref_variants` 和 `group_flow_abstain_ref_ok`，关掉暂归一。整理本不可靠（殿本）就用暂归一。见[分篇 1.3](1-类型与码位结局.md#13-照录整理本和按参校本取字的区别)。
3. **预跑 L3**：在有 key 的机器上把要问的格先跑一遍，写进裁定库，别的机器直接命中缓存。
4. **首跑全书，统计送审**：`guji-manager pending-stats` 按类分（G 组内、V 组外异体对、N 形近护栏、O 其他），再按字组和字对排出绝对数。
5. **先做同义、后做不同义**：先做码位组、edge_pair、ref_margin、陪衬，最后做文意形近。优先级按送审绝对数从小到大。
6. **码位候选给 sheldon 定**：出一张看图页（每对两种码位的已放行格并排，预选「归到放行最多的一形」）。他点完后写进 `codepoints.yaml`，同时建 `cp_*` 组。

## 7.3 按轮修复，统一重跑

规矩见 ai-team `通用/重跑轮次规矩.md`（sheldon 10-31 定）。

1. **每组或每类一个线程**：只管一两组或一类算法，在自己的训练集上按册留出到 0 错。用现有产物包离线回放，新放行和改字的格逐格看图。自己开 PR、合 dev。
2. **报给统一重跑**：用 `python3 process/send.py A31 "…"` 写清改了什么、动了哪些步、从哪步重跑、影响哪些页。**线程不自己重跑整册，也不标 main。**
3. **轮末**：A31 冻结、重跑、标 main，A32 换待审单。之后直接跑 `guji-manager pending-stats`，不用自己分析。
4. **各册配置**：新组要进各册 `group_flow`，由 A31 在冻结时统一写，线程不推。

## 7.4 验证口径

验证一律用三样：

1. **按册留出**。留一偏乐观。
2. **针对本组的离线回放**，比较放行数、送审数、改字数。
3. **新放行和改字的格逐格看图**，误判样例写进组卡。

文意规则是从已知册挖出来的，必须拿没见过的册回测。人裁本身也会错，常见的是**格号漂移**（人裁记在旧切分的格号上），核对前要按锚点重绑。

## 7.5 人工数据与红线

- 所有标注和切线进 dataset `char-groups/`（汇总 `labels/unified.jsonl`，可以重建）。要给 seed_admit 当证据的人裁，必须写成中心库事件。
- 审查页的结论只存在页面里不算落盘，收页当天就要写成文件，并在 `char-groups/标注清单.md` 登记。
- 事件锚点是 `raw_page_px@top-right`，裁字块时 x 要镜像（W−x）。出审查页用已有的字块图或锚点小图，别自己切。
- **写中心库**要 sheldon 在**本线程**亲口说「推」，转来的同意不算；**传 R2** 要说「传」。推之前先 `guji db pull`。
- 凭据不进仓、不进聊天。
