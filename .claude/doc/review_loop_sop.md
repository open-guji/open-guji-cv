# 审阅循环 SOP：每轮怎么走、什么时候修算法、怎么防回归

> 用户 2026-09-04 提的问题：「建立一个完整方便的反馈循环……粒度控制在多少页，
> 什么时候进行算法修复，怎么减少和你的对话，每一轮要做哪些检查防止回归。」
>
> 这份文档的目标是让**一轮循环不需要跟我商量**——页码、判据、动作全部由数字决定。
> 数字都来自控制台或一条命令，不需要我在场。

## 0. 一轮长什么样

```
跑一批(12页) → 你审(10~20分钟) → 收割消费 → 看四个数 → 按判据决定：
   ├─ 全绿 → 直接跑下一批
   └─ 有信号 → 停下修算法 → 回归三件套 → 重跑受影响页 → 继续
```

**一轮 = 12 页**。这个粒度是量出来的，不是拍的：

| 批次 | 字位 | 人审 | 你实际花的时间 |
|---|---|---|---|
| dev_set 12 页 | 1933 | 64 → 22 | —（难页，故意挑的）|
| p15-29 12 页 | 2046 | 18 → 15 | ~15 分钟 |
| p30-43 12 页 | 2036 | 15 → 13 | — |
| p44-56 12 页 | 1965 | 20 | — |

12 页 ≈ 2000 字位 ≈ **15~20 条人审 ≈ 一次坐下能审完**。再大你会疲劳（疲劳会让
裁决质量下降，而错裁会污染字形库）；再小则每轮的固定开销（跑管线、收割、看数）
摊不平，且缺陷聚集信号出不来——**17/33 那个 slot 2 信号是攒了三批才看清的**。

## 1. 每轮的固定动作

### 1.1 跑一批

**控制台 → 审查 → 点「跑这批」**（页码来自体检卡片的「填入页框」）。
约 3 分钟，跑完**自动载入待审卡片**——不用等在那儿猜跑完没有。

命令行等价：

```bash
.venv/Scripts/python -m open_guji_cv pipeline keben_body_v2 vol01 --pages <12个页码>
```

### 1.2 审（卡片已经在眼前了）

规矩三条，别破：
- **己/已/巳 一定填文意**（这三个字的字形与文意会分岔）；
- 图看不清就点「字形不完整」/「有噪声」，**别猜**——猜错会污染字形库；
- 每张卡片载入后**自动带出候选**（字体模板 + CNN 融合，附 IDS / 码点 / 本书频次 /
  字统网深链）；库/OCR 都不对就在这排候选里点，别去外部网站。候选不对再点「重查」。

### 1.3 收割消费（控制台 → 收割 → 按路由表消费）

### 1.4 看四个数（这一步决定下一步）

**控制台 → 审查 → 「本轮体检」→ 点「体检」**。四个判据各一行，带灯和「该怎么办」。

命令行等价（同一套判据，共用 `open_guji_cv/eval/round_check.py`）：

```bash
.venv/Scripts/python scripts/round_check.py --pages <本轮页码>
```

四个判据的含义与阈值见 §2。

### 1.5 下一批页码怎么定

体检卡片底部直接给出下一批，点「填入页框」就切过去了，不用手抄 12 个页号。
命令行等价：

```bash
.venv/Scripts/python scripts/round_check.py --next
```

它按「page-type 金标里 page_type == body」且「没跑过 seed_admit」顺序取 12 页。
**不要按页号顺推**：vol01 的 p89-113 是职名页、p61/159-182 是目录页，
用正文的 21 格先验跑必然全灭（配置注释里记着 p119 混进 dev_set 的教训）。

## 2. 四个判据：什么时候修算法

| # | 指标 | 绿灯 | 黄灯（记着，先攒）| 红灯（停下就修）|
|---|---|---|---|---|
| A | **自动放行错误率**（对整理本金标 + 你的裁决双真值）| 0 | ≤0.1% | >0.1% 或**任何一条错进了字形库** |
| B | **人审率** | ≤1.5% | 1.5~3% | >3% 连续两批 |
| C | **缺陷聚集**（人裁标的 seg_defect 按 页/列/格位 聚）| 无格位 ≥3 条 | 某格位 3~5 条 | **某格位 ≥6 条，且横跨 ≥3 页** |
| D | **生僻字 top-10 命中**（字体模板+CNN 加权融合，rare-char 集）| ≥75% | 60~75% | <60% |

### 判据 C 是这套流程的核心

**孤例是个案，扎堆才是系统性问题。** 版框钉桩那个 bug 就是这么找出来的：
17/33 条缺陷压在 slot 2、横跨 10 页 → 一查就是钉桩把字顶切了。修完 29 条痊愈、
R4 从 0.51% 降到 0.05%、人审从 3.3% 降到 1.1%。

**红灯才动算法**。黄灯只记录、继续跑——因为：
- 样本不够时改算法是在拟合噪声（IDS 护栏那次就是：全通道接进去 487 条本来对的
  被拦，只拦住 3 个错，净亏）；
- 每改一次算法要重跑全部已处理页 + 三件套回归，代价不小。

### 判据 A 是零容忍那条

A 红灯要**立刻停**，因为错的字会进字形库，后面的页会继承这个错
（`charset_and_lm.md` §四的实锤）。停下后：
1. 备份库 `cp output/glyph.db /d/tmp/glyph.db.bak-$(date +%m%d)`；
2. 看图确认到底谁错——**可能是金标错、可能是你被坏图块误导**
   （实测两条：p33c7/p70c4 你判「大」，修好切分后露出顶横，实为「天」）；
3. 确认是管线错才改算法。

## 3. 修算法时的固定流程

```bash
# ① 先备份库（人裁结果不可再生）
cp output/glyph.db /d/tmp/glyph.db.bak-$(date +%m%d)

# ② 改代码，然后回归三件套
.venv/Scripts/python scripts/round_check.py --regression

# ③ 重跑受影响的步骤（只跑受影响那几步，别全跑）
.venv/Scripts/python -m open_guji_cv step <step> vol01 --pages <所有已处理页> --force
.venv/Scripts/python -m open_guji_cv pipeline keben_body_v2 vol01 --pages <同上> --from <下一步>

# ④ 再看一次四个数，确认没退
.venv/Scripts/python scripts/round_check.py --pages <所有已处理页>
```

### 回归三件套（`--regression` 一次跑完）

1. **单测全绿**（当前 262 项）——逐文件跑，因为本机 pytest 收尾会崩
   （`I/O operation on closed file`），退出码不可信；
2. **四把尺子不退**（R1 100% / R2 可改善 ≤0.2% / R3 0 / R4 ≤0.1%）；
3. **双真值准确率不退**（对整理本金标、对你的裁决都要 100%）。

### 改完之后金标要跟着改

缺陷修好了，被标 `truncated` 的字位就不再截断了。**金标记的是「当前切得怎么样」，
不是「历史上出过什么问题」**，所以要复量改回 `clean`（历史留在 `source_events`）。
钉桩那次 35 条里 29 条痊愈。

## 4. 怎么减少对话

三件事已经做成命令，不需要问我：

| 你想做 | 控制台 | 命令行 |
|---|---|---|
| 跑这一批页 | 审查 → **跑这批**（跑完自动载入卡片）| `pipeline keben_body_v2 vol01 --pages …` |
| 这批要不要停下修算法 | 审查 → 本轮体检 → **体检** | `round_check.py --pages <页码>` |
| 下一批审哪几页 | 同上，卡片底部**「填入页框」** | `round_check.py --next` |
| 改完代码有没有退 | —（要跑 272 个单测，走命令行）| `round_check.py --regression` |

**一轮全程不用离开审查页**：体检 → 填入页框 → 跑这批 → 审 → 收割 → 再体检。

判据与阈值的唯一事实源是 `open_guji_cv/eval/round_check.py`，控制台与命令行
共用它——改阈值只改那一处，两边同时生效；否则过一阵子命令行说绿、控制台说黄，
谁也不知道该信哪个。

**什么时候该找我**：
- 判据 C 红灯（缺陷扎堆）——定位根因要看图、要试判据，这是需要来回的活；
- 判据 A 红灯且你确认不是自己看错；
- 想加新能力（新候选源、新通道、新版式）。

**不用找我**：全绿继续跑、黄灯记录、页码选择、常规回归。

## 5. 一轮的时间账

| 步骤 | 耗时 | 谁做 |
|---|---|---|
| 跑 12 页管线 | ~3 分钟 | 机器 |
| 审 15~20 条 | 10~20 分钟 | 你 |
| 收割消费 | 秒级 | 点一下 |
| `round_check` | ~2 分钟 | 机器 |
| （红灯时）修算法 + 回归 | 半天~一天 | 我 |

vol01 还剩 ~60 页正文，**5 轮能扫完**。

## 6. 已经踩过的坑（别重走）

1. **清消费台账重放事件**会把未复核的机器误报灌进金标——
   `2026-09-03-step1-bottom-clip` 那批 137 条（actor=model，实审 127/127 全误报）
   曾把 column-split 从 60 条撑到 195 条。台账是未提交的派生物，清之前先想清楚。
2. **坏图块会让人裁出错**。切分缺陷最隐蔽的代价不是漏字，是你对着被切的图判错字。
   所以判据 C 的优先级高于它看起来的量级。
3. **`git checkout` 数据集文件会连人裁回流一起回退**——金标可从事件重建
   （`route_and_consume` 重放），但要先确认哪些批次不该落金标。
4. **样本不够时别改算法**。IDS 护栏、频次加权都是这么否掉的，负结果记在测试里。
