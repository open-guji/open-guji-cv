### 偏离 1：IDS 护栏**不接**进准入（负结果）

护栏本身是对的——麗/麓、玉/王、數/敷 这些手工表漏掉的对全算得出来。但在
A 刀之后的实测数据上接进去是净亏：

| 接法 | 命中 | 其中本来判对 | 拦下的真错 |
|---|---|---|---|
| 全通道 | 490 (26.2%) | **487** | 3 |
| 只在纯形状通道 | 2 | 2 | 0 |
| 只在三方一致 | 2 | 2 | **0** |

原因：319 次命中落在 `dual` 上，而那条通道有 align × OCR 两路**零同源**证据。
护栏防的是「形状判据自己认错」，对已有文本证据的通道，它拦的全是好人。
**什么时候重新考虑**：库长大后 `match_solo` 放行量上来（现在只有 8 条），
或接了字体模板/部件模型这类没有文本证据兜底的纯形状候选源。

### 偏离 2：B 的「三方一致」通道**没做**

残余 64 条人审里它只命中 5 条，护栏拦下 2 条且拦的都是对的，其中一条还是
vol01:151:4:4 的「已」——用户定的规则本来就是己已巳永远人审。收益太小，
不值得多一条通道（每条通道都是将来出错时要归因的一处）。

### 顺带修掉的三个隐藏 bug（都不报错）

1. `label_page(book="")` → 键是 `":24:1:2"`，与产物对不上，**整理本通道一条
   都不触发**，症状只是「改完没效果」；
2. `dual` 档返回 `(True, None)` **没有通道名**，按白名单取字会漏掉它，char
   掉进库 top1 兜底：判决对、存的字却是第三方的（判错 9 条金标）；
3. 修①②后矫枉过正，让整理本字覆盖 `char`，把 7 个异体位的**字形**写成了
   整理本的形（刻「㫖」存「旨」）——`AdmitRec` 因此新增 `reading` 栏，
   字形与文意分开存。

由此定下一条新规则：**库 unsure 时不拿库 top1 当字形**。

## 0. 一句话结论

**切分不再是瓶颈**：R1 100%、R2 可改善 0.14%、R3 0、R4 0.51%。瓶颈整体挪到了
Step 5-6，而且**不是算法弱，是证据没用上**：

- 人审 152 条里，**65% 能被「整理本 × 库形状」通道吃掉**（127 条真值上 83 自动、82 对）
  ——这条通道 v1 标定过（144/144、70/70、102/102），v2 的 `seed_admit` 却传的
  `align_char=None`，一条都没接。
- 锚定串只收「定了字的位」，p70 整页锚不上；改用库 kNN top1 填满，整理本覆盖
  **1619 → 1897 / 1933**（83.8% → 98.1%）。
- 库的**排序几乎不错**（kNN top1 对金标 99.5%），错的是**置信闸**：cov 0.99 与
  rival95 拦下的大多是对的（稍/精 0.958 是 HOG 饱和，不是真形近）。
- 真正需要人的是**生僻字**：语料频次 ≤3 的字位只占 1.8%，却是人审残余的主体；
  127 条真值里 14 条系统三路候选**都没给出用户定的字**（袤 埴 殫 偓 綺 奩 䙝 㕔 鏤
  濡 槧 効…），其中 䙝 㕔 连整理本都没有——这就是「必须开字统网查」的那类。

人工效率的杠杆按收益/成本排序：**A** 接整理本通道 + 改锚定串（-65% 人审）→
**B** LLM 判形近对 + 三方一致通道（再 -20%）→ **C** 生僻字候选生成（把「查字统网」
变成「候选里点」）→ **D** 审查 UI 改成读文定字 + 同字批裁。目标：正文页人审率
7.9% → **≤1.5%**，自动放行错误率 ≤0.1%，生僻字每条 ≤15 秒。

## 2. 各步瓶颈

### Step 1-4：不是瓶颈了

剩三件小事：R2 那 3 条可改善格线；R4 10 条里人审没走到的 5 条（60/9/2、21/2/2、
151/4/8、151/6/1、137/8/21）；Step4 图块层清版框残线（`_also_second_bar` 负结果
指出的正确方向，见 step3_error_survey §八）。非正文版式（vol01 p90-132 表格/名录）
仍未做，那是另一条 pipeline。

### Step 5 库匹配：瓶颈是「闸」，不是「排序」

1. **闸太保守且判据饱和**。same 闸 0.99 只放 1318；rival95 把 0.958 的 HOG 邻居
   当竞争者。cov 是弹性覆盖率，对「差一个部件」的字对（諭/論、揀/棟）会到 0.98+，
   对根本不像的字对也能到 0.95——**这个标量分不出「形近」和「不像但 HOG 巧合」**。
2. **库稀疏对生僻字是结构性的**。整理本 4593 字种，库有例 1951；出现 ≤3 次的
   1801 字种里 **1551 无例、只有 2 个有 ≥3 例**。人审集库 top1 字的样本中位 11.5，
   自动集 28。调阈值救不了没样本的字。
3. **形近表是枚举不是规则**。手工 21 对 / 字体 78 对 / 人裁 27 对；麓/麗 不在表里
   就以三方一致漏过。glyph_match_research §④ 早写了「只用 IDS 当护栏」这条便宜路
   ——差一个部件即降档——一直没做。

### Step 5-b OCR：字表是硬上限，换模型是最便宜的一刀

rapidocr = PP-OCRv4 简体 6280 字，本书 40% 字种不可达；s2t + 异体扩展后仍 1.2%
字次够不着（彖 詁 筮 帙 歟 禘 蓍 裒…）。**PP-OCRv5/v6 字表 2 万+，含繁体/日文**，
抽查 18 个生僻字（諡 騐 繭 帙 鸞 廳 槧 論 諭 說 謂 彖 詁 筮 歟 禘 蓍 裒）**全在**。
用户在 overview 仓已有 PP-OCRv6 的 GPU 环境（南北朝补 4 页零错）。
OCR 仍然只供候选不投票——但候选里**有没有那个字**，决定上下文和人能不能选到它。

### Step 6 上下文：v2 少接了最强的一路

- `seed_admit` 传 `align_char=None, ref_char=None`。v1 标定过的 match_ref、
  match_replace、match_ref_weak、match_margin 在 v2 一条都不生效。
- 锚定串（`v2_align._slots_from_decision`）只收 `char` 非空的位；改用库 kNN top1
  填满（弃权位也填），实测 12 页全锚上，equal 段 1849。
- 3-gram 在 入/人 上给 0.53 / 0.39，margin 0.14，永远过不了 0.70；confusable-context
  154 题上 n-gram 95.5%、**大模型 98.7%**，但 `context_step.STRATEGIES` 里还没有 `llm`。

### 反馈环：切分缺陷已闭环；定字层缺「时间戳」

人裁 → 事件 → 消费 → 金标/字形库 → 质量看板 这条环通了。但事件的 `ts` 是**收割**
时间（324 条只有 4 个时间戳），量不出每条裁决耗时——**效率工作现在没有基线**。

## 3. 人工效率方案

### 3.1 口径

| 指标 | 现在 | 目标 |
|---|---|---|
| 人审率（需要人点的字位 / 全部）| 7.9% | 正文页 **≤1.5%** |
| 自动放行错误率（对整理本 + 用户裁决双真值）| 0 / 1619 | ≤0.1% |
| 每条裁决耗时 | 未知 | 常规 ≤3s，生僻字 ≤15s |
| 生僻字候选 top-10 命中率 | 无此能力 | ≥80% |

### 3.2 四刀

**A · 接整理本通道进 v2 + 改锚定串**（收益最大、成本最低，1-2 天）

1. `_slots_from_decision` 改为：定字 → 库 top1 → OCR top1 逐级兜底，位位有字。
2. `seed_admit` 跑 `label_page`，把逐位 `align_char` / `op` 喂给 `admission_decision`
   ——match_ref / match_replace / match_margin 原样复用，一行标定都不用重做。
3. 己已巳三字硬编码永远人审（`SPLIT_CHARS` 已有，准入侧也加）。

预期：人审 152 → ~44，**人审率 7.9% → ~2.3%**，回放零错。
反面：整理本 replace 段里的分岔（異体 効/效、㕔/廳）正是该人看的，通道不碰 replace
段的「整理本≠库」情形。

**B · 形近对交给 LLM + 三方一致通道**（3-4 天）

1. `ContextDecider` 加 `llm` 策略：只在候选内选、门槛化不变、语料挖洞纪律照旧；
   先在 confusable-context 154 题复现 98.7%，再在 dev_set 挖洞测。
2. 新通道「三方一致」：库 top1 == OCR top1 == 上下文 top1 且 cov ≥ 0.95。dev_set 47 条，
   对金标 17/17；**必须配 C 的 IDS 护栏**（麓/麗 那 1 错就是差一个部件）。
3. 入/人/八、論/諭、日/曰：LLM margin 过阈自动；不过阈人审，但卡片直接给整句。

预期：再吃掉残余的 1/3-1/2。

**C · 生僻字候选生成**（痛点 2 的正解，分三级，见 §4）

**D · 审查 UI 改造**（1 周，可与 A 并行）

- **读文定字**：整列/整页文本流，已定字正常显示，待审字位高亮，点开才出卡片。
  人读的是句子不是卡片——形近对在句子里一眼就定，这是大模型 98.7% 的人肉版。
- **同字批裁**：库 top1 相同的待审字位并排一屏（「这 12 个都是入？」），一次裁一批。
- **键盘流**：Enter 接受 top1，1-5 选候选，S 切分缺陷，N 非字，Space 跳过。
- **生僻字面板**：top-10 候选各带 码点 · IDS · 本书频次 · 语料例句 · zi.tools 深链；
  无候选 → IDS 编辑器（部件选择器）拼出描述，存入 `待造字` 表（Unicode 无此字时
  本来就该记 IDS，不该硬选近似字）。
- 每条裁决记 `client_ts`——效率从此有基线。

## 4. 生僻字：结构 / 部件 / 笔画识别方案

### 4.1 问题的真实形状

| 事实 | 数 |
|---|---|
| 整理本字种 | 4593；**22.5% 只出现 1 次，39.7% ≤3 次**；覆盖 99% 字数要 2676 字种 |
| 库对 ≤3 次字种的覆盖 | 1801 字种里 1551 无例 |
| dev_set 金标里频次 ≤3 的字位 | 29 / 1619 = 1.8% |
| 用户 127 条裁决里系统三路都没给的字 | **14**（袤² 埴⁵ 殫⁸ 偓¹ 輩¹⁴ 綺¹ 奩⁴ 䙝⁰ 㕔⁰ 鏤⁴ 濡² 槧⁷ 効¹ 巳）|

上标是整理本频次。䙝 㕔 是 0——整理本用了通行字（褻 廳），刻本刻的是异体。
新页面场景更糟：换一本书，库从零开始，**所有字一开始都是生僻字**。

### 4.2 文献怎么做的（诚实评估）

零样本汉字识别（ZSCCR）主流是把字拆成 **IDS / 部首序列**（RAN 2018、HDE 2020、
CCR-CLIP ICCV 2023、FT-CLIP 2024、GL-HPN 2026）或**笔画序列**（Chen IJCAI 2021、
SideNet），图像编码器与结构序列编码器对齐，推理时对全字表检索。

- 数字：GL-HPN 在 500 / 1000 / 1500 已见类设定下未见字 top-1 **36 / 57 / 69%**
  ——这是**印刷体**。手写更低（HMGA 自称比前人高 20 个点，绝对值未在摘要给出）。
  **古籍刻本没有可比的公开数字。**
- 数据：HisDoc1B（30,615 类、10 亿字）只放数据集不放模型，要机构申请，CC BY-NC-ND。
- 笔画级：文献自己说 "stroke-based ones are hard to perceive fine-grained information"；
  刻本笔画粘连更甚。

结论：**端到端零样本模型不能当自动判据，但当候选生成器成立**——top-10 命中率远高于
top-1，人在候选里点。这与本项目「OCR 只供候选不投票」的纪律一致。

### 4.3 三级方案（每级独立有用，逐级加）

**L1 · 字体模板 kNN 候选**（零训练，1 周）

- I.Ming + Jigmo 1/2/3 已在 `fonts/`，覆盖 Unihan 全部 10 万字。用现有
  `synth.render_char` → normalize → HOG kNN，建 `font:*` edition（§6 实验代码已有，
  被锁在 woodblock 通道外——**正确**，它不能判 same）。
- 只在三种情况调用：库 unsure 且 cov < 0.95 / OCR 不可达 / 用户点「生僻字」。
- 已知负结果是「不能自动放行」（对/错 f1 分布重叠）；**作为候选召回**没测过。先在
  那 14 条 + 29 条频次 ≤3 字位上量 top-10 命中率，≥70% 就值得接。
- 候选经 `variants.json`（47,724 字关系）做异体展开：効/效、㕔/廳 连起来一起给人看。

**L2 · IDS 护栏 + 结构检索**（1-2 周）

- 数据：[yi-bai/ids](https://github.com/yi-bai/ids)（MIT，zi.tools 同款，三档粒度，用 lv1）；
  备选 [cjkvi-ids](https://github.com/cjkvi/cjkvi-ids)（`ids.txt` GPLv2、`ids-ext-cdef.txt` 无 GPL）。
- **护栏**：候选 top-2 的 IDS 树编辑距离 = 1 个部件 → 自动降 unsure。把
  `NEVER_MATCH_FAMILIES` 从 21 对枚举升级成全字表规则；麓/麗、稍/精、玉/王、揀/棟
  全部自动覆盖。这是 B 里三方一致通道的前提。
- **结构检索**（用户设想的「识别结构和部件找字」，不训练模型）：
  1. 结构判定：投影 + 连通体估 ⿰ / ⿱ / ⿸ / ⿴（刻本左右、上下结构通常有可见空隙）；
  2. 部件识别：拿**库里已有常用字的局部**（言、木、氵、艹、金、糸…）做模板，在
     对应半区匹配——常用部件在库里样本最多，这是库稀疏问题的反面；
  3. 检索：IDS 表当倒排索引，「⿰言?」取回几百个字，再用 L1 模板排序 → top-10。
- 界面：候选卡并排显示 IDS（⿰言侖 vs ⿰言俞），人对着图一眼定。

**L3 · 部件级识别模型**（4-6 周，需要 torch + RTX 3080，本机有卡没装 torch）

- 训练数据免费得：15,459 个已标刻本字 × IDS = 部件级监督；再用 I.Ming/Jigmo 渲染
  全部 4593+ 字种做合成预训练（arXiv 2506.04807 那条「字体合成补类」路线）。
- 架构：CCR-CLIP 式图像-IDS 对齐，推理对全 Unihan IDS 检索 → top-10。**不做笔画级**。
- 验收：dev_set 生僻字位 + 用户新裁字上 top-10 命中率 ≥80% 才上线。它永远只是候选
  生成器；自动放行仍走两路零同源互证（整理本×形状 / 上下文×形状）。
- **L1+L2 实测之后再决定要不要做 L3**。

### 4.4 「去字统网查」这一步怎么消掉

现在：看图 → 猜 → 开 zi.tools 查 → 对字形 → 查字典看意思 → 回来输。
之后：卡片直接给 top-10（L1/L2）+ 每个候选的 IDS + 频次 + 例句（「帙」整理本 3 次：
「芸帙之名」）+ zi.tools 深链（只链接不抓取，合规）→ 点一下。无候选 → IDS 编辑器拼
→ `待造字` 表。

## 5. 顺序与量法

| 周 | 做什么 | 看什么数 |
|---|---|---|
| 1 | **A**（整理本通道 + 锚定串）+ D 的 `client_ts` + 读文定字原型 | 人审率、自动错误率（双真值）|
| 2 | **B**（`llm` 策略 + 三方一致）+ L2 护栏 | confusable 复现、人审率 |
| 3-4 | **L1** 字体候选 + **L2** 结构检索 + 生僻字面板 + 同字批裁 | top-10 命中率、每条耗时 |
| 之后 | L3 视 L1/L2 实测；换 PP-OCRv6 做 `ocr_candidates` 第二引擎 | OCR 不可达率 |

控制台质量看板加四个数：人审率 / 自动错误率 / 每条耗时 / 生僻字 top-10 命中率。

## 6. 不做什么

- 不做笔画级分割识别（刻本笔画粘连；文献在笔画层更弱）。
- 不抓 zi.tools 数据（无授权条款），只做深链；IDS 用 MIT 的 yi-bai/ids。
- 不用 HisDoc1B（机构申请 + NC-ND）。
- 不让任何单一图像信号自动放行——OCR、字体模板、L3 都只出候选。
- 己已巳永远人审；OCR 永远不与库配对放行（97.1% 那条老账）。
