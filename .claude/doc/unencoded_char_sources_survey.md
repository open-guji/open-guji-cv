# Unicode 未收字：字统网怎么做的、数据从哪来、我们能拿到什么（2026-09-21）

> 用户：「字统网上不但有很多 Unicode 收了的字，还有很多很多 Unicode 未收字，都标出了和哪一个
> 繁体字相同，有些还标出了 IDS 结构。去搜一下他们的信息是哪里来的，或者能不能找到其他相似的
> 信息。我们想对 Unicode 未收字也能达到和已收字类似的效果。」
>
> 本文四件事：§1 字统网的未收字是怎么表示、怎么渲染、从哪来（接口和前端包逆向核过，不是猜）；
> §2 能替代/补充它的公开来源，**每个都在本会话实测过规模和许可**；§3 「和已收字同样效果」到底
> 要哪四样东西、我们缺哪几样；§4 分三层的做法，第一层今天就能动手，已有一块砖
> （`scripts/kage_render_glyphwiki.py`，实测可用）。口径：数字全是本会话跑出来的或抄自原始
> 文件，标 ◇ 的只读到摘要级。

## 0. 一句话

**字统网的未收字 = 「一串 IDS 当身份」+「来源辞书自己说的『同某字』」+「KAGE 动态组字当字形」**；
它的 IDS 是站长白易自己拆的（网站「主要任務」第 2 条原话），**没有开源**（他开源的
`yi-bai/ids` 只有 Unicode 已收字，我们已经在用）。但同样效果的三块料公开都有：
**GlyphWiki dump**（自由许可，215 万字形；其中 IDS 命名的 77,444 条、中华字海 63,167 条、
大漢和 51,127 条……**关联到我们整理本字种的未收/异体字形 33,804 条，覆盖 4,637 字种的 89%**）
提供字形和「关联正字」；**kage-engine**（MIT）14 ms 能把它们渲染成和字体一样的模板（已跑通）；
IDS 则 IDS 命名的自带、其余 75% 能从部件框推、剩下的按字向字统网接口查（它按 IDS 串查也能返回）。
所以路是：**把未收字当第六套「字体」接进现有 5-b 模板库**，身份键用 GlyphWiki 名 / IDS 串，
一律只出候选，人裁后按刻本 IDS 登记——不需要等 Unicode。

## 1. 字统网（zi.tools）的未收字是怎么做的

### 1.1 接口与数据形状（逆向自 `/api/zi/<字>` 与前端包 `app.0689c01a.js`）

`GET https://zi.tools/api/zi/<字或IDS串>` 返回一个 JSON（諭 315 KB、廳 485 KB），四个顶层键：

| 键 | 内容 |
|---|---|
| `font` | 该页要显示的**未收字的 KAGE/SVG 路径**，键就是 IDS 串（諭 页：`⿰忄⿳人二刖`、`⿰言⿳人二刖`…）|
| `yi.nodes` | **字族图的节点**，键 = `<来源>-<来源内编号>-<序>`，值是 17 栏的数组（见 §1.2）|
| `yi.edges` | 节点间的边（同/通/简/异体关系）|
| `yi.ies` | 每个节点的**部件树**（`c` 字段：F 整字 / S 字 / H 合体部件 / X 叶子 / C2·C3 叠置）|
| `yi.kv` | 康熙、`ids_zi_tools`（`⿰言俞(.,T,J,K,V,P)`）、IVD、各标准码位 `ma`… |
| `yi.tu` / `tubrief` | 各书体扫描图（我们 2026-09-07 抓的 `/api/tu/` 就是它）|
| `yi.unihan` / `yin` | Unihan 多版本、读音（含上古音/方言几十套）|

**未收字就是节点**：第 5 栏（glyph）直接是一串 IDS，比如 `⿰日⿱仝刖`；第 8 栏是来源辞书原文的
释义/关系（`同=喻`、`同「廳」`、`「脱」的訛字`、`通=諭 理解`）；第 12 栏是解析后的**指向**
（`喻-*` = 与「喻」同、`諭-1` = 諭的第 1 义项）；第 16 栏是部件串（`言俞`）。`/api/zi/⿰日⿱仝刖`
（URL 编码）同样返回一页——**IDS 串就是它的字 ID**。其它接口：`/api/ids/zu/<IDS>` 动态组字
（返回 KAGE 串 + SVG）、`/api/lookup/lookup/<部件>` 按部件检字、`/api/font/`、`/api/tu/`、
`/api/kxzd/`、`/api/shuowen/` 等。`robots.txt` 不存在（返回首页），站点**没有任何许可声明**，
只有版权页致谢越南喃字基金会；前端「Copyright Notice」也只写了喃字来源。

### 1.3 「同某字」从哪来、IDS 从哪来、字形从哪来

- **「同某字」不是算出来的，是辞书原文**：《汉字海》《漢語大字典》条目本身写「同 X」「X 的訛字」，
  教育部字典的结构本身就是「正字 → 异体」。字统网做的是把这些关系解析成指向（第 12 栏）并连成
  字族图。
- **IDS 是站长自拆**。网站「主要任務」原文：「2. 字形拆解。將 Unicode 以外來源的漢字進行 IDS
  字形拆解。」他给 Unicode 的 IDS 开源在 `yi-bai/ids`（MIT，我们 `config/ids/ids_lv1.txt` 就是它，
  102,031 行，**键全是单个已编码字，没有未收字条目**——本会话查证）；他还写过 Unicode 提案
  L2/21-134《Collections of ideograph components for use in IDSes》（汇总 babelstone / IRGN2225 /
  UCV / GF1997·2009 / HKSCS / CDP 六套部件集，2,000 个部件里 850 个未编码且唯一）。未收字的 IDS
  用了**扩展语法**：`.` 分隔、`#(乛丿^)` 笔画描述、`^` 等（如 `⿰⿸⿻丅⿸#(乛丿^)一⿱一匆.且.`），
  我们的 `ids_struct.parse_ids` 目前**认不了**这些。
- **字形是 KAGE 动态组字**（EPS 导出头写着 "GlyphWiki powered by KAGE system"，部件字体由
  貢獻者葛炳崙提供）：`font` 里给 SVG 路径，`/api/ids/zu/` 给 KAGE 串。也就是说它渲染未收字的
  引擎和 GlyphWiki 是同一个。

### 1.4 能不能直接用它

- 技术上能：按整理本字表逐字拉 `/api/zi/<字>`（4,637 字 ≈ 4,637 次请求，每页几十到几百 KB；
  它按「字族」返回，一页里就带出该字的全部未收异体及其 IDS 与「同」关系；本会话 9 页样本每页
  11–161 个未收节点）。
- 许可上**没有依据**：站点无许可声明、无 robots、无 API 文档；我们 2026-09-07 抓 `/api/tu/`
  时的判断是「古籍扫描图本身无版权」。**IDS 串和「同 X」这类事实数据**按 BabelStone 文件头引的
  美国法理（事实汇编不受著作权保护）风险低，但**站长的整理劳动**没有授权——建议只把它当
  「按字查询的兜底与人审解释」，不整库镜像、不再分发；真要大批量，先给站长写信。

读法：整理本里九成的字种，GlyphWiki 上都挂着至少一个「不是它标准形的形」——这些正是刻本里
会碰到的写法池。**注意关联字 ≠ 等价**：GlyphWiki 只保证「相关」，zihai/dkw 的关联多数是「同字异形」，
IDS 命名的有相当一部分是「部件相关」（`u2ff0-u0033-u4ed6` 关联 帶）——要按来源分级、人裁抽验。

**渲染已跑通**：`@kurgm/kage-engine` 0.7.0（MIT，node 22）：建 215 万条索引 7.4 s，9 个字

脚本 `scripts/kage_render_glyphwiki.py`。**这意味着 GlyphWiki 上任何一个未收字都能像字体一样
进 `_emb_index` 当模板。**

**IDS 怎么来**：IDS 命名的 77,444 条名字即 IDS；其余可从 KAGE 的部件引用框推——劉冠偉（京大人文研，
2024）用 BMP 19,646 字验证，**整体 75.05%，⿲⿳⿴⿵⿶⿷⿻ 几乎认不出**（我们 §6 N3 的 KAGE 框
投影同一原理，要记住这个上限）；推不出的按字向字统网查。

## 3. 「和已收字同样效果」要哪四样，我们缺哪几样

已收字在 5-b 里之所以「有效果」，是因为四样东西齐：

| 要件 | 已收字现在靠什么 | 未收字要靠什么 | 现状 |
|---|---|---|---|
| ① 身份键 | 码点 | **GlyphWiki 名** 或 **IDS 串**（字统网的做法） | `IdsIndex` 已能按结构/槽位/部件查已收字；键空间没有未收字 |
| ② 模板（图） | 5 套字体渲染均值 | KAGE 渲染（§2.1 已跑通）/ 全字庫 Plus 字体 / 字统网 `font` | **无** |
| ③ 结构（IDS） | `ids_lv1` | IDS 命名自带；KAGE 推 75%；字统网按字查；CHISE CBETA | `parse_ids` 认不了扩展语法 |
| ④ 等价（正字） | Unihan/twedu/yitizi → `variants.tsv` | GlyphWiki `related`（相关≠等价）；辞书「同 X」；IRG 「unify to」 | **无**；且我们的纪律是字形层永不按正字合并 |
| ⑤ 评测 | `unseen` / `oov_bench` | 需要一个「未收字」子集 | **无** |

再加一条本项目自己的：**异体标签必须用刻本字形的 IDS 而不是正字**（设计稿 §3.5）——未收字天然
只能这么标，反而没有歧义。

## 4. 做法：三层

### 层 1（云端、零训练、今天可做）：GlyphWiki 未收字目录 + 渲染进模板库

1. **建目录** `config/unencoded/glyphwiki_catalog.tsv`：从 dump 抽「非别名且有关联字」的字形
   （§2.1 的 122,123 条），列：`gw_name / related / source / ids(若名字即 IDS) / kage`；按来源分
   信任级（twedu、irg、cbeta、zihai、dkw、hdic、IDS 命名…）。dump 不进 git（114 MB），目录进。
2. **渲染成模板**：`kage_render_glyphwiki.py` → 256² 灰度，走 `glyph_canonical_format` 归一，
   进 `_emb_index` 当**第 6 个字体档**（`FONT_ORDER` 之外单独一档，`font_set_fingerprint` 要盖到）。
   先只放 33,804 条「关联到整理本字种」的，控制模板矩阵规模。
3. **候选里怎么显示**：候选项键 = `gw:zihai-032338`，卡片显示渲染图 + `related` 正字 + 来源 +
   IDS（有则显示）+ zi.tools/GlyphWiki 深链；**只出候选**，与现役 RRF 同台。
4. **IDS 兜底扩键**：`IdsIndex` 增加未收字条目（IDS 命名的 58,091 条纯 Unicode 部件的直接进；
   扩展语法先跳过），用户「按结构查」就能查到未收字。
5. **评测**：从北行 383 条与 rare-char 里把人裁「无此字/异体」的样本挑出来做「未收字子集」，
   报 top-10；`unseen`/`oov_bench` 不得掉。

### 层 2（云端、需与站长沟通）：字统网按字补 IDS 与「同」关系

- 对整理本 4,637 字（或只对层 1 目录里缺 IDS 的条目）调 `/api/zi/<字>`，取 `yi.nodes` 里 glyph 为
  IDS 串的节点：`IDS / 同或通 / 指向正字 / 来源号`；限速 ≥1 s/请求；**只存派生事实（IDS、对应字、
  来源号），不镜像它的图和释义**；先写信问站长（前端有「歡迎用戶批評指正並一同補充完善」）。
- 用来：给层 1 目录补 IDS（GHZH/TVAR 节点与 GlyphWiki zihai/twedu 可按编号对齐——注意
  `GHZH` 是《汉字海》不是《中华字海》，编号体系与 `zihai-` **不同**，本会话核过 `GHZH-002926`
  ≠ `zihai-002926`；`TVAR` 与 `twedu-` 编号一致）；给候选卡片加「辞书说同 X」。
- `parse_ids` 要兼容扩展语法（`.` 分隔、`#(…)` 笔画描述、`^`）——先当原子处理，不猜。

### 层 3（本机 + 长线）：登记回流与向上游贡献

- 人裁确认的未收字按**刻本字形 IDS** 登记进变体台账（`variant_ledger`），真刻例进 glyph_store；
  与 §6 N14「新字假设」串起来：结构头 + 槽位头给出的 IDS 假设，先查 GlyphWiki 目录，再查字统网，
  都没有才是「疑似新字」。
- 向 GlyphWiki 登记我们发现的刻本写法（自由许可、任何人可登），向 IRG 提交是更长线的事
  （四庫全書 G4K 那条线说明刻本用字有正规入口）。
- IRG ORT 的「unify to」决定可以定期抓一次当**等价关系的权威层**（比 GlyphWiki related 高一级）。

### 风险与预警

- **关联字 ≠ 等价**：分级 + 抽验；字形层永不合并（既有纪律）。
- **KAGE 推 IDS 75%，⿲⿳⿴⿵⿶⿷⿻ 基本推不出**（劉冠偉 2024）——推的 IDS 只当检索键不当标签。
- **三套 PUA 互不相通**（全字庫 P15 / 教育部宋體 / 全宋體）——不用 PUA 当键，用 GlyphWiki 名或 IDS 串。
- **字统网无许可**——层 2 之前先联系；层 1 不依赖它。
- **模板矩阵膨胀**：33,804 条 ≈ 现役字体档的 7 倍（4,654 类 × 5 档）；先按整理本字种过滤，且
  未收字模板只在 5-a `diff` 档触发时参与（N6 的拒识→兜底）。
