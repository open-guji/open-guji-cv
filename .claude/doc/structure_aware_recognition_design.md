# 结构感知的字形识别：把 IDS 拆分接进识别本身（方案草案 + 文献地图，2026-09-21）

> 用户 2026-09-21 的想法（原话要点）：「对文字的识别一定要和 IDS——字符最后的拆分——
> 结合起来。识别一个字，一定要能把它是什么结构（左右还是上下）、每个结构更像什么字
> 提取出来。这样即使匹配不到一个特别像的字，也能大概理解它的结构和信息。现在总是只
> 识别这个图像和哪个字的图像更像；将来要能识别这个字的**笔画结构**和哪个字的笔画结构
> 更像，识别就不太依赖具体的字体、噪点和模糊。」
>
> 本文回答三件事：这个想法在文献里叫什么、谁做过、做到什么程度（§2）；它对「不依赖
> 字体/噪点」的期望能兑现多少（§3）；在本项目上怎么设计、分几步、每步怎么量（§4–5）。
> 口径：文献数字均注明出处；本项目数字抄自已有文档；本机没有 torch，**没跑实验**。

---

## 0. 一句话

方向对，而且不是新路——文献里叫**基于部首/结构的零样本汉字识别**（radical-based
ZSCCR），2018 年 RAN 起有一条十来篇的主线。用户设想的「先显式识别结构和每个槽位的部件，
再按拆字表推理出字」正是其中 **RZCR / ACCID 那一支**（IJCAI'23 / ACM MM'23），
连「14 类结构 + 部件候选 + 知识图推理」的形状都一样。这一支的实证同时说明了两件事：
**显式检测部件要部件级框标注**（ACCID 请了 10 位专家标 15,085 张甲骨图），而**隐式对齐**
（HDE / CCR-CLIP / GRSTR：图像向量 ↔ IDS 树向量）只要字级标签 + IDS 表，更快、成绩更高。
我们的现役网络已经有一个「部件袋」头（`glyph_cnn_explained.md` §3.2），是这条路的第 0 步。

建议：**不做切图、不做检测框**（本项目手工切半已有负结果，文献里框标注太贵），做
「**结构头 + 槽位部件头 → IDS 树编码器 → 槽位级检索**」三步，每步独立落成候选 / 解释 /
兜底检索，**一律不碰放行**。第一步只是一次训练（半天），零标注成本。

## 1. 现役做法 vs 用户设想

| | 现役（`cnn_candidates` + `rare_panel`） | 用户设想 |
|---|---|---|
| 比什么 | 整图 256-d 向量 ↔ **该字字体渲染的均值向量**（图对图） | 图的**结构 + 槽位部件** ↔ 该字的 **IDS**（结构对结构） |
| 结构信息用在哪 | 只在训练时当正则（部件多标签头，~500–750 个部件的「袋子」，不管在哪） | 推理时**显式产出**：结构算符、每个槽位像什么 |
| 没有字体的字（无码异体、刻工写法） | 没有锚，查不到 | 人手写一串 IDS 就能查 |
| 候选全错时 | 人去字统网 | 系统能说「⿰ 言 + 一个像俞的东西」，按结构查表 |
| 可解释性 | 一个余弦分 | 结构 + 部件逐槽位可核对 |

两者不是替代关系：图对图检索在「有字体模板的已编码字」上已经 95–97%（`unseen` 严格
top-1 96.9），文献里的 CCR-CLIP 加印刷模板也是 93.8–95.7（`zero_shot_ccr_survey.md` §一）。
结构路线要补的是它补不了的三块：**无模板的字、候选全错时的兜底、人看得懂的解释**。

## 2. 文献地图：结构是怎么进模型的（三支 + 数据）

### 2.1 显式检测支——「先找部件和结构，再推理」（= 用户的设想）

| 论文 | 怎么做 | 数据前提 | 数字 | 出处 |
|---|---|---|---|---|
| **RAN**（ICME 2018） | 编码器-解码器**生成**部首序列（含结构符），beam 精确匹配 | 字级标签 + 拆字表 | 宋体 2k 类训 → 未见字 55%，10k → 85% | arXiv 1711.01889 |
| **RZCR**（IJCAI 2023，Diao 等） | RIE：**13×13 网格 × 3 anchor 的部件检测**（YOLO 式，要框）+ **14 类结构关系**并行预测；KGR：在「字–部件–结构」知识图上按 θ=0.7 加权推理，Top-1 部件错了也能靠结构救回 | **部件框 + 结构标签**（OracleRC 由 8 位语言学家标） | OracleRC 2,005 类 / 202 部件 / 14 结构，每类 1–32 样本；部件→字：ICDAR 95.9→97.4、CTW 84.9→88.7、OracleRC 58.6→61.4（KGR +2.5）；零样本 800/2,005 未见类 | [arXiv 2207.05842](https://arxiv.org/abs/2207.05842)，[IJCAI](https://www.ijcai.org/proceedings/2023/73) |
| **ACCID**（ACM MM 2023，同组） | 数据集 + 基线：2,892 甲骨字类 15,085 张，**595 部件 28,143 框（每类 30–271）、14 结构**；部件框坐标 + 结构标签；Krippendorff α：字 0.985 / 部件类 0.951 / 部件框 0.930 / 结构 0.989；**拼接合成** 46,800 张扩训练 | 10 位专家、两人一组标注 | 只给了基线，证明「拆分 + 重组」可行 | [arXiv 2308.00655](https://arxiv.org/abs/2308.00655) |
| **JRED**（Pattern Recognition 2024） | 把部件**检测**并进部件级属性嵌入，用检测到的空间信息补嵌入法丢掉的结构 | 部件位置（文中指出「缺部件位置标注是检测法难训的根因」） | — | [ScienceDirect](https://www.sciencedirect.com/science/article/abs/pii/S0031320324010379)（摘要级） |
| **Puzzle Pieces Picker**（ICDAR 2024） | 甲骨文拆成笔画/部件，Transformer 重组成今字；ACCP 数据集覆盖七个历史阶段 | 部件序列标注 | — | [arXiv 2406.03019](https://arxiv.org/abs/2406.03019) |

共同点：**能推理到「不存在于字表的组合」、可解释**；代价是**框级标注**，且检测器在
部件边界糊连时（RZCR 原文自己说手写体「部件间边界重叠不清」）很脆。

### 2.2 隐式对齐支——「图像向量 ↔ IDS 结构向量」（只要字级标签 + IDS 表）

| 论文 | 结构怎么编码 | 关键数字 | 出处 |
|---|---|---|---|
| **HDE**（PR 2020） | 部首 + 结构的**树布局 → 语义向量**，CNN 学去逼近它 | CASIA-HWDB / ICDAR / CTW SOTA（当年） | [ScienceDirect](https://www.sciencedirect.com/science/article/abs/pii/S0031320320302910) |
| **CCR-CLIP**（ICCV 2023） | IDS 递归展开到叶（976 token）过 Transformer，整图整句对比对齐；全字表预编码一次点积 | 手写 m=500→2755：21.8→73.0；**加印刷模板 93.8→95.7** | 见 `zero_shot_ccr_survey.md` §2.2 |
| **HierCode**（PR 2024） | 层级**二叉树多热码本**：非叶=结构、叶=部首；轻量、可上设备 | 行级零样本 | [arXiv 2403.13761](https://arxiv.org/abs/2403.13761) |
| **LERRNet**（ICPR 2024） | **可学习的属性提示向量**引导网络在图上定位判别性部首（弱监督定位，不要框） | — | [Springer](https://link.springer.com/chapter/10.1007/978-3-031-78119-3_21) |
| **Hi-GITA**（2025） | IDS + 5 类笔画双序列，token 级对齐；**结构 token 值 11 点** | 45.3→85.4 | survey §2.3 |
| **EASA**（2026） | IDS 二叉树 + 深度/分支位正弦嵌入（父视角/子视角）+ 部件自信息权 | 树嵌入 +6.7、熵 +0.9；**每类 1 张真样本 → 92%** | survey §2.6 |
| **GL-HPN**（2026） | 全局 CLIP + 局部 FILIP 双分支，**结构算符在局部分支硬掩码**（它没有视觉实体） | m=500：36.2；Top-K=30 精排不丢召回 | survey §2.5 |
| **GRSTR**（PR 2026） | **自顶向下有向部首结构树 + GNN**，方向感知位置编码区分「左/右、上/下」 | 与 CCR-CLIP 同口径领先 | [ScienceDirect](https://www.sciencedirect.com/science/article/abs/pii/S0031320326002797)（摘要级） |
| Radical Sequence + 微调 CLIP（ICDAR 2025）、FaRE（2025）、SIR 自信息（PR 2023）、STAR 笔画+部首（2022） | 同一支的变体 | — | 见 §7 |

共同点：**零框标注**、推理 ms 级、SOTA 都在这一支；代价是「部件本身没见过」谁都没解决
（Hi-GITA 31%、EASA 25%、CCR-CLIP 11%，survey §三），且**推理不产出显式结构**——要结构
得另加头（Hi-GITA 有独立的结构 token 对齐，GL-HPN 反而把它从局部剔掉）。

### 2.3 无 IDS 的潜在组件支

**CoLa**（2025）：3 个 Slot Attention 潜在组件，不用 IDS，图对图模板；**历史文献扫描
57.4 vs CCR-CLIP 22.4**。它的意义是反面教材：对刻本字 陽 IDS 拆出 6 个以上元素、與 含两个
无码 CDP 部件，人工拆分粒度与视觉粒度不一致（survey §2.4）。设计 §4.1 的「停集展开」
就是冲这个问题去的。

### 2.4 历史文献相关数据（能不能拿来训结构模型）

| 数据 | 规模 | 有没有结构级标注 | 授权 | 出处 |
|---|---|---|---|---|

## 3. 对「不依赖字体、噪点、模糊」的诚实评估

**能兑现的**：
- 部件是**跨字共享的中层单元**。「言」在几百个字里出现，网络学「言」的样本是学任一
  整字的几十倍——这是结构路线的真正杠杆：数据效率与向未见组合的迁移。本项目已有旁证：
  带部件头的 CNN 在模拟磨损下 84.3 → 84.3 不掉，HOG 掉 14 点（`glyph_cnn_explained.md`
  §3.3）；CoLa 在历史扫描上 57 vs 22。
- **跨字体**：结构 + 部件的表示与具体字形风格解耦，字体只是训练时的替身。EASA 的
  「一张真样本 24% → 92%」也说明风格差距主要靠真样本弥合，而结构表示让这一张样本的
  收益能摊到所有共享部件的字上。

**兑现不了的、要事先说清的**：
1. **结构判断本身也来自像素**。糊到部件都看不清，结构也判不准；RZCR 自己报告手写体
   部件边界重叠是主要失败源。它降低的是对**风格**的依赖，不是对**信息量**的依赖。
2. **独体字没有部件**：人/入、己/巳、日/目 这些本项目最难的形近对，IDS 是 `#(...)`，
   结构路线一分不加（`ids_guard` 已把它们排除在护栏外，同一原因）。
3. **形近对只是变小了，没有消失**：諭/論 在结构域是离散的（俞 vs 侖），但分辨 俞/侖
   仍是小尺度形状匹配。好处是词表从 7 万字缩到 ~1.7k 部件、每个部件样本多得多。
4. **IDS 不唯一、粒度有争议**：表里 4,350 字有多种拆法，82 个无码部件 `{…}`；全递归到底
   只剩 163 个笔画级原子（本轮实测，`config/ids/ids_lv1.txt`），CCR-CLIP 也说笔画级
   「过细难感知」（92.7 vs 97.2）。粒度要自己定（§4.1）。
5. **异体字的 IDS 必须取刻本字形的、不是整理本正字的**：刻本刻「㕔」（⿰厂丁）整理本
   作「廳」（⿸广聽），拿正字的 IDS 当标签就是教网络说谎。本项目 `variant_form` 的
   shape / reading 之分正好用上——标签一律用 shape。
6. 文献的「部首零样本」（部件本身没见过）无解；我们靠字体渲染兜住了大部分
   （survey §四.3：unseen 1,022 字种里 47 个「一个部件都没在真刻例里出现过」照样能认）。

## 4. 方案设计

### 4.1 表示层：IDS → 「结构码 + 槽位部件」

本轮对 `ids_lv1.txt`（102,032 字）实测的形状：

| 项 | 数 |
|---|---|
| 顶层算符 | ⿰ 66,629（65%）、⿱ 23,004（23%）、⿺ 3,566、⿸ 3,351、⿳ 1,936、⿵ 1,026、⿴ 607、⿹ 570、⿲ 435、⿻ 410、⿷ 206、⿶ 102；独体 `#` 74；自身 82 |
| 嵌套深度（算符个数） | 1 层 91,143（89%）、2 层 8,203、3 层 1,865、≥4 层 821 |
| 前两层结构码 | 153 种，前 12 种覆盖 97% |
| 一级部件（不展开） | 11,527 个，太碎（大量只用一两次的复合部件） |
| 全递归到底 | 163 个原子 = 笔画级，太细 |
| **停集展开**：拆到「出现在 ≥K 个字里」为止 | K=5 → 3,742；K=10 → 2,519；**K=20 → 1,710**（每字 2 个 61% / 3 个 28% / 4 个 7%）；K=50 → 881 |

对照文献：RAN 361/560、ACCID 595、CCR-CLIP 976。**推荐 K=20（1,710 部件）**，理由是
每字部件数集中在 2–3、词表接近 CCR-CLIP，且部件本身都是可渲染的 Unicode 字
（无码 `{…}` 只 82 个）。词表**版本化并进指纹**（`config/ids/` 加 `components_v1.tsv`）。

- **结构码**：顶层算符（17 类 + 独体）；第二层只对 ⿰⿱⿲⿳ 展开成子槽（覆盖 ⿰⿱ 4,032、
  ⿱⿰ 1,527、⿰⿳ 810 …），再深截断为「复合部件」。槽位命名：`L/R`、`T/B`、`L/M/R`、
  `T/M/B`、`O/I`（各种包围）、`A/B`（⿻）。
- **多拆法**：`.` 档为主标签，其余拆法做正例集合（多标签 OR），不当负例。
- **无码部件与未编码字**：允许人手写 IDS 串进入同一表示——这就是无码字通道的接口
  （`rare_char_matching_survey.md` R7）。

### 4.2 模型层：三步，每步独立可交付

**Step A · 结构头 + 槽位部件头（一次训练，半天；零标注）**

- 在现役小 ResNet（256-d）上加两个头：**结构头**（顶层算符多分类）；**槽位部件头**
  （`部件@槽位` 多标签，1,710 × 槽位 ≈ 6–8k 标签，稀疏 BCE）。现有「部件袋」头即升级为
  「部件 × 位置」——这正是 `zero_shot_ccr_survey.md` §五.C 的方案，Hi-GITA 的结构 token
  值 11 点、EASA 树嵌入值 6.7 点是它的文献依据。
- 训练数据不变：字体渲染全字表 + 真刻例，标签由 IDS 自动派生（用 shape 不用 reading）。
- **产出**：每个字块的 结构分布 + 每个槽位的部件 top-k。三个直接用途——
  1. **Top-30 结构一致性重排**（survey §五.E）：RRF 给出 Top-30 后，按「候选字的 IDS
     与预测的结构/槽位部件的一致性」加第四路分，只重排不拦截；
  2. **审字卡片上的解释行**：「⿰ 言 | 俞 / 侖 / 兪」——人对着图一眼定；
  3. **IDS 倒排兜底**：候选全错时，按「结构 + 已确定的槽位部件」查 `config/ids` 倒排
     （「⿰言?」取回几百字，再用 emb 排序）——这就是 L2（pipeline_review §4.3）。
- 验收：`unseen` 严格 top-1 ≥ 96.9 不掉、`oov_bench` 314 条 top-1/10 ≥ 73.2/90.4 不掉、
  北行 383 条 top-10；新增 **结构头准确率**、**槽位部件 top-3**（金标自动来自 IDS）。

**Step B · IDS 树编码器 + 对比对齐（一周；补真正的空白）**

- 文本侧：两层结构树（§4.1）→ 小 Transformer / GNN（GRSTR 的有向树 + 方向位置编码，
  或 EASA 的深度/分支位正弦嵌入——后者全离线零成本），输出 256-d；与图像 embedding
  做 CCR-CLIP 式双向 InfoNCE（图像塔可冻结先试）。
- **推理**：全字表的 IDS 向量离线预编码，作为 RRF 的第五源；**没有字体的字**（无码异体、
  人手写 IDS）第一次有了锚。
- 验收：**新建「无模板零样本」切分**——unseen 里抽 200 类，训练时既无真刻例也**不给字体
  渲染**，只许 IDS 锚；目标 top-10 ≥ 80% 才上线（survey §五.B 的门槛）。

**Step C · 槽位级检索（视 A/B 结果再定）**

- 用注意力软池化（LERRNet 式属性提示，**不切图**）取每个槽位的向量，与「部件原型」比：
  原型 = 部件的字体渲染 + 从真刻例按 IDS 半自动收割的部件区域（IDS 已知 + 网络注意力图
  + 投影/连通体校验，人只裁错例）。
- 产出「这个槽位像哪个部件」的 top-k，支持「结构对上了、某个部件没见过」的半零样本，
  以及**部件级人裁**（人只确认部件，系统组合成字）。
- 这是用户设想里「每个结构更像什么字」的完整形态；放到最后是因为它最像 §2.1 显式支，
  而显式支的坑（边界糊连、要框）我们用软池化绕、不保证绕得过，得先看 A 的注意力图
  是否真落在槽位上。

### 4.3 融合与纪律（一条不改）

- 全部**只出候选 / 解释 / 兜底检索，永不放行**。与 5-a 同源（都看图），**不得互证**放行
  （OCR × 库 97.1% 那条老账的推论，`step5_step6_benchmark.md` §4.7）。
- 结构一致性只在 Top-30 内重排，不拦截；GL-HPN 证明 K ≥ 30 不丢召回。
- IDS 护栏那条负结果（拦 490 条里 487 条本来是对的）不重犯：结构信号进**候选排序**，
  不进**放行判据**。
- 指纹：部件词表版本、IDS 表 stamp、checkpoint、字体集全部进 `full_fingerprint`
  （字体集与参数指纹是 2026-09-21 刚补的洞，见 `steps/rare_candidates.py`）。

### 4.4 数据与评测

- **零框标注优先**。要显式部件位置时，走 ACCID 的「拼接合成」（用已知部件框拼新字，
  框免费得）+ LERRNet 的弱监督定位，不请人标框。
- 真刻例部件区域的半自动收割：IDS 已知 → 注意力图/投影给出候选切分 → 人只裁错例
  （用 `review-artifact` 出页）。
- 评测：现有三套（unseen 1,327 / oov_bench 314 / 北行 383）+ 新增
  **结构金标子集**（从 oov / rare-char 抽 300 条，人裁「结构 + 槽位部件」）+
  **退化鲁棒协议**（现有 wear 模拟与 `config/confusable_font_degraded.json`），
  专门回答用户问的「对噪点/模糊稳不稳」——**没有这条协议，鲁棒性的说法就是感觉**。
- 语料挖洞纪律照旧：训练字体渲染用的字表与评测字表分层报（`step5_step6_benchmark.md` §4）。

### 4.5 风险

| 风险 | 对策 |
|---|---|
| IDS 粒度与视觉粒度不一致（CoLa 的批评） | 停集展开 K 可调；对齐损失允许多拆法 |
| 异体字标签用错（正字 IDS） | 一律用 shape 的 IDS；`variant_form` 已区分 |
| 槽位头标签稀疏（8k）训不动 | 先只做顶层槽位（≈ 1,710 × 2–3）；部件 IDF 权重当开关（EASA +0.9，别指望） |
| 独体字与形近对零收益 | 明说；那一档仍靠上下文与人 |
| 「解释」看着对、字却错 | 解释行只给人看，不进自动判据 |
| 训练成本 | 现役 60 epoch 25 分钟；加两个头 +10% 量级 |

## 8. 范围收窄带来的简化

## 10. 整体架构（数据流）

```
┌ 离线·数据（CPU，云端）─────────────────────────────────────────────────────────┐
│ IDS 多源合并 → 规范化（T 档优先、多拆法保留、82 个 {无码部件} 保留）              │
│   → 停集展开 K=20 → components_v1.tsv（1,710 部件）/ structure_v1.tsv（17 算符 + 二层子槽）│
│   → 每字：结构码 + 槽位→部件 + Unihan 部首/笔画                                   │
│   → 倒排索引：结构码 → 字集；部件@槽 → 字集                                       │
├ 离线·渲染（CPU，云端）───────────────────────────────────────────────────────────┤
│ 全字表 70k × 8 字体档 → 64² 归一图（现有 render_char / normalize_patch）           │
│ 部件 1,710 × 8 档 → 部件模板                                                       │
│ GlyphWiki KAGE → 无码字/异体模板（新）                                            │
├ 真刻例（本机导出一次）───────────────────────────────────────────────────────────┤
│ glyph.db 人裁 15k 例 + 北行 383 裁决 → 64² 归一图 + shape 标签 → IDS(shape)        │
├ 训练（GPU）───────────────────────────────────────────────────────────────────────┤
│ Step A  ResNet-S 四头：emb 256 / cls / **struct** / **comp@slot**（+ 部首、笔画数弱头）│
│ Step B  IDS 树编码器 ↔ emb 对比对齐                                                 │
│ Step C  槽位注意力池化 + 部件原型检索                                               │
│ → checkpoint 进 models/glyph_cnn_r6/（指纹）                                        │
├ 索引（CPU，云端或本机）───────────────────────────────────────────────────────────┤
│ emb 模板矩阵 70k×256 / IDS 向量矩阵 102k×256（B 之后）/ 部件原型 1,710×256（C 之后）│
├ 推理（CPU，Step5-b）──────────────────────────────────────────────────────────────┤
│ 字块 → emb + 结构分布 + 槽位部件 top-k                                              │
│   → RRF（现 3 源 + IDS 向量源 + 部件一致性源）                                     │
│   → Top-30 结构一致性重排 → 候选 + 解释行「⿰ 言 | 俞 / 侖」                       │
│   → 候选全错：倒排兜底（结构码 + 已确定槽位 → 字集 → emb 排序）                    │
│   → 人写 IDS：树编码器出锚（B 之后）                                               │
├ 人裁（控制台 / 审查页）───────────────────────────────────────────────────────────┤
│ 解释行核对 / 部件级裁决 / 结构金标 300 条 / 退化鲁棒协议                           │
└───────────────────────────────────────────────────────────────────────────────────┘
```

只出候选、解释、兜底检索；放行纪律与第一部分 §4.3 相同，一条不改。

## 11. 云端 vs GPU 分工

| # | 任务 | 算力 | 做在哪 | 需要的数据 | 估时 |
|---|---|---|---|---|---|
| 1 | IDS 合并、停集词表、结构码、倒排索引、单测 | CPU | **云端，现在就能做** | 仓内 `config/ids` + Unihan（下载 Unihan.zip） | 半天 |
| 2 | 字体渲染 70k×8 + 部件渲染 + HOG/emb 模板索引 | CPU | 云端可（`fonts/`、`models/glyph_cnn_r5` 都在仓） | 无 | 30–40 min CPU |
| 3 | 结构一致性重排（M0 版）：用**现役** comp 袋头对 RRF Top-30 打「候选 IDS 部件被预测为存在的比例」——零训练 | CPU | 云端写代码；**评测要靶子** | `oov_bench` / 北行 383 图块（本机打包） | 半天 |
| 4 | 真刻例导出包（15k 归一图 + shape 标签 + 三套靶子）`scripts/export_train_bundle.py` | CPU | **本机一次**，几十 MB，传到云端或随实验分支 | glyph.db、`cache/` | 1 h |
| 5 | **Step A 训练**（四头 + 弱头） | **GPU** | 本机 RTX 3080 | #4 | 25–40 min（r5 是 25 min）；CPU 云端估 5–10 h，只当兜底 |
| 6 | Step A 评测（unseen / oov / 北行 / 结构头准确率 / 槽位 top-3） | CPU | 云端或本机（`eval_oov_fast` 16 s 量级） | #4 + #5 checkpoint | 分钟级 |
| 7 | 解释行、倒排兜底、5-a 档位进 5-b 产物的接线（survey R1） | CPU | 云端 | 无 | 1 天 |
| 8 | 结构金标 300 条审查页（`review-artifact`）+ 退化鲁棒协议脚本 | CPU | 云端出页，用户手机裁 | #4 图块 | 半天 + 人裁 |
| 9 | **Step B 训练**（IDS 树编码器 + 对比） | **GPU** | 本机 | #4 + #1 | 1–2 h；CPU 不建议 |
| 10 | IDS 向量矩阵索引 + 「无模板零样本」切分评测 | CPU | 云端 | #9 checkpoint | 分钟级 |
| 11 | GlyphWiki KAGE 渲染无码字模板 | CPU | 云端（核完引擎许可） | GlyphWiki dump | 1 天 |
| 12 | **Step C 训练**（槽位池化 + 部件原型） | **GPU** | 本机 | #4 + Make Me a Hanzi 位置先验 | 视 A 结果 |

**规律**：凡是「表、索引、渲染、接线、评测、审查页」都是 CPU 活，云端做；凡是「反向传播」
都上 GPU，本机做，产出 checkpoint 提交进 `models/`（现役就是这么走的）。云端唯一缺的是
**真刻例与靶子**（#4），一次导出即解锁 #3/#6/#8/#10。

## 13. 落地记录

### 2026-09-21 · M0 第一块：`clustering/ids_struct.py` + `config/ids/components_v1.tsv`

云端做完（CPU，仓内数据）：

- **解析器**吃全了 yi-bai 表的扩展语法：`;` 多写法 + 末尾地区码、`{…}` 无码部件与
  行首形体标注、`#(…)` 笔画式、`⿻[1:]…` 方括号修饰、⿾⿿ 单目、㇯ 双目。第一版把
  `#(H)` 的笔画码当地区码剥掉、又没跳 `[…]`，**488 行解析失败**；修完 **0 失败**
  （`test_whole_table_parses_or_is_atomic` 钉住）。
- **主拆法 T 优先**（含 T 的写法 > `.` > 第一种），13,031 字有多种写法，全部保留在 `alts`。
- **停集词表 K=20 → 1,705 个叶部件**（停集 1,598 / 笔画式 81 / 原子 26），每字叶数
  2 个 61% / 3 个 28% / 4 个 7%，与 §4.1 预估一致（那里的 1,710 是按「第一种写法」
  数的，换 T 优先、修完解析后差 10 个）。`vocab_fingerprint()` 供 Step A 参数进指纹。
- **槽位**：顶层槽名 + 子树路径（`R.T`）；停集展开会把罕见复合部件拆开拼进来——
  廳 → O=广、I.O.L=耳、I.O.R.T=十、…、I.I=壬（聽 作为一级部件不到 20 个字用，所以拆）。
  这是设计选择：换 K 就换粒度，K 进词表文件头。
- **倒排索引** `IdsIndex`：全表 10.2 万字 2.6 s 建成，`search(top=, slots=, components=,
  within=)` 每满足一条 +1、`top` 硬过滤。`⿰ 言 ? + 俞` → 諭 2 分、論 1 分。
- **`component_consistency`**：候选按「它的部件被预测存在的平均概率」打分，一个部件
  都不在 probs 里给 **None**（没意见 ≠ 不像）。**没有接进 `rare_panel`**——现役 r5 的
