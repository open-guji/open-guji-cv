# 切分层反馈：边框混入的四个惯犯位置（进库实审回流）

**日期**：2026-08-24
**证据源**：用户在进库审查页（14/15 页批次）亲手重切的 9 个字位 +
此前 4~13 页实审标出的 46 条 contaminated（`review_label_only` 分片）。
**金标落点**：`open-guji-dataset/char-segmentation/instances`，
`seed="review_recrop"` 条目带 `old_bbox`（切分实际输出）与
`corrected_bbox`（人工拖框金标），由
`scripts/build_recrop_shard.py` 回流。

## 一、四个惯犯位置（用户实审归纳）

| 位置 | 症状 | 实测例 |
|---|---|---|
| **列首字**（idx=0） | 吃进上横版框 | frame_bar_top 类 intrusion 多发于此 |
| **列尾字**（idx=末） | 吃进下横版框；实际更糟——**整格上飘 35~55px**（见二） | 14:1:20 / 14:3:20 / 14:7:20 / 14:8:20 |
| **最左列**（col 最大） | 左缘吃进**断断续续的内边框**，且这条内边框没被版面检测认出来 | 14:9:4（左缘 +25px）/ 14:9:18（+17px） |
| **最右列**（col=1） | 同理，右侧内边框/界行 | 15:1:20（左右各收 11/7px）/ 14:1:20（+23/−26px） |

**核心诉求（G2 版面检测）**：内边框（版框内侧那条不连续的细线）
必须被**识别为边框并从字格中排除**，与外版框同等对待。目前
phase2 只认外框，最左/最右列的格子直接顶到内边框上，线的墨就进了
图块。断续（刻板磨损导致时有时无）不是不检的理由——正因为断续，
逐格用墨量阈值判不出来（`detect_intrusion` 对这类召回最差），只能
在版面层用整页证据（同一 x 位置跨多列的共线短段）把线找出来。

## 二、列尾格的真实病因是格线整体偏移，不只是「多裁了框」

重切 9 例里 5 例是**框整体竖移**而非单边多裁：旧框比人工金标高
35~55px（`grid_shift`），即列尾格上飘——本字下半截在框外、框内上部
是上一字的尾巴。单看「把下边框裁掉」修不了这类：需要 phase3 网格
在列尾处对齐到墨的实际分布（列尾格的下缘应贴住最后一行墨或下版框
内侧，而不是按等分格线硬切）。

量化（新框 − 旧框，px；正=向下/向内）：

```
instance        dy0    dy1   备注
14:1:20  (列尾)  +63    +29   兼最右列，左右也各收 23/26
14:3:20  (列尾)  +55    +33
14:7:20  (列尾)  +56    +37
14:8:20  (列尾)  +50    +34
14:9:18 (列尾近) +73    +6    兼最左列，左缘 +17
```

同页四个列尾全部上飘 50±10px ——这是**系统性**格线偏移（该页版框
定位或行数估计偏差），不是单格噪声。建议 phase3 加一条列级自检：
列尾格墨的重心若显著低于格心（或格内上缘墨带与上一格连通），整列
下移重排。

## 三、下游已有的兜底与它的边界

- `crop_quality.detect_intrusion`（rule_bar_left/right、
  frame_bar_top/bottom）：细直条满贯检测，实测召回 56%、误报 1.0%。
  它只**提示**审查页、不参与准入；对断续内边框和 grid_shift 基本无感
  ——前者不满贯，后者混入的是邻字墨不是直条。上游修好一条，这里的
  兜底就少压一条给人。
- 进库侧已把重切做成纯几何事件（`apply_recrop`），人工可修但成本高：
  每格拖框 ≈ 15s，全书外推是小时级人工。**切分层修一次，全书受益。**

## 四、怎么用这批金标

```bash
# 9 条 review_recrop：old_bbox 是坏例、corrected_bbox 是金标
cd open-guji-dataset/char-segmentation/instances
python - <<'EOF'
import json
for e in json.load(open("expected.json")):
    if e.get("seed") == "review_recrop":
        print(e["page"], e["col"], e["idx"], e["defect"],
              e["old_bbox"], "->", e["corrected_bbox"])
EOF
```

- 回归口径：新切分在这些 (page,col,idx) 上的 bbox 与 `corrected_bbox`
  的 IoU（建议 ≥0.85 为过）；
- 自检口径（`eval_instance_quality.py` 既有）：这些格至少要被 flag
  进审查队列——修不好也不能无声放行。
- 分片是**定向富集**（只有切错的才被重切），不能读作全书错误率。

## 2026-08-25 第二轮：量法先修，再修列尾格

用户把这份文档指为切分层的靶子：「那 18 个字位就是现成回归集，IoU 0.671
是基线，密集失败点是**列尾格（idx=20）**在 14~18 页反复出现」。

### ① 先修量法：`eval_recrop` 在自己考自己

`scripts/replay_recrops.py` 会把 `corrected_bbox` **贴回 index.jsonl**
（人工成果不能只活在产物里）。贴完之后产物里的框就是金标本身，而
`eval_recrop` 读的正是产物 —— 实测一贴回，通过数从 20/24 跳到 23/24，
**算法一行没改**。

改法：`eval_recrop` 现场重跑 `extract_page` 取**算法自己**的框。
顺带把汇总行的措辞改对——过闸条件一直是「含住 + 盖墨」，不是 IoU。

### ② 金标与产物的框口径本来就不同，IoU 不能当过闸条件

人工是**整格拖框**：实测 23 条金标宽 125~175px，与列格窗口
（163~177px）一个量级；而 2026-08-24 裁剪定版之后图块是**墨迹外接框
±2px**，每侧要窄 20~25px。两种口径不同，IoU 天花板就在 0.65~0.75，
再修切分也上不去。所以：

- **过闸**：紧框 ⊆ 金标框 +8px，且金标框内的墨 ≥95% 落在紧框内；
- **IoU**：只当趋势参考打印（用户记的 0.671 即此列）。

### ③ 列尾格的病因（逐格看图查到的）

四条真失败（16:6:1 / 16:2:20 / 14:7:20 / 15:5:20）画出连通体之后一目
了然：**框线与字身粘成了一个连通体**。「院」的阝、「續」「蒐」的末笔都
直接连到下版框上。于是两条既有的路同时失效：

- `strip_frame_debris` / `strip_frame_stub` / `strip_side_rule` 只动
  **独立**连通体 —— 粘上了就不是独立的；
- `carve_end_edge` 的红线是「路径每列必须在该列**字身墨**的最低点之
  下」—— 框线成了字身的一部分，约束自我否定。

还查出 `_char_body` 的一处硬伤：间隙量的是「与**主连通体 bbox** 的
垂直距离」。主连通体又高又瘦时（「院」的阝几乎贯穿整块图块）任何东西
的 y 区间都落在它的 bbox 里，算出来的间隙是 **−96**，于是页底那两条
框线残段被当字身保护，曲刀一刀也切不动。

### ④ 两处落地

1. **`_char_body` 改量「头顶的字料」**：先按形状（薄 + 小）挑候选，
   再看候选**同一批列上、正上方**最近的字料有多远。「覽」下面那两条腿
   （h=27~61、面积 400~870）在第一关就不是候选，红线原样保住。
2. **版框带内缘钉桩**（`frame_band_inner`）：条带的上下界先钉在版框带
   内缘，框墨**根本不进条带**——比进来之后再想办法剥可靠得多。
   踩坑一条：内缘的走法起初用「行墨 ≥0.22 就继续往里走」，把 vol01/28
   末行字整行当成框带，col8 的末字砍掉一半（字身墨 2457→1263）。改用
   grid_segment 标定过的双档 `is_bar`（行墨 ≥0.5，或 ≥0.28 且最长横向
   连续段 ≥0.22 页宽）之后，抽样 36 页 5024 格里掉墨 >3% 的从 13 格
   降到 4 格，逐格看图确认那 4 格删掉的全是框线锯齿与纯框线渣格，
   没有一笔字（vol01/28:4:20「不」下面那排框齿是最典型的一例）。
   再加两条硬保险：框带最厚 25 行；钉桩最多吃掉端格的 35%，越过就不钉。
