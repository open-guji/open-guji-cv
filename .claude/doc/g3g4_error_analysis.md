# G3/G4 误差分析与优化路线（2026-08-23 实测记录）

基于 char-clustering / char-normalization 两个测试集的第一轮误差分析。
所有数字都在冻结分片（pipeline 23ee9a5）上量，实验脚本的关键逻辑与
操作点表都在本文，方便复现。

## 1. 对级分布：三类对，三个事实

从 001/002 分片抽 880 同字对（难例 80 + clean 层随机 800）、879 异字对、
110 形近字对（人/入 大/太 未/末 面/而 曰/日 論/諭 千/于 間/問…），在
现行判据与候选判据下量分布：

| 量 | same 中位 | diff 中位 | near（形近）中位 |
|---|---|---|---|
| 配准 F1（现行）| 0.674 | 0.442 | **0.676** |
| 膨胀 F1 | 0.800 | 0.614 | 0.783 |
| 覆盖率 cov(r=2) | 0.957 | 0.793 | 0.919~0.936 |
| 12×12 窗口残差 wmax | 21px | 52px | 32px |

**事实一：形近字对与同字对在任何全局相似度下分布重合**（F1 中位 0.676 vs
0.674）。调阈值无解，印证 char_clustering_design.md 18.4。

**事实二：同字对 F1 低不是几何变换问题。** 对 f1<0.8 的同字对做扩大配准
（独立 x/y 缩放 ±18%、平移 ±6）：F1 中位 0.670 → 0.668，恢复到 ≥0.8 的
只有 1.2%。纵横比失配在高/低 F1 两组无差（0.044 vs 0.042）。结论：
**每个字位是独立的手工雕刻**，同字天然带 2~3px 的局部笔画位移；刚性重叠
（哪怕加骨架+笔宽归一）的上限就在 0.67~0.75 一带。

**事实三：局部有界位移覆盖率（r=2）能吸收刻工位移**，配上局部残差护栏后
零误并操作点的同字通过率从 0.5%（现行 F1≥0.80）提到 ~20%：

| 判据组合 | 零误并 same 通过 | ≤2 误并 same 通过 |
|---|---|---|
| F1 ≥ θ（现行）| 0.5% | — |
| F1 + 最大差异块 | 8.3% | 15.1% |
| cov + 未覆盖最大连通块 | 10.3% | 21.6% |
| **cov + 12×12 窗口残差 wmax** | 6.4%* | **19.3%** |

*形近对扩到 110 个之后的诚实数字；负例集越对抗，零误并前沿越紧。

## 2. 簇级验证：vol02 已能达标，vol01 差一族形近字

把 `verify_v2`（cov ≥ t 且 wmax ≤ g → same；cov ≥ 0.85 → unsure）接进
现有聚类（kNN + 全连接抽查不动）跑冻结基准：

| 操作点 | vol01 purity / 碎片 | vol02 purity / 碎片 | human purity |
|---|---|---|---|
| 现行 F1≥0.80 | 0.99900 / 2.86（单例 95%）| 0.99903 / 3.71（93%）| 1.0 |
| cov≥0.96, wmax≤(blob0.03) | 0.98234 / 1.73 | 0.98390 / 2.07 | 0.923 |
| cov≥0.98, wmax≤26 | 0.99667 / 2.28（82%）| 0.99839 / 2.78（80%）| 0.945 |
| **cov≥0.985, wmax≤22** | 0.99767 / 2.51（86%）| **0.99968 / 3.09（83%）**| 0.967 |

vol02 在 (0.985, 22) 已经**同时**做到 purity 超过现行基线（0.99968 >
0.99903）且碎片率 3.71→3.09、单例率 93%→83%。vol01 卡在 0.99767。

**漏进来的全部是「整部件替换」型形近字**（vol01 @ (0.985,22) 的错并清单）：
遺/還、諭/論、圓/圖、太/大、廣/贋、候/侯；(0.98,26) 还有 間/問、已/巳、
曾/會、選/過。共同结构：差异是一个完整的小部件（一点、一个内芯），在
密集字里被 r=2 覆盖或摊薄到窗口阈值之下。

**试过且无效**：部件级失配率一票否决（comp_miss>0.30，无平移容忍）——
簇级数字一个没变。原因：漏网对的差异部件要么与主体粘连（諭/論），要么
被邻笔的 r=2 膨胀盖掉一半以上（太的点贴着大的撇捺）。

## 2.5 第二轮实测（P1/P0 执行记录，2026-08-23）

**P1 密度自适应半径：失败，已否。** 密集区 r=1 / 稀疏区 r=3 在对级上
全面差于固定 r=2（≤2 误并同字通过率 4.9% vs 9.4%）——「同字位移主要在
稀疏区」的前提是错的，刻工位移在密集区一样发生，收紧密集区先杀死同字对。
同轮一并否掉的还有：骨架级失配（r=3 骨架匹配，无可行零误并点）、墨芯
加权残差（4.2% < 对照）、部件级失配一票否决（簇级数字一个没变——漏网
对的差异部件要么与主体粘连要么被邻笔覆盖）。

**出路是收紧操作点而不是加护栏。** (cov≥0.992, wmax≤12) 三分片全量验证
never-make-worse 成立：

| 分片 | v1 基线 | coverage (0.992, 12) |
|---|---|---|
| vol01 | 0.99900 / 碎片 2.86 / 单例 95.0% | 0.99900 / **2.80** / **93.0%** |
| vol02 | 0.99903 / 3.71 / 93.2% | **1.00000** / **3.58** / **89.2%** |
| human | 1.00000 / 3.21 / 84.4% | 1.00000 / **2.92** / **77.1%** |

更宽松的 (0.99, 14) 在两册上收益更大（碎片 2.72 / 3.44）但在人工分片
错并 2 个 諭/論——目视确认这版刻本的 侖底「冊」与 俞底「月刂」只差中横
是否贯穿最右竖，图像层面就是极限难题，家族已进永久回归对。

**已落地（verify.py / clusterer.py / CLI）**：`verify_pair_cov` 成为默认
判据（`--verify-method overlap` 保留对照），操作点 (0.992, 12) 收进
verify.py 常量。合成冒烟测试对 coverage 单独设碎片上限——合成磨损是
「挖掉整块墨」，正好是 wmax 护栏该拦的形态，与真实刻工位移不同构。

**P2 量化：unsure 带是碎片率的真正出路。** 对最终聚类统计 unsure 邻簇边：

| 分片 | unsure 边 | 其中同字 | 全审同字边后碎片率 |
|---|---|---|---|
| vol01 | 13877 | 5707（41%）| 2.80 → **1.06** |
| vol02 | 13355 | 6990（52%）| 3.58 → **1.17** |
| human | 256 | 125（49%）| 2.92 → **1.00** |

几何判据的自动合并已经贴到硬约束的墙上；剩余碎片几乎全部躺在 unsure 带
里，且一半是同字。审查一条簇对边 = 合并两簇 + 一条人工标定对回灌 M7。
下一步是把 unsure 边按 cov 降序排进 review-export 的批次页面。

## 3. 优化方案（按优先级，全部可在现有测试集上量）

**P0 —— 已落地**（见 §2.5）：coverage 判据 + (0.992, 12) 操作点为默认。

**P1 —— 已测已否**（见 §2.5）：自适应半径/骨架/墨芯/部件否决四条路都
不如 cov+wmax，负结果记档，别再走。

**P2 —— 已量化**（见 §2.5）：unsure 带全审可把碎片率压到 1.06~1.17。
待做的是 review-export 侧的簇对批次页面（按 cov 降序）。

**P3 —— 归一化去残余的根因修复（4 个已记账缺陷同根因）。**
`remove_edge_specks` 只删**贴边**组件；四个缺陷（022 邻列竖带、026 版框
横线穿中部、032 粘连横线、033 邻字「一」在核心区）全是「不贴边」。
改法要点与风险：
- 把「贴边」放宽为「细长且主体在边缘带内」可修 022/026 一类；
- 「主体 bbox 之外的小面积组件」判残留会**误杀多部件字**——相 的目、
  二 的另一横、之 的上点都在主体 bbox 外。任何此类规则落地前，先给
  golden 集补 之/亦/文（游离点画）与 二/三（平行横）样本，否则回归门
  接不住这类误杀；
- 032 型粘连残留在图块层无解，出路在切分层（F 步的像素归属）。

**P4 —— 已落地**：14 个漏网家族进 hard_pairs（origin=cluster_leak，
vol01 16 对 / vol02 7 对）。当前判据下 vol01 15/16、vol02 7/7——那 1 条
失败是基线就存在的 人/入 错并，留作靶子。

## 4. 后续待办（2026-08-23 记，按杠杆排序）

几何判据已贴到 0.999 硬约束的墙上（§2.5 四条路线全部实测否掉），
剩余收益不在"更聪明的相似度"里。接手人按此清单动工，每条都带量法。

### 4.1 算法/工程侧

1. **unsure 审查队列落地（最大杠杆，纯工程）。** unsure 边同字占
   41~52%，全审碎片率 2.80→1.06 / 3.58→1.17（§2.5 量化表）。做法：
   review-export 增加「簇对」批次页面，unsure 邻簇边按 cov 降序排入，
   审完走既有 review-ingest 回灌。每审一条边白得一条人工标定对——
   审查本身就在造数据集。
2. **量 kNN 候选召回率（便宜的未知数）。** 聚类只验证 kNN 提名的边
   （k=10、分桶内）；同字对若根本没被提名，账在特征检索层而非 verify。
   量法：char-clustering 的同字对落在 kNN 候选集里的比例。召回低就换
   特征后端（emb）或加大 k——那是免费收益。
3. **簇级二段合并（现在才值得试）。** 单例率降到 77~93% 后多成员簇
   变多，簇原型（成员平均像）互验比实例对抗噪。以前否掉它是因为全是
   单例无物可平均，条件已变，可重测。量法照 §2 的三分片流程。
4. **P3 归一化去残余修复**——卡在 4.2 的补样上（§3 P3 的误杀风险）。
5. **在新切分上重跑 label/refine（一石三鸟的前置）。** 解锁：端到端
   准确率刷新（86.4% 已过期）、char-clustering 迁到新切分（README 的
   迁移前置条件）、align 标注产能扩大（新切分下结构一致页会多很多）。
   rapidocr-onnxruntime 离线可装、模型随包分发，本仓库就能做。

### 4.2 需要的新数据（按杠杆排序）

1. **第三册（不同卷）扫描数据。** vol01/vol02 都是同版卷首，操作点
   (0.992, 12) 的「书级参数」主张只有一个数据点。用
   `scripts/ia_download_zongmu.py` 取卷一/卷二，跑通切分后按现有流程建
   第三分片，回答关键问题：**判据与操作点跨册迁移吗？** 这决定后面
   十册的工作方式。
2. **审查导出落图 impure 对两端。** 人工层至今零硬负例（29 条 impure
   对因未导出图块全部丢失，见数据集 known_limitation 2）。改导出流程
   即可，以后每轮审查自动积累形近硬负例——正是卡操作点最缺的样本。
3. **归一化 golden 定向补样 ~10 张**：之/亦/文（游离点画）、二/三
   （平行横画）、相/門（部件横向分离）。解锁 P3——没有它们，任何
   「删主体 bbox 外小组件」的规则都可能静默误杀这几类字，回归门接不住。
4. **断笔确诊样本 20~30 张。** 「断笔容忍」至今零样本验证（数据集
   known_limitation）。独立线索：同字实例间连通体数量的离群（某个
   「言」比兄弟们多两个连通体 → 疑似断笔），与归一化判据不同源。
5. **char-ocr 数据集几乎白拿。** `align_label` 产出的 13000+ 条
   (图块, 金标字) 就是 G5 要的 (crop, label) 对，按册划分与三个溯源
   字段都齐——建 char-ocr 基准约等于换个目录结构，是本轮对下一步
   最大的顺手馈赠。
