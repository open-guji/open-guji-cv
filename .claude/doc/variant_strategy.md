# 异体字策略：忠于刻本字形下的识别、自动确认与资料积累（2026-09-05）

> 用户方针（2026-09-05 定）：**字形层忠于刻本；归一到通行字只为方便理解含义、以及积累
> 关于异体字的数据。** 本文回答用户提出的六个问题：(1) 原则与边界；(2) 公开异体字资料库
> 有哪些、什么格式、好不好用，一对一与一对多怎么处理；(3) 怎么积累"这本书用哪个异体"的
> 资料；(4) 整理本怎么当校验器；(5) 保留异体的同时怎么提高自动确认率；(6) 审阅界面怎么改。
>
> 配套：`charset_and_lm.md`（字形层不可被语义层改写的纪律）、`glyph_set_roadmap.md`
> 层 4（异体偏好表）、`step5_step6_benchmark.md`（报数纪律）。所有数字都是本日实测。

## 0. 一页结论

**骨架已经对了，缺的是三样东西。** 对的部分：`AdmitRec` 分 `char`（刻本形）/ `reading`
（文意）两栏，整理本字永远不覆盖 `char`；准入十条通道全部在 `vmap.semantic()` 空间比较；
人裁事件带 `shape`/`reading`/`conversion`；关系图 `config/variants/variants.json`（47,935 字、
47,181 边、12 个来源）已入库；释义表 `gloss.json` 69,835 字；`_char_hint.std` 已会"在异体
组里找整理本实际用的那个"。

缺的三样：

| 缺口 | 现状 | 后果 |
|---|---|---|
| **语义层默认表只有 21 行** | `VariantMap` 读 `config/dicts/variants.tsv`（手工 21 行）；2,727 条自动表在 `config/charset/` 里没接、只用 Unihan、比关系图旧 | 髪/髮、䙝/褻、㕔/廳、鍾/鐘 这类与已解决的 卽/即、㫖/旨、彚/彙 **同一机制**，却仍在烧人审：剩 7 条人审里 4 条是它 |
| **没有"本书用字账"这一层** | 字形套方案层 4 写了设计，未落地；E5 是手算的 6 组 | 同一异体每次出现都当新问题；无法量"这本书用哪个形" |
| **义定了、形没定时会静默归一** | `_pick_char`：库 unsure + 文本两路一致 → `char = align_char` | 刻 髪、OCR 读 髮（字典偏通行字）、整理本 髮 → 存 髮，字形库错标一例，后续 髪 实例继承错。**现在没发生只因语义表小；一扩表这个洞就打开**，所以扩表必须与新状态同时上 |

方案一句话：**三层表（关系层 → 本书用字账 → 语义层派生）+ 准入加一个状态「义定形未定」
+ 按组审阅**。人审率预期从 1.1% 再降（4/7 异体桥消失），字形保真率变成可量的数。

## 1. 原则与边界（问题 1）

### 1.1 三种关系必须分开，这是全文的基础

字典里叫"异体"的关系至少混着三种东西，对本项目的意义完全不同：

| 类 | 定义 | 例 | 语义层可否合并 | 准入可否当"同字" | 界面 |
|---|---|---|---|---|---|
| **T1 纯异体** | 同一个词的不同写法，任何语境可互换 | 髪/髮、卽/即、㫖/旨、彚/彙、厯/歷、㕔/廳、䙝/褻、无/無、葢/蓋 | 可（LM 计数合并） | 可（桥） | 徽记「異體」 |
| **T2 互通 / 一对多** | 各自是正字，只在某些义项互通，或一形对多个正字 | 鍾/鐘、注/註、后/後、于/於、云/雲、采/採、制/製、囘→回/迴、蓋→葢/盖 | **不可**全局合并（会把不同词并掉）；只能按本书用法定向 | 可桥，但 `reading` 取整理本字 | 徽记「互通」+ 整理本字 |
| **T3 形近 / 通假 / 古文** | 不同的词；或字典收录但刻本不会用的关系 | 己/已/巳、人/入、日/曰、諭/論；借用（讐/仇）；古文（上/二、人/几、王/玉） | 不可 | **永不**桥 | 红色「形近·非異體」 |

关系图里的来源标签**不能直接对应到这三类**——`twedu` 既给 㕔~廳（T1）也给 上~二（T3 古文），
`unihan:kSemanticVariant` 既给 䙝~褻（T1）也给 子~只（T3）。所以来源白名单只是第一道粗筛，
**真正的分类器是本书语料**（§3）。

### 1.2 Unicode 边界

- 现阶段只记 Unicode 已收字（含扩展区，`𠮓` U+20B93、`𨽾` 都已在库）。
- **未收字**三条出路，各有代价：① IDS 文本锚（字形套方案层 5 已定，唯一对口的通用机制）；
  ② IVS（Unicode 官方"同码位异形"机制，IVD 登记很重，私用 IVS 互操作差）；③ 字形库原型
  本身——图像就是最忠实的记录，`glyph.db` 已经在做。**建议**：未收字 = 图像 + IDS，不造 PUA。
- IRG 的 UCV（可认同部件变体）决定了哪些差异**不会**有独立码位（者有无点、辶一点二点）。
  这类差异在本项目只能活在字形库的图像层，码点层不可能"忠于刻本"到这一级——这是边界，
  不是缺陷。
- **不做 NFC/NFKC 归一**：兼容区（U+F900–FAFF）会被折叠到统一区。待核：全仓 grep
  `unicodedata.normalize`，确认没有任何路径对标签做过归一。

### 2.2 一对一 vs 一对多：没有现成的干净表，只能自己算

用户的问题是"有些异体有明确的规范化繁体字（一对一），有些一对多"。查下来的结论：

1. **没有任何公开资料库直接标"一对多"**。要自己算：一个形在 T1/T2 边下连到 ≥2 个整理本
   用字，就是一对多。本书实测：字形库 18 个整理本没有的形里，2 个一对多（囘→回/迴、蓋→葢/盖）；
   整理本自身多形的组 362 个（§3.3）。
2. **一对多有三种来路，处理各不同**：
   - 简化合并（发→發/髮、干→乾/幹、后→後/后）：与繁体刻本无关，但 `cjkvi-simplified` /
     `kSimplifiedVariant` 边把它带进了图，**必须排除出准入桥**（否则 OCR 读 后、整理本 後
     会被当同字）；
   - 义项互通（鍾/鐘、注/註、采/採、制/製）：两边都是正字，刻本按义项或习惯选。本书整理本
     注 748 / 註 526 并用，说明整理本在区分，这时整理本字是形的证据；
   - 古文/篆文异体（上/二、人/几、王/玉、子/只）：字典真有、刻本不会用。**只有本书语料能过滤
     掉它们**——两端在整理本都高频且分布独立，就不是一对异体。
3. **"明确的规范化繁体字"有两个候选，建议都存**：
   - `canonical`：跨书统一键，取教育部正字（twedu 方向）；没有时取整理本用形里码位最小的；
   - `reading`：本书文意字，取整理本实际用形（`_char_hint.std` 的逻辑）。
   两者常常不同（教育部正字 蓋，本书整理本 葢 ×791、蓋 ×0），跨书积累异体资料靠前者，
   本书文本录入靠后者。
4. **方向信息原始文件里有，现在的构建把它丢了**。`twedu-variants.txt`、`hydzd-variants.txt`
   都是正字在前；`build_variants.py` 只存 `ord(a)<ord(b)` 一侧的无向边。重建时要保留每条边的
   `(正字, 异体)` 方向和来源，一对多的判定和 `canonical` 的选取都要它。

### 2.3 关系图现状的两个问题（实测）

- `HIGH_CONFIDENCE_SOURCES` 对准入桥**过宽**。用它给字形库 1,958 字种分组，"本书刻了 ≥2 种形"
  的组有 99 个，其中大半是假的：四×86/肆×6（大写数字）、二×40/上×40（twedu 古文）、
  人×69/几×1（twedu）、王×18/玉×10（hydzd+twedu）、子/祇/祗/只（kSemanticVariant）、
  後/后、乾/干（简繁）、來/勅、某/私、藝/芸（只有 yitizi）。真异体组（卽/即 18/15、彚/彙
  11/4、畧/略 15/1、歷/厯 14/1、註/注 12/6、鑒/鑑 11/7、製/制 10/7、抄/鈔 13/4、迹/跡/蹟）
  混在里面。
- 自动表 `config/charset/variants.tsv`（2,727 条，只用 Unihan，语料限定）对本书 12 个可桥的
  刻本特有形只覆盖 7 个，漏 彚 㓂 㕔 厯 𠮓——因为它建于关系图之前。这张表应改为从关系图
  派生（§3.4），不再单独维护。

## 3. 三层表：关系层 → 本书用字账 → 语义层（问题 3、4）

```
关系层  variants.json     字典知识：无向→改有向，带来源，T1/T2/T3 粗分。通用、有噪声。
   ↓ 用本书语料 + 裁决过滤
用字账  books/<edition>.json   这本书：每个语义组刻了哪些形、整理本印了哪些形、
                                (刻本形→整理本形) 对的次数与来源。自动派生，可重建。
   ↓ 派生
语义层  variants.tsv      LM/准入用的 字形→代表字：只收 T1 + 账本确认的 T2 对；
                          方向 = 整理本用形；手工表覆盖。
```

### 3.1 关系层：改三处，不重写

1. **保留方向**：边存 `(正字, 异体, 来源)`，`ord` 排序只做去重不做方向。
2. **来源分级**（作为 T1/T2/T3 的先验，最终由账本定）：
   - 桥候选：`twedu`、`hydzd/variant`、`unihan:kSemanticVariant`、`unihan:kZVariant`、`yitizi`
     （单独出现降权）；
   - T2 标记：`unihan:kSpecializedSemanticVariant`（官方"部分义项同"）、`hydzd/proper`、OpenCC
     一对多；
   - 永不桥：`unihan:kSpoofingVariant`、`hydzd-borrowed`、`cjkvi-simplified`/`kSimplified`/`kTraditional`
     中**没有**异体来源背书的边（无/無 有 twedu 背书可留，后/後 只靠简繁边不可）、`dypytz` 单独出现。
3. **不传递**照旧（模块 docstring 已写）。组的定义改为：以 canonical 为中心的一跳星形，不做连通分量。

### 3.2 本书用字账（新，`config/variants/books/<edition_tag>.json`）

这就是用户要的"关于本书常用哪个异体字的资料库"，也是字形套方案层 4 的落地。**只由脚本
从产物派生，永不手编**——来源三处：

| 来源 | 字段 | 现有数据 |
|---|---|---|
| `seed_admit` 产物 `AdmitRec(char, reading, channel)` | 自动转换对 | 41,366 条记录，自动进库且 `reading≠char` 的 38 条：卽→即 ×19、彚→彙 ×10、㫖→旨 ×5、厯→歷、櫽→檃、𨽾→隸、註→注 各 1；全部走 `match_replace` |
| 人裁 confirm 事件 `(shape, reading, conversion)` | 人确认的转换对（含 己/已/巳） | 273 + 132 条裁决；`instances.label≠semantic` 的有 卽→即 13、註→注 12、㫖→旨 9、巳→已 5、彚→彙 5… |
| 整理本语料字频 | 整理本用形 | 341,240 字次 / 4,636 字种 |

结构（每个语义组一条）：

```json
"髮": {
  "canonical": "髮",
  "book_forms":  {"髪": 17, "髮": 0},          // 刻本刻了什么（来自 char）
  "ref_forms":   {"髮": 41},                   // 整理本印了什么（语料频次）
  "pairs": {"髪→髮": {"n": 17, "human": 3, "auto": 14, "first": "vol01:60:4:15"}},
  "ref_policy":  "single",                     // 整理本对这一组：single 归一 / multi 保留区分
  "tier": "T1"
}
```

五个用处：(a) 准入先验（§4）；(b) 候选排序（本书常用 卽 就把 卽 排前）；(c) 默认 `reading`；
(d) 新书按时代/版本继承最近的账当初值；(e) **直接导出为研究数据**——"武英殿本《四庫總目》
异体用字表"本身就是可发布的成果，每册跑完自动更新。

实测规模感：字形库 1,958 字种里只有 **18 种是整理本没有的**（59 例），60 页挖出 21 个异体组。
整册估 100–200 组。**账本很短、很尖**（E5 结论：三组占 90%），这决定了 §4 的人审成本是
O(组数) 而不是 O(字次)。

### 3.3 整理本作为校验器（问题 4）

整理本不是全归一的，是**半归一**的。对刻本用到的 1,851 个组：整理本只用 1 种形的 **1,489** 组，
用 ≥2 种形的 **362** 组（注/註 748/526、於/于 3055/171、无/無 41/1370、攷/考 31/1256、
疎/疏/踈/䟽、弁/辨/辯、据/據 17/541、鑒/鑑…）。这个划分决定了整理本字能当什么证据：

| 组的 `ref_policy` | 整理本字能证明什么 | 形从哪来 | 准入要求 |
|---|---|---|---|
| **single**（1,489 组） | 只证明**语义**；整理本自己不区分形，髪/髮 它一律印 髮 | 只能来自图像（库 same / 组内定形器） | 语义两路一致即可桥；形另定（§4.2） |
| **multi**（362 组） | 语义 **+ 形**（它在区分，印 註 就是 註） | 整理本字兼作形证据 | 要求精确一致；不一致时只有账本里有人确认过的转换对才桥（整理本偶尔归一不一致，如 无→無） |

三种校验用法：

1. **确认我们的异体判断**：桥放行的每一对 (刻本形, 整理本形) 都进账本；账本里出现**关系图里
   没有的对** → 三选一（新异体 / OCR 错 / 整理本错）进审队列。现役 38 条里 㫖→旨 就是"关系图
   没有"（UCV 认同形），靠手工表兜的——正是这条通道该抓的东西。
2. **推断整理本的凡例**：`ref_policy` 就是整理本对每组的取舍，可导出成表，反过来给整理本做
   校勘（它在 无/無 上不一致，41:1370，多半是漏改）。
3. **分层报数**：`align` 金标与整理本同源，验异体桥必须用 `human` 层（273 条）单独报，
   `step5_step6_benchmark.md` §4 第 6 条。

### 3.4 语义层派生

`config/dicts/variants.tsv` 改为**生成物**：从关系层取 T1 边 + 账本里人确认过的 T2 对，方向 =
整理本用形（single 组）或不派生（multi 组：LM 用形本身，注/註 各算各的）；一对多形（囘、蓋）
不派生；手工表仍覆盖（21 行留作 override，不再是主表）。`build_charset.py` 的 `pick_orthodox`
逻辑（语料频次定向）保留，输入换成关系图。

LM 的收益小但方向正确：`normalize_text` 现在只合并 21 条；派生后 髪/髮 等计数合并，
n-gram 不再被同词分票。`glyph_layer_immutability` 硬断言不动。

## 4. 准入：保留异体的同时提高自动率（问题 5）

### 4.1 现役唯一的系统性漏洞：首例静默归一

`_pick_char` 的逻辑：库 `same` → `char` = 库形（对）；库 `unsure` 且整理本通道放行 →
`char = align_char`。注释里的理由成立（unsure 时库 top1 不可信，敷/數 那 8 条实锤），但它
默认"整理本形 = 刻本形"。对 single 组这个假设**必然错**在首例上：

```
刻本刻 髪（库里还没有 髪）→ 库 unsure
OCR 读 髮（字典 15,907 字含 髪 但模型偏通行字）
整理本 髮
→ dual 放行，char = 髮        ← 字形库多一个错标的 髮，下一个 髪 实例继承它
```

现在没发生，只因为 `VariantMap` 太小、这些位都落人审了。**把语义表扩大而不补这一步，等于
把人审换成静默错标**——这是保真最要防的事，也是本文所有改动必须一起上的原因。

### 4.2 新状态「义定形未定」（semantic-fixed, form-open）

| | 判定 |
|---|---|
| 进入条件 | 现有通道判"语义两路一致、可放行"（dual / match_ref / match_replace / match_margin / match_ref_weak）**且** 库 ≠ same **且** 组内候选形 ≥ 2（组 ∩ (账本 book_forms ∪ OCR 字典 ∪ 字体模板集)） |
| 处理 | **组内定形器**：现成的三源检索（HOG 0.5 / CNN 分类头 1 / embedding 3，第五轮 checkpoint）**限定在组内 2–4 个形之间**。closed-set 比开放集容易得多；对本书原型（glyph.db exemplar）优先于字体模板 |
| 自动放行 | margin ≥ τ **且** 该形在账本 `book_forms` 里已有人确认 ≥ 1 次 → 放行，`channel = variant_form`，`reading` = 整理本字，产物打 `form_auto` 标记可审计 |
| 人审（一次） | 该形是本书**首次出现** → 组视图人审；确认后账本 +1，之后同形自动 |
| 人审 | margin < τ → 组视图人审 |

τ 用 200 例组视图抽审标定（§4.5），起点参考 `context_margin` 0.70 的标定方式。

### 4.3 决策表

| `ref_policy` | 库 verdict | 账本状态 | 决定 |
|---|---|---|---|
| single | same（形 X） | — | 放行，char=X，reading=整理本字（现役 match_ref 行为，只是语义表扩了） |
| single | unsure，组内只 1 个候选形 | — | 放行，char=该形（现役行为） |
| single | unsure，组内 ≥2 形 | X 已确认过 | **定形器** → 放行 / 人审 |
| single | unsure，组内 ≥2 形 | X 首次 | 组视图人审一次 |
| multi | same（形 X）且 X == 整理本字 | — | 放行（现役） |
| multi | same（形 X）且 X ≠ 整理本字 | X→整理本字 有人确认对 | 放行，reading=整理本字 |
| multi | same（形 X）且 X ≠ 整理本字 | 无 | 人审（可能整理本归一不一致，也可能库错） |
| multi | unsure | — | 现役行为（整理本字兼作形证据，精确一致才放） |
| 任意 | 涉及 己/已/巳 | — | `always_review`，不变 |
| 任意 | 对在 T3 / NEVER_MATCH / 借用 | — | 不桥，走现役形近路径 |

### 4.4 护栏一条不动

`己已巳` always_review；`NEVER_MATCH_FAMILIES`（手工 20 对，每对有案底）；`SEMANTIC_MERGED_PAIRS`
只有 (已,巳)；`kSpoofingVariant` / `hydzd-borrowed` 永不进；OCR 永不投票；`match_precision ≥ 0.999`；
`glyph_layer_immutability`。新通道 `variant_form` 是**第三路证据（形状）补在文本两路之上**，
不是替代——两路零同源的原则没变。

### 4.5 验收：三把尺子，成对报

| 尺子 | 定义 | 现值 | 目标 / 护栏 |
|---|---|---|---|
| 人审率 ↔ 自动放行错误率 | 60 页 1,936 字位 | 1.1% ↔ 0/9,848（整理本）、0/132（人裁） | 人审再降（7 条里 4 条消失）；错误率仍 0 |
| **字形保真率**（新） | 自动放行里 `char` == 实刻形；组视图抽审 ≥200 例，按 `form_auto` / 非 `form_auto` 分层 | 无（现在无法量） | Wilson 下界 ≥ 99%；`form_auto` 层单独报 |
| 账本一致性 | 桥放行的对里不在关系图的数 / 总数 | 38 里 5（㫖→旨，手工表兜） | 全部有来源（关系图或人确认） |

回放集：全部历史人裁（273 + 132）、38 条自动转换、rare-char 21 条。每步改动跑一遍
`survey_review_queue.py` + `round_check.py` 判据 A/B/D，口径不变。

## 5. 审阅界面（问题 6）

现有卡片已有：图块、库/OCR/上下文三路、候选按钮 1-3、`shape`/`reading` 双值（只对 己已巳
显示 reading 框）、「查候选」（字体模板 + CNN 融合 10 个，带释义与整理本对应字）、dwell 计时。
下面都是增量。

### 5.1 组视图（新页「异体」）——首例确认与保真抽审都在这里

一组一屏：**列 = 形，格 = 图块缩略图**。顶栏：语义字 · 释义（`gloss.json`）· 整理本用形与频次 ·
本书各形计数 · 关系徽记。每格默认在系统判的那一列。操作：`Enter` 整组照准；点格 → 换列；
`N` 非此字；`1–4` 把焦点格移到第 k 列。输出沿用 confirm 事件协议（shape / reading /
conversion），不新造。组按「含首例形」「待审数」排序。

一个 5×10 的网格人眼几秒就能扫出异类，比逐卡快一个量级；这也是 §4.5 字形保真率的抽审台。

### 5.2 单卡增强（只在「义定形未定」时变样）

- 候选**只列组内形**（2–4 个大按钮），每个带：本书原型缩略图（glyph.db exemplar；没有就字体
  渲染）、本书计数「髪 ×17」、整理本字徽记、释义、关系徽记（**異體** / **互通** / 红色
  **形近·非異體**）。
- 默认焦点 = 本书惯用形，`Enter` 接受；`reading` 默认整理本字，非 己已巳 折叠显示、不强制填。
- 去掉拼音/码点（用户 2026-09-05 已定）。
- 形近对（己/已/巳、人/入）卡上明写「形近·看字形」，异体对写「異體·同義·本書慣用 X」——
  两类问题人要用的判断完全不同，界面必须先告诉人是哪一类。

### 5.3 卡片 API 加字段

`/api/review/cards` 每张卡加：`align_char`、`reading`、`state`（`semantic_fixed` 等）、
`group: {canonical, forms: [{ch, book_n, ref_n, exemplar_url, tier}]}`。数据全部来自账本 +
glyph.db，不新增计算。

### 5.4 计时

dwell 已有；组视图按组计时，报「每组秒数」与「每格秒数」。UI 改动唯一的验收指标是它。

### 2026-09-06（二）：判据 A 的自证成分（口径修正）

排查「338 条人审能不能自动吃掉」时，先按 cov 分档量库 top1 的准确率，结果**反常**：
`cov < 0.95` 那 93 条也 100% 对。追下去发现是**评测口径陷阱**：

`v2_align` 金标的 `shape` 有三个来源（`GoldChar.source`）——`db_same`（库判 same 继承的
字）、`context`（Step6 定的）、**`fallback`**。而 `_slots_from_decision._fallback` 直接取
`match.candidates[0][0]` = **库 top1**。人审位的金标里 **163/178 是 fallback**，拿它去验
「库 top1 准不准」是纯自证，那个 100% 是假的。

顺藤查判据 A（同一份金标），分层结果：

| shape 来源 | align_op | n | 对 | 独立性 |
|---|---|---|---|---|
| db_same | equal | 12,509 | 12,509 | 半独立：shape 来自库断言，但**整理本文本印证了它** |
| context | equal | 3,270 | 3,270 | 半独立：shape 来自 Step6，整理本印证 |
| **fallback** | equal | **465** | 465 | **自证：shape 就是库 top1** |
| db_same | replace | 76 | 76 | **独立**：整理本与管线不一致，金标取整理本 |
| context | replace | 14 | 14 | **独立** |

**结论比担心的好**：`equal` 不是自证——它的含义是「管线转写与整理本 8-gram 对上了」，
整理本是独立的文本证据；真正自证的只有 **465 条（2.8%）**；而 **90 条 replace**（管线与
整理本不一致、金标取整理本）是零自证的最硬证据，也 90/90 全对。所以「A = 100%」站得住，
**但报数必须把自证那撮单列**。

`accuracy()` 现在返回三个数：`gold`（全量，历史口径）、**`gold_independent`（剔掉
fallback，主数）**、`gold_replace`（只看 replace 段）。`round_check.py` 三行一起打印，
并注明自证条数。

> 我此前多次把「A 对整理本 16,334/16,334 = 100%」当硬证据汇报，那个说法需要这样修正。

## 7. 风险与口径

- 组内定形器对只差一笔的形（髪/髮、鑒/鑑）分辨力要**实测**，closed-set 容易但不是免费的；
  没数字之前 τ 取高，宁可多进组视图。
- 整理本自己的错（漏改、误改）会进账本；账本按 `human` / `auto` 分列来源，报数分层。
- 一对多形（囘、蓋）：LM 不归一、`reading` 按整理本、`char` 按图。
- 账本是**先验不是规则**（字形套方案 §6 的口径不变）：本书 髪 ×17 不禁止第 18 次刻 髮，
  只是让它进组视图而不是自动放行。
- 报数纪律照 `step5_step6_benchmark.md` §4：成对报、带基线、`align`/`human` 分层、语料挖洞。
