# 刻本正文管线手册：分步现状、并行分工、踩过的坑

写给**接手某一步做优化的人**。看完这份就能独立开工，不必回头翻几千行
设计文档。各步的深水区细节仍在 `char_clustering_design.md`，本文只给
「现在到哪了 / 你的靶子是什么 / 别再踩哪些坑」。

**当前策略（2026-08 起）：只优化正文页。** 目录、职名、序跋、牌记等
非正文版式一律先放着——它们各有各的排版规矩，混在一起调参会互相牵扯，
而正文占的量最大、下游收益最直接。下面所有指标都按「正文/非正文」分开报。

# 测试（本环境 pytest 的输出捕获有毛病，必须加 --capture=no）
python -m pytest tests/ -q -p no:cacheprovider --capture=no

`segment` / `chars` 的第一个参数是**书的输出目录**（`output/vol01`），
不是书名——`profile.json` 在那里。传书名会静默退化：读不到 profile →
`n_cols=None` → 整个列网格拟合被跳过，产物看着正常其实全错。

### 怎么筛正文页

`page-type` 金标（394 页人工标注）里 `page_type == "body"`：
vol01 296 页 / vol02 **186 页（全书）**。

⚠️ **管线自己现在筛不出来。** `classify_page_type` 只分得开
`blank / cover / label`（那是「跳过闸门」要的），body / roster / toc /
edict / colophon **全部归到 `body`**（实测混淆矩阵：roster 31→body、
toc 47→body、edict 1→body、colophon 1→body）。所以：

- **评测**时用金标筛正文页；
- **需要管线自己分正文/非正文**的话，那本身是一个待立项的工作
  （见 §3 的 P0）。

### 版面线侵入：审查涌现的缺陷回流上游（2026-08-24）

进库审查不只是产金标，它还是**上游缺陷的探针**——用户逐页审 1916 个
字位时挑出的 46 条「仅定字·不入库」+ 32 条「非字」，逐条目视细分后
41 条是版面线混入，且高度系统性：

| 证据 | 指向的上游问题 |
|---|---|
| 15/46 挤在**第 7 页第 6 列**一列 | G2 该列切窗横向偏移，整列吃进界行 |
| 30/32 非字落在**列尾** | G3 网格越过末字，撞上版框 |

判据落地为 `crop_quality.detect_intrusion`（rule_bar_left/right、
frame_bar_top/bottom）。要害是**不看连通性**：框线常与字身相连，既有的
`residue`（非主体连通体探进核心区）在这恰好失效——46 条里 35 条只落了
个泛泛的 `boundary_ink`。改看几何「贴外带的细实贯穿条」，且横竖分开定阈
（竖界行深入但线实：band 0.40 / fill 0.88；横版框贴极边但「一三世而」的
横笔会撞车：band 0.15 / fill 0.60）。

标定（46 条目视金标 + 600 条 clean 对照）：竖 10/19、横 12/22、合计
**56% 召回 / 1.0% clean 误报**，且对「缺笔·划痕」那 5 条**零误报**
（该管的管、不该管的不碰）。接进 `char-segmentation/instances` 后
**确定层召回 30% → 55%**（精确 96%，误报 3%）——可直接自动处理的比例
接近翻倍。

### 每轮审阅后的固定流程（2026-08-24 定，照单执行）

用户在审查页裁决完一批后，按序做完下面八步——顺序有讲究，标 ⚠ 的
步骤错序会丢数据：

0. **首次 seed 新页前** ⚠：先删掉载体里这些页的旧行、重跑
   `scripts/build_ocr_carrier.py`（断点续跑，只补缺行）。载体是全书
   一次性建的，重跑过切分后新页的 idx 全体挪位——已经栽过两次
   （14 页 auto 82%→38%；16/17 页 auto 直接掉到 8%/2%，
   db_inconsistent 231，库匹配显示图块内容整体错位 2 格）。症状特征：
   align 全灭 + db_inconsistent 异常高 + 库候选对得上**邻格**的 OCR
   字。发现坏 seed 要全量重置该页（admissions/exemplars/derived/
   instances + 队列行 + progress 页条目）再重跑，别在坏队列上缝补。

1. **读回事件**：从审查页 artifact 取最新存档，提取 `GUJI-SEED-EVENT`
   行，与已入库的事件文件 diff 出**新批次**（按 batch+seq 去重，不要
   整文件重灌）。
2. **入库**：`python -m open_guji_cv -o output seed-ingest vol01
   --db output/glyph.db --events <新批次>`。两通道语义：重切（几何）
   先应用、裁决后应用——确认位存的自动就是重切后的字形。
3. **校验重切位** ⚠：index.jsonl 里 flags 含 `recropped` 的每一位，
   已进库的必须与磁盘图块一致。**比的是 canonical 口径，不是原始字节**
   ——`instances.patch_png` 存的是 256×256 灰度规范图（见
   glyph_canonical_format.md），磁盘图块是原始裁切（如 117×146），
   两者永远不可能字节相等：

   ```python
   from open_guji_cv.clustering.canonical import canonical_png
   assert bytes(db_row["patch_png"]) == canonical_png(cv2.imread(patch, 0))
   ```

   （2026-08-25 更正：这一条原来写的是「字节一致」，是**规范化迁移之前**
   的口径。照旧写法查会 100% 报不一致，差点据此判定 ingest 坏了——实测
   按 canonical 口径 14/14 全对。）
   不一致才说明两通道顺序被破坏，那时立刻停下查 ingest。
4. **重切回流上游** ⚠：`PYTHONPATH=. python scripts/build_recrop_shard.py
   output/vol01 --dataset ../open-guji-dataset`。**必须在提交重切改动
   之前跑**（旧框/旧图块从 `--base`（缺省 HEAD）的 git 历史里捞，
   提交后 HEAD 就是新框了；补跑要 `--base` 指到重切前的提交）。
4a. **用新库重匹配下一批页** ⚠（2026-08-26 用户定，**每轮必做**）：
   队列行里的 `match` 是 seed 当时对**当时那个库**算的快照。这一轮刚
   进库的字形，后面页的待审行根本没见过——「很多刚入库的都没用上」。
   所以每轮入库之后，对**下一批要审的页**重跑：

   ```bash
   python -m open_guji_cv -o output seed vol01 --db output/glyph.db \
     --corpus ... --force-pages 31,32,…,40      # 一次十页够了
   ```

   done 页也照跑，人裁行原样保留、已进库的字位只复述不重判（见
   seeding.py 的 keep_ids / already_admitted）。**一次十页**是用户定的
   节奏——反正每轮入库都要重来一次，跑多了是白烧。
   与第 5 步的区别：`readjudicate_pending` 只拿**存量快照**按新规则复裁，
   救不了「库变大了」；只有重跑 seed 才会重新查库。

4b. **准入标定**：`PYTHONPATH=. python scripts/calibrate_admission.py
   output/vol01`——报待审里有多少按现行规则已能自动进（>0 就跑第 5 步
   回填）、人裁被拦行的 疑问×信号 聚类（放行规则候选从这里挑）。
   三条反馈环的机理与去向见 **review_feedback_loops.md**。
5. **规则回填**（本轮若改了准入规则才需要）：`readjudicate_pending`
   对存量待审行按新规则复裁（只动 pending/skipped，人裁行永不触碰）。
   若变的不只是规则、而是**证据本身**（切分/载体/上下文口径改过，队列
   里的 ocr/align/match/context 整页作废），才用
   `python -m open_guji_cv seed <book> ... --force-pages 9,11,12`
   重跑那几页：done 页也照跑，人裁过的行原样留下、那些字位跳过不再判
   （2026-08-25 加；此前 seed 会整页重写队列，所以这一步曾经是禁区）。
   哪几页该重跑由体检给出：
   `PYTHONPATH=. python scripts/repair_seed_queue.py output/vol01`
   —— 它同时修队列的两类硬伤（幽灵行 = id 已不在 index 里；重号 = 同一
   instance_id 两行），`--apply` 落地。重号会让审查页拿 A 的证据配 B 的
   图，实锤见下面「踩过的坑」。
6. **重导出 + 发布**：`python scripts/export_seed_review.py output/vol01
   --page <下一批> --out <scratchpad>/vol01_seed_p4.html`，发布到
   **同一个 artifact URL**（用户书签不换）。各页 URL 台账、快照与
   再生方法在 **[artifacts/README.md](../../artifacts/README.md)**，
   收尾时把最新 HTML 拷回快照目录一并提交。
6b. **压库** ⚠：`PYTHONPATH=. python scripts/compact_glyph_db.py`
   ——`derived.feat_hog` 是**无读者**的 HOG 缓存（`load_matcher_from_db`
   只取 `norm`，`GlyphMatcher.add()` 自己算特征），却按每实例 ~7KB 写盘。
   vol01 铺到 15008 条时它独占 100MB，把 glyph.db 顶到 179MB，
   **超过 GitHub 单文件 100MB 硬上限、推送被 pre-receive 拒掉**
   （2026-08-26 实锤）。压完 73MB。丢了安全：每次 admit / refresh 都会
   重写，要用时自然重建。VACUUM 单独救不了——这库没有空闲页，大小是真的。
7. **两仓库提交推送 + 主干同步**：output/glyph.db、queue.jsonl、
   index.jsonl、重切过的 patch 随 open-guji-cv 提交；expected.json +
   patches 随 open-guji-dataset 提交。库必须随推——其他分支在用。
   随后同步主干（**两个仓库的主干都是 main**——open-guji-dataset 一度写成
   master，2026-08-25 两个会话各自核对后改正；`git branch -a` 实测远端
   只有 `origin/main`（`origin/HEAD -> origin/main`），**没有** master

## 2. 哪些步骤可以并行

判断标准只有一条：**会不会改到同一个产物**。

```
                 ┌─ C 页型闸门 ─┐
   预处理 A/B ──→├─ D 版面几何 ─┤──→ segment 产物 (phase3_char_grid) ──→ chars 产物 (phase4_chars) ──→ 下游
                 └─ E 行列识别 ─┘
```

| 组 | 步骤 | 能否与别组并行 | 理由 |
|---|---|---|---|
| **G1** | C 页型 / D 几何 / E 行列 | 组**内不能**并行 | 都改 `grid_segment.py`、都重写 `phase3_char_grid/`。三者互为上下游（几何错→列型必错），必须串行做、每次跑全量重测三个数据集 |
| **G2** | F 格内净化 / G 图块自检 | 与 G1 **不能**并行 | 改 `extractor.py`，但输入是 G1 的产物；G1 一动，G2 的金标图块全漂 |
| **G3** | H 归一化 | **能** | 纯函数：图块 → 图块，不碰上游产物。逐像素回归，自带 golden |
| **G4** | I 聚类 | **能**（与 G3、G5 并行）| 输入是图块，输出是簇；只要图块不重切就互不干扰 |
| **G5** | J 识别 / K 上下文 | **能** | 输入是图块 + 候选，产物独立 |
| **G6** | L 校对对齐 | **能** | 独立产物 |

**结论：G1 → G2 必须串行且由同一个人（同一个对话）推进**；G3 / G4 / G5 /
G6 四组可以同时开工，互相不踩脚。

### 并行开工的三条约定

1. **上游产物要冻结。** G3~G6 开工前，把当时的 `output/*/phase4_chars/`
   记一个 git commit 号，评测报告里写上。上游一动，你的金标就漂了
   （这个坑本仓库踩了 8 轮，见 §4）。**转写与切分必须同版**：a435d7b 重跑
   切分后 phase6 没跟着重跑，旧转写对新图块做对齐会系统性错标——结构
   指纹相同也保证不了字没换（第九轮重标：10:2:6 从「列」变成「冬」）。
   char-clustering 数据集因此用 `--pipeline-rev` 从 git 固定取产物版本，
   且对齐载体改用 **OCR 载体**（`build_ocr_carrier.py`，rapidocr top1+s2t
   落在 phase4 目录里随版本走）——载体与切分永远同版，不再依赖 label
   步骤的重跑节奏。
2. **各自的数据集各自建**，别改别人的。跨步骤共用的只有原图。
3. **接口契约不许私自改**：`phase3_char_grid` 的列/格 JSON、
   `phase4_chars/index.jsonl` 的字段（`id/book/page/col/idx/bbox/flags`）、
   `layout_spec.PageLayout`。要改先在两个仓库同时改文档。

y=0 到 y≈2000 质心从 x≈1006 漂到 x≈1055（约 2.4% 斜率），col6 同样
漂了 36px，且不同列漂移量不同——不是简单的整页线性错切，更像书页在
装订处局部拱起那类物理弯曲，各列因为离装订边远近不同弯曲程度也不同。
这和 #12 结案的"曲刀"是两回事：曲刀（`_split_touching_curve`，
`extractor.py`）解决的是**同一格内**笔画相连的两个字怎么下刀，跟
本页这种**整列**的几何形变是两个不同层面的问题，仓库里没有现成机制
处理后者。校正思路：逐列量墨迹质心随 y 的漂移曲线，超过阈值就在切格
之前把列内容按这条曲线做水平方向的逐行去畸变（本质上是给这一列单独
再做一次局部 deshear，只是从"整页一个夹角"换成"逐列一条曲线"）。
**没做**：只有 vol02/119 一个实锤样本，先造判据、后写修法这条规矩
在这里同样适用——没有第二个样本验证"多强的漂移才算真弯"，贸然定
阈值大概率会像 89 版"曲刀"那次一样，局部看着对、全书一验就是净负。
需要先在全书扫一遍质心漂移量，找到几个同类页面再动手。

## 4. 踩过的坑（这一节最值钱）

### 量与判据

**危害要直接量，不要用代理量。** 图块按「文字带」裁时 `rule_bar` 只有
0.2%，看着完美——同时它正在**静默切掉 44.8% 的字的笔画**。所有 flag 都
不报，因为切下来的图块自己看不出缺了一块。凡是做「切分/裁剪」这类工作，
先造一个直接量（本字的墨有没有少），再谈 flag。

同理：「列数不对」看着像丢了整列，实测**外侧漏墨**反而更低——列数不对的
页漏墨 1.97%，列数对的页 2.79%。代理量把结论带反了。

**「墨在网格内」和「墨被取出来」是两把尺子。** 2026-08-26 实测：
`clip_refit` 把网格挪到裁窗顶之上，`bounds[0]` 变负 → `crop[负:正]` 切出
空数组 → 整格判 `empty`，**格里的真字整个消失**（vol01/60 c6/c7/c9、
vol01/50 c5 各一枚）。而截断闸（0%，一刀没切）、红线普查（墨确实在网格
覆盖区间里）、seam（少一格 → 少一条缝，分数还变好）、字格总数（-4，
淹在波动里）**四把尺子一齐没报**。凡是做网格/窗口类改动，必须单独有一把
「单字墨段有没有被 char 格接住」的尺子（`scripts/eval_char_drop.py`）。

**比例判据的硬门槛会让「差一点点」和「差很多」一样被否。** Pass 2a4 的
「漏墨率至少减半」通道上，vol02/152 实测 0.02372 → 0.01246，只差 0.0006
没跨过 0.5 倍，于是放开窗口的版本被否、c2 抬头的「周」「易」两个字整个
丢在网格之上。**能直接数的东西不要拿比例去猜**——改成数丢字数
（`dropped_char_runs`）当第三条通道后，17 张候选里只有它一张的丢字数
真的变了（1→0），没有一张是被"顺便"放进来的。

**校验条件写错的表现和「这个修法没用」一模一样。** `refit_window` 的
等宽自检把裁窗 x 范围写成 `left_x~right_x`（真值是
`int(left_x)+2 ~ int(right_x)-2`），差 4px，于是每一列都判「裁不出等宽窗」
走了退回分支，vol01/60 从 0% 弹回 **92%** 截断。和「可行域上下限写反」
（见 char_clustering_design §十一）是同一类：**下「此路不通」的结论之前，
先手算一遍边界值、确认自检条件本身是对的。**

**分布重叠了就别再调阈值。** 界行内缘伸进列格中位 4.9px / 95 分位
19.6px，「臣」外缘离列格边界中位 10.0px / 10 分位 0px——两个分布重叠，
任何固定余量都只是在两种错误之间搬运（余量 9px：21% 裹线 / 44% 切字；
15px：8.7% / 68%）。出路是换一个**两个分布不重叠**的量（这里是竖线
覆盖率），不是把同一个量的阈值挪来挪去。

**观测尺度必须和缺陷的发生尺度对齐。** 用整页的竖线覆盖率当围栏防界行，
失败了：界行只要斜几个像素，墨就摊到二三十个 x 上，整页统计一片 0。而
`rule_bar` 是在**单个字格**上判的——一条斜界行在一格高度里仍是笔直一条。
改成分带（1/6 页高）统计，围栏才生效，`rule_bar` 2.2% → 0.2%。

**中位成立不等于尾部成立。** 「臣从不碰到界行」对中位是对的，对尾部是错的
——而裁切规则是被尾部决定的。定阈值时看 5/95 分位，别看中位。

**没有样本的能力不要先写判据。** 截断检测在四轮金标里一个样本都没有，
一直无从验证。正确顺序是：确认缺口 → 设计一个与判据**不同**的抽样线索 →
补样 → 看样本的结构 → 才定判据。反过来做，多半会写成已有判据的翻版
（当时凭直觉会写「左右边缘墨量」，而那个量在真实截断实例上并不显著）。

**抽样线索要卡对。** 第一版找截断候选用「连通体越出格外的比例 ≥0.35」，
捞上来全是**空格位蹭到邻字**——那是污染不是截断。加上「主体（≥65%）在
本格内」才对。

### 识别 / 语言模型（J、K 这一轮学到的）

**先量字表天花板，再谈排序。** PP-OCR 的字表 6,625 项，本书 **11.03% 的
字次根本不在里面**——缺的还不是生僻字，是 說 則 謂 論 諸 這类各出现上千
次的繁体常用字。不知道这个数就会一头扎进排序优化，而那 11% 是排序碰不
到的。任何识别类工作的报告里，`top1` 都要和「字表可达上界」并排放。

**金标只取「算法本来就对」的位置 = 自证。** 用整理本对齐落标时，只采信
`equal` 段会让金标恒等于当次转写，测出来必然 100%。等长 `replace` 段才是
错误样本，必须一起收——但要用锚夹判据（段长 ≤3 且左右各有 ≥2 字 equal
段）挡住「内部一次漏切 + 一次多切、长度凑巧相抵」的假等长。

**「建集时算法错了」不是难度标签。** `align_opcode: replace` 记的是建集
那台引擎当时对不对。拿它评那台引擎自己，恒为 0，是定义使然不是发现；
拿它评**别的**引擎才有信息（tesseract 在 rapidocr 漏掉的 150 条上救回
18%）。凡是分层用的标签来自某个算法的输出，都要先问一句「我现在评的
是不是它自己」。

**投票类锚定要先按簇合并再比。** 页内一处漏字/多字会把 n-gram 票劈成
相邻的两堆（实测 14 票 vs 13 票），孤立比较时两堆互相"抵消"，整页被判
定不了位。book9 十页里三页因此被误杀，按 ±3 合并后全部回收，页面对齐率
6/10 → 9/10。凡是「投票选一个连续偏移」的场景都有这个坑。

**本书语料必须挖掉测试页，否则是背答案。** 本书 LM 的语料就是本书整理
本，而金标也是从同一份整理本对齐来的。评测脚本必须先剔除测试页窗口并
**打印挖掉了多少字**；打印为 0 就说明挖漏了，后面的数字一概作废。通用
语料同样要打印与测试页金标的 8-gram 重合率。

**多个 LM 混合要用线性插值，不能用对数线性。** 对数线性（几何）混合里，
任何一个分量给出接近零的概率都会把结果拖到零——通用语料没收录的本书
专名恰好就是这一类，等于把混合的收益全否掉。线性混合 `log Σ wᵢpᵢ` 只要
有一个分量给了质量就有质量，这才是「兜底 + 加尖」。

**通用语料的体裁比体量重要。** 同为 500 万字：诏令奏议/政书类语料单用
就 +1.21%、混合后 +2.14%；儒藏/易藏（经解）单用 **+0.00%**、混合还略微
拖后腿。被测页是卷首上谕（公文），体裁对不上，语料再大也是白搭。先问
体裁，再问体量。

**λ（OCR 项 vs LM 项的配比）是有害翻转的主开关。** 旧默认 0.55 的有害
翻转 2.39%，提到 0.70 降到 1.04%，同时净增益还更高；继续降到 0.35 直接
转成 **−1.07%**——语言模型压过字形证据就开始编字。调纠正强度先动 λ，
别先动权重。

**样本量撑不起细粒度调参就直说。** 1,404 个槽位上，权重 0.5/0.75/0.90/
1.00 之间只差 2~6 个样本，在噪声内。能写进结论的只有跨多组一致复现的
效应（混合 > 纯通用；λ 0.55→0.70 有害翻转减半），最优权重的具体取值
**本集分辨不出来**，报告里必须这么写，不能挑一个最高的数字当结论。

### 因果

**相关不等于因果。** 「射影分量」与失败率相关 +0.59，看着像射影形变导致
切分失败；实际是**共因**——稀疏的目录页既容易量出大射影分量，也容易内缩
塌陷。真正的原因是内缩塌陷，改完就好了，射影一点没动。

**上游产物没同步会让相关性结论反号。** 同一个相关系数，用过期的 vol02
网格算出来是 −0.09，重跑后是 +0.59。做跨步骤分析前先确认产物是当前代码
跑出来的。

**指标指向的地方不一定是出问题的地方。** 指标说「列型分类器召回不够」，
分类器却完全正确——真正的 bug 是下游 `cells_from_components` 用自己的
一套阈值否决了分类器，**否决之后还把列型标签改写回 rigid**。凡是下游
能改写上游标签的地方，都要怀疑一次。

**一条判断只该有一个地方做。** 下游模块可以说「我做不到」，但不能拿自己
的阈值去推翻上游的判断。闸门要么管「列型是什么」，要么管「我能不能切」，
不能两个都管。

### 刚性先验

**刻本整版先划栏格再上字，所以格高、列距、内缩都是书级刚性常量。**
逐页自由拟合会锁到谐波上或直接塌掉：列距实测 5~95 分位只有 174~186px，
可有的页拟到 150；内缩中位 32px，可有 69 页塌到 <15px，那些页界行落入
列框的比例是正常页的 14 倍。做法是**书级共识 + never-make-worse 择优**：
先按页拟，再取全书中位，只在本页明显跑偏时替换，且替换后要证明指标真的
变好才采纳。

**never-make-worse 是硬约束。** 错切校正、界行吸附都是「算出候选 → 用
同一个目标函数比一比 → 只有真的更好才采纳」。实测界行吸附 204 页里采纳
193 页，总体 rule_in_col 0.136 → 0.050；没有这道择优，本来就对的页会被
改坏。

**改了共识，就要把共识透传到后续所有 pass。** 一次真实回归：Pass 2a 修好
了格高，Pass 2a2/2a3 重跑 `segment_page` 时没传 `cell_h_prior`，把修好的
格高又冲掉了——格高崩坏的页从 3 张涨到 **17 张**。多 pass 结构里，前一
pass 的成果必须显式传给后一 pass，别指望它自己保留。

### 金标与评测

**金标分两种，务必分清。**
- **不漂移的**：`page-geometry`、`page-type` 挂在**图像**上，算法怎么改
  都还成立。
- **会漂移的**：`char-segmentation/instances` 挂在 `page:col:idx` 上，
  **每次重切都可能失效**。本仓库已经重标 8 轮。

重跑之后的规矩：**先查漂移，再谈数字**。曾经出现「官方 benchmark 说截断
检出 0%、离线分析说 100%」的自相矛盾报告，查下去是标签过期了。查法：
逐个比对图块像素，报告「内容变化 N 个 / ID 消失 N 个」，然后**逐个重看**
变化的那些。

**会漂的金标不能用来判一把新尺子的死活。** 2026-08-25 造「切缝墨率」
时，拿 `instances` 的人工标签验判别力，六种归一化写法 AUC 全部 ≤0.53
（最好的 0.530，最差的 0.320——**反相关**），差点据此判尺子无效。真相是
标签是 r4~r9 之间标的，中间整册重切过好几轮，`page:col:idx` 早已指向
别的图块；反相关恰恰是「正例多半已被后几轮修好、负例反倒漂坏了」的形状。
验新尺子只能用**不漂的量**（图像上的几何/像素）+ 人眼，不能用会漂的标签。

**判不准就标 `uncertain`，评测跳过。** 灌进金标的噪声会**同时**高估和
低估算法：column-layout 曾错标 3 页，修正后 body 从 90.4% 升到 96.3%、
toc 从 62.2% 降到 58.7%——两个方向都被带偏了。

**金标不得用被测算法的输出生成**，那是循环论证。渲染判读图时画的必须是
**纯刚性格线**（书级 cell_h + 页相位），不是算法切出来的 cell。

**「量法陷阱」的判词也会过期。** r9 时把「紧框贴窗边且窗外有墨」3.44%
标成不能信，理由之一是「多数是字本来就贴着界行写」。r10 用户实审确认：
贴着界行写的字被裁掉捺脚**就是真截断**（vol02/168 一页 5 列）。当时的
判词只对了一半——那个代理指标确实分不开「贴着写」与「被裁掉」，但
不等于后者不存在。分不开的时候该做的是**换一把能分开的尺子**（连通体
穿边判据，见 right-cut 分片），不是把整族现象记成假的。

**被测对象改了分母时，先怀疑闸门。** 切缝闸的单页规则是「重切缝比金标
多 ≥3 条就点名」。文字带窗口救援让 vol02/108 多切了 17 个字格、多出 15 条
缝，重切缝 11 → 15——闸门直接判失败，可那是**罚它多切出了字**。改成按
占比比较才对。闸门是拿旧世界的分母定的，别急着怀疑改动。

**比值类指标要连着分母一起读。** 精确率从 0.71 掉到 0.52 不是退步——是
切分变好了、缺陷基数变小了，同样多的误报占比自然升高。报告里必须同时给
分子分母。

**分层报告，别合成一个数字。** 确定层（`rule_bar`/`edge_blob`/
`frame_bars`，零误报，可自动处理）和疑似层（`wide_gap`/`boundary_ink`/
`off_center`，有误报，只用来排人工队列）用途完全不同。合成一个数字会同时
掩盖「确定层能不能免检地用」和「审查队列会被多少噪声灌满」。

**非对称代价要写进指标。** 页型闸门的主指标是 `lost_rate`（该切却跳过 =
静默丢数据），零容忍；反向（该跳过却切了）只是产出可标记的垃圾，可以接受。
阈值从**极端样本**定，留 2 倍余量，不从中位定。

### 工程

**`pgrep -f` 会匹配到「只是提到这串字」的进程。** 长跑脚本里写
`until ! pgrep -f "open_guji_cv segment"; do sleep; done` 来串行等待，结果
被另一个**命令行里含这串字**的等待型 wrapper 匹配上，两边互等、死锁 19
分钟（脚本日志 0 字节，看上去像卡住）。`-f` 匹配的是整条命令行，等待型
外壳自己就带着目标字串。要么用 PID/锁文件等，要么把模式写成进程真正
独有的形状（如 `^python -m open_guji_cv segment`，配 `pgrep -f -x` 或
`pgrep -a` 先看清匹配到了谁）。同一批还踩到：多行 Bash 命令的换行在某些
路径下会被吞成一行，`cmd_a\ncmd_b` 变成 `cmd_a cmd_b`——重定向和参数
全串位，日志文件因此根本没生成。**长命令一律写进 .sh 文件再 bash 它。**

**约束条件写反的表现，和「这条路走不通」一模一样。** clip_refit 的可行域
上下限写反过一次（`lo` 该是 `b-span-slack` 却写成 `t-slack`），窗口整个落在
可行域外：vol01/60 从 135 恶化到 144、随机 30 页 2.8% → 8.1%，看上去就像
「这个方向没救」。写对之后同一份代码把 vol01/60 打到 **0**。
**下「此路不通」的结论之前，先手算一遍边界值。**

**判据的尺子必须和闸的尺子逐字一致，否则闸会跟着一起瞎。** clip_refit
一版用 `column_projection` 取字身墨段——它会剥掉长竖线，于是**看不见**
vol02/141 c8 开头那两个字，可行域算错、网格整体挪了 7.5 格，那两个字被
丢在网格之外，而以同一口径写的红线闸 `_uncovered` **也看不见它们**，
一路放行。代价项该去竖线、判字身不该去——**同一个函数里两把尺子各司其职
可以，但判红线的那把必须和闸一模一样**。

**所有闸都绿而用户一眼看见毛病 → 先怀疑「没有一把尺子在量那件事」。**
2026-08-26 用户第二次实审只说了六个字「太多截断」，而当时 12 道闸全绿、
抽样正确率 99.25%。查下来：`eval_seam` 量的是格线处的平滑墨量比值，
抽样正确率量的是「这一格像不像一个完整的字」——**没有一把在量「字被切掉
了多少」**。补了 `eval_truncation`（字身截断深度，按段高归一）之后，
vol01/60 立刻现形：seam 报 16.4%，字身实测 **91.8%**。
指标口径错（只报全书平均）损失的是判断，**被测的东西缺席**损失的是整个方向。

**判「是什么病」判错，损失一整轮方向——这条一天里踩了两次。** 第二次是
vol01/50 c1：看到「整列差 86px」就判成抬头页的相位病，照着做了逐列相位。
结果 c2（差 44px）确实是相位病、一刀修好，而用户点名最狠的 c1 **一格没动**
——它的病是**这一列的字距和书级格高对不上**（自相关实测 116.1 vs 115.2），
相位那一个自由度治不了。**同一页上不同列可以是不同的病**，别拿一列的
症状去定全页的根因。定位手段：`GUJI_COLPHASE_DEBUG=1` 逐列打印决策，
再用列投影自相关量实测字距。

**判「是什么病」也要放大，不只是判「有没有病」。** r4 把
`vol01:87:2:13` 判成「夹注未拆」——缩略图上我把「行」的下半读成了偏旁
「勹」。它其实是相位错。这个归类错误直接把「夹注按行判」定成了下一刀的
方向，而夹注判定本来就已经是按行段的（`flag_jiazhu_runs`），方向从一开始
就是错的。**判错有没有病，损失一个样本；判错是什么病，损失一整轮方向。**

**切分指标会奖励「少切一个字」，所以看指标之前先跟原图核对首末字。**
逐列相位第一版没有红线护栏时，vol01/60 九列首线整体下移 82px，seam 重切缝
**16.4% → 0.0%**，我逐格看了切出来的图、判定「每格一个整字、全列可读」，
据此宣布该页已修好——**是错的**：字格 171 → 162，每列的首字（col9 的
「種」）被整个丢在网格之上。格少了，坏缝自然少，指标就变好了。
只看产物看不见丢的那个字，**必须回到原图的墨去对首末字**。
护栏 `COLPHASE_LOSS` 因此加在采纳之前，判据是**相对**的（新相位盖住的
文字不许比原相位少超过 0.20 格）；绝对窗口的版本会误伤「本来就没盖住首字、
往上挪反而多盖」的列。

**分片的「丢字」判据分不出「真丢」和「漂了一格」。** jiazhu-tail 闸报
`vol02/145:5:8` tail_a → reject（丢字），查下来是重切把「曰+勿」并回一个
「易」、其后 idx 整体 -1，「撫」从 8a 挪到 7a，字一个没少。**键挂在
`page:col:idx` 上，重切必漂；看到丢字先查漂移**，别急着回退——这次差点
把一个真正修好的切分当红线事故撤掉。各分片 README 的「已知局限」里都写了
这条，重跑后先对键再谈数字。

**新常量先 grep 一遍名字再写。** 加「骑线复切」时新定义了
`STRADDLE_OK` / `STRADDLE_GAIN`，而同一个模块下面 50 行处 Pass 2b 早
已占着这两个名字（页级骑线门槛 / 绝对改善量）。Python 后赋值静默胜出，
新代码里的采纳门槛于是变成了 `0.10`，612 次触发只采纳 4 次——不报错、
不告警，只是**功能几乎不生效**。现在叫 `RECUT_*`。凡是在长模块里加
模块级常量，先 `grep -n '^NAME'`。

**页级闸读的质量分，会被列级修「治好」而不再触发。** Pass 2b 的行相位
重扫用骑线比当触发闸；列级骑线复切干的正是压低骑线比。两者一叠，
几条列被局部救好就能把整页的相位病瞒过去——实测 vol02/102 复切采纳
3 列后重扫不再触发，该页另外 4 列骑线比从 0.20/0.51 涨到 0.40/0.96。
这是「结构性对冲」的一个新形态：不是坐标基准被挪了，是**判据本身被
下游的修复污染了**。治法是把复切**前**的值存进列结果（`straddle_pre`），
页级闸一律读它——页级相位该看的本来就是「刚性网格对不对得上」。
加完对冲后同一次 A/B：83 列复切、**变差列 0**。

**重跑要清理旧产物。** `run_book` 曾经只截断 `index.jsonl` 却留下 2456
个孤儿 PNG，人工标注对着的是过期图片。写产物前先清目录。

**同一个东西的「位置」只能有一个真源。** 审查卡片上有三样东西各自算位置：
图块（按 index.jsonl 取）、卡头的「第几字」、上下文条的高亮位。前者按
**index 的 char 格位**数，后两者一度按 **OCR 载体**数——载体缺一格，整列
文本就短一位，用户对着原图数「文字错了一位」。修法不是给渲染层加偏移，
是让列文也按 index 的 char 格位建（载体缺格补 □），于是
`pos == 列内 char 位次 - 1` 恒成立。回归钉在
`test_context_pos_follows_index_not_carrier`。

**自动保存的「视图恢复」要跟着人走，不能钉在保存那一刻。** 审查页
裁决后 6 秒防抖发布、网络再几秒，成功后 shell 才重载视图——这段飞行
时间里人早已往下审了好几张。旧版只在 `publishNow()` 里 stash 一次位置，
重载就把人拽回**发布那一刻**的卡片（用户 2026-08-25 实锤「focus 经常
自己跳到之前的某个地方」）。治法是滚动安定后就刷新 stash，恢复时用
存下的像素 y、不再 `scrollIntoView` 重算。凡是「异步保存 + 宿主重载」
的页面都有这个形态：**保存点 ≠ 重载点**，中间的用户动作必须继续被记录。

**人工成果不能只活在产物里。** 审查页的重切改的是 `index.jsonl` 的 bbox
和磁盘 patch —— 而 `segment`/`chars` 一重跑就把这两样整份重写，24 条重切
就这么无声无息地归零（逐提交实锤见 segmentation_border_feedback.md
2026-08-25 一节）。凡是**人给的**东西（重切框、裁决、排除名单）都必须有
产物之外的真源：重切的真源是数据集分片
`char-segmentation/instances`（`seed=review_recrop`），
`scripts/replay_recrops.py` 负责重跑之后贴回来，已挂进 run_pipeline.sh。

**「产物是不是最新的」要用重跑对比来答，不能靠 git log。** 代码没动不等于
产物是那份代码出的（中间可能被别的分支的产物换过装）。做法：用当天的代码
往 scratch 目录整册重跑一遍，与盘上的逐页比 JSON。注意两个坑：书级共识
（格高/列距/内缩）是**跨全书**算的，只跑几页结论全错；`segment vol01` 与
`segment output/vol01` 走**不同代码路径**（`profile.json` 按 `args.path`
找，前者找不到 → `n_cols=None` → 退回 Phase 2 列检测），必须照
run_pipeline.sh 的写法传 `output/<book>`。

**队列的「一个 id 一行」是硬契约，破了不报错只出怪现象。**
`migrate_labels_after_resegment.py` 早期版本对「目标字位在新切分里不存在」
的行只改状态、不改 id——那个旧 id 已经被另一条迁移行占了，于是 queue.jsonl
里同一个 instance_id 出两行（vol01 实测 125 处）。审查页按 id 取证据、按
index 取图，正好取到不同那条：卡片是「第」，上下文高亮「一」。
**迁移只搬号，不重算证据**，所以迁完必须对那些页 `seed --force-pages`
刷新，`scripts/repair_seed_queue.py` 负责体检出是哪几页。

**合成测试要用真实量级。** 600×400 的合成页量错切会得到 0.018（真值
0.010）——倾斜在一个形态学核高度内的漂移不足一个线宽，竖线其实没被打断。
真页是 2500×1700、周期 180、界行 2~3px，测试就得照这个量级造。

**下采样会抹掉细线。** `estimate_shear` 里直接 `INTER_AREA` 缩图，界行
全没了、所有候选得分归零。正确做法是**先二值化再最大池化**
（`dilate` + 步长切片）。

**一个步骤挪了坐标基准，所有在同一条边上取证的步骤都要跟着改。**
右缘救援把条带右界外扩之后，两个独立的下游步骤先后踩雷：曲线掩膜的
右界白涂抹掉刚救回的笔尖；`mask_frame_bars_outside` 把「文字带右侧
空档」当横条证据，而外扩带里装的正是救回的笔尖——vol01/34「類」整条
底横被当版框横条抹掉、字身裂成两半（r11，frame-strip 字保全闸抓住）。
左缘救援落地时按这条清单主动排，仍新翻出两处：`_assign_column` 的
边缘噪点门槛（79px 吃掉断墨笔尖）和 `carve_end_edge`（只保护最大
连通体，寻径绕过断墨碎片抹掉）。四处对冲的完整清单见 left-cut 分片
README。这是结构性对冲：凡在条带边缘**取证或涂抹**的步骤，接入/
改动时都要问一句「这条边被谁挪过」。

`tests/recognize-profile/test_recognize_profile.py` 是脚本不是测试，

## 5. 怎么量（可复制的量法）

### 「现在整体多准」——只有无偏随机层能答（每隔几轮必须复量）

定向审查（用户朱批、各专项闸）只看得见**已知病灶**，报不出全书正确率；
各专项闸的通过率也不行（分片都是定向富集）。唯一能读作全书正确率的是
**正文页均匀随机抽样**：`scripts/sample_self_assess.py` 抽（rand 无偏 /
tail 列端富集 / flag 带旗富集三层），`scripts/render_self_assess.py` 出
〔语境图（红框=紧裁框）｜成品图块〕判读表，模型先自评、拿不准的才交人工。

- 报 rand 层的点估计**必须带 Wilson 95% 区间**，否则 n=200 的 ±2pp
  会被当成真差异；
- tail/flag 是富集层，**不能**混进正确率，只用来找病灶形态；
- 缩略图不足以定谳：r2 判读时把上字的下部错看成宀、误判了一个正确件，
  **存疑件一律放大再定**；
- 复量时机：每隔几轮修复、或任何「不知道现在多准」的时候。基线
  2026-08-24 = 93.0%（n=143），2026-08-26 r2 = 98.5%（n=200），
  r3 = 98.5%（n=400，[96.8%, 99.3%]），r4 = **99.25%**（n=400，
  [97.8%, 99.7%]，骑线复切两刀之后）。
- **字身截断率（`eval_truncation`，2026-08-26 新立）**：格线切进字身多深，
  按段高归一，主口径 ≥10% 字高。**这是唯一在量「字被切掉了多少」的闸**，
  其余的都在量「这一格像不像一个字」。首次基线 695/32862（2.11%），
  clip_refit 落地后 **389（1.18%）**；页级 p99 45.5% → 30.4%，
  ≥25% 的页 13 → 8、≥50% 的 2 → **0**。
- **seam 与 truncation 会在浓墨粘连页上给相反结论。** vol02/108、135 上
  seam 报变差而截断报变好，逐格看图是截断对：seam 量的是格线处的**平滑
  墨量**，字与字本来就粘在一起时它分不出「切在缝里」和「切在笔画上」。
  两条一起看，打架时**回到原图逐格核对**，别信任何单独一条。
- **只报全书平均是错的，必须同时报页级分布。** 缺陷按页高度扎堆：全书
  平均 1.1%（r3+r4 合并 9/800），而用户点名的 vol01/50 约 13.5%、
  vol01/60 约 12%。抽样在这两页各抽 2 格、恰好都落在干净列，于是平均数
  把「有一批页不能用」整个掩盖掉了。页级尺子走 `eval_seam.py` 的
  `page_rate`（逐页重切缝率 + ≥5%/≥10%/≥20% 的页数），**回归门也看它**。
- **点估计的移动往往证不了什么，要看构成。** r3→r4 的 98.5%→99.25%
  Fisher 双尾 p = 0.51，**不显著**——n=400 分辨不出 0.75pp。真正的证据是
  r3 里占 5/6 的「切缝相位错」在 r4 里**一个都没有**（5/400→0/400，
  p = 0.06），那正是那两刀瞄的靶子。报改进时把这两句都写上，别只报数字。
- **样本量到了会「问不出新东西」**：r2 在 n=200 上只剩 3 个错，其中 2 个
  当轮就修掉了——1 个残错学不到任何形态。这时该做的不是继续盯着老错，
  是把 rand 层扩大。r3 扩到 400 才把主病灶看清（下条）。
- **抽样可以不整册重建**：`scripts/sample_live.py` 对抽中的页**现场**
  跑 `extract_page`，判读的就是当前代码的产出（每页 ~1.4s）。产物里的
  图块是上一版代码切的，拿它判读量出来的是**旧版**正确率。
  抽样设计是自加权两阶段（正文页按字格数 PPS 抽页 × 每页 2 格），
  少抽几格多抽几页，压住「缺陷按页扎堆」带来的方差膨胀——r3 里
  vol02/108 一页就贡献了 2 个缺陷，正是这种扎堆。

**r3 判到的病灶谱（400 格 6 个缺陷）**：切缝相位错 5 个
（上邻残留 1 / 跨格 1 / 两字一格 2 / 截断 1）、界行残余 1。
相位类是**唯一还成规模的病灶**，且 4/5 已被 `boundary_ink` 旗中——
旗准而没修，所以那一轮做的是「骑线复切」（见 char_clustering_design.md）。

**r4 判到的病灶谱（400 格 3 个缺陷）**：夹注未拆 1（`vol01:87:2:13`
勹+乎 两字挤一格）、夹注误拆 1（`vol02:72:1:7a` 整字「總」被 a/b 分割线
竖切一半）、污损带 1（`vol02:188:6:4`）。相位类清零；**头号病灶换成了
夹注拆分**，而且是一正一反——该拆的没拆、不该拆的拆了还切坏整字。
下一刀该打这里（判据大概率要落在「这一行到底是一个整字还是两个小字」上，
而不是整列一刀切定夹注与否）。

### 「本字的墨被切掉了多少」——切分/裁剪类工作的主指标

```python
# 对每个图块：在 bbox 外扩 40px 的窗口里做连通体，
# 取与 bbox 交集最大的那个当「本格主体」；
# 要求它 ≥60% 的像素在 bbox 内（否则那是邻字，不算）；
# 主体有 ≥20px 落在 bbox 外 → 这一块被切了。
```

按方向（左/右/上/下）分开报——横向和纵向是两个完全不同的成因。

### 「网格盖没盖住字」——窗口/网格采纳类择优

```
未覆盖墨率 = 列带里落在 char 格之外的墨 / 列带总墨
```

窗口救援（Pass 2a4）的采纳硬通货。⚠ **字格数是反向信号**：网格错位时
一字跨两格能数出**更多**「字格」（vol02/152 实测错位版 158、对齐版
156——对的反而少），别拿它当硬门槛。

### 「字有没有被整个丢掉」——网格/窗口类工作的红线闸

```
逐列取单字墨段（口径 = eval_truncation.col_runs：高 0.45~1.35 格）
段内被 type=="char" 的格覆盖 < 50% 行 → 记一个「丢字」
```

闸在 `scripts/eval_char_drop.py` + `char-segmentation/char-drop`
（全书正文页 29791 段）。**零容忍那一类：只许降不许升。**
与「未覆盖墨率」的区别是它量的是**格的类型**而不是格的区间——墨落在
网格里、但承载它的那一格被判成空，只有这把尺子看得见（见上「两把尺子」）。
同一套判据也做进了 `grid_segment.dropped_char_runs`，供 Pass 2a4 择优。

### 「列尾空格」——切分错误的强信号（用户版式知识）

空格一般在**行首**（低格起排、抬头避讳）；列尾一串空格几乎必是网格
错锚（伸出文字区的假空格）。vol02/152 就是这么被用户抓出来的。

### 「窗口够不够装下一整列」——版面窗口/静默丢字类工作

```
窗口比 = (inner_frame.bottom − inner_frame.top) / (每列字数 × 书级格高)
```

<0.90 记一张「窗口偏短」页。不看像素、只比模型，因此不受污渍/墨色影响。
闸在 `scripts/eval_text_band.py` + `char-segmentation/text-band`。配套的
反向护栏是「正文字格总数不许掉超过 2%」——防止为了让偏短数好看而少切字。

### 「格线是不是切在字上」——网格落点/接壤类工作

```
切缝墨率 = 平滑列投影(格线 y) / max(min(上格峰, 下格峰), 0.35 × 本列峰中位)
```

≥0.7 记一条「重切缝」。全自动、不需要标注，闸在
`scripts/eval_seam.py` + `char-segmentation/seam`（正文 294 页）。
⚠ 它量的正是 `snap_bounds_to_gaps` 优化的目标，**只能守住、不能自证**。

### 「刚性格合不合身」——列型/格高类工作

在**纯刚性格线**（书级 cell_h + 页相位，不是算法切的 cell）上量：
格线处的墨量 / 列内平均墨量。注意这个量在现有 289 列金标上**区分度很差**
（rigid p95 0.77 vs elastic p25 0.17，大面积重叠），别指望它单独能用。

### 报告格式

每个数据集目录下放 `report.json` + `metadata.json`：
- `baseline` 是**当前**数字，`baseline_history` 记历史（带 note 说明为什么
  不可直接相比）；
- `known_limitation` 必须写，**没验证过的能力不许当作已验证**；
- 数字变了要说清是「算法变好」还是「分母变了」。

## 6. 全流程运行与耗时

```bash
bash scripts/run_pipeline.sh          # 两册并行，逐阶段计时，≈11 分钟墙钟
```

单册各阶段实测（vol01，两册并行跑、每册 GUJI_WORKERS=2）：

| 阶段 | 并行化前 | 并行化后 | 说明 |
|---|---|---|---|
| segment | 482s | 318s | Pass 1/2a/2a2/2a3/2b 页级进程池 |
| chars | 62s | 148s | 吃下了归一化 + npz 压缩（净赚在 cluster）|
| cluster | 318s | 161s | verify 并行预计算 + 归一化缓存全命中 |
| label | 7s | 8s | — |
| **合计** | **869s** | **635s** | 两册并行总墙钟 663s |

- 并行度由 `GUJI_WORKERS` 控制（run_pipeline.sh 多册并行时自动按册分核，
  单册单跑时不设即用满核，segment 还能再快约一倍）。
- 并行只改执行顺序不改计算，**产物与串行逐字节等价**（验证法：重跑后
  `git status output/` 应只有未跟踪的新文件，无任何 modified）。
- 进程池必须用 **spawn 不能用 fork**：父进程跑过 cv2 之后自带线程池，
  fork 子进程一碰 cv2 就死锁在 futex 上（pytest 里 100% 复现，
  全部挂起、负载归零、无任何报错——症状就是"跑着跑着不动了"）。
- chars 阶段顺手把归一化图块写进 `phase4_chars/normalized.npz`
  （压缩后 ~4MB/册），cluster 查缓存、缺了 imread 兜底。

热点构成与优化记录见 char_clustering_design.md「全流程耗时画像」。
量耗时**别用产物 mtime 推**——多轮重跑会把时间戳搅在一起（实测把 5 分钟
的聚类推成了 34 分钟）。

**Pass 1 采样化评估后搁置**：采样会改变字距共识的取样总体，
`consensus_h` 中位数微移 → 全书网格相位/尺度都变 → 产物不再逐字节
等价，按金标漂移协议 91 个实例样本全得重核对。页级并行后它只值
~60s/册墙钟，不抵人工重核成本。

## 9. 已确认的上游坑 #2：s4_enhance_lines 会在列中间画出假界行（待专项）

**现象**（用户实审发现）：vol01/18 第 4 列正中一条 1906px 的粗黑竖线贯穿
所有字。**原图对证：该列干干净净**（原图 06061300.zip::otiff/00000018.tif
对应区域无任何 >800px 竖向游程，全图最长才 1201px）。这条线是
s4_enhance_lines（画线增强，本意把磨损界行描粗帮版面检测）把一条界行
**误检到列中间**后画上去的，s6 二值化后固化。

**危害**：线穿过字身、与笔画连成一体，rule_bar 的「独立细高连通体」判据
抓不到（该列 21 块只有 1 块 rule_bar，全靠 boundary_ink 弱标记兜着），
下游聚类/识别整列被污染。该页 rule_in_col=0.13 也由此而来。

**指纹**：人造线是完美直线——等宽、≥1500px 连续无断；真实印刷界行磨损
弯曲，二值化后极少有这种游程。排查法：扫全书「完美长线 ∩ 文字带内部」。

**已定版（2026-08-24，vol02 全册 A/B/C 试跑）**：采用**证据闸**
（`enhance_lines._line_is_isolated`）：线带 ±2px 沿程覆盖率 ≥0.35 且两侧
5~14px 侧翼墨 ≤0.18 才准整条复原——假线（字笔画共线）过得了覆盖率但
过不了侧翼（两侧全是字身）。实测三方案：全删 s4 → 检出界行数守住但
截断 +44%（磨损界行无描线后墙锚定变差）、外漏 1→3 页；带闸 → 全部
基准持平且截断 145→133，p18 假线消失、真界行照常增强到 2500px 级。
**产物重建待办**：闸只影响预处理，现有 output/ 是无闸 s4 的产物，
与 s3 裁切修复（§8）捆绑成一轮重建，金标漂移协议一次付清。

## 10. 迭代纪律：先测试集、后整册（2026-08-24 用户定）

整册重跑（segment+chars 两册 ≈15 分钟）只留给**定版动作**；日常迭代
必须走快循环（~2 分钟）：

- **chars 阶段改动** → `bash scripts/quick_bench.sh`：chars 逐页独立
  （无书级共识），只跑金标涉及的页，结果与整册逐字节一致。
  ⚠ 不要直接 `chars --range` 在 output/ 上跑——index.jsonl 是整写的，
  子集跑完别的页就从 index 里消失了；quick_bench 用符号链接临时书目录
  隔离。
- **segment 阶段改动** → 书级共识依赖整册，子集会移共识（金标漂移
  之源）。快循环用**病例页装具**：单页调 `segment_page` 并显式传书级
  先验（cell_h_prior/period_prior/…，取当前产物 grid 里的值），对照
  HEAD 产物验证；整册只在定版时跑一次。
- **裁剪策略定版（2026-08-24）**：图块=本字墨迹外接框 ±2px（TIGHT_MARGIN），
  不再从墙裁到墙——贴墙空白装的从来不是字。自检 flags/夹注在裁紧**前**
  的格框图块上算（阈值按格框标定）。recrop 回归口径同步改为
  「紧框 ⊆ 金标框(+8px) 且盖住其中 ≥95% 墨」（人工拖框带余量，IoU
  对更紧的正确框会误判）。
- **框线归后处理，判定看「去框后」（2026-08-25 用户 r4 定口径）**：
  版框离列端字太近时，格框一裁必然带进框线——切分层做不到，也不该背
  这个指标。分层是：**网格层**管格位对不对，**图块层**管图块=本字墨
  （含 `strip_frame_debris` 剥框渣），**判定层**标剩余风险。自检 flags
  与紧裁都排在剥框之后，所以任何「图块脏不脏」的指标一律是去框后的读数。
  专项测试集 `char-segmentation/frame-strip`（残余率/误剥率/字保全，全
  自动），评测入口 `scripts/eval_frame_strip.py`。
- **「截断」要分三件事说（2026-08-25 用户问「到底解决没有」）**：
  ① 列端纵向截断——解决（版框行锚定 + 逐页格高 + 版框带内缘钉桩）；
  ② 中段纵向接壤——**没解决**，但表现是「混入邻字残渣」而不是「本字被
  切掉」，缺量法，待办 #27；③ 横向截断——界行那侧解决（宽缝补齐 + 侧边
  剥离），**最外列被 s3 裁掉的那侧不在切分层**，量法见分片
  `char-segmentation/page-crop`（6 页 / 387，全自动），待办 #7。
  别用「紧框贴窗边且窗外有墨」当横向截断指标：抽样看图，命中的绝大多数
  是「字贴着界行写」与「脏页霉斑」，不是截断。
- **版框不进条带（2026-08-25 用户指列尾格为密集失败点）**：列端格的
  格线是等分算出来的，撞上版框就会裁到框上。框墨一旦进来常与字的竖笔
  **粘成一个连通体**，剥离（只动独立连通体）与曲刀（红线不许切与字身
  连通的墨）双双失效。所以把桩打在进来之前：`extractor.frame_band_inner`
  量出版框带内缘，条带的上下界钉在那儿。量内缘必须用 grid_segment 那套
  标定过的 `is_bar` 双档，只看行墨率会把末行字当框带吞掉。
- **recrop 口径两条铁律**：① 量的必须是**算法自己**的框——
  `replay_recrops.py` 会把金标贴回产物，读产物等于自己考自己（实测一贴
  回通过数就从 20 跳到 23，算法没改）；`eval_recrop` 因此现场重跑
  `extract_page`。② 过闸看「含住 + 盖墨」不看 IoU——人工是整格拖框、
  产物是紧裁，两种口径差每侧 20~25px，IoU 天花板只有 0.65~0.75。
- **侧边界行也归后处理（2026-08-25 用户 r7）**：图块左右缘吃进来的
  界行竖条由 `strip_side_rule` 剥，判据是「整条落在**文字带之外**」
  ——只按形状（细高贴边）剥必砍字，忄/阝/川/而 的边竖同样是与主体
  断开的细高连通体。专项测试集 `char-segmentation/side-rule`
  （残余率/误剥率/字保全），入口 `scripts/eval_side_rule.py`。
- **异常宽列缝要补（2026-08-25 用户 r7）**：双行夹注写满整个列格，
  比文字带还宽；这一侧没界行时围栏「无墙不敢扩」会把小注竖着切断。
  `grid_segment._widen_wide_gutters` 把宽于页内中位数 2× 的列缝两侧
  一起挪到缝内最宽空白段的中心，**逐带**算并写进 `cell_bands`
  （全书 387 页只 27 条缝命中）。
- **自检队列口径：版式标注不算缺陷（2026-08-25 用户 r7）**：flags 里
  `jiazhu` 这类**版式标注**由 `extractor.INFO_FLAGS` 摘出「待审」口径
  ——照旧写进产物给下游用，但不计 `flagged`、审查页不画橙边。审查页
  的自检橙边现在**默认关**，「自检框」按钮才打开。
- **双行夹注 a/b 拆分（2026-08-25 用户定）**：夹注格整格实例替换为
  a=右子列 / b=左子列 两个半宽实例（id 后缀 a/b、`sub` 字段、flags
  含 `jiazhu`——下游据此隔离字形，不进正文簇/训练）。文本读序唯一
  权威是 `extractor.jiazhu_reading_order`（连段内先 a 全部再 b 全部），
  G5/G6 装配文本一律走它。设计与桥接细节见
  char_clustering_design.md「双行夹注 a/b 子列拆分」。夹注跨度的尺子是
  **列距**（书级刚性常量），不是图块宽度、更不是文字带宽度——后两个
  分别会随窗口漂移、和把左右结构字劈开（2026-08-25 实测记录同上文档）。
