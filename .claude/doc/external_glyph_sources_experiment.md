> 用户 2026-09-07：「完整下载康熙字典和字统网的字形，比较一下用它们做训练，得到的模型匹配
> 我们字形库里已有的这些异体字，准确率是否更高。」本文是实验设计 + 进度账。
> 配套：`glyph_cnn_explained.md`（现役模型）、`ocr_engine_and_zero_shot.md`（七轮台账）、
> `variant_strategy.md`（异体字三类 T1/T2/T3、组内定形器）、`glyph_db_expansion_research.md`

## 0. 为什么现在做

现役第五轮 CNN 的 unseen 类训练样本**全部是字体渲染**（I.Ming + Jigmo，每类每 epoch 24 张
+ 强增广）。第六、七轮堆更多字体样本不再涨（台账 §2.12：「数据轴到头了」），todo 里写的下一步
就是「换数据来源（真刻例回流、GlyphWiki 一字多形）」。

字体渲染的两个结构性短板，正好是异体字最疼的地方：

1. **字体给的是「新字形」或标准形**，不是刻本形。髪/髮、卽/即、囘/回、㫖/旨 这类 T1 异体，
   字体要么没有（缺字→整类只剩 IDS 部件头兜底），要么两形渲染得几乎一样（同一字体设计师
   对异体只改一笔）。网络学不到「刻本上这两形长什么样、差在哪」。
2. **字体是矢量净图**，增广只能模拟磨损，模拟不了刻工的结体习惯（横细竖粗、撇捺收锋、
   部件挤压）。学习曲线实验（台账 §2.13）证明真刻例加多了分类头反而退化，是**类别覆盖失衡**
   ——真刻例只有 658 类。要是每一类都有 ≥1 张真刻本图，这个失衡就没了。

康熙字典恰好是：**清代官刻楷体、4 万余字头、每字一张大字、有逐字页码索引、公有领域**。
这是唯一一部能给全 Unicode 汉字每类配一张真刻本图的公开来源。

## 2. 假设（每条都能被否掉）

| # | 假设 | 若成立看到什么 | 若不成立 |
|---|---|---|---|

| H3 | **异体形辨**：康熙给刻本正统异体形，字体给不了 | 异体子集**严格** top-1 涨（不算「异体算对」）；组内定形 closed-set 准确率涨 | 字典对异体的收录形与刻本用形不一致 |
| H4 | 字统网多朝代印刷体（宋廣韻、明洪武正韻）再叠加 | 相对只加康熙再涨 | 风格更远、量更少，增量 ≈ 0 |

### 5.1 R0/T0 基线重跑（2026-09-07，run-5 checkpoint，同机同日）

|---|---|---|---|---|
| unseen | 1,327 | 95.9 / 94.5 | 95.0 / 93.5 | 99.0 / 98.3 |
| 异体子集（variants.tsv 映射到别字）| 95（73 字种）| 83.2 / 80.0 | 83.2 / 80.0 | 95.8 / 89.5 |

异体子集比全集低 12 个点、严格再低 3 个点——正是外部真刻本源要打的地方。

### 5.2 早期信号：字统网「印+楷」当模板（T3 的部分覆盖版，不重训）

字统网抓取进行中，只拿已抓到的 ~1,500 字做**配对比较**：只评「外部源已覆盖的字」，
T0 与 T3 用同一批 items（`--eval-chars covered_zitools_partial.txt`）。

| 集（只含已覆盖字）| n | 模板 | emb top-1 异体算对 / 严格 | emb top-5 | rrf top-1 异体算对 / 严格 |
|---|---|---|---|---|---|
| unseen ∩ 覆盖 | 399 | T0 字体 | 94.0 / 92.7 | 97.2 | 92.7 / 91.5 |
| | | **字体 + 字统网印楷** | **97.5 / 95.7** | **99.2** | 95.2 / 94.0 |
| | | 只字统网（无字体）| 96.5 / 94.0 | 98.5 | 95.7 / 94.0 |
| 异体子集 ∩ 覆盖 | 28 | T0 字体 | 67.9 / 64.3 | 78.6 | 67.9 / 64.3 |
| | | **字体 + 字统网印楷** | **82.1 / 67.9** | **92.9** | 71.4 / 64.3 |

读法：
- **H1 成立的第一个证据**：模板换成真刻本图，embedding 检索 top-1 +3.5 点（严格 +3.0），
  top-5 错误率从 2.8% 降到 0.8%。n=399 时 3.5 点约等于 14 例，超出噪声。
- **异体子集涨得最多**（+14 点，但 n=28，只是方向）；严格口径只 +3.6——说明模板帮它「进了异体组」，
  组内定形还没解决，正好对应 variant_strategy §4.2 的定形器要做的事。
- rrf 涨幅小于 emb：HOG 与分类头没变，权重 0.5/1/3 是按字体模板标的；外部模板上线后要重扫权重
  （很可能 emb 权重再抬、HOG 归零）。
- 「只字统网、不要字体」略低于两者合并——字体仍有贡献，不是替代关系。
- 注意：三次运行的模板覆盖 32→35%（抓取在长），是「部分覆盖版」；抓完、康熙切图完再跑正式 T1–T5。

### 5.3 正式模板实验（字统网第一批抓完，4,654 字；不重训，run-5 checkpoint）

外部模板覆盖字表 4,560/4,636 字（98.4%）。全 unseen 1,327 条：

| 模板 | 权重 hog/cls/emb | emb top-1 异体算对 / 严格 | emb top-5 | rrf top-1 异体算对 / 严格 | rrf top-10 |
|---|---|---|---|---|---|
| T0 字体（现役）| 0.5/1/3 | 95.9 / 94.5 | 98.3 | 95.0 / 93.5 | 99.0 |
| T3 字体 + 字统网「印」（23,299 张）| 0.5/1/3 | 96.9 / 95.5 | 99.2 | 95.4 / 94.1 | 99.2 |
| T4 字体 + 字统网「印+楷」（43,081 张）| 0.5/1/3 | **97.4 / 95.6** | **99.2** | 96.1 / 94.5 | **99.5** |
| T4，重扫权重 | **0/1/4** | 97.4 / 95.6 | 99.2 | **97.2 / 95.6** | 99.2 |
| 只字统网、无字体 | 0.5/1/3 | 96.2 / 93.7 | 98.4 | 95.5 / 93.4 | 98.7 |

| 集 | 模板 | emb top-1 异体算对 / 严格 | emb top-5 | rrf top-1（0.5/1/3）|
|---|---|---|---|---|
| 异体子集 95 | T0 | 83.2 / 80.0 | 92.6 | 83.2 / 80.0 |
| | **T4** | **91.6 / 84.2** | **97.9** | 84.2 / 81.1；权重 0/1/4 → **89.5 / 84.2** |
| rare-char 21 | T0 | 90.5 / 81.0 | 100 | 81.0 / 66.7 |
| | T4 | 90.5 / 76.2 | 100 | 81.0 / 66.7；权重 0/1/4 → **90.5 / 76.2** |

结论（H1 成立，达到 §3.3 预设的赢线）：
1. **模板换真刻本图就涨**：emb top-1 +1.5（严格 +1.1），top-5 错误率 1.7% → 0.8%；rrf 按新模板重扫权重到 0/1/4 后 **95.0 → 97.2**（严格 93.5 → 95.6），超过预设 ≥96.0 的赢线。HOG 归零是对的——它的字体模板检索被外部模板的 emb 完全覆盖。
2. **异体子集涨最多**：emb 83.2 → 91.6（+8.4，n=95 约 8 例），top-5 92.6 → 97.9。严格口径只 +4.2：模板让它「进对了异体组」，组内定形仍是下一步（variant_strategy §4.2 定形器）。
3. 「印」再加「楷」书法还能多 +0.5（97.4 vs 96.9）；只用字统网不用字体反而低 1.2——两者互补。
4. rare-char 严格 top-1 掉 1 例（n=21，噪声量级），top-5/10 仍 100。
5. 这一切**没有重训**。下一步：康熙字典切图（自有、可分发）当 T1/T2 复现同样的实验；再做 R1–R4 训练实验看分类头能不能也涨。

| | **R4 × T4** | **95.2 / 81.0** | 90.5 / 71.4 | 90.5 / 71.4 | 100 / 85.7 |

**H2、H3 成立**，且两条路加起来不重复：

1. **分类头 +2.2 点**（94.3 → 96.5，严格 +1.2）——这是「类别覆盖失衡」被真刻本图补上的直接效果
   （台账 §2.13 的负结果：真刻例越多分类头越退化，因为真刻例只覆盖 658 类；现在 4,569 类都有真图）。
   训练曲线：**第 61 轮就到 96.8%**（R0 跑满 160 轮 93.7%），data 轴换源立刻兑现。
2. **模板与训练是加法**：R4×T0 96.0 / R0×T4 97.2 / R4×T4 **97.6**。
3. **异体子集**：83.2 → 92.6（+9.4），top-5 92.6 → 98.9（错误率 7.4% → 1.1%）。
   严格口径 80.0 → 84.2（+4.2）——「组内定形」仍是瓶颈，与 §5.3 的判断一致。
4. rare-char 分类头 90.5 → 95.2；emb 严格降 2 例（n=21 噪声）。
5. seen_test 99.5 → 99.8，**没有回退**。

判定：§3.3 的赢线（rrf top-1 ≥ 96.0）**达到**，实际 97.6。

### 5.8 组内定形（variant_form）：真正的收益在自动放行率，不在准确率

**重要更正**：此前本文多处写「组内定形器是下一步、还没做」——**错的**。
`clustering/variant_form.py` 已在管线里（`seed_admit` 每遇「义定形未定」就调），
其 `fixed_form` 通道用的正是本实验改进的三样（HOG / 分类头 / embedding）。
所以接入不需要改架构，只是换数据 + 重标阈值。

组内 closed-set 定形（bench unseen 落在 ≥2 形异体组里的 n=691 / 520 字种）：

| 配置 | 定形准确率 | **平均 top1−top2 差** |
|---|---|---|
| 现役 × 字体 | 96.4% | **0.0138** |
| 现役 × 康熙 | 96.7% | 0.0157 |
| 现役 × 康熙+字统网 | 96.5% | 0.0160 |
| R4 × 字体 | 96.8% | **0.1125** |
| **R4 × 康熙+字统网** | **97.8%** | **0.1734** |

准确率只 +1.4 点，**差距拉大 12.6 倍**。后者才是关键，因为放行闸是
`gap >= FORM_EMB_GAP`（现行 0.03）。

**阈值-放行率-精度曲线**（`cache/exp_extglyph/calib_gap.py`）：

| 阈值 | 现役 放行率 / 错 | R4+TKZ 放行率 / 错 |
|---|---|---|
| 0.01 | 65.0% / 0 | 92.9% / 2 |
| 0.02 | 23.0% / 0 | 91.8% / 2 |
| **0.03（现行）** | **1.0% / 0** | 91.2% / 2 |
| 0.05 | 0% | 89.7% / 2 |
| 0.08 | 0% | 83.8% / 2 |
| **0.12** | 0% | **69.9% / 0** |
| 0.20 | 0% | 35.6% / 0 |

读法：
1. **现行阈值下这条通道基本是废的**——现役配置只放行 1.0%，99% 的异体位落人审。
2. 换 R4+TKZ 后同一阈值放行 91.2%，但**有 2 个错**（99.68%）。这条通道错一次就把
   错标写进字形库，管线别处要求 `match_precision ≥ 0.999`，所以不取。
3. **建议 `FORM_EMB_GAP = 0.12`：放行 69.9%、零错**，n=691 的 Wilson 下界 ≈99.5%。
   即「原本 99% 要人裁的异体位，70% 能自动定形且零错」。
4. 现役配置在 0.01 上放行 65% 也零错——它的**排序本来就对，只是分数挤在一起**。
   新配置的价值是把分布拉开，让阈值有意义、有余量。

**接入建议因此修正**（§5.4 曾说「模板路线性价比高、重训只多 0.2 点」——那是对
开放集候选而言）：对**异体定形**，**重训是必须的**，把 gap 从 0.0138 拉到 0.1125
的是重训不是换模板；两者一起上最好（0.1734 / 97.8%）。

待办：`FORM_EMB_GAP` 从 0.03 改 0.12 之前，需在**真实书页**上跑一遍 seed_admit
量实际人审率（bench 上的 69.9% 是「落在异体组里的位」的放行率，不等于全书人审率）。

### 5.9 无整理本场景 + CNN 背书档（2026-09-07 收尾）

**无整理本时的人审率**（vol01 实际产物抹掉整理本证据重放，17,245 位）：

| 场景 | 自动率 | 人审率 |
|---|---|---|
| 有整理本（现状）| 97%+ | ~1.1% |
| 无整理本 + 有 OCR | 95.6% | **4.4%** |
| 无整理本 + 无 OCR | 88.7% | **11.3%** |

cov 分布解释了为什么比预想好：同书同刻工，cov ≥ 0.99 占 92.5%、≥0.95 占 99.1%。
整理本的价值集中在**头部**（库还空时）与**异体定形**，不在稳态。

**OCR 通道占比实测**（vol01 全书）：dual 84.7% + match_solo_ocr 0.6% = **85.3% 依赖 OCR**。
取消 OCR 自动率 97% → 15%。它的 45% 准确率够用，因为 dual 是**核对**不是识别。

**CNN 能否替代 OCR —— 否，但理由与直觉不同。**
实测 P(CNN 错 | 形状路错) = **8.8%**（CNN 无条件错误率 3.4%，形状路 25.8%），
**两路错到同一字仅 3.2%** —— 相关但远非同源，此前「同输入必同错」的推理不成立。
真正的障碍是那 3.2% 在 dual 场景下会**一致地错**从而静默误放行，达不到 ≥0.999。

**新通道 `match_solo_cnn`**（seeding.py）：只在**无整理本 + 库 cov 0.95~0.99 灰区**触发，
护栏与 OCR 档完全一致。bench seen_test 2,480 位（排除 己已巳/人入/日目 等护栏字）：

| 档位 | 数量 | CNN 背书 | 错 | 精度 |
|---|---|---|---|---|
| cov ≥ 0.99（现行）| 978 | — | 4 | 99.59% |
| **cov 0.95–0.99 灰区** | 1,432 | **1,408（98.3%）** | **0** | **100%** |

放行 39.4% → **96.2%**，精度 99.83%。旁证：灰区里 CNN 不背书的 31 条中库本来就错 16 条
（51.6%）——它既放行也挡。
