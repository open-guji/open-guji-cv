# 第二册夹注（雙行小注）方案

> 2026-09-06 调研。数据全部来自当前产物（p1–20 + dev_set 为新鲜产物，其余 156 页仍是 09-03 旧产物，
> 全书口径要等整册重跑）。切分（Step1–4）另有人负责，本方案只在切分**已经够用**的前提下定识别与审阅。

## 一、盘点：哪些页有夹注

全书 188 页里 **70 页**含夹注：75 段 / 76 列 / 601 格（a 323 / b 278）。按转写内容分**两类**，性质完全不同：

| 类 | 内容 | 段 | 格 | 页 | 特征 |
|---|---|---|---|---|---|
| **T1 版本注** | 「兩江總督採進本」「永樂大典本」「內府藏本」「浙江吳玉墀家藏本」… | 60 | 391 | 60 页各 1 段 | **闭集短语**，紧跟书名卷数，以「本」收尾 |
| **T2 案語** | 「如王柏吳澄攻駁經文輒刪改之類」「案中興書目今不傳此據馮椅易學所引」… | 15 | 204 | 4, 5, 9, 13, 20, 24, 30, 31, 36, 100 | 开放文本，可多列；p4 一页 4 段 82 格 |

**T1 的词表**（语料 `corpus/zongmu_wuyingdian_reference.txt` 里「书名卷数+版本注」行 1,025 条）：去重 **140** 短语，
长度 3–19 字、7 字占 57%；top 15 覆盖约 80%（浙江巡撫採進本 ×180、兩江總督採進本 ×91、內府藏本 ×74、
江蘇巡撫採進本 ×74、浙江吳玉墀家藏本 ×68、永樂大典本 ×59 …）；只出现 1 次的 100 条（多为「某某家藏本」）。
字种 271。

> 文档此前写「整理本里夹注文本已知（`<...>` 包裹）」——**语料里没有 `<...>`**，注文是直接内联的。
> T1 的段界靠行结构（书名行以注收尾）能取到；T2 的段界语料里没有标记，只能靠格数反推。

**版式事实**（新鲜页 193 个小字格量的）：小字紧框 **83×98px**，正文 117×110——小字约 0.7 宽、0.9 高，
**一格一小字、与正文同行距**（不是两小行对一大行），a = 右子列先读。这一点决定了现有「按正文格线切、
缝中心劈 a/b」的设计对本书是成立的。

## 二、切分不是瓶颈（四张样张 + 三个数）

- 样张逐格看图：T1 p95c8「兩淮鹽政｜採進本」、p152c2「副都御史黃｜登賢家藏本」，T2 p4c3、p13c7——
  格线、a/b 分边、紧框**全对**，单字尾（政）收编正确。
- 段端金标 jiazhu-tail 57 条现役 56/57；a/b 格数差 >1 的段 **0**（没有整半格丢失）。
- 紧框离外侧格边中位 0–1px、63–72% ≤2px——小字贴着内容窗口边，但样张里没有被切的笔画。

**结论：夹注的问题不在切分，在识别层。** 不动 `jiazhu_split` 判据，不给夹注半格上折线缝（小字间无粘连样本）。

## 三、问题在哪：三个确切的 bug + 一个数据缺口

新鲜页 193 个小字格：自动放行 171、人审 22（**11.4%**；旧产物全书口径 T1 a 23.1% / b 9.7%、T2 16%）。
22 条人审逐条看：

### bug 1 · 读序错了（识别层，最重）

`steps/context_decide.py:135` 与 `gold/v2_align.py:117` 都按 `sorted(key=(slot, sub))` 列举字位，
a/b **交错**：LM 看到的是「兩採淮進鹽本政」，不是「兩淮鹽政採進本」。前向 n-gram 在这种串上
margin 必然不足——22 条人审里 **13 条库 top = OCR top**（動/末/黃/賢/按/典/商/道/國…），本该 dual 放行，
全被「上下文 margin 不足」拦下。权威读序 `row_boundaries.reading_order`（先 a 全部再 b 全部）早就有，
下游没用。

### bug 2 · 金标盲区

`v2_align` 的 `slots` 键 `(col, slot)`、生成的 id 不带 sub → a/b 互相覆盖，**gold 里一条夹注格都没有**
（p4 有 82 格，gold 0 条）。判据 A 从来没量过夹注。更糟的是交错串会让 8-gram 锚定在注附近出 replace /
丢段，**连邻近正文的金标也被污染**。

### bug 3 · 准入护栏误伤小字

4 条「库 same 但准入被拦(cov=1.000, wmax=0.0)」+ 4 条「护栏:never_match」——库里同字小字只有 1 例，
`wmax=0`。护栏是给正文标的，没考虑小字样本稀。

### 数据缺口

字形库 16,019 例里**小字 59 例 / 52 字种**。版本注词表 271 字种：有小字实例 **11**，有任意（正文）实例 251，
完全没有 **20**（于亭冤友埤察岱廵彛徽敏昶桂溎澍煥砭葦蕃隷——全是人名地名用字）。

> a 侧人审率高于 b 侧**不是几何问题**（紧框宽 83 vs 82、对称）——a 侧词（兩江總督 / 浙江巡撫 / 永樂大）
> 字种比 b 侧（採進本 / 藏本 / 典本）多且生僻。

## 四、dev_set 有没有代表性：没有

dev_set 12 页只含 **4 段 T1、0 段 T2**（95:8、108:1、152:2、171:2）。它是切分链的分层集，为版框/界行/粘连选的页，
改它会让历史数字全断。**不改 dev_set，另立 `jz_set`**：

| 层 | 选页 | 页数 |
|---|---|---|
| T1 top-10 短语各 ≥1 段 | 从 60 页里挑 | ~8 |
| T1 长短语（≥10 字，如 副都御史黃登賢家藏本 / 浙江范懋柱家天一閣藏本） | 152 + 1 页 | 2 |
| T1 单字尾（奇数字） | 95（政）+ 1 页 | 2 |
| T2 全部 | 4, 5, 9, 13, 20, 24, 30, 31, 36, 100 | 10 |
| **合计** | | **~22** |

落地：`books/vol02.yaml` 加 `sets: {jz: [...]}`；`BookSpec.resolve_pages` 现只认 `dev_set / all / 表达式`，
要加命名集解析（`--pages jz`）。

## 五、测试集够不够：不够，但大头能自动生成

现有分片：jiazhu-tail 57（段端三分类，定向富集）、cell-truncation 23（旧坐标系）、instances 709
（**无一条带 sub**）。夹注小字的**定字金标 = 0，切分格金标 = 0**。

要建两个，但不必都手标：

- **(a) 夹注定字金标**（字级）：bug 2 修好后，整理本自动给出——T1 是闭集短语 + 行结构可锚，
  T2 语料里有原文也能锚。人只裁 replace 段。目标 **≥500 条**（601 格的大部分）。
- **(b) 夹注段金标**（段级）：每段一条「a 串｜b 串｜段端 slot｜格数」——从 (a) 派生，格数与读序即金标，
  不另标。新分片 `char-segmentation/jiazhu-segments`。

回归门加两把尺（`eval/rulers.py`）：
- **夹注格人审率**：goal 与正文同 <2%，黄 5% / 红 10%；
- **夹注丢字率**：段内格数 vs 整理本注字数，goal 0。

## 六、算法：按序、按收益

### 第 0 步 · 修三处 bug（半天，先做，不做后面都是白算）

1. `context_decide` / `v2_align` / `seed_admit` 里所有 `sorted(key=(slot, sub))` 改为按 `cells.order`
   （读 `row_segment` 产物 join；或直接调 `reading_order`）。
2. `v2_align`：`slots` 带 sub、id 带 sub、`meta` 键 `(col, slot, sub)`。
3. 验收：p4 / p13 的 gold 出现 a/b 条目；jz_set 夹注人审率下降；含注页正文的 replace 段数下降。

### 第 1 步 · T1 闭集短语通道（1 天）

- 词表 `config/jiazhu/version_notes.json`：从语料派生（同 `build_book_variants` 纪律：**永不手编**，
  脚本重建）。派生规则改成「书名行去掉 `…[一二三四五六七八九十百]+卷` 之前的部分」，比本次调研用的
  机构前缀正则稳；100 条单例要人过一遍。
- `seed_admit` 新通道 **`note_lexicon`**：**段级**证据——把段的 a+b 读序串对词表做编辑距离匹配，
  段长 3–19、≥70% 位与库/OCR 一致 → 整段按短语放行；否则逐位回落现有通道。它与库/OCR 误差独立
  （与 `match_ref` 的「文本 × 形状同源性为零」同理），可以做双信号的一路。
- 三条护栏：短语必须以「本」收尾；段前一格必须是 char（书名末字）；**段格数 = 短语长度**（丢字直接拒，
  不许「差不多」）。
- 验收：T1 人审率 <2%；判据 A 在 T1 上 100%；20 个无实例字（于亭冤…）靠短语通道也能过。

### 第 2 步 · 小字进库 + 护栏放行（随审阅积累，代码半天）

- 审阅确认的小字走现有 confirm → `glyphdb_admit`，`instance_id` 已带 a/b，不用改。
- bug 3 的修法：对 `sub` 实例把 wmax 护栏从「同字例数 ≥2」放到「≥1 且 cov ≥0.99」，**只针对小字**，
  正文不动。阈值等 jz_set 审完 100 例再标定，别拍脑袋。

### 第 3 步 · T2 案語（不另写算法）

T2 是开放文本，但语料里有原文 → bug 修好后 `match_ref` / `dual` 照常评。看 jz_set 上 T2 的人审率；
若仍 >5%，再考虑 normalize 缓存按 sub 分档（小字单独归一化尺寸）。**先别做**——没证据说它需要。

### 不做

- 不改 `jiazhu_split` 五个阈值（四样张 + 56/57 已够；每个值后面都有实测案例）；
- 不给夹注半格上折线缝（`cell_shrink` 已跳过 sub，无粘连样本）；
- 不训小字专用识别模型（数据 59 例，且第 1 步的短语通道能吃掉 T1 大头）。

## 七、怎么让你审：段卡，不是格卡

夹注一段 5–19 字、人一眼能读整句，逐格出卡是浪费。控制台审查页加：

- **`only=jiazhu` 过滤 + 段视图**：一张卡 = 一段。列条裁图（复用 `/api/cutline/img` 的 y 窗口）+
  a 串、b 串并排 + **整理本对应注文放第一行**（bug 2 修后 gold 就有）。
- 三个动作：
  1. **整段确认**（一键：短语对就全过，逐格发 confirm 事件）；
  2. **改某一格**（点格改字，沿用现有 verdict 协议）；
  3. **标切分缺陷**（少格 / 多格 / a-b 分错边 → `seg_defect` 事件，`quality` 新值 `jiazhu_split`）。
- 后端：事件协议不变（confirm / seg_defect），`gold_add` 路由到 `jiazhu-segments` 分片；
  段视图数据来自 `/api/review/column` 的列串（它已按格给 slot/sub，只差按 `order` 排 + 按段分组）。
- 节奏：jz_set 22 页一轮，第 0 步修完先跑一轮**看数**，再做第 1 步；每轮审完 `--from glyph_match` 重放 jz_set。

# 落地记录（2026-09-06，全部完成）

方案里的第 0/1/2 步与段卡、回归门都已落地并在浏览器实测通过。下面只记**与方案不同**
的地方和**踩到的坑**——方案本身的论证不重复。

## 第 0 步：三个 bug（实际只需修两个）

新增 `utils/jiazhu_order.py`：把 `row_boundaries.reading_order` 的规则抽成只依赖
`(slot, sub)` 的排序键（`order_keys` / `sort_by_reading` / `segments`），因为下游拿到的是
`MatchRec`/`AdmitRec` 而不是 `Cell`。与权威实现**随机交叉验证 400 组**（含抬头列、
slot 跳 0、单半格、乱序输入）零不一致——规则抄第二遍就该这么验，不然两边迟早漂移。

- **bug 1**（读序）：`context_decide` 与 `v2_align` 都改用 `sort_by_reading`。
- **bug 2**（金标）：`label_page` 的 `slots` 加 `sub` 维（兼容旧三元组），`instance_id`
  带 `a`/`b` 后缀；`GoldChar` 加 `sub` 字段。
- **bug 3**（护栏）**不用改**。那 4 条「库 same 但准入被拦(wmax=0.0)」的根因就是缺
  `align_char`——bug 2 修完自动消失。方案里把它当独立问题是判断错了。

实测（9 页含夹注）：夹注格 167，人审 **22 → 7（11.4% → 4.2%）**，判据 A 夹注
**161/161 = 100%**（此前为 0，量都量不了）。剩 7 条全是真 unsure（惟/淮、蜀/馮），该停。

## 第 1 步：jz_set 与 note_lexicon

`BookSpec` 加 `sets`（yaml `sets:`），`--pages jz` 可用。**不动 dev_set**。

`scripts/build_note_lexicon.py`：在最后一个「N卷/無卷數」后切，1026 行切动 1023，
78 短语 / 183 字种。未切的 3 行是语料自身毛病（十三篇 / 寸卷 / 元吳澄原本），**不特判**。

`clustering/note_lexicon.py` 两处标定，都是先做错再改对的：

1. **固定 margin 是错的**。词表满是一字之差的孪生短语（浙江巡撫／廵撫、江蘇／江西／
   江南巡撫、副都／左都御史黃登賢），7 字段差一字就是 0.857，`MIN_MARGIN=0.15` 把
   **完美命中也否掉了**——28 段只认出 4 段，认不出的全是转写本来就对的。
   改成按 `(1-sim)` 缩放：sim=1.0 只需严格胜出，sim=0.7 需领先 0.045。
2. **相似度要按语义比**。刻本刻 直𨽾總督採進本、词表作 直隸，不认异体就永远差一字，
   还会与孪生的 直隷 打平双双出局。接 `vmap.semantic` 后 𨽾→隸 归一，与 直隷 拉开
   0.857 的差，正确胜出；而账本 `preferred` 仍是 𨽾，**字形照旧忠于刻本**。

接法上**没按方案劫持 `align_char`**——那会绕过 `match_ref` 用数百条人裁标定出来的
允许集。另立通道名 `note_lexicon`，四条护栏（只对 sub 格 / 库候选须语义同字 /
形近与 guard 照拦 / always_review 不碰），并入 `_CORPUS_CHANNELS` 让 `reading` 照填、
组内定形照走（漏进去会让刻本形被整理本形盖掉，正是判据 E 82/91 那次的机制）。

**note_lexicon 实际只接住 1 格**。第 0 步修好金标后 `align_char` 大多已在，
`dual`/`match_ref` 先接走了——它是**兜底不是主力**。无金标的 7 格全是 T2 案語，
开放文本，词表里没有，正确未碰。这条要如实记：方案高估了它的作用。

## 段卡：两处冒烟才发现的

- **`seg_defect` 不是合法 `Event.kind`**（`Literal` 里没有）。审查页的既有协议是
  `kind='confirm'` + `payload.v='seg_defect'`，`v` 才是载荷判别。照抄之；
  `quality` 沿用 instances 四分类的 `contaminated`，不另造 `jiazhu_split` 这个词，
  段况写进 `note`。
- **提交失败时前端永远停在「提交中…」**——第一次冒烟就栽在这，肉眼看不出错。
  加 `try/catch` 显示原因。这类「失败无声」比失败本身更该修。
- 列条原先 `max-height:22rem`，27 格的长段（p4c6）被裁掉一半等于看不见图，
  改成按宽度缩、高度自适应。

## 判据 F

`jiazhu_rates`：人审率（阈值 0.05/0.10，起点高先宽）+ 丢字率（a/b 格数差 >1 的段，
**不设黄档**，有一段就红）。单位统一**分数**——`review_rate` 的 `rate` 是分数，
混进百分比灯会永远绿。没有夹注的册 `light=none`，不报假警。
