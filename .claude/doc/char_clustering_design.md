# 刻本古籍字符聚类识别系统 — 详细设计

> Phase 4~7：字符提取 → 保守聚类 → OCR 候选 → 上下文排序 → 人工审查 → 反馈训练 → 跨书字形库

## 1. 目标与核心思路

针对**刻本**古籍的一个关键先验：同一书版中同一个字是同一枚刻字反复印出来的，
字形几乎完全一致（差异仅来自磨损、着墨、纸张噪声）。因此可以：

1. 从古籍页面中切出所有单字图块（复用 Phase 3 字符网格的位置信息）；
2. 用**保守聚类**把"确定是同一个字"的图块聚成一类 —— 宁可把同一个字拆成多类（碎片化），
   也绝不把不同的字合进一类（污染）；
3. 对每一类只需识别少数代表样本 → 一次标注/识别惠及全类所有实例；
4. 利用切分时保留的**位置与顺序**信息，把每列还原成候选字格子（lattice），
   用古文语言模型做上下文概率排序；
5. 把可疑字排队交给用户审查，审查结果回灌到聚类阈值、识别器和语言模型；
6. 确认后的"字形-标签"对沉淀为**字形库**，识别下一本书（尤其同一书版/同一刻工体系）时直接命中。

### 设计原则

- **模块化**：每个阶段是独立模块，有明确定义的输入/输出 JSON 契约，可单独运行、单测、benchmark。
- **纯函数核心 + 薄 IO 壳**：算法核心不做文件读写，便于单测；CLI/pipeline 负责 IO。
- **保守优先**：聚类指标以 purity（纯度）为硬约束（目标 ≥ 99.9%），碎片率是可优化的软指标。
- **字形层/语义层分离**：标签、候选、字形库、最终转写全部工作在**字形层**——异体字
  （爲/為、逰/遊…）是不同的字，精确区分、绝不合并；**语义层**（异体字→通行繁体正字的映射）
  只作为辅助注记供语言模型理解上下文与用户阅读，语言模型无权改判异体字形。
- **一切可复算**：每个模块输出带版本号和参数快照，任何一步可用新参数重跑而不影响上游。
- **反馈闭环**：人工确认的标签是全系统最高优先级信号，用于阈值标定、分类器训练、语料扩充。

## 2. 与现有管线的关系

```
现有:  s0 profile → s1~s6 预处理 → Phase2 版面(列结构) → Phase3 字符网格(cells)
                                                              │
本设计:                                                        ▼
  Phase 4  字符提取     phase3 cells + s6 二值图/s4 灰度图 → 单字图块数据集
  Phase 5  保守聚类     单字图块 → 聚类结果 clusters.json
  Phase 6  识别与排序   聚类代表 → OCR 候选 → 列 lattice → 上下文后验
  Phase 7  审查与反馈   可疑队列 → Web 审查 → 标签 → 字形库/阈值/模型更新
跨书持久:  GlyphLibrary  glyph_store/（独立于 output/bookX/，跨书共享）
```

Phase 3 输出的 `cells[]`（`char`/`empty`/`margin`，含 `index`、`y_top/y_bottom`、列号）
天然携带了阅读顺序（列从右到左、列内从上到下），是本系统位置/顺序信息的唯一来源，
Phase 4 之后不再接触整页图像的几何解析。

## 4. 核心数据模型

### 4.1 全局字符实例 ID（CharInstanceId）

```
{book}:{page}:{col}:{idx}        例: book1:3:2:14
```

- `page`：页面文件 stem（拆分半页后如 `1_right`）；
- `col`：Phase 2 列编号（从右到左，1 起）；
- `idx`：Phase 3 cell 的 `index`（char 与 empty 共享的编号序列）。

此 ID 是四个 Phase 之间引用字符的唯一外键，天然编码了阅读顺序：
`(page, col, idx)` 字典序即文本顺序（col 需按数值升序 = 从右到左）。

## 5. M1 — CharExtractor 字符提取

### 职责

把 Phase 3 的逻辑 cell 变成物理图块数据集，并固化顺序/位置元数据。**本模块之后，
下游不再需要读取整页图像与版面 JSON。**

### 接口

```python
@dataclass
class CharInstance:
    id: str                  # book1:3:2:14
    book: str
    page: str
    col: int
    idx: int
    bbox: tuple[float, float, float, float]   # 页面坐标 (x0, y0, x1, y1)
    cell_type: str           # "char"（empty/margin 不提取但记录在 meta 统计中）
    ocr_text: str | None     # Phase3 整列 OCR 对位到该格的字（弱先验）
    patch_path: str          # 相对 phase4_chars/ 的路径

class CharExtractor:
    def __init__(self, padding_ratio: float = 0.08,
                 source_step: str = "s4_deskew"):   # 灰度源；二值图仅用于统计
        ...
    def extract_page(self, page_gray: np.ndarray, grid: dict,
                     book: str, page: str) -> list[tuple[CharInstance, np.ndarray]]:
        """纯函数：输入整页灰度图 + phase3 grid JSON，输出实例与图块。"""
```

### 算法要点

- **裁切源用灰度图（s4_deskew 输出）而非二值图**：二值化损失笔画灰度层次，
  归一化和特征提取阶段需要自己控制二值化参数；bbox 来自 Phase 3（其坐标系即 s6/s4 图坐标系）。
- bbox 外扩 `padding_ratio`（默认 8%），并裁到列边界内，避免切掉笔画出头。
- 记录 `ink_ratio`（黑像素占比）、`h/w` 到 index.jsonl，供 M3 粗分块与异常过滤。
- `empty` cell 不产出图块但计入 meta 统计（转写重建时需要占位）。

### 参数

| 参数 | 默认 | 说明 |
|------|------|------|
| `padding_ratio` | 0.08 | bbox 外扩比例 |
| `source_step` | `s4_deskew` | 裁切像素来源步骤 |
| `min_ink_ratio` | 0.01 | 低于视为疑似空格，标记 `suspect_empty` 但仍提取 |

### 测试与 benchmark

- **单测**：构造合成 grid JSON + 合成页面图（`synth.py` 渲染），断言图块数量、bbox 外扩、
  越界裁剪、ID 生成与排序正确性。
- **benchmark**：`python -m open_guji_cv.clustering.extractor --bench data/book1`
  报告：提取吞吐（字/秒）、图块尺寸分布、ink_ratio 分布直方图。
- **不变量**：`len(index.jsonl) == Σ page 各列 char cell 数`；ID 无重复。

## 6. M2+M3 — 归一化、特征与保守聚类

### 6.1 M2 归一化（normalize.py）

每个图块 → 标准形态，消除"位置/大小/着墨浓淡"差异，只留字形差异：

1. 灰度 → Sauvola 局部二值化（参数固定，与 s6 解耦）；
2. 去除边缘毛刺：连通域分析，删除面积 < `noise_area`(6px) 且贴边的组件（界行残留）；
3. 以**墨迹质心**平移居中，按**墨迹外接框**等比缩放到 `S×S`（默认 64×64），四周留 12% 空白；
4. 输出两份：二值归一图（供配准验证），及轻度高斯模糊图（供特征提取，抗锯齿）。

### 6.2 M2 特征后端（features.py）

注册表模式，与 analyzers/preprocessors 的注册表一致，便于横向 benchmark：

```python
FEATURE_BACKENDS: dict[str, type[BaseFeature]] = {
    "raw":  RawDownsample,     # 归一图降采样 16×16 展平，L2 归一 —— 基线，零依赖
    "hog":  HogFeature,        # skimage HOG，对笔画方向敏感 —— 默认
    "emb":  CnnEmbedding,      # 小型 CNN 嵌入（可选，见 M7 训练）
}
```

特征只用于**粗分块与近邻检索**，不作为合并依据（合并只信配准验证），
因此换后端不影响正确性，只影响碎片率和速度。

### 6.3 M3 两两配准验证（verify.py）——保守性的核心

```python
def verify_pair(a: np.ndarray, b: np.ndarray,
                max_shift: int = 3, scales: tuple = (0.95, 1.0, 1.05),
                ) -> PairVerdict:
    """a, b 为 64×64 归一二值图。返回 (score, aligned_shift, verdict)。
    score = 最优配准下墨迹像素的 F1（2*|A∩B| / (|A|+|B|)）。
    """
```

- 在 ±`max_shift` 平移 × 3 档缩放的小网格上搜索最优对齐（64×64 上代价极低，可向量化）；
- 相似度用**墨迹 F1** 而非像素相关：对着墨浓淡（笔画粗细膨胀）比较鲁棒；
  另计 `dilated_f1`（双方膨胀 1px 后的 F1）作为磨损容忍度参考；
- 判决三档：
  - `same`：`f1 ≥ θ_high`（初始 0.80，标定后收紧/放宽）
  - `unsure`：`θ_low ≤ f1 < θ_high` —— **不合并**，但记录为"潜在同类对"供审查/标定
  - `diff`：`f1 < θ_low`（初始 0.62）
- **形近字防线**：即使 `f1 ≥ θ_high`，若差异像素集中在某个连通区域
  （`largest_diff_blob_area / ink_area > 0.06`，如"曰/日"“大/太”的一点之差），降级为 `unsure`。
  这是保守性的关键补丁：整体相似度对"局部一笔之差"不敏感。

### 6.4 M3 聚类编排（clusterer.py）

O(n²) 不可行（一本书数万字），采用 **分块(blocking) → 近邻图 → 验证 → 全连接合并**：

1. **粗分块**：按 `(h/w 比分桶) × (ink_ratio 分桶)` 先粗筛，块内用特征向量建
   kNN 图（`sklearn NearestNeighbors`，k=10）——只有近邻对才进入验证，
   避免明显不同的字做昂贵配准；
2. **验证**：对每条 kNN 边跑 `verify_pair`，保留 `same` 边；
3. **合并**：在 `same` 边图上做**全连接校验的凝聚合并**（complete-linkage 语义）：
   两个候选簇合并前，抽查跨簇样本对（≤ `cross_check_k`=3 对）也必须 `same`，
   否则不合并 —— 防止链式传递污染（A~B, B~C 但 A≁C）；
4. **簇代表**：每簇选 medoid（与簇内平均 F1 最高者）+ 最远成员 + 随机成员，
   共 `n_reps`（默认 3~5）个代表，写入 clusters.json；
5. 单例簇（磨损严重/独字）保留，天然流向审查队列。

**clusters.json 结构**：

```json
{
  "params": {"feature": "hog", "theta_high": 0.80, "...": "..."},
  "clusters": [
    {"cluster_id": "c00042", "size": 137,
     "members": ["book1:1:1:0", "..."],
     "reps": ["book1:3:2:14", "..."],
     "cohesion": 0.91,
     "unsure_neighbors": ["c00107"]}
  ],
  "stats": {"n_instances": 18760, "n_clusters": 2210, "singleton_ratio": 0.31}
}
```

### 参数

| 参数 | 默认 | 标定方式 |
|------|------|---------|
| `theta_high` / `theta_low` | 0.80 / 0.62 | M7 用人工标签标定（见 10.2） |
| `diff_blob_ratio` | 0.06 | 用形近字对（回归集）标定 |
| `knn_k` | 10 | 碎片率-速度权衡，benchmark 决定 |
| `cross_check_k` | 3 | 越大越保守越慢 |

### 测试与 benchmark

- **单测（verify.py 为重点）**：
  - 同图平移/缩放扰动后必须 `same`；
  - 合成磨损（随机腐蚀+笔画断裂，`synth.py` 提供）后仍 `same`；
  - 已知形近字对（曰/日、大/太、干/千、王/玉…渲染自繁体字体）必须不为 `same`
    —— 这组是**永久回归集**的种子，人工审查发现的新混淆对持续追加；
  - 链式污染场景：构造 A~B~C 而 A≁C，断言不合并。
- **benchmark（两级）**：
  - *合成集*：`synth.py` 用繁体字体渲染 N 字 × M 份 + 磨损增强 → 真值已知，
    报告 **purity**（簇内多数标签占比，硬指标 ≥ 99.9%）、
    **碎片率**（每个真实字被拆成的平均簇数）、吞吐（对/秒）；
    合成集使 M2/M3 无需人工标注即可回归测试。
  - *真实集*：对 data/bookX 跑全量，purity 由后续人工审查事件回填统计
    （每次审查改判都是一条 purity 证据），报告簇数/单例率/吞吐。
- **指标基线要求**：purity 是发布门槛；碎片率只影响审查工作量，可迭代优化。

## 7. M4 — CandidateGenerator OCR 候选生成

### 职责

对**每个簇**（而非每个实例）生成候选字分布。簇是识别单元 —— 这是聚类带来的
核心收益：一个 137 实例的簇只需识别 3~5 个代表。

### 候选来源（按优先级）

1. **字形库 kNN（M8）**：代表图块特征在 glyph_store 中查近邻，命中
   （`verify_pair` 达 `same`）则直接给出高置信候选 —— 同一书版再印本可大面积命中；
2. **PaddleOCR 单字识别 top-k**：对每个代表图块调用 rec 模型。PaddleOCR 默认只返回
   top-1，取 top-k 的途径（按实现成本排序）：
   a. 直接读取 rec 模型 CTC softmax 输出，对（去 blank 后的）主导时间步取 top-k 字符及概率
      （需要绕过 `TextRecognizer` 后处理，用 predictor 拿原始 logits —— 封装在
      `candidates.py::PaddleTopK`，是本模块唯一"深入 Paddle 内部"的点，单独隔离+单测）；
   b. 回退方案：对代表图块做 t 次轻微增强（±2px 平移、±3° 旋转、伽马抖动）分别识别，
      汇总出现过的字及频次作为伪 top-k；
3. **Phase 3 整列 OCR 弱先验**：CharInstance.ocr_text 对位字，权重最低（对位可能错位）。

### 聚合

簇内多代表的候选分布做加权融合（权重 = 各来源可靠性 × 识别置信度），输出：

```json
{"cluster_id": "c00042",
 "candidates": [{"char": "通", "semantic": "通", "p": 0.83, "sources": ["glyph_knn", "ocr"]},
                 {"char": "遇", "semantic": "遇", "p": 0.09, "sources": ["ocr"]},
                 {"char": "逰", "semantic": "遊", "p": 0.04, "sources": ["ocr"], "surface_uncertain": false}],
 "source_detail": {"glyph_knn": {"hit": "g_000381", "f1": 0.87}, "...": "..."}}
```

- **异体字不合并（字形层原则）**：本系统的标签体系是**字形层**的——"爲/為/为"是三个
  不同的候选，各自独立计票，绝不归并。刻本的异体字字形本身是有价值的信息
  （版本学/刻工特征），必须精确区分并保留。每个候选同时挂一个**语义层**注记
  `semantic`（经 `config/dicts/` 异体字→正字映射表查得的通行繁体正字，查不到则等于自身），
  仅供 M5 语言模型理解语义使用，不参与候选合并与最终标签；
- **OCR 字表覆盖不足的处理**：PaddleOCR 字表可能不含生僻异体字，对异体字形往往输出
  通行正字——此时该候选的 `char` 暂记 OCR 输出，但标记 `surface_uncertain: true`，
  精确字形以人工审查确认为准（M6 确认后入字形库，后续同版书由 kNN 直接给出精确异体字形，
  不再依赖 OCR 字表）。标签允许任意 Unicode 码位（含 CJK 扩展区）。

### 测试与 benchmark

- **单测**：候选融合逻辑（纯函数）：来源加权、异体字合并、空候选兜底；
  `PaddleTopK` 用录制的 fixture（保存一次真实 rec 输出 npz）离线测试，不依赖 GPU。
- **benchmark**：在人工确认过标签的簇上报告 **top-1 / top-5 命中率**、
  字形库命中率、每簇平均识别耗时。命中率按簇加权和按实例加权各报一份
  （大簇识别对了收益更大）。

## 8. M5 — ContextRanker 上下文概率排序

### 职责

利用阅读顺序把候选分布放回文本流，用古文语言模型重排，输出每个**实例**的后验分布
与可疑标记。注意：同簇实例共享候选分布，但上下文不同 → 后验可以不同；
簇级标签的最终裁决取簇内实例后验的聚合 + 一致性检查。

### 算法

1. **重建文本流**：按 `(page, col asc, idx)` 恢复每列字序列（empty cell 作为可断句提示）；
2. **构建 lattice**：每个槽位放该实例所属簇的候选（top-k，含 `<unk>` 兜底）。
   每个候选携带两层信息：`char`（字形层，精确异体字形，最终输出）与
   `semantic`（语义层，映射到通行繁体正字，仅供 LM 打分）；
3. **beam search 解码（语义层打分，字形层输出）**：
   `score = λ·log P_ocr(char) + (1-λ)·log P_lm(semantic | semantic_context)`
   —— LM 的输入输出全部在语义层进行（语料训练前也做同样的正字化归一，
   否则语料中低频异体字会被 n-gram 判为低概率，反而惩罚正确的异体字候选）；
   同一槽位若有多个候选映射到同一 semantic（如"逰/遊"同现），LM 分相同，
   排序由字形层的 P_ocr（含字形库 kNN 的配准分）决定——**字形之争只由字形证据裁决，
   语言模型无权改判异体字形**。beam 宽度默认 8，λ 默认 0.55（标定见 M7）；
   跨列衔接：同页相邻列首尾相连（古文不分词断句，n-gram 直接跨列滚动是合理近似；
   夹注/表格页面例外，按 profile 关闭跨列）；
4. **后验与边际**：对每槽位输出归一化后验 `p(char)`（键是字形层精确字形）及
   `margin = p(1st) - p(2nd)`。

### LM 后端（lm.py，注册表）

| 后端 | 依赖 | 场景 |
|------|------|------|
| `ngram`（默认） | kenlm，字符级 5-gram | 训练语料：开源古文全文（殆知阁/CText 等电子文本，繁体化后）+ M7 回灌的已确认转写 |
| `masked-lm`（可选） | GuwenBERT/SikuBERT 类模型 | 精排：仅对 suspects 二次打分，控制算力 |

### 8.5 可疑标记（suspects.json）

实例进入审查队列的条件（任一命中，带原因标签）：

| 原因 | 条件 |
|------|------|
| `low_margin` | margin < 0.25 |
| `lm_ocr_conflict` | LM 最优 ≠ OCR 最优且两者都不弱 |
| `singleton` | 所属簇 size == 1（无聚类互证） |
| `cluster_inconsistent` | 同簇实例后验最优字不一致（强烈暗示簇污染 → 优先级最高） |
| `unsure_pair` | 所属簇有 `unsure_neighbors`（潜在应合并） |
| `low_ink` / `damaged` | M1 标记的疑似残损 |

队列按 `预期收益 = 簇大小 × 不确定度` 降序 —— 先审大簇，一次确认收益最大。

### 测试与 benchmark

- **单测**：lattice 构建（empty/跨列/缺字对齐）、beam search 正确性（小词表手工可验算例）、
  后验归一化。LM 用 3 行玩具语料训练的微型 n-gram 做确定性测试。
- **benchmark**：在有真值转写的页面上报告：
  重排前后 top-1 准确率提升、suspects 的**召回率**（真实错误中被标可疑的比例，目标 ≥ 95%）
  与**误报率**（审查工作量），解码速度（字/秒）。

## 9. M6 — ReviewUI 人工审查

### 职责

以最小人力消化 suspects 队列，产出机器可消费的标签事件流。复用
`open_guji_cv/web/server.py` 的本地 HTTP 骨架，新增 `clustering/review/`。

### 交互设计（三个视图）

1. **簇视图**（主力）：蒙太奇网格展示整簇 + 当前候选与后验；操作：
   - ✅ 确认标签（一键给全簇 size 个实例打标 —— 审查效率的来源）；
   - ✏️ 改判为其他字（输入或从候选点选）。**标签必须是精确异体字形**：输入某字时
     UI 自动展开其异体字组（来自 `config/dicts/` 映射表 + 字形库中已有字形），
     并排显示各异体字的标准字形与本簇 medoid 图块对照，用户点选精确形体；
     生僻字支持直接输入 Unicode 码位或 IDS 描述式；界面同时以灰字显示 semantic 正字作辅助；
   - ✂️ 拆簇：框选不属于本簇的成员移出（生成 `split` 事件 + 一条回归对）；
   - 🔗 并簇：对 `unsure_neighbors` 并排展示，确认合并（生成 `merge` 事件）。
2. **上下文视图**：点击任一实例 → 显示该字在原页的裁切上下文（前后各 3 字 + 整列缩略），
   解决"孤立看图认不出"的问题；位置数据直接来自 CharInstance.bbox。
3. **队列视图**：suspects 按预期收益排序，显示原因标签；支持按原因过滤。

### 9.3 标签事件流（labels.jsonl，只追加）

```json
{"ts": "...", "op": "confirm", "cluster": "c00042", "char": "通", "scope": "cluster"}
{"ts": "...", "op": "relabel", "instance": "book1:3:2:14", "char": "遇"}
{"ts": "...", "op": "split",   "cluster": "c00042", "moved": ["book1:5:1:3"], "reason": "different_char"}
{"ts": "...", "op": "merge",   "clusters": ["c00042", "c00107"]}
{"ts": "...", "op": "mark",    "instance": "...", "flag": "damaged|empty|illegible"}
```

事件流是唯一真源；当前标注状态 = 重放事件流。好处：可撤销、可审计、
M7 的所有训练数据都从这里派生，且天然增量。

### 测试

- 事件重放器（纯函数）单测：乱序/冲突事件（先 confirm 后 split）的最终状态确定性；
- server 层用 HTTP 集成测试（无浏览器）：队列拉取、事件提交、幂等性。

## 10. M7 — FeedbackLoop 反馈更新

### 职责

消费 labels.jsonl，更新四类下游资产，并驱动重跑。所有更新都是**离线批处理命令**，
显式触发（`update` 子命令），不做隐式魔法。

### 10.1 标签派生数据

从事件流重放得到：`instance → char` 真值表、`same-pair`（同簇确认对）、
`diff-pair`（split/形近改判产生的异类对）。

### 10.2 聚类阈值标定（→ M3）

在 same/diff 对上计算 `verify_pair` 分数分布，选 `theta_high` = 满足
`P(diff | score ≥ θ) ≤ 0.1%` 的最小值；`diff_blob_ratio` 在回归对上网格搜索。
写入 `glyph_store/calib/thresholds.json`（按特征后端分别存）。
**每次标定后必须全量通过 `regression_pairs.jsonl` 回归集才允许生效。**

### 10.3 识别器更新（→ M4）

- **第一档（默认，零训练）**：确认字形入库（M8），kNN 检索天然变强；
- **第二档（可选）**：用标注图块训练小 CNN 嵌入（triplet loss，同字近/异字远），
  升级 M2 的 `emb` 特征后端 → 同时降低 M3 碎片率和提升 M4 kNN；
- **第三档（可选，数据量大后）**：微调 PaddleOCR rec 模型（PP-OCRv5 单字微调），
  独立脚本 `scripts/finetune_rec.py`，产物模型路径写入 config，M4 可切换。

### 10.4 语料更新（→ M5）

确认转写按页导出纯文本，追加进 `glyph_store/lm/corpus_confirmed/`，
重训领域 n-gram（与通用古文语料插值，权重可配）。
**入语料的是语义层文本**（`text_semantic/`，异体字已正字化），与 LM 的打分空间一致；
字形层原文（`text/`）另行归档，不进 LM——LM 只管语义，异体字形由字形证据裁决（见 8 节）。
同时从确认标签中统计**本书的异体字用字习惯**（如全书"遊"一律作"逰"），
存入 `glyph_store/lm/variant_prefs/{edition_tag}.json`，作为 M4 候选的字形层先验：
同版书中某语义字已确认过的字形获得加权。

### 10.5 重跑语义

`rerun` 命令按依赖图最小重算：阈值变了只重跑 M3 合并阶段（验证分数有缓存）；
标签只增不改时 M5 可以只对受影响列重解码。每个 meta.json 记录上游产物的
内容哈希，实现"参数或输入变了才重算"。

### 测试与 benchmark

- 标定算法单测：构造已知分布的 same/diff 分数，断言选出的 θ 满足纯度约束；
- **闭环 benchmark（系统级）**：在合成书或已全标注的真书上模拟审查过程 ——
  按队列顺序"自动人工"（用真值回答），报告曲线：
  **审查次数 → 全书准确率**。这是整个系统的北极星指标：
  好系统应该在审查 < 5% 簇后达到 > 99% 准确率。曲线存档对比每次算法改动。

## 11. M8 — GlyphLibrary 跨书字形库

### 11.1 条目 schema（glyphs.jsonl）

```json
{"glyph_id": "g_000381", "char": "通", "semantic": "通",  // char=精确异体字形, semantic=通行正字
 "book": "book1", "edition_tag": "book1",  // 用户可把同书版的多书标同 tag
 "source_instances": ["book1:3:2:14", "..."], "n_confirmed": 137,
 "patch": "patches/g_000381.png", "feature_backend": "hog",
 "created": "...", "labels_version": "..."}
```

每个 `(char, edition_tag)` 存代表字形（簇 medoid），`char` 是精确异体字形——
"爲"和"為"是两个独立条目，绝不合并；同字不同版也可多条。字形库因此
同时是"某书版的字样档案"（含该版的异体字用字全貌），本身就有版本学价值
（未来可做刻工/书版比对、异体字用字统计）。`semantic` 字段仅用于按正字检索
（"查这本书里'遊'用的什么形体"）。

### 11.2 检索接口

```python
class GlyphLibrary:
    def add(self, entries: list[GlyphEntry]) -> None
    def query(self, patch: np.ndarray, feature: np.ndarray,
              edition_hint: str | None = None, k: int = 5) -> list[GlyphHit]
    # 两级：特征 kNN 粗排 → verify_pair 精验，返回 (char, f1, glyph_id)
```

- `edition_hint`：识别新书时若用户声明与库中某 tag 同书版，则该 tag 条目优先且
  阈值可放宽一档；否则全库检索、阈值保持保守；
- 库只进人工确认过的字形（**不进机器猜测**），保证"命中即高置信"这一性质。

### 冷启动第二本书的流程

M1/M2/M3 照常跑（聚类不依赖库）→ M4 优先查库：同版书大部分簇直接命中 →
suspects 队列显著变短 → 审查只处理新字/磨损差异 → 新确认继续入库。
系统的边际成本随书量递减，这是第 6 条需求的直接实现。

### 测试

- 入库/查询/去重单测（内存小库）；
- **跨书 benchmark**：book1 确认标签入库后识别 book1 的另一半页面（自留验证），
  报告库命中率与命中准确率（命中准确率要求 ≈ 100%，否则收紧精验阈值）。

## 15. 真实数据试验记录（book5《钦定四库全书总目》，刻本，10 页）

无 OCR 环境（stub）跑通 preprocess → layout → 切分 → chars → cluster 全链路。
按发现顺序修复的问题（均已进代码 + 单测）：

| 问题 | 修复 | 效果 |
|------|------|------|
| profile 自动检测 chars_per_line=15（实际 21） | 以 README 先验覆盖 | 切分粘连大减 |
| 图块裹进界行竖线，质心/外接框被拉偏 | 提取水平内缩 + 归一化删贯穿线 | 同字 F1 0.4→0.6 |
| 相邻字残片切入图块，外接框忽大忽小 | 浅入侵清除 + 稳健外接框 + 受限各向异性缩放 | 同字 F1 0.6→0.63~0.93 |
| 着墨浓淡差异（同字笔宽差 2 倍）压垮墨迹 F1 | 笔宽归一（Zhang-Suen 骨架化+统一膨胀） | 关键一环 |
| 投影自由切分对断笔/磨损脆弱（bad_seg 35%） | **grid_segment 严格网格切分**（刻本格式固定：N 等分先验网格 + 投影谷微调） | 切分数与理论格数完全吻合；真字簇覆盖 178→300 |

结论：**"同版同字聚类"假设在真实刻本上成立**——之×6、易×5、其×5、家×3、
言×3、子×3、卷×3 等簇全部零污染（θ_high=0.72）。

### book9《四库全书总目·卷首》试验（与 book5 同版的另一册，整书 206 页，取 10 页入库）

切分算法在更多样本上暴露并修复的规律（grid_segment 迭代）：

| 规律/问题 | 对策 |
|----------|------|
| （中间结论，后被推翻）"跨列行位浮动/字距局部不均" → 曾引入逐列相位与弹性 DP | 领域知识修正（见下行） |
| **刻本整版先划栏格再上字：格高固定、跨列统一；列首/列尾空格占格位但无墨** | 最终模型 = **刚性统一网格**：页级聚合投影拟合一个 (相位, 格高)，每列仅 ±0.12 格微调（板歪/扫描形变），格高绝对一致。网格锚定栏格周期证据而非内容范围——**抬头空格列按内容锚定会整体错位**（"乾隆…"奏折抬头、职名页是真实场景）。此前测得的"列间相位差/字距不均"均为弱信号伪像；刚性模型一举修正全部列（含此前失败的左右边缘列），职名页（每列几字+大片空白）也完全正确 |
| inner_frame 检测偏差可近一格，首末字被裁掉 | 纵向外扩一格；网格真实范围由投影内容决定 |
| 边框横线（3~10 行短游程）、扫描黑边（近满宽实心块）污染内容范围 | content_range 游程过滤：短游程 + 高填充游程剔除；阈值参考用 90 分位（抗边框尖峰） |
| 贯穿竖线（边框/界行残留）给每行投影加常量偏置，**填平字间谷** | 投影前竖直开运算剔线（连续贯穿 ≥30% 列高；字的竖笔 ≤1 字高不误伤） |
| **被错误列边界切残的字残形趋同 → 跨字污染簇**（書/督 实例） | 聚类隔离：归一图块含"独立窄高组件"（界行特征；中/串类通高竖笔与主体连通不误伤）→ 强制单例进审查 |

**列网格拟合**（刚性先验在水平方向的同构复用，替代 Phase 2 自由列检测）：
- `page_column_projection`：形态学剔除界行竖线（垂直投影上的假峰，恰在列边界处）
  与边框横线（常量偏置）后，垂直投影呈纯净周期结构（文字列=台地、列间=谷），
  谷/峰代价模型直接复用 `fit_page_grid`；
- 列格 = 文字带 + 界行缝（完整周期）；文字带在周期内位置刚性固定，
  逐列格测内缩取页面中位统一应用——否则图块裹界行，竖线隔离误伤 57% 字符；
- 附带发现：book9 实际为每半页 9 列（README/profile 曾误抄 book5 的 8），
  自由列检测下不暴露，列数先验一启用立即现形——先验本身就是校验。

结果（行列双网格）：book9 十页 1786 字，切分异常 0、隔离 179；
書/之/各/家×10、有×8、者/大×7 等 **167 个真字多成员簇覆盖 28% 实例**零污染
（演进：投影切分 11% → 行网格 16% → 行列双网格 28%）；
抬头空格页与职名页（每列几字+大片空白）行列全对齐、空白格全部正确判 empty；
此前 Phase 2 列检测受害的左右边缘列全部恢复。

### book9 全书试验（204 页，无 OCR 跑到聚类）

预处理 1.8 分 → 版面 3 分 → 行列双网格切分 2.5 分 → 提取 17 秒 →
聚类 5.5 分（3 万实例、20 万次配准验证），全程 CPU。

新增**书级共享网格**（刚性先验第三层：整书同版式）：

### 无 OCR 环境的候选生成路径（book9 全书实测）

代理封锁 paddle 模型源（BOS/HuggingFace 均 403）但放行 PyPI，故用
**rapidocr-onnxruntime**——PP-OCR 同一套 det/rec/cls 权重的 ONNX 版，
16MB 模型随 wheel 分发、零下载。配合视觉语言模型（VLM）识别构成双来源：

| 来源 | 覆盖 | 特点 |
|------|------|------|
| vlm（Claude 视觉识别，size≥4 的 492 簇）| 5272 实例（17%）| 强在字形整体与繁体/异体字 |
| ocr（RapidOCR / PP-OCRv4）| 25287 实例（83%）| 强在高频常用字，有简体偏差 |
| 融合后 | **83%**，双来源首选一致率 **91%** | 分歧簇自然进审查队列 |

**简→繁修正**（`traditional_candidates`）：PP-OCR 是简体中文模型，对繁体
刻本有系统性偏差。修正分三档，**给多候选而非二元替换**：
非简体原样；纯简体（内/检/群）繁体主候选 0.9 + 原字 0.1 兜底；
**自身即合法繁体（卷/万/后/里）原字首选 0.55 + 其他形式平级 0.45**。
效果：双来源一致率 86%→91%，纯简体残留 **0 实例**。

**两个方法论教训**（都由真实数据暴露）：
1. *静默失败*：批量改写把 `self.s2t` 插进没有该属性的类，`AttributeError`
   被 `CandidateGenerator` 的 try/except 吞掉——候选静悄悄变空而测试全绿。
   现在按来源统计失败率、>50% 打 `[错误]` 并写入 `source_failures`。
2. *错误的质量判据*：用 `opencc.s2t(ch) != ch` 判"残留简体"报出 178 例，
   看图才发现是"云/干/里/范/游/于/斗/卷"等古籍本字（子云、干支、里巷、
   范姓、十二卷）——假警报。正确判据见 `residual_simplified()`：
   只有不在自身繁体列表中的才是无歧义简体。**指标本身也需要被验证。**

### 多 OCR 引擎对比（book9 黄金集实测）

黄金集两种模式（`ocr_bench.build_goldset`）：`consensus`（vlm 与 ocr 独立
给出同一首选，430 簇）对参与构建的引擎有偏；**跨引擎对比须用
`vlm_only`**（仅我方视觉识别的无歧义单候选，434 簇 / 5013 实例，
对所有 OCR 引擎都是外部标准）。

| 引擎 | top1（vlm_only） | 加权 top1 | 字/秒 |
|------|-----------------|----------|-------|
| **RapidOCR(PP-OCRv4)+s2t** | **85.2%** | **91.0%** | 29 |
| RapidOCR 原始（无简繁修正） | 80.4% | 88.7% | 30 |
| Tesseract 5 chi_tra（繁体） | 52.8% | 56.5% | 7 |
| Tesseract 5 chi_sim | 33.5% | 41.1% | 7 |
| 三引擎平权投票 | 82.0% | — | — |

- 简繁修正贡献 **+4.8pt**；
- Tesseract 繁体模型虽是"对口"的繁体字表，但准确率远低于 PP-OCRv4，
  **平权投票反而拖低整体**（85.2%→82.0%）；
- 互补性分析：Tesseract 能救回 rapidocr 错误中的 18/205（8.8%，
  占总体 4.1%）——有价值但**只宜作低置信兜底，不可平权**；
- 模型可得性：代理封锁 HuggingFace / jaided.ai / modelscope，
  cnocr、EasyOCR 均因模型下载失败不可用；tesseract 语言包走 apt 可得。

### M5+ 上下文自动修正（context_refine）

两个自动信号，实测结论截然相反：

**簇级边缘化（默认开启，零劣化）**——聚类特有的强约束：同簇 N 个实例
必是同一个字却分布在 N 个不同上下文，把各实例上下文后验按簇聚合
（对数域求和后按实例数几何平均，保证大小簇尺度可比），再回灌全簇。
单点歧义被多处证据消解。全书实测：黄金集零劣化，高置信 +93，可疑 -24。

**同书自举 n-gram（默认关闭，实测净有害）**——见 context_refine 模块
文档中的消融表：自举 LM 把已知正确的字改错（林→你、編→漏），
因为语料本身带 ~15% 识别错误、2 万字训 3-gram 不足以压过噪声。
**M5 设计的正途仍是外部古文语料**；无语料时不要用识别结果自举。

方法论：这两个结论都来自同一套消融实验（`refine_book(use_lm=,
use_cluster_prior=, write=False)`），设计假设必须用数据检验——
"合理的想法"与"有效的想法"是两回事。

### 异体字识别调研（哪些 OCR 认识异体字库）

本环境实测两个可用引擎的字表（解包 unicharset / rec 字典）：

| 引擎 | 字表规模 | CJK 扩展 A | 扩展 B+ | 结论 |
|------|---------|-----------|---------|------|
| PP-OCRv4 (RapidOCR) | 6625（简体常用） | 0 | 0 | 遇异体字必输出形近常用字 |
| Tesseract 5 chi_tra | 4588（基本区繁体 4464） | 0 | 0 | 同上 |

**通用 OCR 的封闭字表结构性地不认识异体字**——它们只能输出字表内
最相近的常用字，且不会告诉你"这是近似"。可行路径按可靠性排序：

1. **本系统字形库（M8）——最可靠，已实现**：异体字一次人工确认后按
   **字形** kNN 匹配，与任何字表无关；标签允许任意 Unicode 码位
   （含扩展区）甚至无码字（IDS 描述式）。这正是 M8 的设计初衷，
   也是"识别下一本同版书时异体字零成本"的机制。
2. **VLM（视觉语言模型）——无需训练即可用，已实现**：训练语料含
   大量古籍影印与全 Unicode 文本，能直接读出"逰/爲/羣"类异体
   （本项目 vlm 来源已实证）；是目前开箱即用的最强异体字识别器。
3. **可训练开源 OCR + 异体字数据**（长期，M7 第三档已设计）：
   Kraken（历史文献 OCR 框架）或 PaddleOCR 微调都支持自定义字典
   （dict.txt 可含任意 Unicode）；数据可取台湾教育部《异体字字典》
   （约 10 万字形）、GlyphWiki、CHISE/IDS 库，而**本系统审查积累的
   标签正是最贴合的训练数据**。需要 GPU 与标注量。
4. 专业古籍 OCR（汉典重光、籍合网等）字表较全但闭源，不可集成。

配套动作：`config/dicts/variants.tsv`（语义层映射）可用教育部
异体字表批量扩充——只影响 LM 打分与检索，不影响字形层标签。

已知余留问题（按优先级）：
1. **Phase 2 列检测**是最大上游瓶颈：真实列宽 60~301 连续分布
   （半列/双列粘连），被劈开的字形成部件碎簇（亻等）。刻本先验同样适用：
   列宽/列距固定，可做列网格拟合（与本模块的行网格同构）。
2. 同字-异字分数带偏窄（同字 0.63+，异字最高 ~0.65）：θ=0.72 下最规整的
   字直接合并，其余落 unsure 带交审查并簇；后续可用弹性配准或 CNN 嵌入拉宽。
3. 无 GPU/OCR 环境未验证 M4 的 ocr 来源与 CTC top-k；候选生成暂靠
   字形库 + prior。

## 16. 主要风险与对策

| 风险 | 对策 |
|------|------|
| Phase 3 切分误差（粘连/切半）传导 | M1 记 ink_ratio/h-w 异常 → 标 `bad_seg` 进审查；审查 UI 支持标"切分错误"反馈给 Phase 3 参数迭代（跨 Phase 信号，不在本系统内自动处理） |

| 磨损重导致碎片化过高 | 碎片化不影响正确性，只增审查量；用 emb 特征与 dilated_f1 迭代；unsure 对进并簇审查 |
| PaddleOCR 内部 API 变动（top-k 提取） | PaddleTopK 单独隔离 + fixture 离线测试 + 增强投票回退方案 |
| OCR 字表不含生僻异体字 → 首轮只能给出正字候选 | 候选标 `surface_uncertain`，精确字形由人工审查定；确认一次即入字形库，同版书后续由 kNN 直接命中精确形体；`variant_prefs` 用字习惯先验进一步降低复发 |

## 17. 无命令行审查工作流（review-export / review-ingest）

用户场景：只能通过 Claude Code 远程会话工作，无法开终端、无法访问
`review` 命令起的本地 HTTP 服务。方案：**审查批次静态化 + 事件行回收**，
实现在 `review/artifact_export.py`。

### 17.1 架构

```
Claude 会话                     用户（浏览器，零安装）
──────────────                 ──────────────────────
review-export                   打开页面点击审查：
  → 自包含 HTML 批次              点候选字=confirm；其他字；存疑=mark
  （top-N 可疑簇，图块内嵌         每次点击把 GUJI-EVENT {json} 行
   base64，±3字/±3列上下文）       追加进页面内 <pre id=guji-log>
  → 发布为 Claude Artifact
     （live-doc：点击产生的 DOM
      变化自动保存）
                     ↓
review-ingest ← WebFetch 读回保存后的页面
  → 解析 GUJI-EVENT 行，(batch,seq) 去重
  → 逐条 ReviewSession.post_event 校验 → labels.jsonl
update → 字形库/阈值/用字习惯/语料（原 M7 闭环）
```

### 17.2 持久化三层保险

1. **Artifact live-doc**（首选）：声明 `capabilities: {artifact:{}}`，
   用户手势产生的 DOM 变化（事件日志、卡片状态）被自动保存为共享文档；
   Claude 之后 WebFetch 该 URL 即可回收，用户全程零配置。
2. **downloads 能力**：Artifact 环境下"下載 labels.jsonl"按钮直接导出
   事件文件（能力探测 `window.claude?.use`，静态托管时按钮隐藏）。
3. **可见事件日志**：页面底部 `<pre>` 可全选复制贴回对话——任何托管
   环境（含 GitHub Pages）下都成立的兜底。

GitHub Pages 备选：同一 HTML 提交进仓库任意分支即可静态托管（页面无
外部依赖），但静态页无法写回仓库——回收只能走第 3 层（复制粘贴）或
浏览器端 GitHub API + 用户 PAT（未实现：PAT 管理成本高，Artifact 路径
已覆盖需求）。

### 17.3 事件行格式与幂等

`GUJI-EVENT {"op":"confirm","cluster":"c00192","char":"林",
"batch":"book9all-gain-400-79701896","seq":3,"ts":"..."}`

- 与 labels.jsonl 事件同构（confirm / mark[flag=uncertain]），额外带
  `batch`（书-排序-簇数-簇集哈希）+ 页内自增 `seq` 供去重；
- `ingest_events` 对 (batch,seq) 幂等——重复回收同一页面安全；
- 改判 = 再点一次其他候选（追加新 confirm，重放后发覆盖先发）；
- 解析容错：从任意文本（HTML 原文 / WebFetch markdown 转写 / 粘贴片段）
  按行正则提取，坏行静默跳过。

### 17.4 批次页面 UI

- 每簇一卡：成员图块（≤4 + 计数）、候选按钮（字 + 概率 + →语义注记）、
  "其他字"输入、存疑、稍後（纯视觉收起，不产生事件）；
- 問題按钮行（簇级 flag 事件，用户反馈新增）：不同字混簇 impure（仅
  多成员簇显示）/ 截斷 truncated / 混入邊框鄰字 contaminated / 非文字
  not_text；"改"离开 flag 态时自动发 flag:clear 撤销。flag 簇退出审查
  队列，update 时汇总为 phase7_review/flags.json 缺陷清单（供 Phase 3
  切分参数迭代）；本地 SPA 同步加同组按钮，两端事件模型一致；
- 上下文：同列 ±3 字内联（目标朱框），`<details>` 展开 ±3 列全文竖排
  （flex 纵向堆叠实现——**不用 writing-mode**：Google Fonts 子集常剥
  vmtx 竖排度量，实测 span 行进高度塌缩为 2px）；
- 筛选（全部/未審/已審）为 per-viewer 状态，存于 `data-local-filter`；
- 纸墨主题（米纸/墨字/朱砂点），亮暗三态 token（bare :root + prefers
  guard + data-theme 覆盖）。

### 17.5 验证

- 单测 5 项（tests/clustering/test_artifact_export.py）：批次构建、
  自包含渲染（含主题三态、能力探测守卫）、文件导出、容错解析、
  回收往返 + 幂等 + 未知簇计入 errors 不中断；
- 真实数据：book9all top-400（gain 排序）批次 2.3 MB（16 MB 限制内），
  Playwright 无头点击验证事件行生成、进度更新、竖排上下文渲染。

## 18. 第一轮人工审查反馈闭环（book9all，27 条事件）

用户审查 23 簇给出 27 条反馈（8 confirm / 1 mark / 18 flag）。这是系统
第一次真正闭环，暴露的问题比预期严重，且**两条最有价值的结论都是
「不要动」**——记录在此以防重蹈。

### 18.1 网格格高谐波锁定（已修，最大缺陷）

反馈中 6 条 truncated + 部分 not_text 指向同一根因。溯源：

- 图块原始尺寸暴露异常：正常字高 ~132px，问题页只有 62–66px（恰好一半）；
- 全书 203 页中 **14 页（7%）的 cell_h 落在真值的 1/3~2/3**
  （ratio 0.33/0.47/0.49/0.50…），整页每字被切成两三段；
- 独立物证：逐页测字符连通体高度，**p75 稳定在 96–111px（全书一致）**，
  证明真值格高处处相同，是拟合错了而非排版不同。

根因：`cell_h` 源自 `base = (bottom-top)/n_chars`，该式**假设列是满的**。
稀疏页（目录/职名，每列仅十余字）与密排页的谐波都会落到 1/2、1/3 的
伪解，而搜索窗只有 ±8%，永远跳不出去。

为何现有书级校正救不了：判据是「墨量低 或 rule_in_col>0.2」，而这 14 页
里页 18/70/140 墨量**高于**中位、rule_in_col=0.0；且择优门控要求
`new_rule ≤ old_rule`，old 已是 0.0，任何校正一律被拒。

修复（`grid_segment.py`）：书级格高共识。刻本全书同版，格高是**物理刚性
常量**，一页不可能是别页的一半——偏离共识 >10%（`CELL_H_TOL`）即判锁错，
以共识格高重拟、相位仍按本页投影重搜（`fit_page_grid(cell_h_fixed=…)`）。
不设择优门控：`rule_in_col` 度量列相位，对行格高无判别力。

实测：25 页修正；cell_h 标准差 15.1→2.56，零页偏离；半高图块
**1343→0**；幻影格位消失（实例 30285→29438）；受损页汉字识别率
**77.9%→97.0%**，全书 91.2%→92.4%。页 18 从 `國能早收隆二一！一"↑`
变成 `乾隆三十九年七月`。

### 18.2 簇 id 重绑（已修，正确性缺陷）

簇 id 由聚类过程生成，重跑聚类后整体变号——审查标注会绑到**错误的簇**上，
反馈循环形同虚设。修复：簇级事件记录成员实例 id（`book:page:col:idx`
永久稳定），加载/回收时按成员投票重绑（`feedback.remap_events`）。
实测 27 条历史反馈全部正确迁移（25 条重绑）。批次页面同步在
`data-members` 上带出成员，事件发出时自动附带。

### 18.3 impure 标记未进标定（已修）

`calibrate_threshold` 的 diff 对全部来自随机异标签簇（f1 很低的易分对），
标定出 **theta=0.565** 的荒谬值——而真实混簇的 f1 在 0.73 附近。
impure 标记的簇内成员对是**最有价值的难负样本**（比 split 更省事，
用户点一下即可），现全部进入标定且不参与采样截断。标定值 0.565→0.745。

### 18.4 结论一：形近字混簇**不能靠调阈值**解决（不动）

3 个 impure 簇（周/局、力/方、司/部）与 8 个用户确认正确的簇：

| | f1 范围 | diff_blob 范围 |
|---|---|---|
| 同字对（n=9） | 0.720–0.821 | 0.019–0.048 |
| 混簇对（n=3） | 0.727–0.744 | 0.040–0.055 |

**两个分布完全重叠**。任何能拦住 3 个混簇的 diff_blob 阈值（≤0.040）
会同时误伤 4–8 个正确对；提 theta 到 0.75 要打散 40% 的多成员簇。
即：在 f1≈0.72–0.75 区间验证器本质上无判别力，不存在能同时改善纯度与
碎片化的阈值。正确出路是标定（用户标注积累后由 18.3 的机制给出），
而非拍脑袋调参——本项目此前已因弱信号调参吃过一次亏（见 15 节书级校正 v1）。

### 18.5 结论二：界行残片**不能自动删**（只标记）

not_text 反馈指向界行/版框渗入空格位。判据尝试与实测：

- `blob_frac`（两维都有实体延展的连通体占墨比）：低值样本 24 个全是残片，
  但真「一」字同样 blob_frac=0；
- 「贯穿格位的细直线」占比 ≥0.6：全书命中 4042 个（13.7%），
  但**被 OCR 判为「一/二/三/十」的实例中 37.6% 也命中**——真横笔同样贯穿格宽；
- 位置先验有信号但不足以定论：idx=0 处命中率 33.6%，向列尾升至 25%。

故只写入 `rule_like` **提示标记**（`extractor.py`），不删除、不隔离；
阈值待人工审查反馈标定。注意判定必须在**原始格位图块**上做——归一化的
各向异性缩放会把细线拉宽，证据就没了（这正是 `has_through_vline`
在归一化图上对全部 8 个已知残片判 False 的原因）。

### 18.6 审查页持久化（已修）

经典 Artifact **无手势自动保存**（那是 live-doc 才有的），首版页面因此
丢失了用户的全部 23 条操作。现每次操作防抖 3s 调
`artifact.publish({"labels.jsonl": …})` 发布数据文件新版本（本视图不重载），
重开页面 `fetch("labels.jsonl")` 恢复并重放卡片状态；另有 localStorage
崩溃备份（恢复时按 (batch,seq) 合并补发布）。导出按钮改为**始终可见**：
能力可用则存文件，不可用则自动展开日志并全选，提示 Ctrl/Cmd+C 复制
——此前仅在能力就绪时才显形，能力缺失的视图里用户看不到任何导出入口。

### 18.7 第二批：保存又失效——副檔名不可推斷（已修）

第二批 400 簇用户审完后，读回页面发现日志仍为空、400 张卡片全是
`open`。根因不在能力授权，而在 **`publish()` 的文件类型推断**：平台只对
常见副檔名（html/css/js/json/txt/md/png…）推断 MIME，**`.jsonl` 不在
清单里**，于是每次保存都被判 `invalid_content` 拒绝，而我的错误分支把
自动保存整个关掉，只留一行灰色小字提示——用户没察觉，一整批白做。

三处修复：

1. 文件名改 `labels.txt` 并**显式传 `contentType: 'text/plain'`**
   （显式类型可让任意文件名通过，双保险）；
2. 保存失效改为**红底常驻告警并带错误码**（`儲存被拒（invalid_content）
   — 請點「匯出審查記錄」複製後貼回對話`）。此前失败是静默的，
   我因此连续两轮在盲飞——错误码必须出现在用户能看见的地方；
3. 保存成功后清 `disabled`，允许从暂时性失败中恢复。

三条路径均以 Playwright 实测：正常保存（檔名/类型正确）、模拟
`invalid_content` 拒绝（红底 + 错误码）、本机备份还原（关页重开后
日志与卡片状态完整回来，导出兜底可全选复制）。

教训（写给以后的自己）：**跨进程持久化必须先做一次真实往返验证**，
不能只验证「调用发出去了」。两轮丢失的共同点都是——我验证了页面
产生事件，却没验证事件真的落到服务端。

### 18.8 第三次失败：状态机悬挂 → 改为「复制优先」（已修）

修好副檔名后用户再次反馈「顯示未儲存」。原因是状态机**没有出口**：
`claude.use()` 或 `publish()` 返回的 promise 若永不落地，状态就永远停在
「未儲存…」/「儲存中…」，既不成功也不失败——用户无从判断该不该复制。

至此伺服器保存连续三轮失效（没调用 → 副檔名被拒 → promise 悬挂）。
结论：**不能再把平台保存当主路径**。改为：

- **复制优先**：顶栏常驻「複製 N 條記錄」按钮，有未导出记录时琥珀色
  高亮显示「（N 條未匯出）」。点击走 `navigator.clipboard`，失败则展开
  日志全选提示 Ctrl/Cmd+C。这条路径不依赖任何平台能力，永远有效；
- **一切 promise 加超时**（`withTimeout`，use 15s / publish 20s），
  超时归类为失败并显示错误码，绝不悬挂；
- 自动保存降级为加分项，失败只提示「記錄仍在本機，請點上方複製」。

Playwright 实测三条失效路径：publish 悬挂 → 20s 后红底
`publish_timeout`；use 悬挂 → 15s 后「此視圖無自動儲存」；无任何平台
能力 → 复制按钮正常写入剪贴板、pending 归零。

另修一个自伤 bug：`_JS` 是 Python 三引号字符串，其中 JS 字面量里的
`\n` 必须写成 `\\n`，否则 Python 先解释成真换行，插进 JS 字符串即
`Invalid or unexpected token`，整个脚本不执行（页面看起来正常但毫无
反应）。已加 `test_js_has_no_unterminated_string` 守门。

## 19. 字形數據庫（GlyphDB，M8 升級）

目標：把 OCR 結果與人工反饋**跨書累積**——下一本書直接借力，且支持
反復重訓。取代 M8 的 jsonl 字形庫（保留其「只進確認字形、兩級檢索」
的原則），升級為 SQLite 單檔 `glyph_store/glyphdb.sqlite`。

### 19.1 設計原則

1. **原始字形是唯一不可變真源**。歸一化圖、骨架、特徵都是派生物，
   帶 `algo_version`，算法改進後 bump 版本重生成——這就是「反復訓練」
   的基礎：任何時候都能從原始圖塊重新出發。
2. **字形層與語義層分離**（沿用全局約束）：`char` 存精確異體字形，
   `semantic` 只是檢索/語言模型用的正字註記；缺 Unicode 碼位的字形
   留 `ids`（表意文字描述序列）位置。
3. **字形隨版本變**：glyphs 表按 `edition_tag` 分域，同字不同版永不
   合併（武英殿的「爲」和別本的「爲」是兩個字形類）。
4. **簇號不入資產**。聚類是可重跑的過程，簇掛在 cluster_run 下；
   可累積的標註只掛實例 id（永久穩定）。
5. **事件溯源**。用戶反饋 append-only 入 events 表（batch,seq 冪等），
   當前標註狀態=重放，與 labels.jsonl 完全同構、可互導。

### 19.2 表結構（9 表）

| 表 | 鍵 | 內容 | 理由 |
|---|---|---|---|
| sources | source_id | 叢書、書名、冊次、edition_tag、**字體** script_style、刊刻年代、版式（列數/字數）、pipeline_version | 字體/叢書是冊級屬性，歸一化避免 3 萬行重複 |
| instances | instance_id (book:page:col:idx) | 位置（頁/列/字序）、bbox、**原始字形 PNG blob**、ink_ratio、quality_flags、label、label_status、label_confidence、semantic、unicode_cp、ids | 一字一行；label_status 區分 confirmed（用戶）/propagated（簇傳播）/auto（機器，不入訓練） |
| derived | (instance_id, kind, algo_version) | kind=norm/**skeleton**/feat_hog…，data blob | 派生物版本化；只為 exemplar 和已標註實例存，其餘按需重算 |
| events | (source_id, batch, seq) 唯一 | op/payload JSON/ts | 反饋事件鏡像，冪等入庫 |
| cluster_runs | run_id | source_id、params、stats | 聚類過程資產 |
| cluster_members | (run_id, instance_id) | cluster_id | 簇號限定在 run 作用域內 |
| glyphs | (edition_tag, char) 唯一 | semantic、unicode_cp、ids、status(sparse/stable)、n_confirmed | 跨書字形類 |
| exemplars | (glyph_id, instance_id) | role=medoid/diverse/boundary | 「不要太多不要太少」的落點（見 19.3） |
| pairs | (inst_a, inst_b, relation) 唯一 | relation=same/diff、origin=confirm_same/split/impure_flag | 跨書累積的閾值標定金集——18.3 的難負樣本自然歸宿 |

### 19.3 Exemplar 政策（同簇字不要太多也不要太少）

- **下限** K_MIN=3：不足時 glyph 標 `sparse`，kNN 命中降權
  （單例無法估計類內方差，閾值不可靠）；
- **上限** K_MAX=12（常用字）：全留 337 個「一」只會拖慢檢索並讓
  訓練集偏向高頻字；該 edition 內總數 ≤ K_MAX 的（罕見字/異體字）
  **全留**；
- **選法**：medoid 起步 → 特徵空間最遠點採樣（FPS，覆蓋墨色深淺、
  磨損程度的變體）→ 近重複剔除（verify f1>0.95 視為重複）；
- **邊界例優先**：曾被用戶改判/split/標 impure 的實例 role=boundary
  強制保留——它們是最有訓練價值的難例。

### 19.4 應用場景 → 查詢路徑

1. **新書冷啟動**：新書字塊 → exemplar 特徵 kNN 粗排 → verify_pair
   精驗。同 edition 命中＝精確字形直接定；異 edition 命中只作語義
   候選（字形須人工確認一次後入庫）。
2. **每書收尾**（update 擴展）：events/instances/exemplars/pairs 入庫。
3. **閾值標定**：pairs 表跨書累積 same/diff 分數分布 → per-edition θ。
4. **單字模型微調導出**：label_status∈{confirmed,propagated} 的實例
   按字頻均衡採樣（高頻截頂、罕見全留），輸出 (norm_patch, char)。
5. **異體字研究**：by semantic 列全部字形類；跨 edition 對比用字。
6. **variant_prefs / LM 語料**：從 instances 重建，不再單獨落盤。
7. **切分回溯**：quality_flags + flag 事件按 source 聚合 → Phase 3
   參數迭代清單。
8. **edition 識別**：新書前幾頁對各 edition 的 kNN 命中率即匹配信號。

### 19.5 存儲量估算

整書 3 萬字：原始 PNG blob ~30MB；derived 只存 exemplar+已標註
（~千級實例 × norm/skeleton/feat ≈ 10MB）；其餘表皆為文本行。
單書 <50MB，SQLite 舒適區。

### 19.6 持久化：Git 是真源，SQLite 是可重建索引

容器是臨時的，SQLite 檔案本身不能當長期存放處。體積分解說明了正確做法：

| 內容 | 大小 | 是否積累知識 | 存哪 |
|---|---|---|---|
| 未標註實例圖塊 29420 個 | 34.2 MB | 否（掃描件重跑即得） | 不存 |
| derived（norm/skeleton/feat） | 0.14 MB | 否（原始圖的純函數） | 不存，重算 |
| cluster_members 29438 行 | — | 否（過程資產） | 不存 |
| **已標註/代表實例圖塊** | 0.023 MB | **是**（跨書比對的參照圖） | **存** |
| **glyphs / exemplars / pairs / events / sources** | 0.006 MB | **是**（全部人工知識） | **存** |

於是真源改為倉庫內的 `glyph_store/`（文本 JSONL + 小 PNG），
`glyphdb.sqlite` 進 .gitignore、由 `glyph-db rebuild` 隨時生成。
book9all 全量：**53 MB → 143 KB**（375 倍）。

三條額外好處：① 審查結果進入版本控制，可 diff、可回滾、可在 PR 裡評審；
② 導出**字節確定性**（JSONL 排序 + 剔除自增 glyph_id），重複導出無假 diff；
③ 算法升級時派生表示自動按新版本重算，原始圖永不失真。

規模外推：每書約 3000 字形類 × ≤12 代表 × 1.5 KB ≈ 20 MB/書，且是
**只增不改**的小檔案，Git 歷史線性增長，十幾本書仍在舒適區。真到那時
再把 patches 轉 Git LFS 即可，文本部分不受影響。

順帶修一個潛伏 bug：`feat_*` 派生物此前寫死 `feat_hog`，但各書聚類
可能用不同特徵後端（raw 256 維 / hog 1764 維），混入同一庫後檢索時
維度對不上且**錯得無聲無息**。現在特徵後端由庫自持，入庫與檢索都由
庫內部按自持後端重算，`query()` 只收歸一化圖塊——調用方無從弄錯。

### 18.9 第二轮反馈（49 条）：剩余切分缺陷的三个根因（已修）

   对齐页 ~0.25，骑线页 >0.8）与全周期相位重扫 `sweep_row_phase`
   （Pass 2b，never-make-worse 门控）。**重要否定结论：相位相对版框
   全书并不一致**（对齐良好的 105 页间 σ≈0.45 格，版框检测基准漂移）
   ——书级中位相位不可传递，旧弱页校正曾把中位相位硬套到 p206/130/

2. **职名页拉开排版**（结构性，网格模型根本不适用）。实测官衔字距

### 18.10 第三轮反馈（65 条）：去线判空 + 重绑法定人数（已修）

第三批 not_text 几乎全是**不贯穿整格的界行竖线段**（逃过 rule_like 的

### 20.3 参考校对（collate）：位于自动识别与人工审查之间

现实三情境：
- **A 无参考**（冷启动）：模块退化为直通。辅助只有字形库 kNN（已是
  候选源）与**同版已确认册的文本作 LM 语料**（比自举语料干净）。
- **B 有参考、质量未知**：先估质量，再按质量加权使用。
- **C 有参考、质量高**（本次整理本）：强先验。

机制设计（B/C 统一，A 是 ρ̂=0 的特例）：

1. **对齐**：页内 n-gram 锚定 + 局部序列对齐（18.11 原型固化为模块），
   输出 slot↔ref_char 映射 + 逐页/逐段对齐置信度。
2. **参考质量估计 ρ̂**：用我们自己的高置信槽位作探针（top-p>0.95 且
   多源一致——其错误率已知很低），ρ̂ = 参考与探针的一致率，
   **分段估计**（参考可能局部差：某卷换底本、某段脱漏）。
   人造校验：向高质量参考注入可控替换噪声 x%，验证 ρ̂ 响应曲线。
3. **注入第 4 步**：参考字作为额外候选源 `ref`，融合权重 ∝ ρ̂ ×
   对齐置信；参考字不在候选中时补入（18.11「补主形」机制的推广）。
4. **注入第 5 步**：(a) 参考文本按 ρ̂ 加权并入 LM 语料；
   (b) 对齐槽位解码时给 ref char 加 log-先验偏置 ∝ ρ̂。
5. **分歧挖掘 → 审查**：我们高置信 ∧ 参考不同 → `ref_conflict` 队列
   进第 6 部分。要么我们错（难例金矿）要么参考错（可反哺整理本修订）
  ——人工裁决后是最高价值样本，且顺带持续修正 ρ̂。
6. **自动标注闸门**：对齐置信高 ∧ ρ̂ 高 ∧（top1==ref ∨ ref∈候选且 p
   不低）→ 产 `align` 级标签，喂数据集与字形库（exemplar 归 auto 层，
   human 层永远优先）。
7. **字形层纪律**：参考多为正字化文本，对齐与注入一律在**语义层**
   比较；落字形层标签时 surface 由「本版用字习惯 + 字形库 kNN」定，
   定不了标 surface_uncertain 交审查。参考文本无权改写字形层。

## 21. 格内净化：列级连通体归属（第 2 部分的核心算法）

### 21.1 问题

人工审查里最扎眼的一类问题：图块左右混进界行/版框，上下混进邻字的小块
残余。刻本格高是刚性的，但字有大有小、位置略偏，格线不可能同时贴合每个字。

直觉解法是「按纵向间隙丢弃孤立小块」。**先量了再说**：

```
污染块与主体的间隙   p10=2  p50=10  p90=16   (n=20，用户 contaminated 标注)
「高/卞/示」顶部部件 p10=4  p50=12  p90=30   (n=655)
```

分布**完全重叠**。任何间隙阈值都必然误伤——和早先形近字合并的教训一样，
这是判别维度选错了，不是参数没调好。

> 顺带一个采样教训：本想用 OCR 标为「高/卞/示」的实例当干净正例，实测其中
> **77.8% 自己就带着邻字残余**——邻字污染本就是普遍现象，正例集先脏了。
> 后续所有正例改按**结构**筛（连通体数 ≥2 且有纵向间隙），不看 OCR 标签。

### 21.2 算法：先定字身，再就近投靠

整列一次二值化 + 连通体分析，四步：

1. **剔线**。界行竖线按**分窗投影**剔除（窗高 2 倍格高，窗内某 x 列覆盖率
   ≥0.90）。不能整列一次投影——残余倾斜下界行在 2000px 列高上会横移几像素，
   投影一摊平就够不着阈值（实测整列投影只清掉 20% 的界行残留）。
   版框横线**不做横行投影**：「宀」「一」「書」顶横同样能占满列宽，实测按
   横行投影剔除会把「守」削成「寸」、「書」削掉顶横。改在连通体层面按
   「贴条带上下端 + 极扁 + 满宽」三条同时成立才丢。
2. **切粘连**。上一字的长竖拖到格线下面碰到下一字的顶点，两字连成一体，
   归属算法只能整块判给其中一格，另一格凭空少一个部首。在格线附近的
   **细杆**处下刀：取细颈里**离格线最近**的一行（不是最细的一行——竖尾是
   一根长而匀的细杆，没有局部谷底，按最细取会跑到杆子末端，切完上半块
   还是两个字）；且上半块必须够得上一个字（0.50~1.15 倍格高），否则说明
   刀下在「上一字残尾与本字之间」，切下去本字反倒少一个部首（实测把
   「草」的艹切给了上一格）。
3. **定字身**。每格取「与该格行区间重叠最多、且自身多半落在格内」的连通体
   作字身，**贪心最大重叠匹配**，一格一个、一块只当一次。逐格取最优会漏配：
   某块被隔壁以更大重叠抢走后本格再无第二选择，整格没了字身，零散部件只好
   去投靠隔壁，连锁错到底。
4. **就近投靠**。其余零散部件不看格线，按 `(装得下, 越格量, 间隙, 横向距离)`
   四级键选字身：
   - **装得下**：并入后总高 ≤1.15 倍格高——刻本单字装得进格；
   - **越格量**：并入后越出该格格线的量。这一条把「顶部部件该归谁」从模棱
     两可的距离比较变成确定判断：归本格则整字仍在格内，归上一格则整字要跨出
     格线一大截；
   - **间隙**：有交叠时取**负值**（交叠越多越近）。截到 0 的话，一个纵向同时
     压到两个字身的部件两边都算 0，只能靠横向距离瞎猜（实测「廁」的左右两竖
     就是这样被判给了下一格）。

最后逐格裁框时把 owner 不属于本格的墨迹**抹白**（连 2px 灰晕一起抹，抹除掩膜
再减去本格墨迹的膨胀，保证不啃到本字笔画）。

**间隙大小全程不作为判据**——这正是绕开 21.1 那个死结的关键。

### 21.3 数据集与评测

`open-guji-dataset/char-segmentation/cells/`，60 样本 / 480 格，逐像素金标。

样本**不造假墨**：从真实页面挑出「结构上确定干净」的格位（连通体全部落在
格线内、不碰列边），按书级格高重新码成一列，每格加 ±10% 格高抖动（真实刻本
里字有大有小、位置略偏，正是溢出邻格的成因），再画界行竖线、版框横线、纸纹

## 列宽问题：残余错切是根因（2026-08）

### 现象

`chars` 切出来的单字图块里，**约四分之一带着界行竖线**（vol01 23.7%、
vol02 20.0%，目视抽查 24 例全部属实：竖线在、本字完好）。这是下游
「混入」类缺陷的最大单一来源。

### 排查

按页统计 `rule_in_col`（界行落进列框内部的比例）与图块 `rule_bar` 命中率，
相关系数 0.78~0.83——问题**集中在少数页**，不是全体略偏：

| rule_in_col | 页数（vol01）| 该组 rule_bar 命中率 |
|---|---|---|
| < 0.02 | 108 | 5% |
| 0.1~0.3 | 29 | 24% |
| 0.3~0.6 | 19 | 60% |
| > 0.6 | 35 | 74% |

翻出最差的几页看原图，看见了真正的原因：**界行竖线不竖**。一页高
2500px，界行从上到下要横向漂 20~30px，而列周期才 180px。列框是竖直
矩形，跟不上斜线——要么把界行圈进去，要么让出漂移量把字裁窄。

### 这不是「没转够」的旋转，是真错切

同一页分别求「竖线最佳旋正角」与「横线最佳旋正角」，两者能差 0.95°
（页 55：竖 -0.70°、横 +0.25°）。deskew 已经把横线摆平了，竖线仍斜——
纸张/扫描造成的错切，旋转修不掉。

副作用是**界行本身检不出来**：形态学开运算要求一段足够长的竖直连续
像素，斜线过不了。页 55 原图界行最大覆盖率 0.19（等于没有），错切
校正后 1.000、26 个 x 列覆盖率 >0.6。所以「界行没检出」和「列相位拟
错」是同一个根因的两个表现——原先靠文字投影间接拟合相位，正是因为
直接证据被糊掉了。

### 解法：先摆正，再拿界行定相位

1. **`estimate_shear`**——以「界行证据强度」（竖直长线覆盖率里高覆盖
   部分之和）为目标函数直接搜错切量。不需要先把界行找出来：摆正时同
   一条界行的墨全落在一个 x 上，这个和自己就冲起来。
   - 择优：至少提升 1.05 倍才采纳，且要在**全尺寸**上复核（半尺寸赢
     不等于全尺寸赢）。实测 80 页证据合计 1.45×、变差 0 张。
   - 降采样必须**最大池化**而非面积平均：界行只有 2~3px 宽，面积平均
     把它拉成灰的、直接掉到二值阈值以下，等于把要找的证据先擦掉了。
2. **`snap_columns_to_rules`**——摆正之后界行看得见了，就拿它把列相位
   钉死（界行是版上刻出来的列分隔，是列边界的**直接证据**）。偏移取
   **环形**平均（列格是周期结构，偏移只在模 period 意义下有定义）。
   相位一动，原先在旧相位下逐格量的内缩就作废，必须重量一遍。
3. **坐标系约定**：`segment` 之后一切坐标都在**去错切帧**里，错切量
   写进 `grid.shear`；`chars` 读它做同样的变换再裁图块。顺带图块也就
   摆正了，对下游归一化与识别只有好处。

### 效果（vol01，24883 → 24872 个图块，字数基本不变）

| flag | 起点 | 仅去错切 | ＋界行吸附 |
|---|---|---|---|
| `rule_bar` | 23.7% | 8.9% | **3.5%** |
| `wide_gap` | 25.8% | 10.2% | **4.8%** |
| `boundary_ink` | 44.1% | 33.6% | 30.4% |
| 无 flag | 51.0% | 63.6% | **66.2%** |

vol02 同步：`rule_bar` 20.0% → 2.9%。

**没有把字裁窄**：列宽中位 128.4 → 119.8px（让出了界行），但把格位左右
各放宽 30px、扣掉界行成分后统计「落在列框外的字墨」，中位 0.0112 →
0.0109、超过 2% 的格 37.8% → 35.4%——不升反降。

### 一个只能到页级取证的判据

单条满宽扁横条，形状上分不清是**版框横线**还是**「一」字**：w/W、h/H、
笔画厚度变异都重叠。区别在列**之外**——版框横线横穿整版，「一」字停在
本列文字带里。所以 `_bar_crosses_column` 去列框左右各探 12px，两侧都还
在走才判版框。13 个人工核对样本全对。

## 页型闸门：非正文页不该套网格（2026-08）

### 现象

管线**完全没有页型判断**：profile 说每半页 9 列，就一律按 9 列切。

- `vol01/2`（书签页，整页只有一条书名）→ 切成 126 个块，`bad_seg` 94%；
- `vol01/158`（近空白页，只有一列「春秋類一」）→ 格高锁到 37.8px
  （真值 114），切出 0 个字。

全书 394 页里 7 页如此（1.8%），产出的是纯垃圾。

### 八种页型 → 三种网格策略

判别的落点不是文学分类，而是**网格该怎么用**：

| 策略 | 页型 | 理由 |
|---|---|---|
| `skip` | `cover` `label` `blank` `colophon` | 没有正文栏格，列拟合是无中生有 |
| `custom` | `edict` | 字大列宽，列数少于正文 |
| `standard` | `body` `roster` `toc` | 共用 9 列网格；三者的差别是**列内字距**，由 column-layout 那层判，不在这里重复 |

### 关键设计：两个方向的代价不对称

- 该跳过却切了 → 一页垃圾，可被 `bad_seg` 等**事后标记**；
- 该切却跳过了 → **整页真数据丢失**，下游连「这里有东西」都不知道。

由此定下三条：

1. 主指标是 `lost_rate`（误跳过正文页的比例），**零容忍**；不是八分类准确率
   （body 占 75%，全判 body 就有 75% 却毫无用处）。
2. 分类器判不准时**默认走网格**。
3. 阈值按「正文类页的**极值**」留一倍余量定，不是拟合出来的：正文类 373 页
   实测 `y_cover` 最小 0.275、`n_glyph` 最小 60，于是空白页判据取
   `y_cover < 0.15 且 n_glyph < 40`。

### 特征只用结构，不用文字

转写依赖切分，拿它判页型是循环论证；且非正文页的转写质量最差（封面页基本
是乱码），**最需要判别的地方恰好最不可信**。所以只用：界行条数、墨量、
字形连通体数与尺寸、墨的横纵向覆盖比例。

### 效果

页型闸门跳过 7 页（vol01 5、vol02 2）。`bad_seg` vol01 1.0% → 0.6%、
vol02 0.4% → 0.0%。网格策略准确率 99.5%，**误跳过正文页 0**。

### 立不出来的两条规则，要留痕

`colophon`（牌记）与 `edict`（上諭）**没有判据**——不是忘了，是证据不足：
全书各只有 1 例，且结构量与最稀疏的目录页重叠。

| 页 | 类别 | `x_cover` | `n_glyph` |
|---|---|---|---|
| vol01/205 | colophon | 0.496 | 90 |
| vol01/182 | toc | 0.616 | **90** |
| vol01/61 | toc | **0.265** | 60 |

硬立规则去抓 205 就会把 61 这样的稀疏目录页一起跳过——丢真数据比多切一页
废页严重得多。**样本不够就不立规则，把它写进 known_limitation。**

## 列梳子夹逼 + 窄页按实际列数切（2026-08）

### 先纠正一个错判

一开始把「18 页切出 7~8 列」定性成「边缘列被 `MIN_COL_WIDTH_RATIO` 误伤，
整列消失，危害最大」。**两处都错了。**

真实机制：`columns_info` 一直是 9 条，被丢的永远是**最后一条**，原因是
`x2 <= x1`——列框整个落在**图像右边界之外**。

而危害根本不在这里。量「落在最外侧列框之外的字墨」（丢整列才会出现在
那里）：

| | 外侧漏墨中位 |
|---|---|
| 非 9 列页（18 张）| **1.97%** |
| 9 列页（369 张）| **2.79%** |

**非 9 列页反而更好**——它们的第 9 个框落在图外，图外本来就没有像素。
漏得最多的（最高 14.1%）全是 9 列页。**列数是个很差的危害代理量。**

### 两个子原因

**D1 图被上游裁窄（13 页）**：图宽 1460~1530（正常 1696，差整整一个列距），
而且直接数文字带条数——窄页 **8 条**（跨度 7.5 个列距），正常页 **9 条**
（8.5~9.1 个列距）。少的那一列在图上就不存在。

也不是把字切断了：图像左右边缘 25px 内的字墨，窄页 0.06~3.0%、相邻正常页
0.05~3.7%，没有差别。是**整列被切掉**。

**D2 梳子起点偏移（4 页）**：图宽正常、够 9 列，但梳子起点偏右 1~5 个列距。
根因是相位由 `fit_page_grid` 按**文字带的 content_range** 锚定，而
`content_range` 会把长度不足的游程当噪声跳过——卷尾页左侧整片**空列**
（有界行、无字）正好是这种情况，梳子于是从版面中间起步（vol02/38 起点
落在 x=981，图宽 1714，末 5 列全出图；vol01/164 偏右 1.1 列，把最左边那列
真有字的列排除在外）。

### 修法

**D2：列梳子夹逼。** 列数与列距都是刚性先验 → 梳子跨度固定 → 起点的自由度
只有 `W - span` 这么多。夹进去即可，4 页全部修复。夹逼管「别跑出页面」
（误差可达几个列距），界行吸附管一个列距以内的精调，两者互补。

**D1：不硬凑，按装得下的列数切 + 标 `narrow_page`。** 硬凑 9 列会把 8 列
文字摊到 9 个框上、全部错位（实测居中摊开后外侧漏墨反而降到 0，因为"外侧"
已经没有像素了——指标看着好，对齐更糟）。真正该修的是上游裁切，`segment`
这边只如实反映 + 留痕。

### 效果

`page-geometry`：界行落入列框 5.19% → **5.00%**，全清页 30 → **31**；
`column-layout` 91.1% → **91.3%**；列数≠9 的 18 页现在全部带 `narrow_page`
标记，且列数与图上真实文字带条数一致。

### 一条方法论

**危害要直接量，不要用代理量。** 「列数不对」听起来就是丢数据，但真去量
字墨，结论正好反过来。这一轮如果不先做「外侧漏墨」这个指标，就会花力气去
修一个根本不是问题的问题。

## 书级内缩共识：剩余失败不是射影（2026-08）

### 又一次先入为主

`page-geometry` 上量到「列距渐变 vs 界行落框」相关 +0.59、3 张坏页全是射影页，
于是断定该上射影矫正。**结论是错的。**

真去看那 3 张坏页的参数：`inset_l` **只有 6px**，正常页 28~38px。列框贴着
界行走，界行当然被圈进去——和形变无关。

全书量一遍：

| | `rule_in_col` 均值 |
|---|---|
| 有一边 `inset` <15px 的 69 页 | **0.083** |
| 其余 318 页 | **0.006** |

差 14 倍，相关系数 −0.346。

那个 +0.59 是**共因**不是因果：目录页界行稀疏，既让内缩量不准，又让列距
渐变的估计噪声变大。

### 修法：内缩也是书级刚性常量

文字带在列格内的位置由版子决定，全书一致——和格高、列距同理。但内缩是
**逐页从投影量**出来的，稀疏页（目录/职名）的列格切片里内容范围量不准，
会塌到 0~6px。塌了就用书级中位值（Pass 2a3，择优门控）。

效果：`rule_in_col` **5.00% → 0.57%**，坏页 **3 → 0**，全清页 31 → 36/39，
目录页 16.13% → 0.72%。**没有动任何射影矫正。**

代价记账：外侧漏墨中位 3.52% → 4.07%，逐格字墨外溢中位 1.09% → 1.29%
（均值不变）——用「列框离界行更远」换来的。

### 一个自己造的回归，以及它暴露的结构问题

加完 Pass 2a3 之后格高坏掉的页从 3 张涨到 **17 张**。原因：Pass 2a 修好了
行格高，Pass 2a2/2a3 重跑 `segment_page` 时**没把它带上**，行网格被重新
自由拟合、又锁回谐波（页 168 整页格高 59px = 书级 113.7 的一半）。

这不是一个笔误，是**结构问题**：这些 pass 只该改**列**参数，却在重跑整个
`segment_page`，顺带把行参数也重算了。修法是把当前行格高原样传回去
（`cell_h_prior=row_prior.get(stem) or 当前值`）。修完之后格高坏页 **0 张**
——比引入 Pass 2a3 之前的基线（3 张）还好。

**教训：多 pass 择优结构里，每个 pass 都必须显式声明它不动哪些参数，
否则"重跑一遍"会静默撤销前一个 pass 的成果。**

### 顺带：数据集终于有了第一个截断实例

`168:2:6` 由 contaminated 转 **truncated**——界行是不混了，但那一格只切到
「學」的下半。此前连续四轮样本里都没有截断实例，这条能力一直无从验证。
它**一个 flag 都没触发**，缺陷检出率因此 100% → 89%。这正是它的价值：
暴露了管线没有截断判据。

## 截断判据 off_center（2026-08）

### 先补样本，再定判据

`char-segmentation/instances` 前四轮**一个截断实例都没有**，"管线能不能发现
截断"这条一直无从验证。第五轮偶然出现一个，它一个 flag 都没触发——缺口是
明确的，但 1 个样本上定阈值必然过拟合。

所以先补样。抽样线索用「**本字自己的**连通体越出格外的比例」：在放宽的裁剪
里做连通体，只保留主体（≥65% 面积）落在本格内的，邻字不计。

第一版没加"主体在本格内"这个条件（只要 35% 探进来就算），捞上来的全是
**空格位蹭到邻字**——那是 `contaminated` 不是 `truncated`。加上条件之后
分布变得干净：全书 5826 个有实质墨的格里中位 0.009、99 分位 0.291，
候选在 0.32~0.35。目视确认后补进 5 个（含 2 个 vol02，数据集自此收两册）。

### 判据：重心偏移，不是边缘墨量

6 个截断实例分成两个子型：

| 子型 | 特征 | 现有判据 |
|---|---|---|
| 纵向截断（3 个）| `band_ink` 0.055~0.217 | `boundary_ink` 已覆盖 |
| 横向截断（3 个）| **重心偏移 0.148~0.339** | 无 |

`boundary_ink` 只看上下带。横向被切时字整个被推到格位一侧，**边缘墨量未必
高、但重心明显偏**。标注集里 clean 的重心偏移最大 0.088，横向截断的三个是
0.148~0.339，**没有重叠**。

阈值取 0.15。全书命中 3.1%(vol01)/1.4%(vol02)；随机抽 18 个目视，**15 个
属实**，另 2 个是空格位（由别的 flag 覆盖）。

效果：截断检出 **4/6 → 6/6**，缺陷总检出 86% → **100%**，而**误报率不变**
（仍 17%）——新判据没有贡献任何误报。

### 顺带发现一个系统性切分错误

命中里有一大批是**职名列的「臣」字坐在格位右缘、一半在框外**。这不是随机
噪声，是同一种结构性失败。判据能把它标出来，但**根因是切分**——职名页的
双行/偏格排布没有被正确建模。已记进 known_limitation，待查。

### 一条方法论

**没有样本的能力不要先写判据。** 这一轮的顺序是：确认缺口 → 设计一个与
判据不同的抽样线索 → 补样 → 看样本的结构 → 才定判据。如果反过来（先按
直觉写个判据再找样本验证），大概率会写成 `boundary_ink` 的横向翻版
（左右边缘墨量），而那个量在这 3 个实例上并不显著。

## 图块横向裁切边：按界行走，不按文字带走（2026-08）

### 问题：「臣」被静默切掉

上一节末尾记下的那个系统性错误——职名列的「臣」坐在格位右缘、一半在框外——
量出来是这样（403 个实例）：

| 量 | 「臣」 | 正常字 |
|---|---|---|
| 字高 / 格高 | 0.77~0.84 | ~1.0 |
| 字宽 / 列宽 | 0.39~0.47 | 0.73~1.00 |
| 横向中心 / 列格 | 0.77~0.81 | 0.44~0.55 |

它是**小字，贴着界行写**，右缘越出「文字带」中位 15px（最多 31px）。而图块
一直是按文字带裁的——文字带是「正常居中字」的范围，是网格拟合用的量，
不是字的实际占地。于是「臣」的右半边被切掉。

全书量下来这不是「臣」一个字的事：vol01 24605 个字格里 **44.8% 的字被切到
了笔画**（vol02 46.4%）。而且这种损失是**静默**的——切下来的图块自己看不出
缺了一块，`rule_bar`/`boundary_ink` 一个都不报。按项目的非对称代价原则，
静默丢数据比产出可标记的垃圾严重得多。

### 死路一：固定余量

第一版实现是「列格边界内缩一个固定余量 `CELL_EDGE_CLEARANCE`」。跑完全书
直接崩：`rule_bar` 0.2% → **17.5%**，`wide_gap` 1.2% → 21.5%。

回头量了两个分布才明白它为什么不可能work：

| 量 | 中位 | 75 分位 | 90 分位 | 95 分位 |
|---|---|---|---|---|
| 界行内缘伸进列格 | 4.9px | 8.2 | 13.9 | 19.6 |
| 「臣」外缘距列格边界 | 10.0px | — | (10 分位 0px) | — |

**两个分布重叠**，任何固定阈值都只能在两害之间选一个：

```
余量  6px → 38.6% 裹进界行 / 30.0% 切到「臣」
余量  9px → 21.2% 裹进界行 / 43.7% 切到「臣」
余量 15px →  8.7% 裹进界行 / 68.1% 切到「臣」
余量 22px →  3.6% 裹进界行 / 80.5% 切到「臣」
```

我原本的设计前提是「臣从不碰到界行」。量完才知道那对**中位**成立、对**尾部**
不成立——而裁切规则是被尾部决定的。

### 死路二：贴着检出的界行裁

第二版改成「找到这一侧的界行，贴着它的内缘裁」。`rule_bar` 降到 1.1%，
但仍是基线的 5 倍，而且新增的 rule_bar **全部落在最外两列**。

原因：最外两列挨着的不是界行，是**版框**。vol01/33 右侧实测是一条 40px 宽、
覆盖率在 0.0~0.4 之间忽高忽低的乱带（双边框 + 磨损 + 页边脏），`rule_segments`
只认得出最外面 12px 的实心核心。贴着核心裁，等于把内侧那一大片乱带全圈进来。

### 正解：拿竖线覆盖率当围栏，一格一格往外走

不去「找线」，而是**从文字带边缘往外走，撞到竖线结构就停**，再退 4px：

- 文字笔画过不了竖直开运算（带内实测覆盖率 ≈0），界行和版框是 0.2~1.0，
  两者在这个量上**不重叠**——所以覆盖率本身就是围栏。
- 走到列格边界还没撞到东西，就**一步不扩**（退回旧的文字带裁法）：没有
  分隔物时再扩就是往邻列的墨里扩。
- 全程取 min/max，保证只放宽、不收紧。

### 关键细节：覆盖率必须分带统计

第一次跑这个方案时 `rule_bar` 还有 2.2%。查下去是因为围栏用的是**整页**
覆盖率（`_vline_cov`，要求一条竖直连续段跨 0.3 页高）。界行只要斜或弯几个
像素，同一条线的墨就被摊到二三十个 x 上，每个 x 都过不了阈值——整页统计看
到的是一片 0，围栏形同虚设，裁切边直接穿过界行。

而 `rule_bar` 是在**图块**上判的（细长、近乎满高的独立连通体）：一条斜界行
在单个字格的高度里仍然是笔直的一条，照样触发。**围栏的观测尺度必须和缺陷
的发生尺度对齐。**

改成把页面切 6 条带、带内各自做竖直开运算、逐 x 取各带最大
（`_vline_cov_banded`）之后，斜线在每条带里都是直的，覆盖率照样接近 1，
取 max 得到的正是这条线**最往里探**的位置。

### 效果（vol01 全书 24605 字格，端到端跑完 segment + chars）

| | 旧（按文字带裁） | 新（按界行外扩） |
|---|---|---|
| 被切掉笔画的字格 | 44.8% | **9.2%** |
| 「臣」形字格被切 | 79.7% | **35.1%** |
| `rule_bar` | 47 块（0.2%） | 53 块（0.2%） |
| 无标记图块 | 67.7% | 67.0% |

vol02 同向：被切 46.4% → 14.7%，`rule_bar` 95 → 118 块（0.3% → 0.4%）。

`instances` 金标上，66 个图块全部变宽、ID 一个没丢，只有 2 个标签要改——
就是那两个专为「横向截断」补进来的「臣」，由 `truncated` 转 `clean`。缺陷
检出仍 100%，确定层仍**零误报**（外扩没把界行裹进来）。

### 残余与代价

- 仍有 35% 的「臣」形字格被切，**全部落在根本没有界行的页上**（序、目录）。
  那里没有围栏可依，按设计就不扩。要救得另找证据，不能靠放宽阈值。
- 误报率 17% → 20%：那两个「臣」变成正例之后仍被 `off_center` 标记。「臣」
  的墨天然偏在格位右侧，裁全了重心照样偏——这是 `off_center` 的固有代价。
- **横向截断这一类现在没有金标样本了**（原有的 2 个被修好了）。`off_center`
  的阈值实质是在已经消失的案例上定的，需要另行补样。

### 两条方法论

**危害要直接量。** 这一轮从头到尾是被「切掉了多少本字的笔画」这个直接量
牵着走的；三个死路都是先跑全书、看这个量和 `rule_bar` 一起怎么动才淘汰的。
如果只盯 `rule_bar`，旧的裁法看起来完美（0.2%），而它正在静默地切掉 44.8%
的字。

**分布重叠了就别再调阈值。** 量出「界行内缘」和「臣外缘」重叠的那一刻，
固定余量这条路就已经死了，继续扫参只是在两种错误之间搬运。出路是换一个
两个分布**不重叠**的量（这里是竖线覆盖率），不是把同一个量的阈值挪来挪去。

## 弹性列：闸门不该重判列型（2026-08）

### 症状

`column-layout` 金标上 elastic 召回只有 0.81，漏判的 20 列**全部**在职名页。
逐列看下去，漏判的列长这样（vol01/121 第 1 列）：字距 1.95 格、13 个字，
被刚性格线切成 **19 块**——4 块是空的，3 块是半个字。

### 根因：两处判断打架

流程是「先判列型，再按列型切分」：

```
layout = classify_column_layout(...)        # ← 判对了：elastic
if layout == "elastic":
    cells = cells_from_components(...)      # ← 返回 None
if cells is None:
    if layout == "elastic":
        col_result["layout"] = "rigid"      # ← 据实回落，标签也改回 rigid
```

`classify_column_layout` 判得没错（run_med = 1.00 → 拉开型）。问题在
`cells_from_components` 里还留着一套**旧的触发条件**——组件数 ≤12、
至少 2 个中心间距 > 2.2 格。那是当初在 3.5 格拉开的职名列上定的，而这批
官衔列是 **2 格**拉开、13 个组件，两条都不满足，于是被一票否决。

否决之后列型标签被改回 rigid，**金标比对看到的是 rigid**——所以这个 bug
在指标上表现为「分类器召回不够」，查分类器却查不出毛病。

**一条判断只该有一个地方做。** 下游模块可以说「我做不到」，但不能拿一套
自己的阈值去推翻上游的判断——尤其是推翻之后还改写上游的输出标签。

### 改法

`cells_from_components` 的闸门只保留**输出可用性**三条：组件数落在
[3, 30]、单组件不超过 8 格高（更高的是粘连或线条）、切出的格数不超过
3×n_chars。删掉「至少 2 个间距 > 2.2 格」这条列型判据。

### 效果（column-layout 金标，36 页 289 列）

| | v1 | v2 |
|---|---|---|
| 列型准确率 | 91.3% | **93.8%** |
| elastic P / R / F1 | 0.94 / 0.81 / 0.87 | **0.95 / 0.88 / 0.91** |
| roster 页准确率 | 80.8% | **87.5%** |

vol01/121 第 1 列从 19 块（4 空 + 3 半个字）变成 14 块，13 个完整字。
全书 chars 24605 → 24513，`suspect_empty` 220 → 158，无标记图块
67.0% → 67.6%。vol02 一个字都没动（该书没有这种列）。

### 剩下的一类：压缩型（一格两字）

仍有 13 列漏判，集中在 vol01/90（8 列）与 vol01/93（4 列）。这类列的官衔字
比格**小**（字距 0.65~0.79 格），姓名字比格**大**（2.6~3.1 格），一列里两种
字号。占位形态上它是**满格**的，跟密排正文一模一样。

试过四组特征，在 289 列金标上都与刚性列大量重叠：

| 特征 | rigid p95 | elastic p5 / p25 |
|---|---|---|
| 字距中位 / 格高 | 1.61 | 1.03 / 1.74 |
| 字距非整数比例 | 0.67 | 0.09 / 0.38 |
| 格线处墨量 / 列均墨量 | 0.77 | 0.02 / 0.17 |
| 亚格字距比例（<0.85 格）| 0.31 | 0.00 / 0.00 |

最后一个尤其说明问题：p90 那些列里**量不出**亚格字距，因为挨得近的官衔字
在投影上连成了一段，压根没有"两个字之间的距离"可测。

方向：这类列真正缺的是**逐列格高**，而不是又一个判别特征——书级格高对它
本来就不成立。那是更大的改动，单独立项。

### 方法论

**指标指向的地方不一定是出问题的地方。** 这一轮指标说「分类器召回不够」，
分类器却完全正确；真正的 bug 在下游模块**改写了上游的输出标签**。凡是
下游能改写上游标签的地方，都要怀疑一次。

## 书级格高：改由「实测字距」定 + 格线逐条吸附到空隙（2026-08）

### 症状

正文页上 vol02 有 **21.1%** 的图块被 bbox 切掉了本字的笔画（vol01 8.9%）。
同一套算法两册差 2.4 倍，说明有书级的系统性因素没被建模。

按格序号拆开看，两头明显更糟：

```
vol02 纵向被切比例 vs 格序号
  0:18% 1:14% 2:8% ... 10:12% ... 18:12% 19:19% 20:27%
vol01
  0:13% 1: 3% 2:3% ...  10:5% ... 18: 4% 19: 4% 20:17%
```

**误差在列的两端累积**——这是格高不对的指纹。

### 根因：格高被系统性低估

投影拟合的格高基准是 `(文字带高) / n_chars`，而文字带由 `content_range`
划定，它会把首末字探出去的那点笔画当短游程剔掉。于是格高偏低：

| | 拟合格高 | 实测字距 | 偏差 |
|---|---|---|---|
| vol01 | 113.7 | 115.0 | −1.1% |
| vol02 | 109.7 | 111.4 | −1.5% |

21 格累积下来漂 0.23 / 0.32 格，正好对上实测的**末格字下出头 0.19 格
（p90 0.39）**。

刻本一格一字，所以**字距就是格高**——这是可以直接量的物理常量，不必
从文字带间接推。

### 弯路：估计量对先验敏感，把格高推过了头

第一版用「给每个墨段中心配一个整数格号，再对格号做最小二乘」。它在
先验准的时候没问题，先验偏 3% 时列末的格号会配错一位，斜率被带偏——
实测把 vol02 从真值 110.6 推到 **112.6（+1.8%）**，末格反而开始吃版框
（`frame_bars` 405 → 489）。

**量物理常量的估计量必须对先验不敏感。** 改成**环形集中度**：候选字距 p
下把每个中心折算成相位 2π·y/p，中心都落在格线上时这些相位聚成一束
（|均值|→1），p 不对就散开；在 ±10% 的窗口里取集中度最高的 p。先验故意
给 ±6%，估出来只差 0.1%。

### 还不够：格高对了，单条格线仍会切在笔画上

等距格线只保证「格距对」，不保证每一条线都落在空隙里——刻工排字有微偏、
字身大小不一，一条线偏个七八像素就从笔画上切过去。而 vol02 的字几乎填满
格子（单字墨高/格高中位 0.945，vol01 是 0.897），字间空隙只有 **6px**，
容错极小。

所以格高定死之后再逐条吸附（`snap_bounds_to_gaps`）：每条格线在
±0.10 格内滑到局部墨谷。三条约束：

- **滑动半径只有 0.10 格。** 再大就会滑到邻格的空隙上，等于把一个字整个
  让给隔壁——那比切一刀更糟。
- **没有谷就不滑。** 上下两字真连在一起时（谷底墨量仍高于相邻两格平均的
  35%）保持刚性位置：宁可在原处切一刀。这类「必须带墨的分隔线」交给下游
  `_split_touching` 在颈部处理。
- **平局偏向原位。** 整段空白时谷底到处都是 0，取离刚性位置最近的那个。

首末两条线同样吸附——版框与首/末字之间也有一道小空隙。

这条改动打破了旧的「所有格高度完全相等」不变量。新的契约是：
**格距刚性，切哪一刀允许在空隙里挑位置**，离散度被吸附半径框住。

### 效果（端到端跑完 segment + chars）

| | vol01 改前 → 改后 | vol02 改前 → 改后 |
|---|---|---|
| 无标记图块 | 67.6% → **78.9%** | 44.5% → **68.2%** |
| `boundary_ink` | 27.4% → **16.0%** | 52.3% → **28.6%** |
| 笔画被 bbox 切掉 | 8.9% → **8.3%** | 21.1% → **17.9%** |
| `suspect_empty` | 158 → 176 | 328 → **176** |
| `rule_bar` | 53 → 49 | 118 → **102** |
| `frame_bars` | 524 → 568 | 405 → 471 |

几何与页型基准不动（界行落入列框 0.57%、全清页 36/39；页型策略 99.5%、
误跳过正文页 0）。列型准确率 93.8% → 92.7%（body 页多了 3 列误判弹性）。

`instances` 金标这一轮漂得最狠：**格高一变，格序号对应的字就换了人**
（10:2:6 从「列」变成「冬」），65 个图块里 49 个内容变化、3 个 ID 消失。
重标后缺陷 12 → 7，检出仍 100%，误报率 19% → **11%**。

### 剩下的

被切的图块里横向已占多数（vol02 左 30% + 右 26%），集中在序、目录那些
**没有界行**的页上——裁切边靠界行当围栏，那里没有围栏。纵向的残余
（上 13% + 下 17%）还没定位到单一成因。

### 方法论

**误差在两端累积 = 尺度错了，不是位置错了。** 按格序号把错误率画出来，
中间平、两头翘，指向的一定是格高/周期这类**尺度**参数；如果是相位错，
错误率会整体偏而不是两头翘。

**量物理常量的估计量必须对先验不敏感。** 这是判断一个估计量能不能用来
「纠正先验」的硬标准——它自己依赖先验，就只会把先验的偏差放大。验法很
简单：把先验故意拨偏 ±5%，看估计值跟不跟着跑。

## 界行检不出来时，整套机制会静默失效（2026-08）

### 症状

vol02 正文里 5.4% 的图块缺掉**整个偏旁**——「但」被裁成「且」、「說」丢了
言字旁。集中在 151/154/119/149/153 这几页。

### 查错的第一步：先修度量

最初的度量是「在 bbox 外扩一圈做连通体，主体在框内、却有墨落在框外 → 被切」。
按它算 vol02 有 3072 块横向被切（10%），逐个看下去**多数字其实是完整的**：
被算成损失的那些像素属于跟字粘在一起的**界行**或**上下邻字**，管线把它们
切开是对的。

改成用管线**自己的归属算法**比对：同一列分别按「现在的裁切边」和「整个列格」
跑一遍 `_assign_column`，看本格拿到的墨量差多少。这样界行剥除、粘连切分都
按管线自己的规则处理，剩下的差额才是真损失。按缺失比例分档：

| 缺失比例 | 块数 | 是什么 |
|---|---|---|
| 3~10% | 1640 | 界行碎片，不是损失 |
| 10~15% | 362 | 少半笔 |
| **>15%** | **515** | **整个偏旁级——真损失** |

**度量本身错了，后面所有结论都是错的。** 这一轮先花时间把度量修对，才看清
真正的问题只有 515 块而不是 3072 块，且集中在少数几页。

### 根因链条

那几页的共同点：**界行几乎检不出来**（p151 整页只检出 1 条、p119 是 0 条，
正常页 p179 有 9 条）。界行一没了，一整套机制同时失效：

```
界行检不出
  ├─ snap_columns_to_rules 不触发（要 ≥3 条）→ 列相位失去直接证据
  ├─ _period_from_rules 不触发             → 列距拟歪 2~3%，9 列累积漂 40px
  ├─ cell_bounds_from_rules 的围栏没有墙    → 裁切边一步不扩，退回文字带
  └─ rule_in_col 恒为 0                    → 所有以它为判据的择优门控一律放行
```

最后一条最要命：**页面悄悄退化成纯投影拟合，而质量指标显示一切正常。**

### 界行其实都在——是弯的，不是斜的

p151 每一条带的竖线覆盖率都到 1.00，只是整页统计看不见。在 ±0.02 的全部
候选角度上试过错切校正，界行证据最多只提升 **1.02×**——任何整体线性变换都
摆不正它，因为它是**弯**的。

### 改法一：检测改用分带覆盖率

`rule_segments` 从整页覆盖率改成 `_vline_cov_banded`。实测：

| 页 | 整页检出 | 分带检出 |
|---|---|---|
| vol02/151 | 1 | **9** |
| vol02/119 | 0 | **7** |
| vol02/153 | 1 | **5** |
| vol02/154 | 1 | **15** |

代价是漂移的线给出偏宽的 x 区间（各带取并集）：p151 一条界行跨 6~7px、
正常页 2~3px，相对 33px 的内缩仍然够用。

### 改法二：阈值挂在列距上，不挂在页高上

分带的「连续段至少多长」原先按**带高**（=页高/6）的比例取。折算成「几个
字高」时这个阈值会随页面尺寸浮动：

- 真页 2483px 高 → 1.66 个字高，安全；
- 合成测试页 420px 高 → **0.53 个字高，文字块自己就被当成界行**。

两个列几何测试因此挂掉，正好暴露了这个隐患。改成 `1.2 × 列距`——列距是
版面自身的尺度，字的竖笔最长约 1 个字高（≈0.6 列距），留了一倍余量。

### 改法三：内缩共识两侧都要管

原先只救「塌掉」的一侧（`inset < 0.5 × 共识`）。**涨上去的一侧危害相反且
更隐蔽**：文字带被人为收窄、字的偏旁被裁掉，而 `rule_in_col` 一路是 0，
以「界行有没有进框」为判据的门控完全发现不了。

实测 vol02 有 14 页 `inset_l` 超共识 25%（最极端 63px vs 共识 33px），
vol01 有 9 页。加 `INSET_TOL_HI = 1.25` 的上侧钳制。

### 实测结果（两册全跑）

| | vol01 | vol02 |
|---|---|---|
| 无标记图块 | 78.9% → **79.2%** | 68.2% → 68.0% |
| `off_center` | 3.2% → **2.7%** | 1.6% → **1.1%** |
| `bad_seg` | 0.8% → **0.5%** | 4 块 → 2 块 |
| `wide_gap` | 1.6% → 2.1% | 2.3% → 3.2% |
| **偏旁级截断** | — | **515 → 296 块（−43%）** |

基准：`page-geometry` 列数 35/39 不变、坏页 0；`page-type` 不变（误跳过正文
0 页）；`column-layout` 93.8% → 92.7%（elastic 精确率 0.95 → 0.92）；
`instances` 缺陷检出仍 100%、误报 19% → 9%。

代价是 `wide_gap` 升了 0.9pp（图块变宽，空隙判据本来就更容易触发），换来
偏旁级截断少掉 43%——按「静默丢数据 ≫ 可标记的垃圾」的原则，这笔划算。

### 中途踩的坑：我把自己的修复抵消掉了

改动分两步：(1) 检测改分带，p151 检出 1→9 条；(2) 把长线阈值从挂页高改成
挂列距，以修合成页上文字块被误判的隐患。**第 (2) 步顺手把「带高至少 3 倍
min_run」也定死了**，真页因此从 6 带掉到 3 带——带一变高，弯的界行在带内
又断了：p151 从 9 条掉回 2 条、p119 从 7 条掉回 0 条。第 (1) 步的收益被第
(2) 步全部抵消，而**两步的测试都是绿的**。

扫参后取 1.7：

| 带高系数 | p151 | p119 | p154 | 合成页误判 |
|---|---|---|---|---|
| 1.5 | 4 | 6 | 11 | 无 |
| **1.7** | **7** | **5** | **10** | 无 |
| 2.0 | 2 | 3 | 15 | 无 |
| 3.0 | 2 | **0** | 7 | 无 |

### 顺带挖出一个潜伏的结构性 bug

vol02/38 一页 88 个图块全部 `bad_seg`。追下去：自由拟合列距 70.2px（书级
184.4），Pass 2a2「列距共识」修成 187.3，**Pass 2a3「内缩共识」重跑
`segment_page` 时没带列距先验**，列距被自由拟合又掉回 70.2；而它的择优判据
`rule_in_col` 在这种退化几何下恒为 0（列框窄得界行根本落不进去），门控一律
放行。

这和早就记过的格高教训逐字相同（「后续各 pass 必须把修好的行格高带上」），
当时只给格高做了，列距和内缩漏了。是内缩双侧钳制把页 38 拉进 Pass 2a3 的
名单，才让它现形——在此之前一直潜伏。

### 四条方法论

**「检测」和「校正的目标函数」不能用同一个量。** 原先 `rule_segments`（检测
界行）和 `rule_evidence`（错切校正的目标函数）都用整页覆盖率。这在逻辑上
自相矛盾：目标函数**必须**对倾斜敏感（不敏感就找不到最佳角度），检测**必须**
对倾斜不敏感（不然线一歪就检不到）。同一个量不可能既敏感又不敏感——于是
凡是错切救不了的页，检测也一起瞎掉，而且是静默瞎掉。

**别把阈值挂在与被测对象无关的尺度上。** 「竖直长线至少多长」本该按版面
自身的尺度（列距/字高）定，挂在页高上时在真页上碰巧安全、换个尺寸就悄悄
失效。合成测试用真实量级能发现这类问题——前提是别把测试也一起改小。

**一个改动同时动了两个耦合参数时，必须分别验证。** 上面那次抵消里，我只
验证了「合成页不再误判」这一半，没回头确认「真页的检出还在不在」——默认
第二步只是个尺度换算。实际上带高与检出能力强耦合：带越高越容易把弯线切断。

**门控判据必须在「被门控的失败形态」下仍然有意义。** `rule_in_col` 度量列
相位，但几何退化时它恒为 0——列距缩到 70px，列框窄得界行根本进不去，于是
「最干净的页」和「彻底崩掉的页」得分相同。用它当门控，等于对最严重的那类
失败完全免检。这类判据都要额外加一条**物理合理性检查**（列距不可能是书级
的 38%），不能只靠比大小。

## rule_in_col 从「门控」升级为「触发条件」（2026-08）

### 缺口

修完界行检测后仍有 12 页报 `rule_in_col > 5%`。典型是 vol01/94：列距拟到
177.6，离共识 184.7 只差 3.8%——在 `PERIOD_TOL`（4%）以内，参数触发抓不到；
而界行实测间距 186.5、`rule_in_col` 0.18，页面**自己已经报了警**，却没有
任何 pass 把这个直接质量信号当触发条件，它只被用作择优门控。

### 两类报警要分开

逐页渲染后发现 12 页分两类：

- **列距真错的**（vol01/94）：偏移 mod period 沿列号线性走满整个周期——
  周期错的经典签名。给共识先验重扫即修（0.184 → 0.000）。
- **网格本来就对的**（vol02/163、vol01/26）：报警来自**穿过文字列的折痕**
  或粗界行的边缘探进文字带。p163 那条「界行」实为一道纵贯折痕，正好从
  「曰通釋曰書釋…」一列的中间穿过。这类 refit 不会更好，never-make-worse
  门控自然拒掉，页面原样保留——正是想要的行为。

所以改动只有一行：Pass 2a2 的触发条件加上 `rule_in_col > RULE_IN_COL_T`。
能救的救，救不了的门控挡住，无需人工分类。

### 顺带加固 _period_from_rules：近邻中心合并

p94 还暴露了第二个问题：它的界行测量**本来就做过、但被自己弃掉了**。
磨损的左版框给同一条物理线出了四个中心（9/25/38/47），全被指到 k=0，把
最小二乘的斜率拉出 6% 容差 → 整个测量弃用 → 保留的先验恰恰是错的 177.6。

修法：量列距前先把 0.3×先验以内的中心并成一个。合并后无论先验给 177.6
还是 184.7，都量出 187.3——**量物理常量的估计量对先验不敏感**，这条原则
（字距测量那一节立的）在这里再次适用。

## edge_blob 的零误报失守与修复（2026-08）

### 症状

格线吸附收紧图块后，vol01/10:2:6 一个干净的「冬」被 `edge_blob` 标记——
确定层第一次出现误报。确定层的全部价值就是「零误报、可自动处理」，
这一条一破，下游就不能再免检地用它。

### 根因与判据

「冬」的下两点是**本字的分离部件**，图块收紧后整体落进底部 18% 带内。
原判据只看「连通体整体在带内」，不看它离主体多远。量了金标（含从 git
历史捞回的真残余图块）：

| | 与主体的纵向间隙 / 图块高 |
|---|---|
| 真邻字残余（87:1:18 历史图块）| **+0.206**（隔着整条字间空白）|
| 「冬」的下两点 | +0.015（贴着主体）|
| 其余 clean 的带内部件 | 全为负值（与主体纵向重叠）|

两类在这个量上分得很开。加条件：带内块与主体的间隙 > `EDGE_BLOB_GAP`
(0.10×图块高) 才算残余。修后「冬」不再报，真残余仍报 0.199。

**样本局限**（如实记录）：真残余只有 1 个可量的历史样本，0.10 的阈值
实质是在 0.015 与 0.206 之间取的中点偏下。上游修得越好，这类样本越少
——判据的验证反而越难，这是整个 instances 数据集的共同处境。

## boundary_ink 改造：三个候选特征全部失败（负结果记录，2026-08）

### 背景

第十二轮补样量出 `boundary_ink` 单独命中的精确率只有 ~25%：vol02 有 7391
块仅由它压进审查队列，其中约四分之三是**完整干净的高字**（vol02 字高/格高
中位 0.945，墨天然顶到 10% 边缘带）。但金标里 15 个缺陷有 **8 个只靠它
兜着**——不能简单提阈值，只能找一个能把「高字」和「缺陷」分开的量。

试了三个，全部在 91 样本金标上失败：

| 候选 | 思路 | 死因 |
|---|---|---|
| 边缘行切口宽 | 截断的切口宽平、笔画尖端收窄 | 5 个缺陷在边缘行完全没墨（污染在带内但不贴边）；带底横的 clean（「是」的长捺、底部横画）反而高到 0.65 |
| 带内外来墨 | 带内不属最大连通体的墨 | 「吃进下一字」的污染与本字**粘成一体**，没有独立连通体（6 个缺陷 <0.02）；clean 的分离部件（「冬」两点）反而得高分 |
| 格外墨 | 图块里越出本格网格线的墨 | 字的笔画本来就探出格外（clean p90=0.147、最大 0.263），与污染（p50=0.137）大面积重叠 |

### 结论与决定

**`boundary_ink` 保持原样。** 按非对称代价原则：它的误报是审查队列的人工
成本，它的漏报是静默缺陷——8/15 的缺陷只有它兜着，动它的下行风险远大于
上行收益。

三次失败指向同一个原因：**在单个图块的局部统计里，「高字」与「缺陷」就是
同分布的**。真正分得开的信息在图块之外——「鍾下面粘着讲头」和「一个高高的
藏」的区别，要么在列级上下文里（邻格的墨承接关系），要么在识别层
（知道这个字形应该长什么样）。后者属于 G5（识别组）的地界：下游拿到 OCR
置信度后按置信度排审查队列，比在这里再造第四个特征更对路。

### 剩余尾巴的形态（一并记录）

偏旁级截断稳定在 294 块（vol02 正文），榜首 p151（50 块）的界行是
**重度弯折**：一条界行在 6 条带里横向漂 50px，被 RULE_MERGE_GAP=4px
打成 6 段碎片，围栏在多数边界没有墙。这类页需要「顺着弯线走」的检测
（逐带跟踪同一条线的漂移轨迹），与现有「x 区间」表示是不同的抽象，单独立项。

### 方法论

**负结果也要花力气记下来。** 三个特征每个都「听起来该行」，不记下来，
下一个人还会按同样的直觉再走一遍。记录的格式：思路一句话 + 死因一句话 +
关键数字，让后来人五分钟内确认「这条路真的走过了」。

## 正文/职名判别：切分后细化 + 顺手抓出 17 页金标错误（2026-08）

### 设计：判别放在切分**后**

`classify_page_type` 在切分前跑，只看得到灰度统计，分不开 body/roster/toc
（实测 roster、toc 全被归 body）。但「筛正文页做指标与优化」不需要在切分前
知道——切分之后强特征就有了：**职名页的列几乎全是弹性列，正文页几乎没有**。

新增 `refine_page_type(result)`：body 且弹性列比例 ≥0.5（且 ≥3 条）→ roster。
只改标签不改切分策略。toc **不判**：卷首页（标题短列+正文列混合）与 toc 在
列占用形态上真重叠（body fill 最低 0.24 vs toc 最高 0.65），按「分布重叠就
不设阈值」的规矩放弃，如实记录。

### 量特征时抓出金标错误

body 的弹性列比例应该是 0，vol01/89、91 却以 body 身份出现在 0.33/0.67 处。
追查：**职名段界在金标里标错了**。逐页目视复核 89-95、127-133：

- 89 是职名段**首页**（勘閱繕校諸臣職名/總裁官職名/皇六子多羅質郡王…）
- 91-95 是歷任副總裁官/總纂官/提調官/日講起居注官/協勘總目官
- 127-132 是國子監學正/篆隸分校官/筆帖式/武英殿監造官
- 133 起才是凡例正文

原标（89-91 body / 92-95、127-133 uncertain）错了 17 页。「uncertain=过渡处
判不准」的说法不成立——这些页并不难判，是当初标注在段界偷了懒。修正后
roster 31 → 44、uncertain 11 → 0。

### 基线（修正后金标 394 页）

| | |
|---|---|
| roster 检出 | **41/44（93%）** |
| body 误判成 roster | **0 页**（零容忍项）|
| 阈值余量 | el≥0.5 vs body 极端 0.22 = **2.3×** |

漏判的 3 页（89 段首、90 压缩型、107）都是弹性列检出不足的已知案例
（column-layout 的 known_limitation），归 body 是可接受方向——上游弹性列
检出改善时这里自动跟着变好，不用再动。

### 方法论

**特征量出反常值，先怀疑金标再怀疑算法。** 「body 的弹性列比例 0.67」有
两种解释：算法把正文列判错了，或这页根本不是正文。先看图再定——这次是
后者。金标错误对判据设计的伤害是双向的：不修正，阈值就得迁就 0.67 这个
假极端，余量从 2.3 倍被压到 1.3 倍。

### 附：page_type 也被 pass 替换丢掉了（同一家族的第三次发作）

第一次实现时打印「细化 132/164 页改判 roster」——vol02 全书正文，绝不可能。
追查：Pass 2a 起各 pass 用 `segment_page` 的返回值**整体替换** `results[stem]`，
Pass 1 写进去的 `page_type` 就丢了；Pass 2a3 曾「显式保留」，但它保留的是
上一个 pass 已经丢掉后的 **None**（实测 69 页写盘成 None，正好等于
inset_fixed_pages）。而 refine 对「键缺失」默认 body、把补齐误计成改判，
打印数字全是假的。

这是同一结构问题的第三次发作（第一次 cell_h、第二次 period/inset，见前文）。
逐个 pass 补「记得保留 X」已被证明会漏——治本是**把跨 pass 的状态放在
results 之外**（`ptypes` 字典，写盘前统一盖章）。凡是「segment_page 返回值
之外还要活过多个 pass」的信息，都该这么放；下次再加这类字段时不要再走
「在每个 pass 里保留」的老路。

## 弯折界行的逐带围栏 + 夹注隔离 + toc 判别的负结果（2026-08）

### 1. 弯折界行：围栏逐带各自走

vol02/151 一条界行沿页高横向漂 49px（逐带中心 172→182→192→203→211→221），
任何一条竖直裁切线要么在某些高度裹线、要么在另一些高度切字——这是此前

修法出乎意料地不需要「轨迹跟踪」：`cell_bounds_from_rules` 的围栏本来就

矩阵）重走一遍即可——墙在哪条带就停在哪条带，链接是隐式的。各带围栏彼此
差超过 CELL_BOW_T(3px) 才输出 `cell_bands`（逐带裁切边），直边界保持扁平
表示，schema 向后兼容。extractor 端按带把墙外像素抹白（在归属之前做，
弯线不进连通体分析）。

实测 p151：列格 0 右墙 164→190、列格 1 左墙 199→229（同一条漂移线的两侧）、
右墙 355→338（另一条反向漂 17px 的线），全部贴线。

### 2. 夹注/双行小字：检出 + 隔离（轻量方案）

定位（按用户要求）：**不是当前重点，只求不污染下游**。不做子列切分与 OCR
（那是旧文档 jiazhu_detection.md 的全量方案），只做检出 + flag + 聚类隔离。

单格几何险些又重蹈 boundary_ink 的覆辙——「夹注行」与「左右结构字」（部/
郎/剛）在缝宽、子列宽、字高上全部重叠。救回来的是两个观察：

- **span**：夹注两个子列合起来**占满列宽**（0.99~1.0），单字只占 0.60~0.70
  ——唯一天然不重叠的量（物理原因：夹注就是把一列劈成两半用）；
- **列上下文**：夹注是列区域现象，连续多格双列形态、缝中心对齐（±8px，
  图块按列条带裁、x 同系可直接比）；散在的左右结构字对不齐。

判据 = span ≥0.85 ∧ 缝 ≥3px ∧ 两侧均衡 ∧ **连续 ≥2 格缝对齐**。实测命中
vol02 241 块（「永樂大典本/通志堂本/黃氏本」版本注）、vol01 123 块（职名页
双行结衔），抽 18 个目视 ~90% 为真。落 `jiazhu` flag（疑似层）；clusterer
把它并进已有的隔离机制（强制单例）——**不进簇、不丢数据**。

| | 最长列 fill p5 | med | 反例 |
|---|---|---|---|

不可分**。真正分得开的证据在内容层——toc 每列以「卷X」结尾，G5 的 OCR
出来顺手就能判。移交，不在几何层硬造第三个特征。

## 弯折/磨损界行的放宽档围栏 + 行相位「盖不住内容」惩罚（2026-08）

### 放宽档围栏（第一刀）

严格档竖线判据（游程 ≥1.2×列距）对**磨损断裂**的界行残段（实测 122~197px）
是瞎的，「无墙不敢扩」于是拒绝外扩——vol02/119 col7 整列的字被切。加放宽

### 行相位惩罚：一个改动养出来的三条病，各自一刀

## 归属整片错删的治理：中央带否决 + 穿行保护（2026-08-24，用户实审反馈）

  保留；只有带内有墨的 x 才抹。「只裁横条本身，不动与它连通的字」。

**探针的教训**：第一版探针把格上下边缘带也算「核心区」，3574 的大数

## 抬头行：清代官书的多级抬头让列字数不是 21（2026-08-25，用户 p32/p33）

用户报 p32/p33「有抬头，导致一页多于 21 个字」。查证属实且是**漏字**
硬伤——比框渣严重：清代官书的抬头制遇尊称要提行顶格甚至高出一到三格
（平抬/单抬/双抬），抬头列因此多 1~2 个字位；网格按书级
`chars_per_line=21` 固定行数时，抬头字**整字掉在网格顶之外**。
实测 p33 col5-9 网格上方各有 120~150 行墨全是没切进去的字。

**检出**（`head_raise_rows`）：拟合出 21 行网格后，量各文字列在网格顶
之上的**最长连续墨段**。常规页那里只有版框线（全书 p50=8px、p90=22px），
抬头字是整格高的连续墨（实测 0.63~1.98 格）。≥0.55 格的列达 2 列
判抬头页（抬头成片出现，单列多半是噪声）。

**修法**：补行后**重拟合**，而不是把网格硬往上挪。21 行拟合时抬头墨把
相位拉成两不靠的折中值（p32 实测：抬头字在 285-390、普通列首字在 ~500，
拟合给出 409，谁都不对齐）；补行后网格能同时覆盖抬头字与正文，相位
自己归位。补行数受版框顶约束，最多 3 行（清制最高三抬）。

**实测**：p32/p33 各补 1 行 → 22 格，抬头字（天/太/賫/祖/開）正确落进
第 1 格，普通列第 1 格空着（框线区，交给列端渣格闸与框渣剥离）。

**分型（重要）**：全书 11 页候选（vol01 8 / vol02 3）只有一部分能靠
网格层修。p50/p70/p195 型的抬头字**在裁剪窗之外就被切掉了**
（实测 y1=188/353/48，框顶 ft 落在窗外为负），crop 里根本没有那些墨，
网格层无论怎么扩行都够不着——根因在 s3 的 content_range 按主体墨带定
上边界，孤悬在上的抬头字被当窗外噪声。那一型另立专项（见任务 #22）。

## 列端曲线切边：图块的边不必是直线（2026-08-25，用户定）

用户看过框渣剥离结果后提的：

> 最好还是做成一步……让最后这一个字它就不是一个方框，它可能是一个曲线
> 或弧线的一个边框，这样在截这个方框时，它的最下边这个边就直接不要去
> 取到它的下边框。

`carve_end_edge`：列末切下边、列首切上边，沿一条**紧贴字身外沿、绕开
版框**的路径切，路径以外抹白。复用曲线切分那轮的 `_min_ink_path`——
它在「分离上下两字」上是负结果（路径钻进下字的无墨走廊），用在「绕开
版框」上却正好对路：框线是横贯的直条，字底与框线之间几乎总有低墨走廊。
比矩形剥离强在能绕开**侧下方**的框线断段（与字身垂直位置重叠，矩形
判据够不着）。

**红线写成硬约束**：路径每一列都必须在该列**字身墨的最低点之下**
（+margin），所以字一个像素都切不到——连「从字内部空隙穿过去」这种
绕法都被禁掉（首版没有这条约束时，路径就从字的笔画间隙钻了过去）。

**两次踩坑，都是「什么算字身」判错**：

1. **形态学膨胀不行**：首版用 3px 膨胀判「紧邻部件」，把「黙」的四点底
   整个抹掉了——灬的点与最近笔画的**像素距离**远大于它们的 bbox 间隙。
   改用 bbox 垂直间隙（实测灬 -5~-2px 与字身重叠、框渣 +2~+28px 在其下）。
2. **只看间隙也不行**：「覽」下部与主体断开（刻本墨色不匀）的两条腿
   间隙 5px，被当框渣切掉，recrop 金标立刻抓到（20→19 过、覆盖率 0.85）。
   两组几何实测——框渣高 1~11px（版框线本来就薄）、面积 56~302；字的
   部件高 27~61px、面积 416~867。可切条件遂收紧为「间隙 ≥1 **且** 高
   ≤10 **且** 面积 ≤200」。

**实测**（frame-strip 65 条）：残余率 19%→**9%**、误剥 **0%**、字身墨
**65/65 保全**；recrop 20 过、误报 16%。大块框线残段（高 36~43）切不掉
是有意的保守档——宁可留框渣绝不切字，相比矩形剥离的 19% 仍是一半。

**只切最外一格**：`order[:2]` 与 `order[-2:]` 在短列里会重叠，按 end_cand
切会把列首格**下方的邻字残余**当版框切掉（合成用例实测）。

## 侧边界行残余剥离：判据搬到「文字带之外」（2026-08-25，用户 r7）

用户审完 18 页新批（vol01 4/18/53/70/84/142，vol02
7/9/29/51/52/75/92/105/115/138/144/171，共 2880 个实例）后说：

> 标完 有一个自检太多了 我就没消除 还是有很多侧面边框误入
> 然后有一页左边小注 被竖着切断

三件事分别对应下面三节。先看「侧面边框误入」——用户判「切错」的
52 格里，**20 格**是图块左右缘吃进来一条竖线（vol02/115、vol02/171 是
整列整列地中招）。

### 为什么会漏进来

图块条带按 `cell_left_x`/`cell_right_x` 裁，那条边是「从文字带往外扩、
扩到撞上竖线结构为止」（`cell_bounds_from_rules`）。界行磨损断裂时那道
墙检不出来，条带就一路扩到列格名义边界，把界行整条圈进图块。列端框渣
那一轮（`strip_frame_debris`/`strip_frame_stub`/`carve_end_edge`）只管
**上下**，侧边一直没人管。

### 判据：只按形状必砍字

「细高、贴图块边缘、与字身不连通」这组几何条件**单独用不成立**。本批
71 个这样的候选里，混着大量字自己的竖笔——忄的左竖、阝、川、而 的边竖
都是与主体断开的细高连通体，其中一个正是用户判**对**的「訓」字最右竖。

分得开的是**位置**：文字带（`left_x`~`right_x`）是「正常居中字」的范围，
界行按定义在带外的留白里；字的竖笔无论多细都在带内。实测：

| 候选落点 | 条数 | 落在用户判错的格 | 落在用户判对的格 |
|---|---|---|---|
| 完全出文字带 | 33 | **28** | **0** |
| 带内 | 34 | 10（多是别的毛病）| 1（「訓」的川字竖）|

`strip_side_rule(patch, x0, text_x0, text_x1)` 于是只剥「**中心**落在
文字带之外」的细高连通体（`w ≤ 12`、`h ≥ 2w`、`area ≥ 40`），主连通体
永不参与——红线不变。判「中心」而不是「整条」，是因为最外一列挨着的
版框线常常正好压在文字带边上（vol02/171 col1 的框线 1653~1660、带边
1653.7，差 0.7px），按整条判会全数漏掉；改判中心后本批命中的判错格
17→21，误伤的判对格仍是 **0**。

还有第二条闸：**竖条近旁（12px 内）不许有字料**。带外并非只有界行——
职名列贴着界行写的「臣」、以及（本轮宽缝补完之后）宽过文字带的夹注
左子列，都住在带外，它们的外沿竖笔同样细高、同样出带。区别在**距离**：
界行与字之间总隔着一段留白（本批实测最近的字身也在 17px 之外），而字的
外沿竖笔身后紧挨着这个字剩下的部分（隔几个像素）。

「字料」的定义调了三版，每一版都是被自摆的乌龙逼出来的：

1. 「竖条与文字带之间不许夹着墨块」——凡是**笔画伸出文字带**的字
   （「作」的右竖、「人」的捺、「朱」「公」的末笔）都把自己算成挡路的，
   25 条正样本放过 5 条。改判**距离**。
2. 距离 + 「够大就算」——同一条界行常断成好几段，细高的成了候选、
   矮胖的没成，两截**互相挡住**谁也剥不掉。加「宽 > 12」。
3. 距离 + 「宽 > 12」——版框拐角那截**横**的框线又宽又矮（实测
   24×9），照样把紧挨着的竖线挡下来。最终定为「**两个方向都 > 12**」：
   线状的东西一律不算字料，字料在两个方向上都有厚度。

留下两条有意的保守漏网（vol02/138 的「郎」「人」两格）：框线断段确实
紧贴着阝的竖笔，12px 之内。宁可留框渣，绝不切字。这是**第三次**把判据搬到图块之外还奏效：列外墨率（框线断段）、
上下探针（版框横线）、文字带位置（界行竖条），三次都是「图块自己看不出
来、放回版面里一眼就分得清」。

**实测**（新建分片 `char-segmentation/side-rule` 265 条）：残余率
**25/25 → 2/25**（剩两条是有意的保守漏网，见下），误剥 **1/240**
（那一条是基线错位：该格的窗口被宽缝补齐改过，不是真剥），字保全
**262/262**。

回归口径：frame-strip 0/55、0/10、65/65 全平；recrop 20/24 不变；
page-geometry 38/39 不变；instances 检出 27%、精确 54%→**55%**、
误报 17%→**16%**。整册 flagged：vol01 3134→**2902**（−7%）、
vol02 5668→**4932**（−13%）。

## 异常宽列缝：夹注写得比文字带还宽（2026-08-25，用户 r7）

「有一页左边小注被竖着切断」定位到 vol02/171 col2——四库提要的书名列
「周易傳義附錄十四卷」下面挂着双行夹注「兩江總督／採進本」。

双行夹注写满整个列格：两个子列合起来跨 170px，而文字带只有 136px。
这一侧既没界行也没墙，围栏「无墙不敢扩」把窗口停在文字带上，**左子列
被竖着切掉 37px**。连锁反应：`_jiazhu_gap_center` 的两侧墨量均衡检查
随之落空，整列压根没拆成 a/b——一格里挤着「採」和「兩」两个小字。

判据不看单列，看**列缝**：正常缝 9~15px，这种漏扩的缝 44~75px，全书
387 页只有 **27 条**。`_widen_wide_gutters` 把缝两侧的边界一起挪到缝内
**最宽空白段的中心**——空白段是版面自己给出的分界，比名义中线可靠
（p171 的空白段中心 1285，名义中线 1309 仍要切掉 9px 小字）。

三个细节，前两个是踩出来的：

- **必须逐带算**。首版用整页投影找空白段，p171 恰恰量出 **0px**——
  摆正（deshear）之后页面仍有残余弯曲，同一条缝在页顶和页底差十几个
  像素，整页一投影就糊成一片。改成按围栏那套 `spans`（6 条带）逐带
  找、写进 `cell_bands`、扁平边界取包络，与「弯的界行」分支同一套口径；
  夹注所在的那两条带立刻量出 8px 空白段。逐带还有个额外好处：只有
  夹注那一段的窗口变宽，同列其它高度照旧，不会把邻列的正文圈进来。
- 投影要先滤掉**版框横线行**（`行墨率 ≥ FRAME_ROW_T`）。上下框线横贯
  全宽，不滤则每个 x 都有墨、空白段永远量不出来。
- 空白段窄于 `GUTTER_MIN_BLANK`(4px) 就不动——证据不足时宁可维持现状。

### 连带修好的：夹注跨度改用列距当尺子

宽缝补齐之后 vol02/171 col2 的窗口从 150px 变成 202px，同一段夹注反而
**判不出来了**——`_jiazhu_gap_center` 的跨度比拿**图块宽度**当分母，
窗口一宽比值就掉（0.88 → 0.83，门槛 0.85）。

尺子换了两次才对：

1. **换成文字带宽度 → 灾难**。文字带的定义就是「正常居中字的范围」，
   任何一个正常字的跨度除以它都接近 1，判据直接失效：vol01 的夹注列
   从 10 列涨到 36 列，涨出来的全是「如=女+口」「外=卜+夕」「頗=皮+
   頁」「郭=享+阝」这种**左右结构被拦腰劈开**。抽样图一眼可见。
2. **换成列距（period）→ 对了**。列距是书级刚性常量，与窗口宽窄无关，
   又恰好接近原先标定用的图块宽度，两头都占。

顺带把「缝要在中段」和「单侧不超过 0.6」改成按**墨迹跨度**算（同样的
道理：图块两侧留白多少不该影响判据）。

尺子定下来之后重新标定门槛：两册抽样 4023 个格，普通字的跨度/列距
中位 **0.592**、95 分位 **0.676**，夹注在 **0.78~0.97**。原门槛 0.85
会漏掉写得略窄的夹注——vol01/184 col9 的「陰陽五行／相宅相墓」量到
0.785，正是用户 r6 报的那一列。下调到 **0.75**：上面四页左右结构仍
全部拒判，抽样 30 页拆出的列数一格没变，而 vol01/184 col9 拆开了
（**#23 结案**）。

## 上下接壤：先造尺子，再动刀（2026-08-25，#27）

### 一、病名是猜的，不是量的

待办 #27 写的是「vol02/92 型**行相位漂移**，col1/3/4 的 idx=18 齐中招」。
量了才发现：那一页每列只有 17 个 char 格、末格序号正好是 **18**——所谓
「中段相位漂移」其实是**列尾格**，跟 #28 同族，早在版框带内缘钉桩那一轮
就修掉了。病名从一开始就挂错了。

### 二、造尺子：切缝墨率

「上下接壤」这一族——邻字的墨蹭进本格、本字的尾巴留在隔壁——根子是同
一件事：**两格之间那一刀切在了笔画上**。这件事不需要人工标注：

```
切缝墨率 = 平滑列投影(格线 y) / max(min(上格峰, 下格峰), 0.35 × 本列峰中位)
```

两个分母细节都是被实测逼出来的：

- 取上下两格的**较小**峰——一刀要同时挨着两边的字才叫切在字上；只挨
  一侧的是列端/空格，不该进指标。
- 再用本列峰中位兜底——稀疏邻格（一个「一」字）会把 min 压到极小，比值
  直接放飞。不兜底时 `clean` 格的比值最高到 **3.6**。

比值 ≥ **0.7** 记一条「重切缝」。落地在 `scripts/eval_seam.py` +
数据集分片 `char-segmentation/seam`（正文 294 页，全自动无需标注）。

### 三、先撞了一次「拿漂了的标签验尺子」

第一反应是拿 `instances` 的人工标签验（`grid_shift` + `neighbor_residue`
共 25 条当正例、`clean` 216 条当负例）。六种归一化写法全试：

| 写法 | AUC |
|---|---|
| /min(上下峰) | 0.320 |
| /本列峰中位 | 0.313 |
| /上下格均墨 | 0.300 |
| 绝对墨率 | 0.305 |
| 谷深 | 0.432 |
| 离最近谷底的距离 | 0.530 |

**全部 ≤0.53，最好的还不如抛硬币。** 差点据此判尺子无效。

真正的原因写在那份 README 第一段：**「人工标签描述的是当前输出的质量，
重跑切分后标签就不再对应，因此它不能当作可自动重跑的切分回归基准。」**
这批标签是 r4~r9 之间标的，中间整册重切过好几轮。AUC 0.32（**反相关**）
恰恰是「正例多半已被后几轮修好、负例反倒漂坏了」的形状。

**教训**：验一把新尺子之前，先确认手里的标签还挂得住。会漂的金标不能
用来判尺子的死活，只能用不漂的量 + 人眼。

### 四、动刀：无谷时的微挪

`snap_bounds_to_gaps` 本来就逐条把格线吸附到字间空隙，但有一条一票
否决：**谷底墨量仍高于相邻两格均墨的 0.35 倍 → 判为「这里没有空隙」，
原地不动。**

这条否决的**理由**是防止大幅滑动把整个字送给隔壁——可它的滑动半径
本来就只有 0.10 格高（≈11px），而半格是 57px，根本够不着邻格的空隙。
也就是说：**这条否决保护的东西，在这个半径下根本不存在风险**，它唯一
的实际效果是让线在「上下两字连着」时**彻底不动**。

量一下它留下多少钱：正文页 1685 条重切缝里，只要允许挪 6px 就有 926 条
能显著变瘦；位移中位数只有 6~10px——刀差的就是这么一点。

于是加第二档 `_micro_slide`：**没有谷的时候，仍在 ±SNAP_TIGHT 格高内
挪到墨最少的一行**，且要求墨量明显下降（≥SNAP_TIGHT_GAIN×参考墨）才动。
后一个条件是防止在平坦区抖动——产物必须在无关重跑之间稳定。

### 六、挪动是散点，不是整列——排除了「替相位擦屁股」

### 七、这条闸不能证明什么

## 文字带窗口塌陷：静默丢掉三分之二页（2026-08-25，#22 一族）

### 一、量出来才看见

待办 #22 写的是「p32/p50/p70/p195 的**抬头字**落在 content_range 窗外」。
真去量才发现抬头字只是这个病最轻的切面。列的纵向窗口来自 phase2
`inner_frame` 的上下界；版面检测把**正文中间的某条横线**当成上框或下框
时，窗口能塌到只剩三分之一页，窗外的字全部判空、**静默丢掉**。

判据仍然是那条走了四次的路——**把判据搬到图块之外**：

```
应有窗口高 = 每列字数 × 书级格高（全书 cell_h 中位）
窗口比 = (inner_frame.bottom − inner_frame.top) / 应有窗口高
```

不设任何像素阈值，是网格模型跟页面几何的直接比较，因此不受污渍、墨色、
扫描亮度影响（横向截断那次栽在像素阈值上，见「截断到底解决没有」一节）。

实测 294 张正文页，窗口比 <0.9 的有 **21 张**：

| 页 | 窗口比 | 字格（正文中位 168）|
|---|---|---|
| vol02/77 | 0.302 | 71 |
| vol02/97 | 0.322 | 47 |
| vol02/67 | 0.324 | 87 |
| vol02/18 | 0.341 | 98 |
| vol02/153 | 0.352 | 54 |
| vol01/70 | 0.483 | 101 |
| …共 21 张 | | 按中位估算丢 ≈1276 格 |

画出 `inner_frame` 叠图核实过：这些页的上下界确实落在正文中段，
而正文铺满整页。**这是目前锤到的最大一处静默数据损失**——比窄页
（≈400 字）和 page-crop（387 条）都大。

### 二、修在哪一层：不是 phase2

手册 §8 给的接手提示是改 `border_detect` 的外框判据。真做下去代价很大：
改完必须从原图重跑受影响页的 s2~s6 + phase2 + 全下游，**页面坐标系一变，
四个金标里落在这些页上的样本全部要按漂移协议重核**。

换个位置就便宜得多：**phase3 本来就知道 inner_frame 不可靠**
（`content_range` 的注释里写着「版面检测的 inner_frame 常有偏差」），
而且 phase3 手里有书级格高共识、有 `measure_row_frames`、有多 pass 的
「共识 + never-make-worse 择优」骨架。于是新增

**Pass 2a4：窗口塌了就整页放开重扫**

1. 用书级格高算出应有窗口高，挑出窗口比 <0.90 的页；
2. 这些页用 `band_override=(0, 页高)` 重切——让投影自己定文字带；
3. 逐页 never-make-worse 择优：字格数必须真的涨，且骑线比要么本身
   ≤0.35（全书中位 0.38）、要么没比原来糟过 0.05。

放在 Pass 2a 之后是因为要用书级格高；21 张坏页拉不动 ~200 页的中位，
不必为它再多做一遍共识。

### 三、踩到的两个坑

**坑一：后续 pass 会把救回来的窗口再裁掉。** 手册里写过「改了共识，就要
把共识透传到后续所有 pass」——这次轮到窗口。2a2/2a3/2a-bis/2b 都会重跑
`segment_page`，不带 `band_override` 就会重新去读 layout 的 inner_frame。
加了 `band_prior` 字典，跟 `row_prior`/`col_prior`/`ins_prior` 并排透传。

**坑二：`grid_meta` 在列网格分支里被整个重建过一次**（只保留 `shear`），
写在那之前的键全丢。`band_widened` 标记第一次就写错了位置，跑完两遍
整册才发现产物里根本没有这个键。写在重建之后才生效。

### 五、金标漂移：vol01/70 的十条重键

vol01/70 被救回来之后整列多出一行，`page:col:idx` 上挂着的 11 条

### 六、闸门自己也会冤枉人：切缝闸的单页判据

## recrop 无声放行三例：缝边归属的三个漏洞一次补（2026-08-26，#29）

## 无偏正确率复量 r3 + 骑线复切（2026-08-26，#39）

### 一、先扩样本：n=200 已经问不出新东西

（r3 里 vol02/108 一页就贡献了 2 个缺陷），每页抽满会把方差撑大。

**结果 394/400 = 98.5%，Wilson 95% [96.8%, 99.3%]**，与 r2 持平——
r2 修掉的两类本来就稀有，没指望它们抬动整体。价值在病灶谱：

| 类 | 数 | 例 |
|---|---|---|
| 切缝相位错 | **5** | 上邻残留 vol01/50:1:1（欽的下部混进「定」）、跨格 vol02/93:8:20（參/之）、两字一格 vol02/108:6:15「學正」与 6:17「朗順」、截断 vol02/145:5:1（「易」的日被切掉）|
| 界行残余 | 1 | vol02/118:9:16 右侧一条竖条 |

相位类是**唯一还成规模的病灶**，而且 4/5 已经被 `boundary_ink` 旗中：
**旗是准的，只是没人去修**。这一轮就修它。

### 二、为什么刚性网格修不动这一类

主路径是 `rigid_bounds`：整列只有「一个格高 + 一个相位」两个自由度，
再靠 `snap_bounds_to_gaps` 逐条吸附。吸附半径只有 `SNAP_RANGE=0.10` 格
（≈11px），刻工手写上版一列 20 字漂半格很常见——**漂出半径之后吸附
就够不着了**，格线只能骑在字身上。

弹性 DP（`dp_boundaries`）本来就在模块里，每格高度可 ±elastic 伸缩、
全局最优，正是为这种累积漂移设计的，但只挂在 `segment_column` 这个
旁路上，生产路径根本没走。

### 三、做法：骑线才复切，且必须锚住首末线

```
骑线比 = 内部格线上的平滑墨 / 格中心的平滑墨
```

首末线不计——它们贴版框，墨来自框不是骑线，算进去每列都判骑线。

- `RECUT_STRADDLE = 0.45`：骑线比 ≥ 此才试复切（全书中位 0.10）；
- `RECUT_ANCHOR = 0.30`：复切后**首/末线**位移 ≤ 0.30 格才算数；
- `RECUT_GAIN = 0.75`：线上墨须压到原来的 0.75 以下才采纳。

锚定护栏是这条设计里最要紧的一条。DP 若把整张网格整体滑掉半格，
线上墨照样会降——那不是复切，是把**每个字都让给隔壁**，比骑线更糟。
实测 612 次触发里 **328 次就是被锚定否掉的**（一半以上），52 次被增益
否掉，采纳 232 次。没有这道闸，这个改动会是净负。

### 四、踩到的两个坑

**① 常量重名被静默覆盖。** 第一版把常量取名 `STRADDLE_OK` /
`STRADDLE_GAIN`——同模块下面 50 行处 Pass 2b 早已占了这两个名字
（页级骑线门槛 / 绝对改善量）。Python 后赋值胜出，采纳门槛于是变成
`0.10`，612 次触发只采纳 4 次。**不报错、不告警，只是几乎不生效。**
改名 `RECUT_*` 之后才看见真实效果。

**② 页级闸读的质量分被列级修污染了。** Pass 2b「行相位重扫」用
`straddle_score` 当触发闸，而列级复切干的正是压低这个分。两者一叠，
几条列被局部救好就把整页的相位病瞒了过去——实测 vol02/102 复切采纳
3 列后重扫不再触发，该页**另外 4 列**骑线比从 0.20/0.51 涨到
0.40/0.96。这是「结构性对冲」的新形态：不是坐标基准被挪了，是
**判据本身被下游的修复污染**。治法是把复切**前**的比值存进列结果
（`straddle_pre`），`straddle_score` 一律优先读它——页级相位本来该看的
就是「刚性网格对不对得上」，那正是复切前的值。

## 用户实审 vol01/50、60：抬头页相位 + 页级尺子（2026-08-26）

用户点名这两页做测试，说「似乎结果很差」——**结果确实很差，而我报的
99.25% 没错**。两件事都成立，因为它们量的不是同一个东西。

### 一、先把「差在哪」量清楚

`vol01/50` c1：字身从 y=6 起、格边从 92 起，**整列差 86px（0.75 格）**，
21 格里 7 格骑在两字之间；c2 差 44px。c3~c9 全对。
`vol01/60`：缺陷散在多列，seam 重切缝 **16.4%**（正常页 0%）。

当时我把根因判成**抬头页**：上諭页的「朝」「欽定」比正常起排线高出
大半格，各列起点不同，一个页级相位套不住所有列；而 `rigid_bounds`
只在页相位 ±0.12 格（≈14px）内微调，86px 够不着。

**这个判断只对了一半**（下面第七节有实测）：
- **c2 确实是相位病**，逐列相位一刀修好——重切后整列
  「本集首卷庶眉目清而開帙了然將此諭令館臣遵…」每格一个整字（已逐格看图）；
- **c1 不是相位病**。逐列相位找到了更低代价的相位、增益远超门槛，
  但红线闸否决了（下挪会削掉首字 43px），**否决是对的**——
  c1 的病是**这一列的字距和书级格高对不上**（实测 116.1 vs 115.2），
  20 格累积 18px，相位那一个自由度治不了。
- **vol01/60 也没修好**，它是另一种：n 与实际字数不符。两者都归第七节。

**教训重复了一次**：判「是什么病」判错了，整整一刀打在了偏门上——
c2 修好是顺带的，用户点名最狠的 c1 一格没动。

### 二、为什么抽样没报出来——不是判读太松

把这两页 12 个已确认切坏的格，按 r3/r4 判读表**完全相同的规格**重渲染，
每一个在那个尺寸下都一眼可见（红框跨两字或砍半）。r3 实际抽到过
`vol01/50:1:1`，判的就是 contaminated。**判读没放水。**

真相是**缺陷按页高度扎堆**：全书平均 1.1%（r3+r4 合并 9/800），但
vol01/50 约 13.5%、vol01/60 约 12%；r4 从 vol01/60 抽的两格恰好都落在
干净的 c4。**平均数掩盖了「有一批页是不能用的」——报数时只报全书率是
我的失误。**

### 三、修一：页级尺子（seam 闸加页级分布）

`eval_seam.py` 原先只报全书总数。加 `page_rate`：逐页重切缝率的
中位/p90/p99、以及 ≥5%/≥10%/≥20% 的页数与最差 20 页；**回归门也看它**
——总数持平但烂页变多，等于把病灶挪了个地方。

### 四、修二：逐列相位第二意见（COLPHASE_*）

窄搜之后在**整周期**内再搜一遍，代价按本列墨量归一、压得决定性地低
（`COLPHASE_GAIN = 0.60 × 本列平滑墨均值`）才改判。稀疏列代价面平坦，
自然不触发。

全书触发率（vol01，`GUJI_COLPHASE_DEBUG=1` 实测）：3610 次逐列评估里
**128 次代价够低**，其中 **92 次采纳、36 次被红线闸否决**——闸拦下了
28% 的候选，不是摆设。

**红线护栏（`COLPHASE_LOSS = 0.20`）**：第一版没这道闸，代价是丢字。
两处实证：

- vol01/50 c1：窄搜相位 0、宽搜要往下挪到 57~66，代价从 24.8 掉到 −11.4
  （增益 36.2，门槛 22.5，**远远够触发**）。但该列文字从 crop y=0 起，
  下挪之后盖住的文字 2354 → 2311，少 43px > 允许的 23px（0.20 格）——
  **首字要被削掉 43px**，红线闸据此否决。这一否决是对的（见第七节：
  这列真正的病不是相位）。
- vol01/60：九列首线整体下移 82px，seam 重切缝 **16.4% → 0.0%**、逐格看图
  「每格一个整字、全列可读」——但字格 **171 → 162**，每列的首字被整个丢在
  网格之上（col9 的「種」字身 y136~243，网格从 245 起）。

**我据此宣布过「vol01/60 已修好」，那是错的。** `seam` 这类指标会**奖励
少切字**（格少了、坏缝自然少），而只看切出来的格、不跟原图核对首末字，
就看不见丢的那个。凡是让切分指标变好的改动，**都要跟原图的墨对一遍首末字**。

护栏判据必须是**相对**的（新相位盖住的文字比原相位少多少 ≤ 0.20 格），
不能是绝对窗口——绝对窗口版本会把「原相位本来就没盖住首字、往上挪反而
多盖」的列也一并挡掉。

### 五、修三：穿边救援额度 12 → 16px

抽 60 页实测 602 个穿边组件，越出量中位 3px、**p90 = 14px**——12px 挡掉了
11.5%。r4 的 `vol02/72:1:7a`（夹注 a 半的「總」右伸 14px）就死在这 2px 上。
抬到 16px 覆盖到 p93，再往上收益迅速变平（>20px 只剩 3.7%，那一档多是
版框/界行）。拦假阳的从来不是这个上限，是 `RIGHT_RESCUE_H`（高 ≤30）与
「须从裁切边内 ≥6px 处伸出来」——上限只决定救多远。

⚠ 顺带查明 `7a` 真正没被救的原因**不是**额度：那个穿边组件高 31px，
被 `RIGHT_RESCUE_H = 30` 当界行挡掉了。全书抽样穿边组件高度中位 59px、
只有 29.5% ≤30——也就是说这道闸只救**短笔画**（撇尖/捺尾），高的一律
当界行。这是有意为之（高组件多半是「列边界画错了」而不是笔画伸出去），
**但它会顺带挡掉小字的长笔画**。要动它得先造出「笔画 vs 界行」的分片，
没有证据之前不动。记为待办。

### 六、又一次「归类错了」的教训

r4 初判把 `vol01:87:2:13` 判成「夹注未拆」，据此宣布头号病灶换成了夹注、
还定了「夹注按行判」这个方向。放大复核：那格装的是「行」的下半 + 整个
「乎」，两个都是正常大字，**是相位错**——我在缩略图上把「行」的下半读成了
偏旁「勹」。夹注判定本来就已经是按行段的（`flag_jiazhu_runs`），方向从一开始
就是错的。

**「存疑件一律放大」这条规矩，判「是什么病」时和判「有没有病」时一样要
执行。** 判错了有没有病，损失是一个样本；判错了是什么病，损失是一整轮
修复的方向。

### 七、还没治的：一个格高套不住每一列（vol01/50 c1 / vol01/60 型）

**vol01/50 c1 的病是逐列字距，不是相位。** 打开 `GUJI_COLPHASE_DEBUG`
逐列看决策，c1 的宽搜增益 36.2 远超门槛 22.5、被红线闸挡下（上面第四节），
而挡得对——真正的原因是**这一列的字距和书级格高对不上**：
用列投影自相关量实测字距（抛物线插值到亚像素）

| 列 | 实测字距 | 书级格高 | 差 | 20 格累积 |
|---|---|---|---|---|
| c1 | 116.1px | 115.2px | +0.9px（+0.8%）| +18px |
| c2 | 116.7px | 115.2px | +1.5px（+1.3%）| +30px |
| c5 | 113.1px | 115.2px | −2.1px（−1.8%）| −43px |

**同一页上各列的字距散布 3.6px（±1.5%）**，20 格累积 18~43px，接近
0.4 格——刻工手写上版，各列本来就不一样齐。相位只有一个自由度（整列
平移），治不了「越往下越偏」；`snap_bounds_to_gaps` 只能在 ±0.10 格里
局部补救，于是同一列里出现「有的格对、有的格切在字上」的花斑，正是
用户在 c1 看到的样子。

下一刀的方向已经清楚：**在页级格高之上再做一层列级微调**（±2% 量级），
和已有的逐页格高（#14）、二次页距（#17）是同一族，只是把粒度从页降到列。
本轮不动——要动得先把「列级格高」的测量做成能上闸的尺子。


**vol01/60 型：n 与实际字数不符。** vol01/60 每列 20 个字身、网格 21 格，看似绰绰有余，但**唯一让每一刀都
落在字缝里的相位，会把首字甩出网格**。这说明格高与该页实际字距有系统
偏差（累积一格），不是相位能解决的——要么让 n 随列伸缩，要么让格高逐列
微调。护栏现在把这类列**原样留着**（宁可骑线，不许丢字），因此 vol01/60
在 seam 上仍是 16%。这是有意的取舍，不是漏修。

同类旁证（**逐列相位之前就存在**，不是这一刀带出来的）：`vol01/88` c2
首字「曰」字身 y 29~106，而该列网格从 y=109 起——这个字在改动之前就已经
整个落在网格之外。全书正文页红线普查（字身段落完全落在网格外的列）共
10 列，集中在 vol01 的 47/48/49/52/82/88，逐一核对过：**没有一列是逐列
相位新造出来的**，全部属于本节这一类。

### 九、金标重键一例：丢字判据分不出「真丢」和「漂一格」

**不是丢字**：该列旧网格首线 y=2（整列比字身高出近一格），把「易」切成

### 版式知识备忘（用户口授）

- 双行小注奇数字时，**末行单字在 a 行（右）**；
- **空格一般在行首**（低格起排、抬头避讳），列尾一串空格是切分错误
