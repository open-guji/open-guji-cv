## 为什么旧条目不迁、为什么重扫是对的

1. **没有任何图像凭证**：这分片从来不是人标的——README 说是「全书扫描机扫」，判据是纯墨迹（连通体穿裁切边）。
   没存图块、没存指纹、没存 v1 页图到原图的映射。条目只是 v1 页图坐标系里的几个数。
2. **判据的一半是裁切边本身**：穿边点的定义依赖 `cell_left_x`（v1 裁切边，2026-08-28 起随裁边修复整体平移过一次，
   README 自己记了「金标锚点本身也该修，锚到列的裁切边」——未做）。v2 的裁切边是 Step3 `content_x`，换了一个东西。
3. 所以正确做法是**用同一条判据对 v2 列图重扫**，而不是把 v1 的点硬搬过来（没法证明搬得对）。
   这是「无监督/冻结基线」型，不是人标金标，重扫不违反「不硬造金标」。

## 重扫判据（`scan_cut_crossings_v2.py`；常数直接 import `clustering/extractor.py`，不另抄）

连通体从裁切边**外** ≥4px 连进格内 ≥6px；高 ≤30；面积 ≥25；**宽 ≤45 且不贴探测窗左缘**（排横向栏线）；
离列图上下端 >12px。裁切边 = v2 Step3 `content_x[0]`；坐标=列图（左上原点），列号右起 1；`extent`=穿边组件左端 x。
扫描范围：page-type 金标 body 页（vol01 108 + vol02 186 = 294）**去掉用户排除页**（vol02/3、vol01/89/90、vol02/159/160；
2026-08-25 用户定「不判读、不入测试集」）= 291 页（实际 vol01 89/90 不是 body，所以剔掉的是 vol02/3、159、160 三页）。
被测：v2 `cell_shrink` 产物里非夹注半格、`cell_type=="char"`、y 区间含穿边点±2 的格，取最左紧框 `bbox_col[0]`，须 ≤ extent+2。
